# Domain 05 — Laboratory & Diagnostic Imaging Management

เจ้าของข้อมูล: Domain 05

รับผิดชอบกระบวนการตรวจวิเคราะห์ทางห้องปฏิบัติการและการตรวจวินิจฉัยด้วยภาพของคลินิกสัตวแพทย์อย่างครบวงจร ตั้งแต่การบริหารทะเบียนรายการตรวจและชุดตรวจ (Test Catalogs & Panels) ช่วงค่าอ้างอิงหลายสายพันธุ์และหลายเงื่อนไข การรับคำสั่งตรวจวินิจฉัยและการส่งตรวจห้องปฏิบัติการภายนอก (External Reference Labs) การเก็บตัวอย่างทางชีวภาพ การแบ่งตัวอย่าง (Aliquoting) การตรวจสอบและรับเข้าหรือปฏิเสธตัวอย่าง การบันทึกการเคลื่อนย้ายตัวอย่าง (Chain-of-Custody) กระบวนการตรวจวิเคราะห์ การบันทึกผล การตรวจสอบและรับรองผล 2 ระดับ ประวัติการแก้ไขผลหลังรับรอง การแจ้งเตือนผลผิดปกติและค่าวิกฤต การตรวจซ้ำ (Retest) กระบวนการตรวจเอกซเรย์และอัลตราซาวด์ การจัดเก็บภาพทางการแพทย์และ DICOM/PACS Metadata รายงานผลวินิจฉัยด้วยภาพและการติดตามการเปิดดูภาพ ไปจนถึงทะเบียนเครื่องมือ การบำรุงรักษา การสอบเทียบ การควบคุมคุณภาพภายใน (IQC) และการบันทึกการใช้วัสดุและน้ำยาห้องปฏิบัติการ

ทั้งนี้ Domain 05 ยึดหลัก **Single Source of Truth (SSOT)** โดยเป็นเจ้าของข้อมูลรายการตรวจ ตัวอย่างทางชีวภาพ งานตรวจวิเคราะห์ ผลตรวจทางห้องปฏิบัติการ ภาพทางการแพทย์ รายงานผลวินิจฉัยด้วยภาพ และเครื่องมือ/คุณภาพการตรวจ ส่วนการตัดสินใจทางการแพทย์และคำสั่งรักษาอยู่ที่ Domain 03 (`clinical`), ทะเบียนบริการกลางและราคาบริการอยู่ที่ Domain 00 (`core`) และ Domain 07 (`billing`), ทะเบียนสินค้า ล็อต และยอดสต็อกน้ำยาอยู่ที่ Domain 04 (`pharmacy`), และการจัดซื้อ/ผู้ให้บริการแล็บภายนอกอยู่ที่ Domain 09 (`procurement`)

## กลุ่ม Test & Imaging Catalog, Parameters, Reference Ranges & Panels

### ตาราง `laboratory.diagnostic_test_categories`

**หน้าที่**: จัดเก็บหมวดหมู่ของรายการตรวจทางห้องปฏิบัติการและการตรวจวินิจฉัยด้วยภาพแบบลำดับชั้น (Hierarchy) เพื่อจัดกลุ่มรายการตรวจ การค้นหา และการออกรายงานวิเคราะห์ปริมาณงานตรวจ

#### โครงสร้าง Field:

| Column               | Data Type    | Constraint                                       |
| -------------------- | ------------ | ------------------------------------------------ |
| `category_id`        | UUID         | PK, NOT NULL                                     |
| `parent_category_id` | UUID         | FK → laboratory.diagnostic_test_categories, NULL |
| `category_code`      | VARCHAR(30)  | UNIQUE, NOT NULL                                 |
| `category_name`      | VARCHAR(150) | NOT NULL                                         |
| `category_name_en`   | VARCHAR(150) | NULL                                             |
| `category_domain`    | ENUM         | NOT NULL                                         |
| `sub_discipline`     | ENUM         | NOT NULL                                         |
| `description`        | TEXT         | NULL                                             |
| `display_order`      | SMALLINT     | NOT NULL DEFAULT 0                               |
| `status`             | ENUM         | NOT NULL                                         |
| `created_at`         | TIMESTAMPTZ  | NOT NULL                                         |
| `created_by`         | UUID         | FK → hr.employees, NOT NULL                      |
| `updated_at`         | TIMESTAMPTZ  | NULL                                             |
| `updated_by`         | UUID         | FK → hr.employees, NULL                          |

#### ข้อกำหนด:

- `category_id`: รหัสประจำหมวดหมู่รายการตรวจ ใช้เป็น Primary Key
- `parent_category_id`: รหัสหมวดหมู่หลัก อ้างอิง `laboratory.diagnostic_test_categories` (เป็น `NULL` เมื่อเป็นหมวดหมู่บนสุด)
- `category_code`: รหัสหมวดหมู่ทางธุรกิจ เช่น `LAB-HEM`, `LAB-CHEM`, `IMG-XRAY`, `IMG-US`
- `category_name` / `category_name_en`: ชื่อหมวดหมู่ภาษาไทยและภาษาอังกฤษ
- `category_domain`: โดเมนย่อยของการตรวจวินิจฉัย (`LABORATORY` สำหรับงานห้องปฏิบัติการ, `DIAGNOSTIC_IMAGING` สำหรับงานภาพวินิจฉัย)
- `sub_discipline`: สาขาวิชาการตรวจ ค่าที่เป็นไปได้ คือ `HEMATOLOGY`, `BLOOD_CHEMISTRY`, `URINALYSIS`, `FECAL`, `MICROBIOLOGY`, `IMMUNOLOGY`, `CYTOLOGY_HISTOPATHOLOGY`, `PARASITOLOGY`, `ENDOCRINOLOGY`, `COAGULATION`, `XRAY`, `ULTRASOUND`, `ECHOCARDIOGRAPHY`, `CT_MRI`, `ENDOSCOPY`, `OTHER`
- `description`: คำอธิบายขอบเขตรายการตรวจในหมวดหมู่นี้
- `display_order`: ลำดับแสดงผล
- `status`: สถานะใช้งาน (`ACTIVE`, `INACTIVE`)
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit อ้างอิง `hr.employees`

#### หมายเหตุ:

1. `category_code` ต้องไม่ซ้ำกันทั้งระบบ
2. ห้ามกำหนด `parent_category_id = category_id` ของตัวเอง
3. หมวดหมู่ที่มีรายการตรวจใช้งานอยู่ห้ามลบจริง ให้เปลี่ยน `status = 'INACTIVE'` แทน

### ตาราง `laboratory.specimen_types`

**หน้าที่**: จัดเก็บทะเบียนประเภทตัวอย่างทางชีวภาพ (เช่น เลือดครบส่วน EDTA, ซีรัม, พลาสมา, ปัสสาวะ, อุจจาระ, เนื้อเยื่อ, สารคัดหลั่ง) พร้อมข้อกำหนดภาชนะบรรจุ สารกันเลือดแข็ง ปริมาณขั้นต่ำ และเงื่อนไขอุณหภูมิ/ความคงตัวก่อนตรวจ

#### โครงสร้าง Field:

| Column                    | Data Type     | Constraint                  |
| ------------------------- | ------------- | --------------------------- |
| `specimen_type_id`        | UUID          | PK, NOT NULL                |
| `specimen_type_code`      | VARCHAR(30)   | UNIQUE, NOT NULL            |
| `specimen_name`           | VARCHAR(150)  | NOT NULL                    |
| `specimen_name_en`        | VARCHAR(150)  | NULL                        |
| `biological_source`       | ENUM          | NOT NULL                    |
| `preferred_container`     | VARCHAR(100)  | NOT NULL                    |
| `anticoagulant`           | VARCHAR(100)  | NULL                        |
| `minimum_volume`          | NUMERIC(10,3) | NULL                        |
| `volume_unit`             | VARCHAR(20)   | NULL                        |
| `storage_temp_min_c`      | NUMERIC(5,2)  | NULL                        |
| `storage_temp_max_c`      | NUMERIC(5,2)  | NULL                        |
| `max_stability_hours`     | NUMERIC(6,2)  | NULL                        |
| `collection_instructions` | TEXT          | NULL                        |
| `status`                  | ENUM          | NOT NULL                    |
| `created_at`              | TIMESTAMPTZ   | NOT NULL                    |
| `created_by`              | UUID          | FK → hr.employees, NOT NULL |
| `updated_at`              | TIMESTAMPTZ   | NULL                        |
| `updated_by`              | UUID          | FK → hr.employees, NULL     |

#### ข้อกำหนด:

- `specimen_type_id`: รหัสประจำประเภทตัวอย่าง ใช้เป็น Primary Key
- `specimen_type_code`: รหัสประเภทตัวอย่าง เช่น `SPC-EDTA`, `SPC-SERUM`, `SPC-URINE`, `SPC-FECES`, `SPC-SWAB-EAR`
- `specimen_name` / `specimen_name_en`: ชื่อประเภทตัวอย่างภาษาไทยและภาษาอังกฤษ
- `biological_source`: แหล่งตัวอย่างทางชีวภาพ ค่าที่เป็นไปได้ คือ `WHOLE_BLOOD`, `SERUM`, `PLASMA`, `URINE`, `FECES`, `SKIN_SCRAPING`, `EAR_SWAB`, `WOUND_SWAB`, `THROAT_NASAL_SWAB`, `TISSUE_BIOPSY`, `FINE_NEEDLE_ASPIRATE`, `BODY_FLUID`, `CSF`, `HAIR_NAIL`, `OTHER`
- `preferred_container`: ภาชนะมาตรฐานที่ใช้เก็บ (เช่น หลอดจุกม่วง EDTA, หลอดจุกแดง Plain/Clot activator, กระปุกปัสสาวะปลอดเชื้อ)
- `anticoagulant`: สารกันเลือดแข็งที่ใช้ในหลอด (เช่น `K2EDTA`, `K3EDTA`, `Lithium Heparin`, `Sodium Citrate 3.2%`, `NONE`)
- `minimum_volume` / `volume_unit`: ปริมาณตัวอย่างขั้นต่ำที่ต้องเก็บได้เพื่อให้ตรวจวิเคราะห์ได้ถูกต้อง (เช่น `0.500` `mL` หรือ `2.000` `mL`)
- `storage_temp_min_c` / `storage_temp_max_c`: ช่วงอุณหภูมิจัดเก็บตัวอย่าง (°C) ก่อนนำเข้าเครื่องตรวจหรือส่งแล็บนอก
- `max_stability_hours`: ระยะเวลาความคงตัวสูงสุด (ชั่วโมง) นับจากเวลาเก็บจนถึงเวลาตรวจหรือปั่นแยกตัวอย่าง
- `collection_instructions`: คำแนะนำการเก็บและการเตรียมตัวอย่าง
- `status`: สถานะการใช้งาน (`ACTIVE`, `INACTIVE`)
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit

#### หมายเหตุ:

1. `specimen_type_code` ต้องไม่ซ้ำกันทั้งระบบ
2. ข้อมูล `max_stability_hours` และ `minimum_volume` ใช้ประกอบการตรวจสอบคุณภาพตัวอย่างใน `laboratory.specimen_acceptances`

### ตาราง `laboratory.diagnostic_tests`

**หน้าที่**: ทะเบียนรายการตรวจวินิจฉัยกลางทั้งหมดของคลินิก ทั้งงานห้องปฏิบัติการ (Lab) และการตรวจวินิจฉัยด้วยภาพ (Imaging) เป็น Single Source of Truth ที่ Domain 03 (`clinical`) และ Domain 06 (`surgery`) ใช้เลือกรายการสั่งตรวจ โดยเชื่อมรหัสบริการและราคาขายมาตรฐานกับ `core.service_catalogs` และ `core.service_prices`

#### โครงสร้าง Field:

| Column                       | Data Type    | Constraint                                       |
| ---------------------------- | ------------ | ------------------------------------------------ |
| `test_id`                    | UUID         | PK, NOT NULL                                     |
| `test_code`                  | VARCHAR(50)  | UNIQUE, NOT NULL                                 |
| `service_catalog_id`         | UUID         | FK → core.service_catalogs, NOT NULL             |
| `test_name`                  | VARCHAR(200) | NOT NULL                                         |
| `test_name_en`               | VARCHAR(200) | NULL                                             |
| `category_id`                | UUID         | FK → laboratory.diagnostic_test_categories, NOT NULL |
| `test_domain`                | ENUM         | NOT NULL                                         |
| `default_specimen_type_id`   | UUID         | FK → laboratory.specimen_types, NULL             |
| `test_method`                | VARCHAR(150) | NULL                                             |
| `expected_turnaround_minutes`| INTEGER      | NULL                                             |
| `execution_location`         | ENUM         | NOT NULL                                         |
| `requires_fasting`           | BOOLEAN      | NOT NULL DEFAULT FALSE                           |
| `fasting_hours_recommended`  | SMALLINT     | NULL                                             |
| `is_panel_only`              | BOOLEAN      | NOT NULL DEFAULT FALSE                           |
| `default_equipment_id`       | UUID         | FK → laboratory.laboratory_equipment, NULL       |
| `clinical_notes`             | TEXT         | NULL                                             |
| `status`                     | ENUM         | NOT NULL                                         |
| `created_at`                 | TIMESTAMPTZ  | NOT NULL                                         |
| `created_by`                 | UUID         | FK → hr.employees, NOT NULL                      |
| `updated_at`                 | TIMESTAMPTZ  | NULL                                             |
| `updated_by`                 | UUID         | FK → hr.employees, NULL                          |

#### ข้อกำหนด:

- `test_id`: รหัสประจำรายการตรวจภายในระบบ ใช้เป็น Primary Key
- `test_code`: รหัสทางธุรกิจที่ไม่ซ้ำกัน รูปแบบ `TST-{YYYY}{MM}{DD}-{NNNN}` หรือรหัสตรวจมาตรฐานของคลินิก
- `service_catalog_id`: รหัสบริการกลางใน `core.service_catalogs` เพื่อใช้ดึงราคาจาก `core.service_prices` และส่งเรียกเก็บเงินใน Domain 07 โดยไม่สร้างตารางราคาแยกใน Domain 05
- `test_name` / `test_name_en`: ชื่อรายการตรวจภาษาไทยและภาษาอังกฤษ
- `category_id`: หมวดหมู่รายการตรวจ อ้างอิง `laboratory.diagnostic_test_categories`
- `test_domain`: ประเภทหลัก (`LABORATORY` = การตรวจวิเคราะห์จากตัวอย่าง, `DIAGNOSTIC_IMAGING` = การตรวจด้วยภาพทางการแพทย์)
- `default_specimen_type_id`: ชนิดตัวอย่างหลักที่ต้องใช้ (บังคับระบุเมื่อ `test_domain = 'LABORATORY'`; เป็น `NULL` สำหรับ `DIAGNOSTIC_IMAGING`)
- `test_method`: วิธีการตรวจวิเคราะห์มาตรฐาน (เช่น Automated Hematology, Dry Chemistry, ELISA, Microscopic Floatation, Digital Radiography)
- `expected_turnaround_minutes`: ระยะเวลาคาดหมายในการตรวจและออกผล (นาที) สำหรับใช้ประเมิน SLA และวางแผนตารางใน Appointment
- `execution_location`: สถานที่ดำเนินการ ค่าที่เป็นไปได้ คือ `IN_HOUSE` (ตรวจภายในคลินิก), `OUTSOURCED` (ส่งตรวจห้องปฏิบัติการภายนอกเท่านั้น), `HYBRID` (ตรวจเองได้และส่งออกได้ตามความเหมาะสม)
- `requires_fasting` / `fasting_hours_recommended`: ระบุว่าสัตว์เลี้ยงต้องงดอาหารก่อนตรวจหรือไม่ และจำนวนชั่วโมงที่แนะนำ
- `is_panel_only`: ระบุว่าเป็นรายการตรวจย่อยที่เปิดสั่งเฉพาะภายในชุดตรวจ (Panel) โดยไม่ให้สั่งเดี่ยวหรือไม่
- `default_equipment_id`: เครื่องตรวจมาตรฐานที่ใช้วิเคราะห์หรือถ่ายภาพรายการนี้ อ้างอิง `laboratory.laboratory_equipment`
- `clinical_notes`: ข้อแนะนำทางคลินิกหรือข้อจำกัดของรายการตรวจ
- `status`: สถานะรายการตรวจ (`DRAFT`, `ACTIVE`, `INACTIVE`, `RETIRED`)
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit

#### หมายเหตุ:

1. ตารางนี้ทำหน้าที่เป็นรายการตรวจกลางเพียงชุดเดียวของระบบ ห้าม Domain 03 (`clinical`) สร้างทะเบียนรายการตรวจซ้ำ (กฎ §3.1)
2. การแก้ไขข้อมูลรายการตรวจ (เช่น วิธีตรวจหรือชื่อ) ต้องไม่กระทบ Snapshot ชื่อและผลตรวจในอดีตที่บันทึกไว้แล้ว
3. สำหรับการสร้าง SQL DDL จริง ควรเพิ่ม FK `default_equipment_id → laboratory.laboratory_equipment` ภายหลังด้วย `ALTER TABLE`

### ตาราง `laboratory.imaging_test_configs`

**หน้าที่**: จัดเก็บคุณสมบัติเฉพาะของการตรวจวินิจฉัยด้วยภาพ (แบบ 1:1 กับรายการตรวจใน `laboratory.diagnostic_tests` ที่มี `test_domain = 'DIAGNOSTIC_IMAGING'`) เช่น รูปแบบภาพ (Modality) อวัยวะ/บริเวณที่ตรวจ ท่าทางมาตรฐาน จำนวนภาพขั้นต่ำ และการเตรียมสัตว์ก่อนตรวจตามข้อ 3.14

#### โครงสร้าง Field:

| Column                      | Data Type    | Constraint                                     |
| --------------------------- | ------------ | ---------------------------------------------- |
| `imaging_config_id`         | UUID         | PK, NOT NULL                                   |
| `test_id`                   | UUID         | FK → laboratory.diagnostic_tests, UNIQUE, NOT NULL |
| `modality`                  | ENUM         | NOT NULL                                       |
| `body_region`               | VARCHAR(150) | NOT NULL                                       |
| `standard_projections`      | JSONB        | NULL                                           |
| `default_image_count`       | SMALLINT     | NOT NULL DEFAULT 2                             |
| `sedation_often_required`   | BOOLEAN      | NOT NULL DEFAULT FALSE                         |
| `patient_prep_instructions` | TEXT         | NULL                                           |
| `default_estimated_minutes` | SMALLINT     | NULL                                           |
| `responsible_role`          | VARCHAR(100) | NULL                                           |
| `status`                    | ENUM         | NOT NULL                                       |
| `created_at`                | TIMESTAMPTZ  | NOT NULL                                       |
| `created_by`                | UUID         | FK → hr.employees, NOT NULL                    |
| `updated_at`                | TIMESTAMPTZ  | NULL                                           |
| `updated_by`                | UUID         | FK → hr.employees, NULL                        |

#### ข้อกำหนด:

- `imaging_config_id`: รหัสประจำการตั้งค่ารายการตรวจภาพ
- `test_id`: รหัสรายการตรวจต้นทาง อ้างอิง `laboratory.diagnostic_tests` (กำหนด `UNIQUE` เพื่อเป็นความสัมพันธ์ 1:1)
- `modality`: ประเภทเทคโนโลยีสร้างภาพ ค่าที่เป็นไปได้ คือ `XRAY` (เอกซเรย์), `ULTRASOUND` (อัลตราซาวด์), `ECHOCARDIOGRAPHY` (อัลตราซาวด์หัวใจ), `CT` (เอกซเรย์คอมพิวเตอร์), `MRI` (คลื่นแม่เหล็กไฟฟ้า), `FLUOROSCOPY` (เอกซเรย์เคลื่อนไหว), `ENDOSCOPY` (ส่องกล้อง), `EXTERNAL_IMAGE` (รับภาพจากภายนอก)
- `body_region`: บริเวณหรือระบบอวัยวะที่ตรวจ (เช่น ช่องอก, ช่องท้อง, กระดูกสันหลัง, ข้อสะโพก)
- `standard_projections`: ท่าทางมาตรฐานในการจัดท่าถ่ายภาพ (JSON Array เช่น `["VD", "RIGHT_LATERAL", "LEFT_LATERAL"]`)

#### ข้อกำหนด:

- `reference_range_id`: รหัสประจำชุดช่วงค่าอ้างอิง ใช้เป็น Primary Key
- `parameter_id`: พารามิเตอร์เจ้าของช่วงค่าอ้างอิง อ้างอิง `laboratory.diagnostic_test_parameters`
- `species_id`: ชนิดสัตว์ที่ช่วงค่าอ้างอิงนี้มีผลบังคับ อ้างอิง `owner.species` (เป็น `NULL` ได้เฉพาะกรณีค่ามาตรฐานสากลที่ไม่ได้แยกชนิดสัตว์)
- `age_min_days` / `age_max_days`: ช่วงอายุสัตว์เป็นวัน (เช่น ลูกสัตว์แรกเกิด, วัยเจริญพันธุ์, สูงวัย; `NULL` หมายถึงไม่จำกัดอายุฝั่งนั้น)
- `sex` / `reproductive_status`: เพศ (`ALL`, `MALE`, `FEMALE`) และสถานะการทำหมัน (`ALL`, `INTACT`, `NEUTERED`) กรณีค่าฮอร์โมนหรือค่าชีวเคมีแปรผันตามเพศ
- `equipment_id` / `test_method`: เครื่องตรวจวิเคราะห์หรือวิธีการตรวจที่กำหนดค่าอ้างอิงชุดนี้ (เป็น `NULL` หากใช้ทั่วไปทุกเครื่อง)
- `normal_low` / `normal_high`: ค่าต่ำสุดและสูงสุดของช่วงค่าปกติสำหรับผลแบบ `NUMERIC`
- `critical_low` / `critical_high`: ค่าต่ำวิกฤตและค่าสูงวิกฤตที่ระบบต้องสร้างแจ้งเตือนเร่งด่วนใน `laboratory.abnormal_result_alerts` ทันที
- `expected_qualitative_normal`: ค่าปกติที่คาดหมายสำหรับผลแบบข้อความ/ตัวเลือก (เช่น `NEGATIVE`, `ABSENT`, `CLEAR`)
- `reference_source`: แหล่งอ้างอิงทางวิชาการหรือคู่มือน้ำยา/เครื่องตรวจที่ใช้กำหนดช่วงค่า (เช่น IDEXX Canine Reference Interval)
- `effective_from` / `effective_to`: ช่วงวันที่มีผลบังคับใช้
- `status`: สถานะ (`ACTIVE`, `INACTIVE`)
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit

#### หมายเหตุ:

1. หากระบุครบทั้ง `normal_low` และ `normal_high` ต้องตรวจสอบว่า `normal_high >= normal_low` และเมื่อระบุ `critical_low` / `critical_high` ต้องให้ `critical_low <= normal_low` และ `critical_high >= normal_high`
2. หากระบุ `age_min_days` และ `age_max_days` ต้องตรวจสอบว่า `age_max_days >= age_min_days`
3. เมื่อบันทึกผลตรวจใน `laboratory.laboratory_result_items` ระบบต้อง Snapshot `ref_low_snapshot` และ `ref_high_snapshot` ณ เวลาตรวจไว้ด้วย เพื่อไม่ให้การแก้ไขค่าอ้างอิงในอนาคตเปลี่ยนแปลงประวัติผลตรวจเก่า
4. สำหรับการสร้าง SQL DDL จริง ควรเพิ่ม FK `equipment_id → laboratory.laboratory_equipment` ภายหลังด้วย `ALTER TABLE`

- `branch_id` / `diagnostic_order_id` / `pet_id`: สาขา คำสั่งตรวจ และสัตว์เลี้ยงที่เก็บตัวอย่าง
- `collected_by` / `collected_at`: เจ้าหน้าที่ผู้ดำเนินการเก็บตัวอย่างและวันเวลาที่เก็บจริง (สำคัญต่อการคำนวณอายุความคงตัวและเวลา TAT)
- `collection_site`: ตำแหน่งร่างกายที่เก็บ (เช่น Jugular Vein, Cephalic Vein, Urinary Bladder, Left Ear Canal)
- `collection_method`: วิธีการเก็บตัวอย่าง ค่าที่เป็นไปได้ คือ `VENIPUNCTURE`, `CYSTOCENTESIS`, `CATHETERIZATION`, `FREE_CATCH`, `FECAL_LOOP`, `SWAB`, `SKIN_SCRAPING`, `FINE_NEEDLE_ASPIRATE`, `BIOPSY`, `CENTESIS_FLUID`, `OTHER`
- `pet_fasting_verified` / `sedation_used`: ยืนยันสถานะการงดอาหารก่อนเก็บ และระบุว่ามีการให้ยาซึมระหว่างเก็บหรือไม่
- `collection_notes`: ข้อสังเกตหรือความผิดปกติขณะเก็บ (เช่น เส้นเลือดแตก หยุดเก็บกลางคัน)
- `collection_status`: สถานะรอบเก็บตัวอย่าง (`COMPLETED`, `PARTIAL`, `FAILED`, `CANCELLED`)
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit

#### หมายเหตุ:

1. หนึ่งรอบการเก็บตัวอย่างสามารถสร้างหลอด/ภาชนะตัวอย่างใน `laboratory.specimens` ได้หลายชิ้น (เช่น หลอด EDTA 1 หลอด และหลอด Serum 1 หลอด)
2. ต้องเชื่อมโยงกับ `pet_id` ตรงกับใน `diagnostic_orders` เสมอ

### ตาราง `laboratory.specimens`

**หน้าที่**: จัดเก็บข้อมูลตัวอย่างทางชีวภาพแต่ละชิ้น/แต่ละหลอดพร้อมบาร์โค้ดเฉพาะตัว ควบคุมวงจรชีวิตตั้งแต่รอเก็บ เก็บแล้ว ตรวจสอบ จัดเก็บ แบ่งส่วน ไปจนถึงใช้หมดหรือทำลาย รวมถึงเชื่อมโยงประวัติเมื่อถูกปฏิเสธและเก็บใหม่ตามข้อ 3.5, 4.3, 5.2 และ 9.2

- `specimen_barcode`: รหัสบาร์โค้ดเฉพาะของหลอด/ภาชนะตัวอย่าง ใช้พิมพ์ฉลากติดหลอด รูปแบบ `SPC-{YYYY}{MM}{DD}-{NNNN}` (ห้ามเปลี่ยนรหัสเดิมโดยไม่มีประวัติ)
- `collection_id`: รอบการเก็บตัวอย่างต้นทาง อ้างอิง `laboratory.specimen_collections`
- `diagnostic_order_id` / `pet_id` / `specimen_type_id`: คำสั่งตรวจ สัตว์เลี้ยง และชนิดตัวอย่าง
- `recollected_from_specimen_id`: รหัสตัวอย่างเดิมที่ถูกปฏิเสธ (`REJECTED`) ในกรณีต้องเจาะ/เก็บตัวอย่างใหม่แทน (อ้างอิง `laboratory.specimens`) เพื่อรักษาประวัติตัวอย่างที่ไม่ผ่านตามกฎ §4.3

- `initial_volume` / `remaining_volume` / `volume_unit`: ปริมาณเริ่มต้นเมื่อเก็บ ปริมาณคงเหลือปัจจุบัน และหน่วย (เช่น `mL`, `g`)
- `collection_condition`: สภาพเบื้องต้นของตัวอย่าง (`NORMAL`, `HEMOLYZED`, `LIPEMIC`, `CLOTTED`, `ICTERIC`, `CONTAMINATED`, `INSUFFICIENT`)
- `storage_temperature_c` / `storage_location_label`: อุณหภูมิและตำแหน่งจัดเก็บตัวอย่างปัจจุบัน (เช่น ตู้เย็นตัวอย่าง ชั้น 2 ถาด A)
- `received_at_lab_at` / `expires_at`: วันเวลาที่ห้องปฏิบัติการรับตัวอย่างและวันเวลาหมดอายุความคงตัวของตัวอย่าง
- `disposed_at` / `disposed_by` / `disposal_method`: วันเวลา ผู้ดำเนินการ และวิธีทำลายตัวอย่างหลังครบระยะเวลาจัดเก็บ
- `specimen_status`: สถานะตลอดวงจรชีวิตตัวอย่างตามข้อ 5.2 ค่าที่เป็นไปได้ คือ
  - `PENDING_COLLECTION`: รอเก็บตัวอย่าง
  - `COLLECTED`: เก็บตัวอย่างใส่ภาชนะแล้ว รอนำส่งห้องปฏิบัติการ
  - `RECEIVED`: ห้องปฏิบัติการรับตัวอย่างแล้ว รอตรวจคุณภาพ
  - `UNDER_INSPECTION`: กำลังตรวจสอบความเหมาะสมของตัวอย่าง
  - `ACCEPTED`: ผ่านเกณฑ์ตรวจรับและพร้อมนำไปตรวจวิเคราะห์
  - `REJECTED`: ถูกปฏิเสธเนื่องจากไม่ผ่านเกณฑ์คุณภาพ (ต้องคงประวัติไว้เสมอ)
  - `PROCESSING`: กำลังอยู่ระหว่างดำเนินการตรวจวิเคราะห์
  - `STORED`: จัดเก็บสำรองหลังตรวจเสร็จ (เพื่อตรวจซ้ำหากจำเป็น)
  - `EXHAUSTED`: ใช้ตัวอย่างจนหมดแล้ว (`remaining_volume = 0`)
  - `DISPOSED`: ทำลายตัวอย่างแล้วตามนโยบายขยะติดเชื้อ
- `notes` / `created_at` / `created_by` / `updated_at` / `updated_by`: หมายเหตุและข้อมูล Audit

#### หมายเหตุ:

1. ตัวอย่างหนึ่งชิ้นสามารถใช้ตรวจได้หลายรายการใน `laboratory_work_order_items` และต้องไม่ถูกรวมเป็นตารางเดียวกับผลตรวจ (กฎ §9.2)
2. ห้ามลบประวัติตัวอย่างที่อยู่ในสถานะ `REJECTED` หรือ `DISPOSED`

- `specimen_id` / `aliquot_id`: ตัวอย่างหลักหรือส่วนแบ่งที่ถูกตรวจสอบคุณภาพ
- `diagnostic_order_id`: คำสั่งตรวจที่อ้างอิง อ้างอิง `laboratory.diagnostic_orders`
- `inspected_by` / `inspected_at`: เจ้าหน้าที่ห้องปฏิบัติการผู้ตรวจสอบและวันเวลาที่ตรวจสอบ
- `acceptance_result`: ผลการตรวจสอบตามข้อ 3.6 ค่าที่เป็นไปได้ คือ

  - `ACCEPTED_WITH_COMMENT`: ยอมรับตัวอย่างโดยบันทึกข้อจำกัดทางคุณภาพ (เช่น เม็ดเลือดแดงแตกเล็กน้อย) เพื่อให้สัตวแพทย์ทราบขณะอ่านผล
  - `REJECTED`: ปฏิเสธตัวอย่าง ไม่สามารถนำไปตรวจได้
  - `PENDING_REVIEW`: อยู่ระหว่างรอสัตวแพทย์หรือผู้มีอำนาจพิจารณาว่าจะตรวจต่อหรือเก็บใหม่
  - `RECOLLECTION_REQUIRED`: ปฏิเสธและส่งคำขอเก็บตัวอย่างใหม่ทันที
- `rejection_reason_code`: รหัสสาเหตุความผิดปกติ/ปฏิเสธ (`INSUFFICIENT_VOLUME`, `HEMOLYSIS`, `CLOTTED`, `WRONG_CONTAINER`, `UNLABELED_MISMATCH`, `CONTAMINATED`, `EXPIRED_STABILITY`, `TEMPERATURE_BREACH`, `LIPEMIC_INTERFERENCE`, `OTHER`)
- `abnormality_details`: รายละเอียดความผิดปกติที่พบและข้อจำกัดของตัวอย่าง
- `approved_with_comment_by`: ผู้อนุมัติกรณียอมรับตัวอย่างที่มีข้อจำกัด (`ACCEPTED_WITH_COMMENT`)
- `recollection_requested` / `clinical_notified_at`: ธงแจ้งขอเก็บตัวอย่างใหม่และเวลาที่แจ้งเตือนฝ่าย Clinical แล้ว
- `notes` / `created_at`: หมายเหตุเพิ่มเติมและเวลาบันทึก

#### หมายเหตุ:

1. หาก `acceptance_result` เป็น `REJECTED` หรือ `RECOLLECTION_REQUIRED` ต้องระบุ `rejection_reason_code` และระบบต้องเปลี่ยน `specimens.specimen_status = 'REJECTED'` โดยห้ามนำตัวอย่างนี้เข้าสู่ `laboratory_work_order_items`
2. หากเป็น `ACCEPTED_WITH_COMMENT` ควรระบุ `approved_with_comment_by` และ `abnormality_details` เพื่อนำไปแสดงบนใบรายงานผลตรวจ

## กลุ่ม Lab Work Execution, Results, Verification, Revisions, Alerts & Retests

### ตาราง `laboratory.laboratory_work_orders`

**หน้าที่**: จัดเก็บงานตรวจวิเคราะห์ทางห้องปฏิบัติการ (Lab Work Order / Analytical Run Job) ที่แตกมาจากคำสั่งตรวจเพื่อจัดคิวงาน มอบหมายเจ้าหน้าที่ห้องปฏิบัติการ ควบคุมเวลาเริ่ม-สิ้นสุด และแยกสถานะงานปฏิบัติการออกจากคำสั่งตรวจและผลตรวจตามข้อ 3.7 และ 5.3

#### โครงสร้าง Field:

| Column                 | Data Type   | Constraint                                  |
| ---------------------- | ----------- | ------------------------------------------- |
| `work_order_id`        | UUID        | PK, NOT NULL                                |
| `work_order_number`    | VARCHAR(30) | UNIQUE, NOT NULL                            |
| `branch_id`            | UUID        | FK → core.branches, NOT NULL                |
| `diagnostic_order_id`  | UUID        | FK → laboratory.diagnostic_orders, NOT NULL |
| `pet_id`               | UUID        | FK → owner.pets, NOT NULL                   |
| `priority_level`       | ENUM        | NOT NULL                                    |
| `assigned_to`          | UUID        | FK → hr.employees, NULL                     |
| `scheduled_at`         | TIMESTAMPTZ | NULL                                        |
| `started_at`           | TIMESTAMPTZ | NULL                                        |
| `completed_at`         | TIMESTAMPTZ | NULL                                        |
| `work_status`          | ENUM        | NOT NULL                                    |
| `hold_or_cancel_reason`| TEXT        | NULL                                        |
| `notes`                | TEXT        | NULL                                        |
| `created_at`           | TIMESTAMPTZ | NOT NULL                                    |
| `created_by`           | UUID        | FK → hr.employees, NOT NULL                 |
| `updated_at`           | TIMESTAMPTZ | NULL                                        |
| `updated_by`           | UUID        | FK → hr.employees, NULL                     |

#### ข้อกำหนด:

- `work_order_id`: รหัสประจำใบงานตรวจวิเคราะห์
- `work_order_number`: เลขที่ใบงาน รูปแบบ `WRK-{YYYY}{MM}{DD}-{NNNN}`
- `branch_id` / `diagnostic_order_id` / `pet_id`: สาขา คำสั่งตรวจ และสัตว์เลี้ยงต้นทาง
- `priority_level`: ระดับความเร่งด่วน (`ROUTINE`, `URGENT`, `STAT_EMERGENCY`)
- `assigned_to`: เจ้าหน้าที่ห้องปฏิบัติการผู้รับผิดชอบงานตรวจ
- `scheduled_at` / `started_at` / `completed_at`: เวลาจัดคิว เวลาเริ่มดำเนินการตรวจ และเวลาตรวจเสร็จสิ้น (ใช้คำนวณ Turnaround Time ตาม §3.20)
- `work_status`: สถานะงานตรวจทางห้องปฏิบัติการตามข้อ 5.3 ค่าที่เป็นไปได้ คือ `PENDING` (รอดำเนินการ), `SCHEDULED` (จัดคิวแล้ว), `IN_PROGRESS` (กำลังตรวจวิเคราะห์), `ON_HOLD` (พักการดำเนินการ), `FAILED` (ตรวจไม่สำเร็จ), `COMPLETED` (ตรวจวิเคราะห์เสร็จแล้ว — ยังไม่เท่ากับรับรองผล), `CANCELLED` (ยกเลิก)
- `hold_or_cancel_reason` / `notes`: เหตุผลกรณีพักงาน ยกเลิก หรือตรวจล้มเหลว และหมายเหตุเพิ่มเติม
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit

#### หมายเหตุ:

1. สถานะ `work_status = 'COMPLETED'` บ่งบอกเพียงว่าการวิเคราะห์ทางแล็บเสร็จสิ้น ไม่ถือว่าผลตรวจผ่านการตรวจสอบและรับรองพร้อมเผยแพร่แล้ว (กฎ §5.5 และ §9.9)

- `work_order_id` / `order_item_id` / `test_id`: ใบงานตรวจ รายการในคำสั่งตรวจ และรายการตรวจจาก Catalog

- `performed_by` / `started_at` / `completed_at`: ผู้ดำเนินการตรวจและเวลาเริ่ม-สิ้นสุดของรายการนี้
- `work_item_status`: สถานะรายการงานตรวจ (`PENDING`, `SCHEDULED`, `IN_PROGRESS`, `ON_HOLD`, `FAILED`, `COMPLETED`, `CANCELLED`)
- `failure_reason` / `notes` / `created_at` / `updated_at`: สาเหตุกรณีตรวจไม่สำเร็จ (เช่น เครื่องขัดข้อง) และข้อมูลเวลา

#### หมายเหตุ:

1. ต้องตรวจสอบก่อนเริ่มดำเนินการ (`IN_PROGRESS`) ว่าตัวอย่างที่ผูกมัดผ่านเกณฑ์ `specimen_acceptances` แล้ว และเครื่องตรวจ `equipment_id` อยู่ในสถานะ `READY` ไม่ติดล็อก IQC (กฎ §3.7 และ §3.12)
2. สำหรับการสร้าง SQL DDL จริง ควรเพิ่ม FK `equipment_id → laboratory.laboratory_equipment` ภายหลังด้วย `ALTER TABLE`

### ตาราง `laboratory.laboratory_results`

**หน้าที่**: จัดเก็บข้อมูลหัวเอกสารผลตรวจทางห้องปฏิบัติการของแต่ละรายการตรวจที่สั่ง (ทั้งผลที่ตรวจในคลินิกด้วยมือหรือจากเครื่องอัตโนมัติ และผลที่รับมาจากแล็บภายนอก) โดยเป็นตารางเป้าหมายที่ `clinical.diagnostic_result_reviews` ใน Domain 03 อ้างอิงตรงและแยกสถานะตั้งแต่ Draft จนถึง Approved/Released/Amended ตามข้อ 3.8 และ 5.4

#### โครงสร้าง Field:

| Column                       | Data Type   | Constraint                                       |

| `order_item_id`              | UUID        | FK → laboratory.diagnostic_order_items, NOT NULL |
| `work_order_item_id`         | UUID        | FK → laboratory.laboratory_work_order_items, NULL|

| `aliquot_id`                 | UUID        | FK → laboratory.specimen_aliquots, NULL          |

#### ข้อกำหนด:

- `laboratory_result_id`: รหัสประจำเอกสารผลตรวจทางห้องปฏิบัติการ ใช้เป็น Primary Key (อ้างอิงจาก `clinical.diagnostic_result_reviews`)
- `result_number`: เลขที่ผลตรวจ รูปแบบ `RES-{YYYY}{MM}{DD}-{NNNN}`
- `branch_id` / `diagnostic_order_id` / `order_item_id` / `work_order_item_id`: สาขา คำสั่งตรวจ รายการคำสั่งตรวจ และรายการงานตรวจต้นทาง
- `specimen_id` / `aliquot_id` / `pet_id` / `test_id`: ตัวอย่าง สัตว์เลี้ยง และรายการตรวจที่รายงานผล
- `result_source`: แหล่งที่มาของผล (`IN_HOUSE_MANUAL` บันทึกเอง, `IN_HOUSE_ANALYZER` รับค่าจากเครื่องอัตโนมัติ, `OUTSOURCED_LAB` ผลจากแล็บภายนอก)
- `external_referral_item_id`: อ้างอิงรายการส่งตรวจภายนอกเมื่อ `result_source = 'OUTSOURCED_LAB'`
- `performed_by` / `performed_at`: ผู้ตรวจวิเคราะห์หรือผู้บันทึกผลและวันเวลาที่ได้ผล
- `verified_by` / `verified_at`: ผู้ตรวจสอบผลระดับเทคนิค (Verification Level 1)
- `approved_by` / `approved_at`: ผู้มีอำนาจรับรองผลฉบับสมบูรณ์และวันเวลารับรอง
- `released_at`: วันเวลาที่เผยแพร่ผลให้ฝั่ง Clinical และเจ้าของ (เมื่อผ่านการรับรองแล้ว)
- `result_status`: สถานะผลตรวจตามข้อ 5.4 ค่าที่เป็นไปได้ คือ `PENDING_RESULT`, `DRAFT`, `PRELIMINARY`, `PENDING_VERIFICATION`, `VERIFIED`, `APPROVED`, `RELEASED`, `AMENDED`, `CORRECTED`, `CANCELLED`
- `has_abnormal_values` / `has_critical_values`: ธงสรุปว่าผลตรวจชุดนี้มีค่าผิดปกติหรือค่าวิกฤตอยู่หรือไม่
- `version_number`: หมายเลขเวอร์ชันของเอกสารผลตรวจ (เริ่มต้นที่ `1` และเพิ่มขึ้นทุกครั้งที่มีการแก้ไขหลังรับรองผ่าน `result_revisions`)
- `overall_interpretation_note`: ข้อสังเกตเชิงห้องปฏิบัติการ (เช่น พบข้อจำกัด Hemolysis เล็กน้อย; ไม่ใช่การวินิจฉัยโรคแทนสัตวแพทย์ตาม §9.4)
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit

#### หมายเหตุ:

1. ผลตรวจที่ยังไม่ถึงสถานะ `APPROVED` หรือ `RELEASED` ต้องไม่แสดงเป็นผลฉบับสมบูรณ์และต้องแสดงป้ายสถานะชัดเจน (เช่น `PRELIMINARY`) หากเปิดให้ดูเบื้องต้น (กฎ §3.9 และ §9.9)
2. ห้ามแก้ไขผลตรวจที่ `APPROVED`/`RELEASED` แล้วโดยตรง ต้องแก้ไขผ่านกระบวนการใน `laboratory.result_revisions` เท่านั้น (กฎ §9.5)

### ตาราง `laboratory.result_verifications`

**หน้าที่**: จัดเก็บบันทึกประวัติการตรวจสอบและรับรองผลตรวจทางห้องปฏิบัติการ รองรับการตรวจสอบหลายระดับ (เช่น Level 1 Technical Check โดยนักเทคนิค และ Level 2 Clinical Sign-off โดยหัวหน้าห้องแล็บ/สัตวแพทย์ผู้รับผิดชอบ) ตามข้อ 3.9

#### โครงสร้าง Field:

| Column                 | Data Type   | Constraint                                  |
| ---------------------- | ----------- | ------------------------------------------- |
| `verification_id`      | UUID        | PK, NOT NULL                                |
| `laboratory_result_id` | UUID        | FK → laboratory.laboratory_results, NOT NULL|
| `verification_level`   | SMALLINT    | NOT NULL DEFAULT 1                          |
| `verifier_role`        | ENUM        | NOT NULL                                    |
| `verified_by`          | UUID        | FK → hr.employees, NOT NULL                 |
| `verified_at`          | TIMESTAMPTZ | NOT NULL                                    |
| `checklist_summary`    | JSONB       | NULL                                        |
| `verification_outcome` | ENUM        | NOT NULL                                    |
| `rejection_reason`     | TEXT        | NULL                                        |
| `notes`                | TEXT        | NULL                                        |
| `created_at`           | TIMESTAMPTZ | NOT NULL                                    |

#### ข้อกำหนด:

- `verification_id`: รหัสประจำรายการตรวจสอบและรับรองผล
- `laboratory_result_id`: ผลตรวจที่ถูกตรวจสอบ อ้างอิง `laboratory.laboratory_results`
- `verification_level`: ระดับการตรวจสอบ (`1` = ตรวจทานความถูกต้องเบื้องต้น/เครื่อง/หน่วย, `2` = ตรวจสอบและรับรองผลขั้นสุดท้าย)

- `verified_by` / `verified_at`: ผู้ตรวจสอบและวันเวลาตรวจสอบ

**หน้าที่**: จัดเก็บทะเบียนเครื่องมือและอุปกรณ์ตรวจวิเคราะห์ทางห้องปฏิบัติการและเครื่องถ่ายภาพวินิจฉัย (เช่น เครื่อง CBC, เครื่อง Chemistry, กล้องจุลทรรศน์, เครื่องปั่นเหวี่ยง, เครื่องเอกซเรย์, เครื่องอัลตราซาวด์) เพื่อติดตามความพร้อมใช้งาน กำหนดบำรุงรักษา กำหนดสอบเทียบ และรองรับการเชื่อมโยงกับระบบ Facility & Equipment Management ในอนาคตตามข้อ 3.12 และ 6.7

#### โครงสร้าง Field:

| Column                      | Data Type    | Constraint                    |
| --------------------------- | ------------ | ----------------------------- |
| `equipment_id`              | UUID         | PK, NOT NULL                  |
| `equipment_code`            | VARCHAR(30)  | UNIQUE, NOT NULL              |
| `branch_id`                 | UUID         | FK → core.branches, NOT NULL  |
| `room_id`                   | UUID         | FK → appointment.rooms, NULL  |
| `facility_asset_id`         | UUID         | NULL                          |
| `equipment_name`            | VARCHAR(150) | NOT NULL                      |
| `equipment_category`        | ENUM         | NOT NULL                      |
| `manufacturer_name`         | VARCHAR(150) | NULL                          |
| `model_name`                | VARCHAR(150) | NULL                          |
| `serial_number`             | VARCHAR(100) | NULL                          |
| `installed_on`              | DATE         | NULL                          |
| `calibration_interval_days` | INTEGER      | NULL                          |
| `last_calibrated_at`        | TIMESTAMPTZ  | NULL                          |
| `next_calibration_due`      | DATE         | NULL                          |
| `maintenance_interval_days` | INTEGER      | NULL                          |
| `last_maintained_at`        | TIMESTAMPTZ  | NULL                          |
| `next_maintenance_due`      | DATE         | NULL                          |
| `responsible_employee_id`   | UUID         | FK → hr.employees, NULL       |
| `operational_status`        | ENUM         | NOT NULL                      |
| `notes`                     | TEXT         | NULL                          |
| `created_at`                | TIMESTAMPTZ  | NOT NULL                      |
| `created_by`                | UUID         | FK → hr.employees, NOT NULL   |
| `updated_at`                | TIMESTAMPTZ  | NULL                          |
| `updated_by`                | UUID         | FK → hr.employees, NULL       |

#### ข้อกำหนด:

- `equipment_id`: รหัสประจำเครื่องมือตรวจวิเคราะห์
- `equipment_code`: รหัสเครื่องมือทางธุรกิจ รูปแบบ `EQP-{YYYY}{MM}{DD}-{NNNN}` หรือรหัสประจำเครื่อง
- `branch_id` / `room_id`: สาขาและห้องที่ติดตั้งเครื่องมือ อ้างอิง `core.branches` และ `appointment.rooms`
- `facility_asset_id`: รหัสอ้างอิงทะเบียนทรัพย์สินกลาง (ใช้เชื่อมโยงเมื่อมีการพัฒนาระบบ Facility & Equipment Management แยกต่างหากตามหลักข้อ 6.7)
- `equipment_name`: ชื่อเครื่องมือตรวจ (เช่น เครื่องตรวจเลือดอัตโนมัติ ห้องแล็บ 1)
- `equipment_category`: ประเภทเครื่องมือ ค่าที่เป็นไปได้ คือ `HEMATOLOGY_ANALYZER`, `BIOCHEMISTRY_ANALYZER`, `URINALYSIS_ANALYZER`, `ELECTROLYTE_ANALYZER`, `PCR_ANALYZER`, `CENTRIFUGE`, `MICROSCOPE`, `RAPID_TEST_READER`, `XRAY_MACHINE`, `CR_DR_DETECTOR`, `ULTRASOUND_MACHINE`, `OTHER`
- `manufacturer_name` / `model_name` / `serial_number` / `installed_on`: ยี่ห้อ รุ่น Serial Number และวันที่ติดตั้งเริ่มใช้งาน
- `calibration_interval_days` / `last_calibrated_at` / `next_calibration_due`: รอบการสอบเทียบ วันสอบเทียบล่าสุด และวันครบกำหนดสอบเทียบครั้งถัดไป
- `maintenance_interval_days` / `last_maintained_at` / `next_maintenance_due`: รอบการบำรุงรักษา วันบำรุงรักษาล่าสุด และวันครบกำหนดครั้งถัดไป
- `responsible_employee_id`: ผู้รับผิดชอบดูแลเครื่องมือ อ้างอิง `hr.employees`
- `operational_status`: สถานะความพร้อมใช้งาน ค่าที่เป็นไปได้ คือ `READY` (พร้อมใช้), `IN_USE` (กำลังใช้งาน), `QC_HOLD` (ถูกระงับเนื่องจากผลควบคุมคุณภาพ IQC ไม่ผ่าน), `MAINTENANCE` (อยู่ระหว่างซ่อมบำรุง/สอบเทียบ), `FAULTY` (ชำรุดขัดข้อง), `RETIRED` (เลิกใช้งาน)
- `notes` / `created_at` / `created_by` / `updated_at` / `updated_by`: หมายเหตุและข้อมูล Audit

#### หมายเหตุ:

1. เครื่องมือที่มี `operational_status` เป็น `QC_HOLD`, `MAINTENANCE`, `FAULTY` หรือ `RETIRED` ต้องไม่อนุญาตให้เลือกใช้ใน `laboratory_work_order_items` และ `imaging_studies` (กฎ §3.12 และ §9.7)

### ตาราง `laboratory.equipment_maintenance_records`

**หน้าที่**: จัดเก็บประวัติการบำรุงรักษาเชิงป้องกัน (Preventive Maintenance) และการแจ้งซ่อมเครื่องมือตรวจวิเคราะห์เมื่อเกิดเหตุขัดข้องตามข้อ 3.12

#### โครงสร้าง Field:

| Column                     | Data Type    | Constraint                                   |
| -------------------------- | ------------ | -------------------------------------------- |
| `maintenance_id`           | UUID         | PK, NOT NULL                                 |
| `equipment_id`             | UUID         | FK → laboratory.laboratory_equipment, NOT NULL|
| `maintenance_type`         | ENUM         | NOT NULL                                     |
| `reported_issue`           | TEXT         | NULL                                         |
| `action_taken`             | TEXT         | NOT NULL                                     |
| `performed_by_internal_id` | UUID         | FK → hr.employees, NULL                      |
| `external_vendor_name`     | VARCHAR(150) | NULL                                         |
| `maintenance_start_at`     | TIMESTAMPTZ  | NOT NULL                                     |
| `maintenance_end_at`       | TIMESTAMPTZ  | NULL                                         |
| `outcome`                  | ENUM         | NOT NULL                                     |
| `next_maintenance_due`     | DATE         | NULL                                         |
| `certificate_ref`          | TEXT         | NULL                                         |
| `recorded_by`              | UUID         | FK → hr.employees, NOT NULL                  |
| `created_at`               | TIMESTAMPTZ  | NOT NULL                                     |

#### ข้อกำหนด:

- `maintenance_id`: รหัสประจำประวัติการบำรุงรักษา
- `equipment_id`: เครื่องมือที่ได้รับการบำรุงรักษาหรือซ่อมแซม อ้างอิง `laboratory.laboratory_equipment`
- `maintenance_type`: ประเภท (`PREVENTIVE` บำรุงรักษาตามรอบ, `CORRECTIVE_REPAIR` แก้ไขตามอาการ, `BREAKDOWN` ซ่อมฉุกเฉิน, `SOFTWARE_UPDATE` อัปเดตเฟิร์มแวร์/ซอฟต์แวร์)
- `reported_issue` / `action_taken`: ปัญหาที่แจ้งและรายละเอียดการดำเนินการแก้ไข
- `performed_by_internal_id` / `external_vendor_name`: ช่างเทคนิคภายในหรือชื่อบริษัทผู้ให้บริการซ่อมบำรุงภายนอก
- `maintenance_start_at` / `maintenance_end_at`: วันเวลาเริ่มและสิ้นสุดการซ่อมบำรุง
- `outcome`: ผลหลังซ่อมบำรุง (`COMPLETED_READY` ซ่อมเสร็จพร้อมใช้งาน, `PARTIAL_LIMITED` ใช้ได้บางฟังก์ชัน, `FAILED_OUT_OF_SERVICE` ซ่อมไม่สำเร็จต้องงดใช้งาน)
- `next_maintenance_due` / `certificate_ref` / `recorded_by` / `created_at`: กำหนดรอบถัดไป ใบรับรอง และผู้บันทึก

#### หมายเหตุ:

1. เมื่อบันทึก `outcome = 'FAILED_OUT_OF_SERVICE'` ระบบต้องปรับ `laboratory_equipment.operational_status` เป็น `FAULTY` ทันที และเมื่อ `COMPLETED_READY` อาจบังคับตรวจ IQC ซ้ำก่อนเปิดใช้งาน (กฎ §3.13)

### ตาราง `laboratory.equipment_calibrations`

**หน้าที่**: จัดเก็บประวัติการสอบเทียบความแม่นยำ (Calibration) ของเครื่องตรวจวิเคราะห์แต่ละเครื่อง พร้อมสารมาตรฐานและวันครบกำหนดสอบเทียบครั้งถัดไปตามข้อ 3.12

#### โครงสร้าง Field:

| Column                   | Data Type    | Constraint                                   |
| ------------------------ | ------------ | -------------------------------------------- |
| `calibration_id`         | UUID         | PK, NOT NULL                                 |
| `equipment_id`           | UUID         | FK → laboratory.laboratory_equipment, NOT NULL|
| `calibration_date`       | TIMESTAMPTZ  | NOT NULL                                     |
| `calibrated_by`          | UUID         | FK → hr.employees, NULL                      |
| `external_vendor_name`   | VARCHAR(150) | NULL                                         |
| `calibrator_lot_number`  | VARCHAR(100) | NULL                                         |
| `calibrator_expiry_date` | DATE         | NULL                                         |
| `standard_reference`     | VARCHAR(200) | NULL                                         |
| `calibration_result`     | ENUM         | NOT NULL                                     |
| `deviation_notes`        | TEXT         | NULL                                         |
| `next_calibration_due`   | DATE         | NULL                                         |
| `certificate_ref`        | TEXT         | NULL                                         |
| `approved_by`            | UUID         | FK → hr.employees, NULL                      |
| `created_at`             | TIMESTAMPTZ  | NOT NULL                                     |

#### ข้อกำหนด:

- `calibration_id`: รหัสประจำประวัติการสอบเทียบ
- `equipment_id`: เครื่องมือที่สอบเทียบ อ้างอิง `laboratory.laboratory_equipment`
- `calibration_date`: วันและเวลาที่ทำการสอบเทียบ
- `calibrated_by` / `external_vendor_name`: ผู้ดำเนินการสอบเทียบภายในหรือหน่วยงานสอบเทียบภายนอก
- `calibrator_lot_number` / `calibrator_expiry_date` / `standard_reference`: เลขล็อตและวันหมดอายุของสารมาตรฐานที่ใช้สอบเทียบ
- `calibration_result`: ผลการสอบเทียบ (`PASSED`, `PASSED_WITH_ADJUSTMENT`, `FAILED`)
- `deviation_notes`: รายละเอียดค่าเบี่ยงเบนที่พบและการปรับค่า
- `next_calibration_due` / `certificate_ref` / `approved_by` / `created_at`: วันครบกำหนดสอบเทียบครั้งถัดไป ใบรับรอง และผู้อนุมัติ

#### หมายเหตุ:

1. หาก `calibration_result = 'FAILED'` ต้องระงับการใช้เครื่อง (`QC_HOLD` หรือ `FAULTY`) และทบทวนผลตรวจย้อนหลังที่อาจได้รับผลกระทบ

### ตาราง `laboratory.laboratory_quality_controls`

**หน้าที่**: จัดเก็บบันทึกผลการควบคุมคุณภาพภายใน (Internal Quality Control - IQC) ของเครื่องตรวจวิเคราะห์ น้ำยาตรวจ และสารควบคุมก่อนและระหว่างเปิดให้บริการตรวจประจำวัน เพื่อป้องกันผลตรวจผิดพลาดจากเครื่องมือหรือน้ำยาเสื่อมสภาพตามข้อ 3.13 และ 9.7

#### โครงสร้าง Field:

| Column                       | Data Type     | Constraint                                        |
| ---------------------------- | ------------- | ------------------------------------------------- |
| `qc_id`                      | UUID          | PK, NOT NULL                                      |
| `qc_number`                  | VARCHAR(30)   | UNIQUE, NOT NULL                                  |
| `branch_id`                  | UUID          | FK → core.branches, NOT NULL                      |
| `equipment_id`               | UUID          | FK → laboratory.laboratory_equipment, NOT NULL    |
| `test_id`                    | UUID          | FK → laboratory.diagnostic_tests, NULL            |
| `parameter_id`               | UUID          | FK → laboratory.diagnostic_test_parameters, NULL  |
| `test_method`                | VARCHAR(150)  | NULL                                              |
| `control_level`              | ENUM          | NOT NULL                                          |
| `control_material_name`      | VARCHAR(150)  | NOT NULL                                          |
| `control_lot_number`         | VARCHAR(100)  | NOT NULL                                          |
| `control_expiry_date`        | DATE          | NULL                                              |
| `reagent_product_id`         | UUID          | FK → pharmacy.products, NULL                      |
| `reagent_lot_id`             | UUID          | FK → pharmacy.inventory_lots, NULL                |
| `measured_value`             | NUMERIC(16,4) | NULL                                              |
| `target_value`               | NUMERIC(16,4) | NULL                                              |
| `acceptable_min`             | NUMERIC(16,4) | NULL                                              |
| `acceptable_max`             | NUMERIC(16,4) | NULL                                              |
| `qualitative_result`         | VARCHAR(100)  | NULL                                              |
| `qc_result`                  | ENUM          | NOT NULL                                          |
| `equipment_locked_triggered` | BOOLEAN       | NOT NULL DEFAULT FALSE                            |
| `corrective_action`          | TEXT          | NULL                                              |
| `performed_by`               | UUID          | FK → hr.employees, NOT NULL                       |
| `performed_at`               | TIMESTAMPTZ   | NOT NULL                                          |
| `reviewed_by`                | UUID          | FK → hr.employees, NULL                           |
| `reviewed_at`                | TIMESTAMPTZ   | NULL                                              |
| `created_at`                 | TIMESTAMPTZ   | NOT NULL                                          |

#### ข้อกำหนด:

- `qc_id`: รหัสประจำการควบคุมคุณภาพ IQC
- `qc_number`: เลขที่อ้างอิง IQC รูปแบบ `IQC-{YYYY}{MM}{DD}-{NNNN}`
- `branch_id` / `equipment_id` / `test_id` / `parameter_id` / `test_method`: สาขา เครื่องตรวจ รายการตรวจ พารามิเตอร์ และวิธีตรวจที่ทดสอบคุณภาพ
- `control_level`: ระดับของสารควบคุม (`LEVEL_1_LOW`, `LEVEL_2_NORMAL`, `LEVEL_3_HIGH`, `NEGATIVE`, `POSITIVE`)
- `control_material_name` / `control_lot_number` / `control_expiry_date`: ชื่อ เลขล็อต และวันหมดอายุของสารควบคุมคุณภาพ (ตรวจสอบวันหมดอายุของสารควบคุมและน้ำยาก่อนใช้งานตาม §3.13)
- `reagent_product_id` / `reagent_lot_id`: อ้างอิงรหัสน้ำยาและล็อตน้ำยาจาก Domain 04 (`pharmacy.products`, `pharmacy.inventory_lots`) ที่ใช้งานในรอบควบคุมคุณภาพนี้
- `measured_value` / `target_value` / `acceptable_min` / `acceptable_max` / `qualitative_result`: ค่าที่วัดได้จริง ค่าเป้าหมาย และช่วงเกณฑ์ยอมรับ
- `qc_result`: ผลการประเมิน IQC ค่าที่เป็นไปได้ คือ `PASSED` (ผ่านเกณฑ์ปกติ), `WARNING_WESTGARD` (เข้าเกณฑ์เฝ้าระวัง), `FAILED` (ไม่ผ่านเกณฑ์ ต้องระงับการใช้เครื่อง)
- `equipment_locked_triggered`: ธงระบุว่ารอบ QC นี้ส่งผลให้ระบบล็อกเครื่อง `equipment_id` เป็น `QC_HOLD` หรือไม่
- `corrective_action`: การดำเนินการแก้ไขปัญหาและผลการทดสอบซ้ำก่อนปลดล็อกเครื่องกลับมาใช้งาน
- `performed_by` / `performed_at` / `reviewed_by` / `reviewed_at` / `created_at`: ผู้ทำ QC ผู้สอบทาน และวันเวลาบันทึก

#### หมายเหตุ:

1. หาก `qc_result = 'FAILED'` ต้องบันทึก `corrective_action` และต้องผ่านการทำ QC ซ้ำจน `PASSED` ก่อนอนุญาตให้เปลี่ยน `operational_status` กลับเป็น `READY` (กฎ §3.13 และ §9.7)

### ตาราง `laboratory.test_reagent_standards`

**หน้าที่**: กำหนดรายการวัสดุสิ้นเปลืองและน้ำยาตรวจมาตรฐานที่ต้องใช้ต่อ 1 หน่วยการตรวจของแต่ละรายการตรวจ (Bill of Materials / Reagent Standards) โดยอ้างอิงตรงไปยังทะเบียนสินค้าและหน่วยนับของ Domain 04 (`pharmacy.products`, `pharmacy.units_of_measure`) เพื่อช่วยให้ห้องปฏิบัติการคาดการณ์การใช้วัสดุและเลือกตัดล็อตได้แม่นยำ

#### โครงสร้าง Field:

| Column                | Data Type     | Constraint                                 |
| --------------------- | ------------- | ------------------------------------------ |
| `reagent_standard_id` | UUID          | PK, NOT NULL                               |
| `test_id`             | UUID          | FK → laboratory.diagnostic_tests, NOT NULL |
| `product_id`          | UUID          | FK → pharmacy.products, NOT NULL           |
| `usage_stage`         | ENUM          | NOT NULL                                   |
| `standard_qty`        | NUMERIC(12,4) | NOT NULL DEFAULT 1                         |
| `uom_id`              | UUID          | FK → pharmacy.units_of_measure, NOT NULL   |
| `is_required`         | BOOLEAN       | NOT NULL DEFAULT TRUE                      |
| `notes`               | TEXT          | NULL                                       |
| `status`              | ENUM          | NOT NULL                                   |
| `created_at`          | TIMESTAMPTZ   | NOT NULL                                   |
| `created_by`          | UUID          | FK → hr.employees, NOT NULL                |
| `updated_at`          | TIMESTAMPTZ   | NULL                                       |
| `updated_by`          | UUID          | FK → hr.employees, NULL                    |

#### ข้อกำหนด:

- `reagent_standard_id`: รหัสประจำรายการมาตรฐานวัสดุต่อการตรวจ
- `test_id`: รายการตรวจ อ้างอิง `laboratory.diagnostic_tests`
- `product_id`: หลอดเก็บตัวอย่าง ชุดทดสอบ น้ำยา หรือวัสดุสิ้นเปลือง อ้างอิง `pharmacy.products`
- `usage_stage`: ขั้นตอนที่ใช้ (`SPECIMEN_COLLECTION` เก็บตัวอย่าง, `ANALYTICAL_RUN` วิเคราะห์ผล, `IMAGING_PREP` เตรียมตรวจภาพ, `QUALITY_CONTROL` ทำ IQC)
- `standard_qty` / `uom_id`: ปริมาณมาตรฐานต่อ 1 ครั้งการตรวจ และหน่วยนับอ้างอิง `pharmacy.units_of_measure`
- `is_required` / `notes` / `status`: บังคับใช้หรือไม่ หมายเหตุ และสถานะ (`ACTIVE`, `INACTIVE`)
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit

#### หมายเหตุ:

1. กำหนด Unique Constraint `(test_id, product_id, usage_stage)`
2. ตารางนี้อ้างอิงสินค้าจาก `pharmacy.products` โดยตรง ไม่สร้างทะเบียนหมวดวัสดุซ้ำใน Domain 05 ตามกฎข้อ 9.8

### ตาราง `laboratory.laboratory_supply_usages`

**หน้าที่**: จัดเก็บบันทึกการใช้งานจริงของน้ำยาตรวจ ชุดตรวจ หลอดเก็บเลือด และวัสดุสิ้นเปลืองในห้องปฏิบัติการ/ห้องตรวจภาพแต่ละครั้ง พร้อมเชื่อมโยงล็อตสินค้าและเอกสารเบิกจ่าย/ตัดสต็อกใน Domain 04 (`pharmacy`) เพื่อให้สามารถวิเคราะห์ต้นทุนวัสดุและตัดสต็อกได้อย่างถูกต้องโดยไม่สร้างระบบคลังซ้ำซ้อนตามข้อ 3.19, 6.4 และ 9.8

#### โครงสร้าง Field:

| Column                         | Data Type     | Constraint                                       |
| ------------------------------ | ------------- | ------------------------------------------------ |
| `usage_id`                     | UUID          | PK, NOT NULL                                     |
| `usage_number`                 | VARCHAR(30)   | UNIQUE, NOT NULL                                 |
| `branch_id`                    | UUID          | FK → core.branches, NOT NULL                     |
| `work_order_id`                | UUID          | FK → laboratory.laboratory_work_orders, NULL     |
| `imaging_study_id`             | UUID          | FK → laboratory.imaging_studies, NULL            |
| `collection_id`                | UUID          | FK → laboratory.specimen_collections, NULL       |
| `qc_id`                        | UUID          | FK → laboratory.laboratory_quality_controls, NULL|
| `product_id`                   | UUID          | FK → pharmacy.products, NOT NULL                 |
| `lot_id`                       | UUID          | FK → pharmacy.inventory_lots, NULL               |
| `quantity_used`                | NUMERIC(12,4) | NOT NULL                                         |
| `uom_id`                       | UUID          | FK → pharmacy.units_of_measure, NOT NULL         |
| `usage_context`                | ENUM          | NOT NULL                                         |
| `internal_stock_issue_item_id` | UUID          | FK → pharmacy.internal_stock_issue_items, NULL   |
| `dispensing_item_id`           | UUID          | FK → pharmacy.dispensing_items, NULL             |
| `stock_movement_id`            | UUID          | FK → pharmacy.stock_movements, NULL              |
| `used_by`                      | UUID          | FK → hr.employees, NOT NULL                      |
| `used_at`                      | TIMESTAMPTZ   | NOT NULL                                         |
| `notes`                        | TEXT          | NULL                                             |
| `created_at`                   | TIMESTAMPTZ   | NOT NULL                                         |

#### ข้อกำหนด:

- `usage_id`: รหัสประจำรายการใช้วัสดุห้องปฏิบัติการ
- `usage_number`: เลขที่อ้างอิงการใช้วัสดุ รูปแบบ `LSU-{YYYY}{MM}{DD}-{NNNN}`
- `branch_id`: สาขาที่ใช้งานวัสดุ
- `work_order_id` / `imaging_study_id` / `collection_id` / `qc_id`: กิจกรรมต้นทางที่ใช้วัสดุนี้ (ใบงานตรวจแล็บ งานตรวจภาพ รอบเก็บตัวอย่าง หรือรอบ IQC)
- `product_id` / `lot_id` / `quantity_used` / `uom_id`: สินค้า ล็อต จำนวนที่ใช้จริง และหน่วยนับ อ้างอิง `pharmacy.products`, `pharmacy.inventory_lots`, `pharmacy.units_of_measure` (ห้ามใช้ล็อตที่หมดอายุหรือกักกันตาม §3.19)
- `usage_context`: บริบทการใช้งาน (`TEST_RUN`, `IMAGING_EXAM`, `SPECIMEN_COLLECTION`, `IQC_RUN`, `WASTE_REPEAT`)
- `internal_stock_issue_item_id` / `dispensing_item_id` / `stock_movement_id`: จุดเชื่อมไปยังเอกสารเบิกใช้ภายในของห้องปฏิบัติการ (`pharmacy.internal_stock_issue_items`), การตัดจ่ายรายตัว (`pharmacy.dispensing_items`) หรือรายการตัดสต็อก (`pharmacy.stock_movements`) ใน Domain 04
- `used_by` / `used_at` / `notes` / `created_at`: เจ้าหน้าที่ผู้ใช้วัสดุ วันเวลาใช้งานจริง หมายเหตุ และเวลาบันทึก

#### หมายเหตุ:

1. ตารางนี้บันทึกเฉพาะการใช้งานวัสดุในกระบวนการตรวจของ Domain 05 ส่วนยอดคงเหลือคลังย่อย (`LAB_STORE`) การแจ้งเติมสต็อก (`replenishment_requests`) และการตัดยอดบัญชีคลังเป็นความรับผิดชอบของ Domain 04 (`pharmacy`) เพียงแหล่งเดียว (กฎ §3.19 และ §9.8)
2. `quantity_used` ต้องมากกว่า 0 เสมอ
