# Domain 01 — Owner & Pet Management

เจ้าของข้อมูล: Domain 01

รับผิดชอบทะเบียนลูกค้า สัตว์เลี้ยง เจ้าของร่วม ผู้ดูแล ช่องทางติดต่อ และข้อมูลประจำตัวสัตว์เลี้ยง

## กลุ่ม Owner Master

### ตาราง `owner.owners`

#### โครงสร้าง Field:

| Column                  | Data Type                              | Constraint                      |
| ----------------------- | -------------------------------------- | ------------------------------- |
| `owner_id`              | UUID                                   | PK, NOT NULL                    |
| `owner_code`            | VARCHAR(30)                            | UNIQUE, NOT NULL                |
| `owner_type`            | ENUM(INDIVIDUAL, JURISTIC)             | NOT NULL                        |
| `prefix`                | VARCHAR(20)                            | NULL                            |
| `first_name`            | VARCHAR(150)                           | NOT NULL                        |
| `last_name`             | VARCHAR(150)                           | NULL                            |
| `display_name`          | VARCHAR(150)                           | NULL                            |
| `tax_id`                | VARCHAR(20)                            | NULL                            |
| `date_of_birth`         | DATE                                   | NULL                            |
| `gender`                | ENUM(MALE, FEMALE, NOT_SPECIFIED)      | NOT NULL                        |
| `registered_branch_id`  | UUID                                   | FK → core.branches, NULL        |
| `acquisition_channel`   | VARCHAR(50)                            | NULL                            |
| `status`                | ENUM(ACTIVE, INACTIVE, MERGED)         | NOT NULL                        |
| `merged_into_owner_id`  | UUID                                   | FK → owner.owners, NULL         |
| `created_at`            | TIMESTAMPTZ                            | NOT NULL                        |
| `updated_at`            | TIMESTAMPTZ                            | NULL                            |
| `created_by`            | UUID                                   | NOT NULL                        |
| `updated_by`            | UUID                                   | NULL                            |

ข้อกำหนด:

- `owner_id`: รหัสไม่ซ้ำกันสำหรับใช้ภายในระบบ
- `owner_code`: รหัสที่ไม่ซ้ำกันสำหรับใช้ภายในองค์กร เพื่อให้เจ้าหน้าที่สามารถสืบค้นได้ ใช้วิธีกำหนดเป็น `OWN-{YYYY}{MM}{DD}-{NNNN}` โดยที่:
  - `{YYYY}{MM}{DD}` คือวันที่ตามปฏิทิน ค.ศ.
  - `{NNNN}` คือ ตัวเลขที่เพิ่มขึ้นอัตโนมัติ เช่น 0001 - 9999 และ Reset เป็น 0000 ทุกวันที่ 1 เที่ยงคืนของทุกเดือน
- `owner_type`: ประเภทลูกค้า มี 2 ประเภท บุคคลธรรมดา (`INDIVIDUAL`) และ นิติบุคคล (`JURISTIC`) การเลือกมีผลต่อ `prefix`
- `prefix`: คำนำหน้าชื่อเจ้าของเป็นได้ 2 กรณี:
  - `owner_type` เป็น `INDIVIDUAL` ให้มีได้ระหว่าง นาย (`MR`), นางสาว (`MS`), นาง (`MRS`), หรือคำนำหน้าอื่นตามบัตร/พาสปอร์ต ให้ยึดตามเอกสารยืนยันตัวตน ห้ามยึดตาม `gender`
  - `owner_type` เป็น `JURISTIC` ให้เป็นได้ระหว่าง บริษัท (`COMMERCIAL`), มูลนิธิ (`NON_PROFIT`), และ อื่นๆ (`OTHER`) กรณีเจ้าของเป็น วัด, สมาคม เท่านั้น
- `first_name`: ชื่อจริงตามบัตรประชาชน/หนังสือเดินทาง หรือ ชื่อนิติบุคคล
- `last_name`: นามสกุลจริงตามบัตรประชาชน เป็นค่าว่างได้ หากเลือก `owner_type` เป็น `JURISTIC` หรือชื่อเดี่ยว
- `display_name`: ชื่อเล่นหรือชื่อที่ลูกค้าต้องการให้เจ้าหน้าที่เรียก (optional)
- `tax_id`: เลขประจำตัวประชาชน เลขหนังสือเดินทาง หรือเลขประจำตัวผู้เสียภาษีนิติบุคคล เป็นค่าว่าง (`NULL`) ได้ในกรณีเจ้าของไม่ประสงค์เปิดเผย หรือรับบริการเร่งด่วน/Walk-in และใช้ Partial UNIQUE Index เฉพาะรายการที่ไม่เป็น `NULL` และยังไม่ได้ `MERGED` (กรณีนิติบุคคลตัวเลขนำหน้าด้วย 0 ได้)
- `date_of_birth`: วัน/เดือน/ปี เกิด ตามบัตรประชาชน ไม่จำเป็นต้องกรอกก็ได้ ให้เก็บเป็น `YYYY-MM-DD` ปีให้เก็บเป็น ค.ศ.
- `gender`: กำหนดไว้ 3 ประเภท ชาย (`MALE`), หญิง (`FEMALE`), และ ไม่ระบุ (`NOT_SPECIFIED`) หากเลือก `owner_type` เป็น `JURISTIC` หรือไม่ประสงค์ระบุ
- `registered_branch_id`: สาขาที่ลงทะเบียนเจ้าของครั้งแรก อ้างอิง `core.branches`
- `acquisition_channel`: ช่องทางที่ลูกค้าเข้ามาใช้บริการครั้งแรก (เช่น `WALK_IN`, `LINE_OA`, `WEB_PORTAL`, `REFERRAL`, `SOCIAL_MEDIA`, `CAMPAIGN`)
- `status`: สถานะบัญชีเจ้าของ ค่าที่เป็นไปได้คือ เปิดใช้งาน (`ACTIVE`), ปิดใช้งาน (`INACTIVE`), และ ถูกรวมเข้ากับบัญชีอื่นแล้ว (`MERGED`)
- `merged_into_owner_id`: รหัสเจ้าของหลักที่บัญชีนี้ถูกรวมเข้าไป (กรณี `status = MERGED` เท่านั้น; อ้างอิง `owner.owners`) เพื่อให้การค้นหาย้อนหลัง Redirect ไปยังเจ้าของหลักได้และรักษาประวัติธุรกรรมเดิมไว้
- `created_at`: เวลาและวันที่ที่เจ้าหน้าที่หน้าเคาน์เตอร์ หรือ เจ้าของเป็นคน "สร้างครั้งแรก" เก็บแบบ `TIMESTAMPTZ` (UTC-aware) และแสดงผลตามเขตเวลาของสาขา (อ้างอิง `core.branches.timezone`)
- `updated_at`: เวลาและวันที่ที่เจ้าหน้าที่หน้าเคาน์เตอร์ หรือ เจ้าของเป็นคน "แก้ไขล่าสุด" เก็บแบบ `TIMESTAMPTZ` (UTC-aware)
- `created_by`: รหัสประจำตัวผู้สร้าง หากเจ้าหน้าที่หน้าเคาน์เตอร์จะใช้ `employee_id`, หากเจ้าของเป็นคนสร้างเองจะใช้ `owner_id`
- `updated_by`: รหัสประจำตัวผู้แก้ไข หากเจ้าหน้าที่หน้าเคาน์เตอร์จะใช้ `employee_id`, หากเจ้าของเป็นคนแก้ไขเองจะใช้ `owner_id`

### ตาราง `owner.owner_contacts`

#### โครงสร้าง Field:

| Column                   | Data Type                            | Constraint             |
| ------------------------ | ------------------------------------ | ---------------------- |
| `contact_id`             | UUID                                 | PK, NOT NULL           |
| `owner_id`               | UUID                                 | FK → owner.owners      |
| `contact_type`           | ENUM(PHONE, LINE, EMAIL)             | NOT NULL               |
| `contact_value`          | VARCHAR(255)                         | NOT NULL               |
| `is_primary`             | BOOLEAN                              | NOT NULL DEFAULT FALSE |
| `is_emergency`           | BOOLEAN                              | NOT NULL DEFAULT FALSE |
| `emergency_contact_name` | VARCHAR(150)                         | NULL                   |
| `emergency_relation`     | VARCHAR(100)                         | NULL                   |
| `do_not_contact`         | BOOLEAN                              | NOT NULL DEFAULT FALSE |
| `verified_at`            | TIMESTAMPTZ                          | NULL                   |
| `verified_by`            | UUID                                 | NULL                   |
| `status`                 | ENUM(ACTIVE, INACTIVE)               | NOT NULL               |
| `created_at`             | TIMESTAMPTZ                          | NOT NULL               |
| `updated_at`             | TIMESTAMPTZ                          | NULL                   |
| `created_by`             | UUID                                 | NOT NULL               |
| `updated_by`             | UUID                                 | NULL                   |

#### ข้อกำหนด:

- `contact_id`: รหัสไม่ซ้ำกันสำหรับใช้ภายในระบบ
- `owner_id`: รหัสอ้างอิงจาก ตาราง `owner.owners`
- `contact_type`: ช่องทางการติดต่อที่เจ้าของสะดวกให้ติดต่อกับ เป็นไปได้ 3 ค่า โทรศัพท์ (`PHONE`), Line ID (`LINE`), และ อีเมล (`EMAIL`)
- `contact_value`: ค่าข้อมูลสำหรับช่องทางการติดต่อ เช่น 0999999999, @petlover_444, somsak@petlover.com
- `is_primary`: ระบุว่าเจ้าของใช้ช่องทางนี้เป็นช่องทางติดต่อหลักหรือไม่ (`TRUE`, `FALSE`) ค่าเริ่มต้นเป็น `FALSE` (ควรมีรายการ `is_primary = TRUE` อย่างน้อย 1 รายการสำหรับช่องทางหลัก)
- `is_emergency`: ระบุว่าช่องทางนี้เป็นผู้ติดต่อฉุกเฉิน (`TRUE`, `FALSE`) กรณีไม่สามารถติดต่อเจ้าของหลักได้ในภาวะวิกฤต
- `emergency_contact_name`: ชื่อผู้ติดต่อฉุกเฉิน (ใช้เมื่อ `is_emergency = TRUE`)
- `emergency_relation`: ความสัมพันธ์ของผู้ติดต่อฉุกเฉินกับเจ้าของสัตว์ (เช่น คู่สมรส บิดา/มารดา ผู้ดูแลร่วม)
- `do_not_contact`: ธงระบุว่าห้ามติดต่อผ่านช่องทางนี้โดยเด็ดขาด (ใช้สำหรับบังคับไม่ส่งแจ้งเตือนหรือข้อความการตลาดไปยังช่องทางนั้น)
- `verified_at`: เวลา/วันที่ ที่ได้รับการยืนยันว่าช่องทางนี้ติดต่อได้จริง
- `verified_by`: ระบุว่าใครคือผู้ยืนยันช่องทางการติดต่อนี้ (เป็นค่าว่างได้หากยังไม่ได้ยืนยัน) อาจเป็น `employee_id` หรือ `owner_id` เอง
- `status`: เลือกว่าช่องทางการติดต่อนี้ยังใช้งานได้อยู่หรือไม่ มี `ACTIVE` และ `INACTIVE`
- `created_at`: เวลา/วันที่ที่สร้าง
- `updated_at`: เวลา/วันที่ที่แก้ไขล่าสุด
- `created_by`: รหัสประจำตัวผู้สร้าง หากเจ้าหน้าที่หน้าเคาน์เตอร์จะใช้ `employee_id`, หากเจ้าของเป็นคนสร้างเองจะใช้ `owner_id`
- `updated_by`: รหัสประจำตัวผู้แก้ไข หากเจ้าหน้าที่หน้าเคาน์เตอร์จะใช้ `employee_id`, หากเจ้าของเป็นคนแก้ไขเองจะใช้ `owner_id`

| `created_by`    | UUID                       | NOT NULL               |
| `updated_by`    | UUID                       | NULL                   |

#### ข้อกำหนด:

- `address_id`: รหัสไม่ซ้ำกันสำหรับใช้ภายในระบบ
- `owner_id`: รหัสอ้างอิงจาก ตาราง `owner.owners`
- `address_type`: มี 2 ประเภท ใช้ระบุว่า เป็นที่อยู่ตามบัตรประชาชนหรือที่อยู่ปัจจุบัน (`RESIDENTIAL`), หรือที่อยู่สำหรับออกใบกำกับภาษี (`BILLING`)
- `address_line1`: เลขที่บ้านหรือเลขหมู่บ้าน เช่น 201/88 หมู่ 7 หมู่บ้าน รักสัตว์ ถ.บางนา-ตราด
- `address_line2`: ตรอก ซอย ชั้น เช่น ชั้น 9 อาคาร เสด็จเตี่ย
- `subdistrict`: ตำบล / แขวง
- `district`: อำเภอ / เขต
- `province`: จังหวัด
- `postal_code`: รหัสไปรษณีย์
- `is_primary`: ระบุว่าเจ้าของใช้ที่อยู่นี้เป็นช่องทางติดต่อหลักหรือไม่ (`TRUE`, `FALSE`) ค่าเริ่มต้นเป็น `FALSE`
- `status`: สถานะการใช้งานของที่อยู่ (`ACTIVE`, `INACTIVE`)
- `created_at`: เวลา/วันที่ที่สร้าง
- `updated_at`: เวลา/วันที่ที่แก้ไขล่าสุด
- `created_by`: รหัสประจำตัวผู้สร้าง
- `updated_by`: รหัสประจำตัวผู้แก้ไขล่าสุด

### ตาราง `owner.owner_preferences`

#### โครงสร้าง Field:

| Column             | Data Type   | Constraint        |
| ------------------ | ----------- | ----------------- |
| `preference_id`    | UUID        | PK, NOT NULL      |
| `owner_id`         | UUID        | FK → owner.owners |
| `preference_type`  | VARCHAR(50) | NOT NULL    |
| `preference_value` | JSONB       | NOT NULL    |
| `created_at`       | TIMESTAMPTZ | NOT NULL    |
| `updated_at`       | TIMESTAMPTZ | NULL        |
| `created_by`       | UUID        | NOT NULL    |
| `updated_by`       | UUID        | NULL        |

#### ข้อกำหนด:

- `preference_id`: รหัสประจำรายการตั้งค่าของลูกค้า
- `owner_id`: รหัสอ้างอิงจาก ตาราง `owner.owners`
- `preference_type`: ระบุว่ารายการนี้เป็นการตั้งค่าประเภทใด เป็นตัวกำหนดความหมายของ `preference_value` ประเภทมาตรฐาน มีดังนี้
  - `CHANNEL`: ช่องทางติดต่อที่ต้องการ
  - `LANGUAGE`: ภาษาที่ต้องการใช้สื่อสาร
  - `NOTIFICATION`: การตั้งค่าการแจ้งเตือนทั่วไปและส่งเสริมการขาย
  - `APPOINTMENT`: การตั้งค่าการแจ้งเตือนนัดหมายเฉพาะ (เช่น ล่วงหน้ากี่ชั่วโมง ช่องทางใด)
  - `CONTACT_TIME`: ช่วงเวลาที่สะดวกให้ติดต่อ
  - `DOCUMENT_DELIVERY`: ช่องทางรับเอกสาร
- `preference_value`: เก็บค่าจริงของการตั้งค่าตามประเภทที่ระบุใน `preference_type` เป็นส่วนที่สำคัญที่สุดของตาราง เพราะรองรับข้อมูลการตั้งค่าที่มีโครงสร้างแตกต่างกัน
  - กรณีที่ 1: ลูกค้าต้องการติดต่อผ่าน `LINE`

  ```
  preference_type: CHANNEL
  preference_value: {
    "primary_channel": "LINE",
    "secondary_channel": "PHONE"
  }
  ```

  - กรณีที่ 2: ลูกค้าต้องการใช้ภาษาไทย

  ```
  preference_type: LANGUAGE
  preference_value: {
    "language_code": "th",
    "language_name": "Thai"
  }
  ```

  - กรณีที่ 3: ลูกค้าต้องการรับการแจ้งเตือน

  ```
  preference_type: NOTIFICATION
  preference_value: {
    "appointment_reminder": true,
    "vaccination_reminder": true,
    "payment_reminder": true,
    "promotional_notification": false
  }
  ```

  ข้อควรระวัง: `promotional_notification: false` เป็นเพียงค่าความต้องการในส่วนติดต่อผู้ใช้ ไม่ใช่หลักฐานการถอนหรือไม่ให้ความยินยอมทางการตลาด ต้องตรวจสอบ owner_consents แยกต่างหาก
  - กรณีที่ 4: ลูกค้าต้องการให้แจ้งเตือนก่อนถึงวันนัด 1 วัน

  ```
  preference_type: APPOINTMENT
  preference_value: {
    "reminder_enabled": true,
    "reminder_before_hours": 24,
    "preferred_channel": "LINE"
  }
  ```

  - กรณีที่ 5: ช่วงเวลาที่สะดวกให้ติดต่อ

  ```
  preference_type: CONTACT_TIME
  preference_value: {
    "available_times": ["MORNING", "AFTERNOON", "EVENING"]
  }
  ```

  - กรณีที่ 6: ความต้องการเกี่ยวกับเอกสาร

  ```
  preference_type: DOCUMENT_DELIVERY
  preference_value: {
    "preferred_method": "EMAIL",
    "format": "PDF"
  }
  ```

- `created_at`: เวลา/วันที่ที่สร้าง
- `updated_at`: เวลา/วันที่ที่แก้ไขล่าสุด
- `created_by`: รหัสประจำตัวผู้สร้าง หากเจ้าหน้าที่หน้าเคาน์เตอร์จะใช้ `employee_id`, หากเจ้าของเป็นคนสร้างเองจะใช้ `owner_id`
- `updated_by`: รหัสประจำตัวผู้แก้ไข หากเจ้าหน้าที่หน้าเคาน์เตอร์จะใช้ `employee_id`, หากเจ้าของเป็นคนแก้ไขเองจะใช้ `owner_id`

#### ความแตกต่างระหว่าง owner_preferences กับ owner_consents

สองตารางนี้มีความหมายใกล้เคียงกัน แต่มีหน้าที่ต่างกัน

| ประเด็น         | owner_preferences             | owner_consents                                  |
| --------------- | ----------------------------- | ----------------------------------------------- |
| วัตถุประสงค์    | เก็บความต้องการ               | เก็บความยินยอม                                  |
| ช่องทางติดต่อ   | ต้องการใช้ LINE               | ยินยอมให้ติดต่อผ่าน LINE ตามวัตถุประสงค์ที่ระบุ |

- `consent_type`: ประเภทเอกสาร PDPA หรือความยินยอม ค่าที่เป็นไปได้:
  - `PRIVACY_NOTICE_ACK`: การรับทราบประกาศความเป็นส่วนตัว (Privacy Notice Acknowledgement) สำหรับการประมวลผลข้อมูลเพื่อการรักษาพยาบาลและการปฏิบัติตามกฎหมาย (ไม่ใช่ความยินยอมทางการตลาดและไม่บังคับผูกมัดความยินยอมอื่น)
  - `MARKETING`: ความยินยอมรับข่าวสารสิทธิประโยชน์ โปรโมชั่น และแคมเปญการตลาด (Opt-in โดยสมัครใจ)
  - `APPOINTMENT`: ความยินยอมในการรับแจ้งเตือนนัดหมาย วัคซีน และผลตรวจผ่านช่องทางดิจิทัล
  - `MEDIA`: ความยินยอมให้เผยแพร่ภาพถ่าย/วิดีโอสัตว์เลี้ยงเพื่อการสื่อสารหรือประชาสัมพันธ์
  - `INSURANCE`: ความยินยอมในการเปิดเผยข้อมูลแก่บริษัทประกันภัยสัตว์เลี้ยง
  - `RESEARCH`: ความยินยอมให้นำข้อมูลทางคลินิกไปใช้ในการวิจัยหรือการศึกษากรณีตัวอย่างแบบไม่ระบุตัวตน
- `purpose`: คำอธิบายวัตถุประสงค์เฉพาะของการเก็บรวบรวม/ใช้/เปิดเผยข้อมูลตามหลัก PDPA
- `privacy_notice_version`: เวอร์ชันของประกาศความเป็นส่วนตัวหรือแบบฟอร์มยินยอมที่ลูกค้าอ้างอิงในขณะนั้น (เช่น `PDPA-2026-V1`)
- `consent_granted`: ระบุผลการตัดสินใจ (`TRUE` = ยินยอม / รับทราบ, `FALSE` = ปฏิเสธหรือไม่ยินยอม) ทั้งนี้ความยินยอมส่วนเสริมต้องเป็นไปโดยอิสระ (`MARKETING`, `MEDIA` ไม่บังคับเป็นเงื่อนไขในการรับการรักษา)
- `consented_at`: วัน/เวลาที่บันทึกการรับทราบหรือให้ความยินยอม
- `withdrawn_at`: วัน/เวลาที่ถอนความยินยอม (หากมีการถอน)
- `status`: สถานะของรายการความยินยอม ค่าที่เป็นไปได้คือ `ACTIVE` (มีผลใช้อยู่), `WITHDRAWN` (ถอนความยินยอมแล้ว), `EXPIRED` (หมดอายุ)
- `source_channel`: ช่องทางการยินยอม ค่าที่เป็นไปได้:
  - `COUNTER`: หน้าร้านผ่านแบบฟอร์ม/แท็บเล็ตลงนาม
  - `WEB_PORTAL`: หน้าเว็บไซต์
  - `LINE_OA`: Line Official
- `evidence_reference`: ลิงก์อ้างอิงหลักฐานการยินยอม (เช่น URL ไฟล์แบบฟอร์มลงนาม หรือ Log ยืนยัน OTP/Click-wrap)
- `recorded_by`: รหัสเจ้าหน้าที่ผู้บันทึก (อ้างอิง `hr.employees`) กรณีบันทึกผ่านเคาน์เตอร์ (เป็น `NULL` หากเจ้าของกดยินยอมเองผ่าน Online Portal)

**หมายเหตุ:** ตารางนี้ต้องเก็บประวัติการให้และถอนความยินยอมแบบ Append-only (หรือบันทึกประวัติใหม่เมื่อมีการเปลี่ยนคำยินยอม) เพื่อตรวจสอบย้อนหลังตาม PDPA ได้โดยไม่ลบหรือเขียนทับหลักฐานเดิม

### ตาราง `owner.owner_merge_histories`

**หน้าที่**: จัดเก็บประวัติการรวมบัญชีเจ้าของสัตว์เลี้ยงที่ซ้ำซ้อนเข้าด้วยกัน (Duplicate Owner Merge) ตาม Business Domain 01 เพื่อรักษาความถูกต้องของ Audit Trail และเชื่อมโยงการย้ายข้อมูลสัตว์เลี้ยง ประวัติติดต่อ และเอกสารไปยังบัญชีหลัก

#### โครงสร้าง Field:

| Column                 | Data Type   | Constraint                  |
| ---------------------- | ----------- | --------------------------- |
| `merge_history_id`     | UUID        | PK, NOT NULL                |
| `source_owner_id`      | UUID        | FK → owner.owners, NOT NULL |
| `target_owner_id`      | UUID        | FK → owner.owners, NOT NULL |
| `merge_reason`         | TEXT        | NULL                        |
| `merged_field_summary` | JSONB       | NULL                        |
| `moved_pet_count`      | INTEGER     | NOT NULL DEFAULT 0          |
| `merged_at`            | TIMESTAMPTZ | NOT NULL                    |
| `merged_by`            | UUID        | FK → hr.employees, NOT NULL |
| `created_at`           | TIMESTAMPTZ | NOT NULL                    |

#### ข้อกำหนด:

- `merge_history_id`: รหัสรายการรวมบัญชี
- `source_owner_id`: รหัสบัญชีเจ้าของต้นทางที่ถูกยุบรวม (บัญชีนี้จะถูกปรับ `status` เป็น `MERGED` และระบุ `merged_into_owner_id = target_owner_id`)
- `target_owner_id`: รหัสบัญชีเจ้าของปลายทางหลักที่คงไว้ใช้งาน
- `merge_reason`: เหตุผลหรือรายละเอียดการตรวจสอบว่าพบข้อมูลซ้ำซ้อน
- `merged_field_summary`: สรุป Field หรือข้อมูลที่นำมารวม/คงไว้ระหว่างบัญชีต้นทางและปลายทาง (JSON)
- `moved_pet_count`: จำนวนรายการความสัมพันธ์สัตว์เลี้ยง (`owner.pet_ownerships`) ที่ถูกโอนย้ายมายังบัญชีปลายทาง
- `merged_at`: วันและเวลาที่ดำเนินการรวมบัญชี
- `merged_by`: รหัสเจ้าหน้าที่ผู้ดำเนินการรวมบัญชี อ้างอิง `hr.employees`
- `created_at`: วันและเวลาที่สร้างบันทึก

#### หมายเหตุ:

1. `source_owner_id` ต้องไม่เท่ากับ `target_owner_id`
2. ห้ามลบ Record ของ `source_owner_id` ออกจาก `owner.owners` เพื่อรักษาประวัติทางคลินิก การเงิน และ PDPA Consent เดิม
3. `target_owner_id` ต้องอยู่ในสถานะ `ACTIVE` ขณะทำการ Merge และไม่รองรับการ Merge เข้าหาบัญชีที่ถูก Merge ไปแล้วโดยตรง (ต้องชี้ไปยังบัญชีปลายทางปัจจุบัน)

#### ข้อกำหนด:

- `pet_id`: รหัสไม่ซ้ำกันสำหรับใช้ภายในระบบ
- `pet_code`: รหัสที่ไม่ซ้ำกันสำหรับใช้ภายในองค์กร เพื่อให้เจ้าหน้าที่สามารถสืบค้นได้ ใช้วิธีกำหนดเป็น `PET-{YYYY}{MM}{DD}-{NNNN}` โดยที่:
  - `{YYYY}{MM}{DD}` คือวันที่ตามปฏิทิน ค.ศ.
  - `{NNNN}` คือ ตัวเลขที่เพิ่มขึ้นอัตโนมัติ เช่น 0001 - 9999 และ Reset เป็น 0000 ทุกวันที่ 1 เที่ยงคืนของทุกเดือน
- `pet_name`: ชื่อเรียกของสัตว์เลี้ยง
- `species_id`: รหัสประเภทสัตว์ อ้างอิงจากตาราง `owner.species`
- `breed_id`: รหัสสายพันธุ์ อ้างอิงจากตาราง `owner.breeds` (เป็น `NULL` ได้กรณีไม่ทราบสายพันธุ์หรือเป็นพันธุ์ผสมที่ไม่ได้ระบุสายพันธุ์หลัก)
- `sex`: เพศ เป็นไปได้ 3 ค่า `MALE`, `FEMALE`, `UNKNOWN`
- `date_of_birth`: วันที่เกิดแบบระบุแน่นอน หรือวันเกิดโดยประมาณ (เป็น `NULL` ได้หากไม่ทราบวันเกิด)
- `birth_date_is_estimated`: เปิดใช้งานการประมาณวันที่เกิด (`TRUE` เมื่อ `date_of_birth` มาจากการประมาณอายุ)
- `color`: สีและลักษณะเด่น ประจำตัวสัตว์เลี้ยง
- `reproductive_status`: สถานะการทำหมัน เป็นไปได้ 3 ค่า `INTACT`, `NEUTERED`, `UNKNOWN`
- `microchip_number`: หมายเลขไมโครชิปสัตว์เลี้ยงที่มีมาตรฐาน ISO11784/11785 15 หลัก (กำหนด Partial UNIQUE Index เฉพาะแถวที่ `microchip_number IS NOT NULL` เพื่อป้องกันการลงทะเบียนซ้ำ)
- `status`: สถานะปัจจุบันของสัตว์เลี้ยง ค่าที่เป็นไปได้คือ
  - `ACTIVE`: ปกติ พร้อมรับบริการ
  - `INACTIVE`: ปิดการใช้งานชั่วคราว
  - `LOST`: สูญหาย (แจ้งสัตว์เลี้ยงหายเพื่อเฝ้าระวังเมื่อมีผู้พบเห็น)
  - `TRANSFERRED`: โอนย้ายออกจากความดูแลของระบบ/ย้ายคลินิกถาวร (กรณีเปลี่ยนเจ้าของภายในคลินิกให้ใช้การปิด/เปิด `owner.pet_ownerships` โดยสัตว์ยังคง `ACTIVE`)
  - `DECEASED`: เสียชีวิตแล้ว (ต้องระงับการสร้างนัดหมายใหม่และแจ้งเตือนสื่อสารทางการตลาด)
- `created_at`: เวลา/วันที่ที่สร้าง
- `updated_at`: เวลา/วันที่ที่แก้ไขล่าสุด
- `created_by`: รหัสประจำตัวผู้สร้าง หากเจ้าหน้าที่หน้าเคาน์เตอร์จะใช้ `employee_id`, หากเจ้าของเป็นคนสร้างเองจะใช้ `owner_id`
- `updated_by`: รหัสประจำตัวผู้แก้ไข หากเจ้าหน้าที่หน้าเคาน์เตอร์จะใช้ `employee_id`, หากเจ้าของเป็นคนแก้ไขเองจะใช้ `owner_id`

- `is_financial_responsible`: ระบุว่าบุคคลนี้เป็นผู้รับผิดชอบค่าใช้จ่าย/วางบิล (`TRUE`/`FALSE`) ใช้แยกบทบาทผู้ชำระเงินจากผู้นำสัตว์มาส่งเมื่อส่งต่อ Domain 07 (Billing)
- `can_consent_treatment`: ระบุว่าบุคคลนี้มีอำนาจลงนามยินยอมการรักษา/ผ่าตัด/วางยาสลบ (`TRUE`/`FALSE`) ใช้ตรวจสอบสิทธิ์ใน Domain 03 (Clinical) และ Domain 06 (Surgery)
- `start_date`: วันที่เริ่มความสัมพันธ์หรือสิทธิ์การเป็นเจ้าของ/ผู้ดูแล
- `end_date`: วันที่สิ้นสุดความสัมพันธ์ (เป็น `NULL` ขณะที่ยัง `ACTIVE`)
- `status`: สถานะความสัมพันธ์ ค่าที่เป็นไปได้คือ `ACTIVE` (มีผลอยู่) และ `ENDED` (สิ้นสุดแล้ว เช่น โอนเปลี่ยนเจ้าของหรือยกเลิกสิทธิ์ผู้ดูแล)
- `transfer_reason`: เหตุผลการโอนย้ายเจ้าของหรือยุติความสัมพันธ์ (เช่น ขายต่อ โอนให้ญาติ ยกเลิกผู้ดูแล)
- `created_at`: เวลา/วันที่ที่สร้าง
- `updated_at`: เวลา/วันที่ที่แก้ไขล่าสุด
- `created_by`: รหัสประจำตัวผู้สร้าง หากเจ้าหน้าที่หน้าเคาน์เตอร์จะใช้ `employee_id`, หากเจ้าของเป็นคนสร้างเองจะใช้ `owner_id`
- `updated_by`: รหัสประจำตัวผู้แก้ไข หากเจ้าหน้าที่หน้าเคาน์เตอร์จะใช้ `employee_id`, หากเจ้าของเป็นคนแก้ไขเองจะใช้ `owner_id`

#### หมายเหตุ:

1. สัตว์เลี้ยง 1 ตัวสามารถมีผู้ที่อยู่ในบทบาท `PRIMARY` และ `status = ACTIVE` ได้เพียง 1 รายการในเวลาเดียวกัน (กำหนด Partial UNIQUE Index ที่ `(pet_id) WHERE ownership_type = 'PRIMARY' AND status = 'ACTIVE'`)
2. เมื่อมีการเปลี่ยน/โอนย้ายเจ้าของ ห้ามลบหรือเขียนทับแถวเดิม ให้ปิดรายการเดิม (`status = ENDED`, ระบุ `end_date` และ `transfer_reason`) แล้วสร้างรายการใหม่พร้อม `start_date` เพื่อให้ตรวจสอบประวัติความเป็นเจ้าของย้อนหลังได้ครบถ้วน
3. `end_date` ต้องไม่ก่อน `start_date` (เมื่อระบุ `end_date`)
4. กรณีผู้นำสัตว์มาส่งที่เคาน์เตอร์เป็น `CAREGIVER` หรือ `AUTHORIZED_PERSON` ที่ `can_consent_treatment = FALSE` ระบบนัดหมาย/เวชระเบียน/ศัลยกรรมต้องแจ้งเตือนและขอความยินยอมจากผู้ที่มี `can_consent_treatment = TRUE` ก่อนหัตถการเสี่ยงหรือผ่าตัด

### ตาราง `owner.pet_weights`

#### โครงสร้าง Field:

| Column               | Data Type                                    | Constraint        |
| -------------------- | -------------------------------------------- | ----------------- |
| `weight_id`          | UUID                                         | PK, NOT NULL      |
| `pet_id`             | UUID                                         | FK → owner.pets   |
| `weight_value`       | NUMERIC(8,3)                                 | NOT NULL          |
| `unit`               | ENUM(KG, G, LB)                              | NOT NULL          |
| `measured_at`        | TIMESTAMPTZ                                  | NOT NULL          |
| `measured_by`        | UUID                                         | NULL              |
| `measurement_source` | ENUM(TRIAGE, CLINICAL, GROOMING, OWNER)      | NULL              |

#### ข้อกำหนด:

- `weight_id`: รหัสไม่ซ้ำกันสำหรับใช้ภายในระบบ
- `pet_id`: รหัสสัตว์เลี้ยง อ้างอิงจากตาราง `owner.pets`
- `weight_value`: ค่าของน้ำหนักที่ชั่งได้ (ต้องมากกว่า 0)
- `unit`: หน่วยน้ำหนักที่ใช้ชั่ง ค่าที่เป็นไปได้คือ กิโลกรัม (`KG`), กรัม (`G`), ปอนด์ (`LB`)
- `measured_at`: วันและเวลาที่ชั่งน้ำหนัก (ใช้ `TIMESTAMPTZ` เพื่อรองรับการชั่งหลายครั้งภายในวันเดียวกันและการซิงค์จาก Triage/Clinical)
- `measured_by`: รหัสประจำตัวผู้ชั่งหรือบันทึก ใช้ `employee_id` (เป็น `NULL` ได้กรณีเจ้าของแจ้งเอง)
- `measurement_source`: แหล่งที่มาของการบันทึกน้ำหนัก (`TRIAGE`, `CLINICAL`, `GROOMING`, `OWNER`) เพื่อใช้วิเคราะห์แนวโน้มน้ำหนักและคำนวณขนาดยาใน Domain 03
