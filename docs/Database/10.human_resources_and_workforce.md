# Domain 10 — Human Resources & Workforce Management

เจ้าของข้อมูล: Domain 10

รับผิดชอบกระบวนการบริหารทรัพยากรบุคคลและกำลังคนของคลินิกและโรงพยาบาลสัตว์อย่างครบวงจร ตั้งแต่การบริหารโครงสร้างองค์กรหลายระดับหลายสาขา ทะเบียนตำแหน่งงานและอัตราอนุมัติ การวางแผนอัตรากำลังและงบประมาณบุคลากร ทะเบียนประวัติพนักงานกลางชุดเดียวสำหรับบุคลากรทุกสายงานพร้อมส่วนขยายคุณลักษณะเฉพาะทางสำหรับสัตวแพทย์/บุคลากรคลินิก สัญญาจ้างงานหลายประเภทและประวัติหลายฉบับ การมอบหมายบทบาทควบคู่และปฏิบัติงานข้ามสาขาแบบมีช่วงวันที่มีผล (Effective-Dated Multi-Role & Multi-Branch Assignment) เพื่อรองรับการสืบค้นโครงสร้างย้อนหลัง ณ จุดเวลาใด ๆ การบริหารการโยกย้าย/เลื่อนตำแหน่ง/ปรับฐานเงินเดือน กระบวนการสรรหาและคัดเลือกผู้สมัครงาน (แยกขาดจากทะเบียนพนักงานพร้อมการคุมความยินยอม PDPA) การเตรียมความพร้อมเริ่มงาน (Onboarding) และการประสานงานคำขอเปิด-ปิดสิทธิ์ระบบกับ IT & Security ทะเบียนใบอนุญาตประกอบวิชาชีพและการตรวจสอบรับรอง (`hr.employee_licenses`) การประเมินทักษะและความเชี่ยวชาญแยกจากประวัติการฝึกอบรม การจัดตารางกะงานหลายสาขาและการแลกกะ การลงเวลาทำงานดิบและการตรวจรับรองเวลาปฏิบัติงานรายวัน ระบบวันหยุดคลินิกและบัญชีคุมสิทธิวันลา การบริหารชั่วโมงล่วงเวลา (OT) การคำนวณเงินเดือน ค่าตอบแทน และค่าคอมมิชชันบริการแยกจากรายได้คลินิกพร้อมส่งต่อยอดให้ Finance & Accounting สวัสดิการพนักงาน การประเมินผลการปฏิบัติงาน การฝึกอบรมและพัฒนาบุคลากร การบริหารวินัยและข้อร้องเรียนความลับสูง อาชีวอนามัยและความปลอดภัยเฉพาะคลินิกสัตวแพทย์ (สัตว์กัด/ข่วน เข็มตำ รังสี X-ray เชื้อโรค วัคซีนพิษสุนัขบ้า) กระบวนการลาออก/พ้นสภาพพนักงาน ไปจนถึงการวิเคราะห์กำลังคนและต้นทุนบุคลากร

ทั้งนี้ Domain 10 ยึดหลัก **Single Source of Truth (SSOT)** โดยเป็นเจ้าของทะเบียนพนักงานกลาง (`hr.employees`) โครงสร้างหน่วยงาน ตำแหน่งงาน แผนอัตรากำลัง คำขอสรรหา ผู้สมัครงาน การสัมภาษณ์และข้อเสนอจ้างงาน สัญญาจ้างและประวัติการเคลื่อนไหว ทะเบียนใบอนุญาตวิชาชีพ (`hr.employee_licenses`) ทักษะพนักงาน ตารางกะการทำงาน เวลาเข้า-ออกงาน วันลา โอที เงินเดือน สวัสดิการ การประเมินผล หลักสูตรอบรม ประวัติวินัย บันทึกอาชีวอนามัย และการพ้นสภาพพนักงาน ส่วนข้อมูลสาขาและทะเบียนบริการกลาง (รวมถึง `is_commissionable`) อยู่ที่ Domain 00 (`core`), ข้อมูลลูกค้าและสัตว์เลี้ยงอยู่ที่ Domain 01 (`owner`), ข้อมูลการนัดหมาย คิวบริการ และข้อยกเว้น/การบล็อกสล็อตเวลาสัตวแพทย์ (`appointment.veterinarian_schedule_exceptions`) อยู่ที่ Domain 02 (`appointment`), เวชระเบียน การตรวจรักษา และการลงนามทางคลินิกอยู่ที่ Domain 03 (`clinical`), การจ่ายยาและควบคุมคลังอยู่ที่ Domain 04 (`pharmacy`), งานห้องปฏิบัติการและรังสีวินิจฉัยอยู่ที่ Domain 05 (`laboratory`), ทีมผ่าตัดและหัตถการอยู่ที่ Domain 06 (`surgery`), รายได้จริงตามใบแจ้งหนี้และการเรียกเก็บเงิน (`billing.invoices`, `billing.invoice_items`) อยู่ที่ Domain 07 (`billing`), กิจกรรมการตลาดอยู่ที่ Domain 08 (`crm`), การจัดซื้ออยู่ที่ Domain 09 (`procurement`), การลงบัญชี GL และการโอนจ่ายเงินเดือนจริงอยู่ที่ระบบ `Finance & Accounting`, และบัญชีผู้ใช้งาน/รหัสผ่าน/สิทธิ์เข้าถึงระบบทางเทคนิคอยู่ที่ระบบ `IT & Security`

## กลุ่ม Governance Config, Organization Structure, Job Positions & Workforce Planning

### ตาราง `hr.document_sequences`

**หน้าที่**: บริหารรูปแบบการออกเลขที่เอกสารด้านทรัพยากรบุคคลและกำลังคนแยกตามสาขาและงวดเวลา (เช่น แผนอัตรากำลัง คำขอสรรหา ผู้สมัคร ข้อเสนอจ้าง สัญญาจ้าง การปรับตำแหน่ง ตารางกะ ใบลา ใบโอที รอบเงินเดือน สลิปเงินเดือน กรณีวินัย อุบัติเหตุอาชีวอนามัย และการพ้นสภาพ) เพื่อรับประกันว่าเลขที่เอกสารไม่ซ้ำกันและตรวจสอบย้อนหลังได้

#### โครงสร้าง Field:

| Column | Data Type | Constraint |
| --- | --- | --- |
| `sequence_id` | UUID | PK, NOT NULL |
| `branch_id` | UUID | FK → core.branches, NULL |
| `document_type` | ENUM | NOT NULL |
| `document_prefix` | VARCHAR(20) | NOT NULL |
| `number_format_pattern` | VARCHAR(100) | NOT NULL |
| `reset_frequency` | ENUM | NOT NULL |
| `current_period_key` | VARCHAR(20) | NOT NULL |
| `last_running_number` | INTEGER | NOT NULL DEFAULT 0 |
| `padding_length` | SMALLINT | NOT NULL DEFAULT 4 |
| `effective_from` | DATE | NOT NULL |
| `effective_to` | DATE | NULL |
| `status` | ENUM | NOT NULL |
| `created_at` | TIMESTAMPTZ | NOT NULL |
| `created_by` | UUID | FK → hr.employees, NOT NULL |
| `updated_at` | TIMESTAMPTZ | NULL |
| `updated_by` | UUID | FK → hr.employees, NULL |

#### ข้อกำหนด:

- `sequence_id`: รหัสประจำชุดรันเลขที่เอกสาร HR ใช้เป็น Primary Key
- `branch_id`: สาขาเจ้าของชุดรันเลขที่ (`NULL` = ใช้รันกลางระดับองค์กร) อ้างอิง `core.branches`
- `document_type`: ประเภทเอกสาร HR (`WORKFORCE_PLAN`, `RECRUITMENT_REQ`, `APPLICANT`, `JOB_APPLICATION`, `JOB_OFFER`, `EMPLOYMENT_CONTRACT`, `EMPLOYEE_CODE`, `EMPLOYEE_MOVEMENT`, `IT_ACCESS_REQUEST`, `WORK_SCHEDULE`, `SHIFT_SWAP`, `LEAVE_REQUEST`, `OVERTIME_REQUEST`, `PAYROLL_RUN`, `PAY_SLIP`, `PAYROLL_HANDOFF`, `PERFORMANCE_EVALUATION`, `DISCIPLINARY_CASE`, `OHS_INCIDENT`, `OFFBOARDING_CASE`)
- `document_prefix`: คำนำหน้าเลขที่เอกสาร เช่น `WFP`, `REC`, `APP`, `OFR`, `CNT`, `EMP`, `MOV`, `ITR`, `SCH`, `SWP`, `LVR`, `OTR`, `PAY`, `SLP`, `HPH`, `EVL`, `DSC`, `OHS`, `OFF`
- `number_format_pattern`: รูปแบบ Template เช่น `{PREFIX}-{YYYY}{MM}-{NNNN}`
- `reset_frequency`: รอบการรีเซ็ตเลขที่รัน (`DAILY`, `MONTHLY`, `YEARLY`, `FISCAL_YEAR`, `NEVER`)
- `current_period_key`: คีย์งวดเวลาปัจจุบันที่กำลังรันเลขอยู่
- `last_running_number`: เลขลำดับล่าสุดที่ออกไปแล้ว (ใช้ `SELECT ... FOR UPDATE` ระหว่างสร้างเลข)
- `padding_length`: จำนวนหลักของเลขรัน (เช่น `4` -> `0001`)
- `effective_from` / `effective_to` / `status`: ช่วงวันที่มีผลบังคับใช้และสถานะ (`ACTIVE`, `INACTIVE`)
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit อ้างอิง `hr.employees`

#### หมายเหตุ:

1. กำหนด Partial UNIQUE Index สองชุดเพื่อป้องกันซ้ำ: `(document_type, current_period_key) WHERE branch_id IS NULL AND status = 'ACTIVE'` และ `(branch_id, document_type, current_period_key) WHERE branch_id IS NOT NULL AND status = 'ACTIVE'`
2. สำหรับการสร้าง SQL DDL จริง ควรเพิ่ม FK `created_by → hr.employees` และ `updated_by → hr.employees` ด้วยคำสั่ง `ALTER TABLE` หลังจากสร้างตาราง `hr.employees` แล้ว

### ตาราง `hr.departments`

**หน้าที่**: จัดเก็บโครงสร้างองค์กร ฝ่าย แผนก และหน่วยงานย่อยแบบลำดับชั้น (Hierarchical Org Chart) รองรับองค์กรที่มีหลายสาขา สามารถกำหนดหัวหน้าหน่วยงานและเก็บช่วงวันที่เริ่ม-สิ้นสุดเพื่อตรวจสอบโครงสร้างย้อนหลังโดยไม่ลบประวัติพนักงานเดิม (§4.1)

#### โครงสร้าง Field:

| Column | Data Type | Constraint |
| --- | --- | --- |
| `department_id` | UUID | PK, NOT NULL |
| `department_code` | VARCHAR(30) | UNIQUE, NOT NULL |
| `department_name` | VARCHAR(150) | NOT NULL |
| `department_type` | ENUM | NOT NULL |
| `parent_department_id` | UUID | FK → hr.departments, NULL |
| `branch_id` | UUID | FK → core.branches, NULL |
| `head_employee_id` | UUID | FK → hr.employees, NULL |
| `cost_center_code` | VARCHAR(50) | NULL |
| `effective_from` | DATE | NOT NULL |
| `effective_to` | DATE | NULL |
| `status` | ENUM | NOT NULL |
| `description` | TEXT | NULL |
| `created_at` | TIMESTAMPTZ | NOT NULL |
| `created_by` | UUID | FK → hr.employees, NOT NULL |
| `updated_at` | TIMESTAMPTZ | NULL |
| `updated_by` | UUID | FK → hr.employees, NULL |

#### ข้อกำหนด:

- `department_id`: รหัสประจำหน่วยงาน ใช้เป็น Primary Key
- `department_code`: รหัสหน่วยงานที่ไม่ซ้ำกัน (เช่น `MGMT`, `VET`, `VET_ASSIST`, `PHARMACY`, `LAB`, `SURGERY`, `RECEPTION`, `FINANCE`, `PROCUREMENT`, `HR`) สอดคล้องกับ `department_code` ที่ใช้อ้างอิงใน Domain 09
- `department_name`: ชื่อฝ่ายหรือแผนก
- `department_type`: ระดับของหน่วยงาน (`EXECUTIVE_BOARD`, `DIVISION`, `DEPARTMENT`, `CLINIC_UNIT`, `TEAM`)
- `parent_department_id`: หน่วยงานแม่ที่สังกัด (Self-referencing `hr.departments`)
- `branch_id`: สาขาที่หน่วยงานตั้งอยู่ (`NULL` = หน่วยงานส่วนกลางระดับสำนักงานใหญ่) อ้างอิง `core.branches`
- `head_employee_id`: ผู้บริหารหรือหัวหน้าหน่วยงานผู้รับผิดชอบ อ้างอิง `hr.employees`
- `cost_center_code`: รหัสศูนย์ต้นทุนสำหรับเชื่อมต่อบัญชีค่าใช้จ่ายบุคลากรไปยัง Finance & Accounting
- `effective_from` / `effective_to` / `status`: วันที่เริ่มใช้งาน วันที่ยุบ/สิ้นสุด และสถานะ (`ACTIVE`, `INACTIVE`, `DISSOLVED`)
- `description`: คำอธิบายภารกิจและขอบเขตความรับผิดชอบของหน่วยงาน
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit

#### หมายเหตุ:

1. การปิดหรือยุบหน่วยงานให้เปลี่ยน `status = 'DISSOLVED'` และระบุ `effective_to` ห้ามลบแถวที่มีประวัติพนักงานหรือธุรกรรมอ้างอิง (กฎ §4.1)
2. สำหรับการสร้าง SQL DDL จริง ควรเพิ่ม FK `head_employee_id → hr.employees`, `created_by → hr.employees` และ `updated_by → hr.employees` ด้วยคำสั่ง `ALTER TABLE` หลังจากสร้างตาราง `hr.employees` แล้ว

### ตาราง `hr.job_positions`

**หน้าที่**: จัดเก็บทะเบียนตำแหน่งงานมาตรฐานของคลินิก (แยกออกจากตัวบุคคลที่ดำรงตำแหน่ง) พร้อมระดับตำแหน่ง หน้าที่ความรับผิดชอบ คุณสมบัติขั้นต่ำ ช่วงฐานเงินเดือน ข้อกำหนดใบอนุญาตวิชาชีพ และรหัสบทบาท (`role_code`) สำหรับเชื่อมกติกาการอนุมัติข้าม Domain (§4.2, §11.1)

#### โครงสร้าง Field:

| Column | Data Type | Constraint |
| --- | --- | --- |
| `position_id` | UUID | PK, NOT NULL |
| `position_code` | VARCHAR(30) | UNIQUE, NOT NULL |
| `role_code` | VARCHAR(50) | NOT NULL |
| `position_title` | VARCHAR(150) | NOT NULL |
| `position_category` | ENUM | NOT NULL |
| `position_level` | SMALLINT | NOT NULL DEFAULT 1 |
| `department_id` | UUID | FK → hr.departments, NOT NULL |
| `reports_to_position_id` | UUID | FK → hr.job_positions, NULL |
| `job_summary` | TEXT | NULL |
| `key_responsibilities` | TEXT | NULL |
| `min_qualification` | TEXT | NULL |
| `min_experience_years` | NUMERIC(4,1) | NOT NULL DEFAULT 0 |
| `salary_band_min` | NUMERIC(14,2) | NULL |
| `salary_band_max` | NUMERIC(14,2) | NULL |
| `approved_headcount_default` | INTEGER | NOT NULL DEFAULT 1 |
| `requires_professional_license` | BOOLEAN | NOT NULL DEFAULT FALSE |
| `status` | ENUM | NOT NULL |
| `created_at` | TIMESTAMPTZ | NOT NULL |
| `created_by` | UUID | FK → hr.employees, NOT NULL |
| `updated_at` | TIMESTAMPTZ | NULL |
| `updated_by` | UUID | FK → hr.employees, NULL |

#### ข้อกำหนด:

- `position_id`: รหัสประจำตำแหน่งงาน ใช้เป็น Primary Key
- `position_code`: รหัสตำแหน่งงานมาตรฐานที่ไม่ซ้ำกัน (เช่น `POS-VET-GP`, `POS-VET-SURG`, `POS-PHARM`, `POS-LAB-TECH`, `POS-BR-MGR`)
- `role_code`: รหัสบทบาทมาตรฐานระดับองค์กร (เช่น `VETERINARIAN`, `BRANCH_MANAGER`, `FINANCE_MANAGER`, `PROCUREMENT_MANAGER`, `EXECUTIVE`) เพื่อใช้จับคู่กับสิทธิ์ผู้อนุมัติใน Domain 07 และ Domain 09
- `position_title`: ชื่อตำแหน่งงานที่แสดงผล
- `position_category`: กลุ่มตำแหน่ง (`EXECUTIVE`, `MANAGEMENT`, `VETERINARIAN`, `SPECIALIST_VETERINARIAN`, `VETERINARY_NURSE`, `VETERINARY_ASSISTANT`, `PHARMACY`, `LABORATORY`, `RADIOLOGY`, `SURGERY_SUPPORT`, `RECEPTION_CUSTOMER_SERVICE`, `FINANCE_ACCOUNTING`, `PROCUREMENT`, `HR_ADMIN`, `FACILITY_SUPPORT`)
- `position_level`: ระดับขั้นของตำแหน่งตามโครงสร้างสายบังคับบัญชา
- `department_id` / `reports_to_position_id`: หน่วยงานสังกัดและตำแหน่งหัวหน้างานโดยตรง
- `job_summary` / `key_responsibilities` / `min_qualification` / `min_experience_years`: ขอบเขตงาน หน้าที่หลัก คุณสมบัติขั้นต่ำ และประสบการณ์ที่ต้องการ (ปี)
- `salary_band_min` / `salary_band_max`: ช่วงอัตราเงินเดือนมาตรฐานของตำแหน่ง
- `approved_headcount_default`: จำนวนอัตรากำลังมาตรฐานที่อนุมัติสำหรับตำแหน่งนี้
- `requires_professional_license`: ระบุว่าผู้ดำรงตำแหน่งนี้จำเป็นต้องมีใบอนุญาตประกอบวิชาชีพที่ผ่านการรับรองหรือไม่
- `status` / `created_at` / `created_by` / `updated_at` / `updated_by`: สถานะ (`ACTIVE`, `INACTIVE`, `FROZEN`) และข้อมูล Audit

#### หมายเหตุ:

1. ห้ามลบตำแหน่งงานที่มีพนักงานดำรงตำแหน่งหรือมีประวัติการเคลื่อนไหวแล้ว ให้เปลี่ยน `status = 'INACTIVE'`
2. หากระบุทั้ง `salary_band_min` และ `salary_band_max` ต้องกำหนด `salary_band_max >= salary_band_min`
3. สำหรับการสร้าง SQL DDL จริง ควรเพิ่ม FK `created_by → hr.employees` และ `updated_by → hr.employees` ด้วยคำสั่ง `ALTER TABLE` หลังจากสร้างตาราง `hr.employees` แล้ว

### ตาราง `hr.workforce_plans`

**หน้าที่**: จัดเก็บแผนความต้องการอัตรากำลังและงบประมาณบุคลากรตามสาขาและช่วงเวลา เพื่อวิเคราะห์ช่องว่างกำลังคนเทียบกับจำนวนพนักงานปัจจุบันก่อนส่งอนุมัติเปิดคำขอสรรหา (§4.3)

#### โครงสร้าง Field:

| Column | Data Type | Constraint |
| --- | --- | --- |

### ตาราง `hr.hr_workforce_snapshots`

**หน้าที่**: จัดเก็บข้อมูลสรุปตัวชี้วัดและรายงานวิเคราะห์กำลังคนและต้นทุนบุคลากรรายงวดแยกตามสาขาและหน่วยงาน (จำนวนพนักงาน อัตราเข้า-ออก อัตราขาดงาน/มาสาย อัตราผ่านทดลองงาน ชั่วโมงและต้นทุน OT ค่าใช้จ่ายเงินเดือน อัตราการฝึกอบรม ความพร้อมใบอนุญาตวิชาชีพ และระยะเวลาสรรหาเฉลี่ย) (§4.24)

#### โครงสร้าง Field:

| Column | Data Type | Constraint |
| --- | --- | --- |
| `snapshot_id` | UUID | PK, NOT NULL |
| `branch_id` | UUID | FK → core.branches, NULL |
| `department_id` | UUID | FK → hr.departments, NULL |
| `snapshot_period_type` | ENUM | NOT NULL |
| `period_start_date` | DATE | NOT NULL |
| `period_end_date` | DATE | NOT NULL |
| `active_headcount` | INTEGER | NOT NULL DEFAULT 0 |
| `new_hires_count` | INTEGER | NOT NULL DEFAULT 0 |
| `separations_count` | INTEGER | NOT NULL DEFAULT 0 |
| `turnover_rate_pct` | NUMERIC(5,2) | NULL |
| `absenteeism_rate_pct` | NUMERIC(5,2) | NULL |
| `tardiness_rate_pct` | NUMERIC(5,2) | NULL |
| `probation_pass_rate_pct` | NUMERIC(5,2) | NULL |
| `total_ot_hours` | NUMERIC(10,2) | NOT NULL DEFAULT 0 |
| `total_ot_cost` | NUMERIC(16,2) | NOT NULL DEFAULT 0 |
| `total_payroll_cost` | NUMERIC(16,2) | NOT NULL DEFAULT 0 |
| `training_completion_rate_pct` | NUMERIC(5,2) | NULL |
| `license_compliance_rate_pct` | NUMERIC(5,2) | NULL |

| `computed_at` | TIMESTAMPTZ | NOT NULL |
| `created_at` | TIMESTAMPTZ | NOT NULL |

#### ข้อกำหนด:

- `snapshot_id`: รหัสประจำข้อมูลสรุปตัวชี้วัดกำลังคน ใช้เป็น Primary Key
- `branch_id` / `department_id`: สาขาและหน่วยงานที่วิเคราะห์ (`NULL` = ภาพรวมระดับองค์กร)
- `snapshot_period_type` / `period_start_date` / `period_end_date`: รอบการสรุป (`MONTHLY`, `QUARTERLY`, `ANNUAL`) และช่วงวันที่ที่ใช้คำนวณ
- `active_headcount` / `new_hires_count` / `separations_count` / `turnover_rate_pct`: จำนวนพนักงานปัจจุบัน (แยกจากพนักงานเดิมที่พ้นสภาพแล้ว) พนักงานเข้าใหม่ พนักงานลาออก และอัตราการลาออก
- `absenteeism_rate_pct` / `tardiness_rate_pct` / `probation_pass_rate_pct`: อัตราการขาดงาน อัตราการมาทำงานสาย และอัตราผ่านการทดลองงาน (ร้อยละ)
- `total_ot_hours` / `total_ot_cost` / `total_payroll_cost`: ชั่วโมงและต้นทุน OT รวม ตลอดจนต้นทุนบุคลากรรวมจาก `payroll_slips`
- `training_completion_rate_pct` / `license_compliance_rate_pct` / `avg_time_to_hire_days`: สัดส่วนพนักงานที่ผ่านการอบรมตามแผน สัดส่วนบุคลากรวิชาชีพที่มีใบอนุญาตใช้งานถูกต้องยังไม่หมดอายุ และระยะเวลาเฉลี่ยในการสรรหาพนักงาน 1 อัตรา (วัน)
- `computed_at` / `created_at`: วันเวลาประมวลผลและวันเวลาบันทึก

#### หมายเหตุ:

1. ตัวเลขทั้งหมดในตารางนี้ต้องคำนวณจากข้อมูลธุรกรรมต้นทางจริงของ HR (`employees`, `attendance_records`, `overtime_requests`, `payroll_slips`, `training_enrollments`, `employee_licenses`, `offboarding_cases`) และจำกัดสิทธิ์การดูต้นทุนเงินเดือนเฉพาะผู้บริหาร/ผู้มีสิทธิ์ตามกฎ §4.24 และ §8
2. กำหนด Partial UNIQUE Index ครอบคลุมกรณี `branch_id` หรือ `department_id` เป็น `NULL` เพื่อป้องกัน Snapshot ซ้ำในงวดเดียวกัน
