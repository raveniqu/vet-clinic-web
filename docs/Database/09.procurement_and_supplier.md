# Domain 09 — Procurement & Supplier Management

เจ้าของข้อมูล: Domain 09

รับผิดชอบกระบวนการจัดซื้อจัดจ้างและบริหารความสัมพันธ์ผู้จำหน่ายของคลินิกและโรงพยาบาลสัตว์อย่างครบวงจร ตั้งแต่การบริหารทะเบียนผู้จำหน่ายหลายบทบาท (ตัวแทนจำหน่ายยาและวัคซีน ผู้ผลิตขายตรง ผู้จำหน่ายน้ำยาและอุปกรณ์แล็บ ห้องปฏิบัติการอ้างอิงภายนอก ผู้จำหน่ายครุภัณฑ์ทางการแพทย์ ผู้ให้บริการซ่อมบำรุงและสอบเทียบ และซัพพลายเออร์ทั่วไป) การจำแนกประเภทผู้จำหน่าย ที่อยู่ ผู้ติดต่อ บัญชีธนาคารรับชำระ พื้นที่จัดส่งรายสาขา เอกสารใบอนุญาตและการต่ออายุ ประวัติความสัมพันธ์และการระงับ/ขึ้นบัญชีดำ แค็ตตาล็อกสินค้าและบริการจัดซื้อแบบผสม (ทั้งสินค้าสต็อกและบริการ/ครุภัณฑ์นอกสต็อก) โครงสร้างราคาซื้อตามปริมาณและสาขา สัญญาคู่ค้าและ SLA การรวบรวมความต้องการจัดซื้อจากหลายหน่วยงานและคลังยา แผนจัดซื้อและงบประมาณพร้อมการกันวงเงิน (Reserved / Committed / Actual) ใบขอซื้อ (Purchase Requisition) และระบบอนุมัติหลายระดับตามเงื่อนไขที่แยกหน้าที่ชัดเจน การขอใบเสนอราคา (RFQ) การเปรียบเทียบใบเสนอราคาแบบถ่วงน้ำหนักหลายมิติ ใบสั่งซื้อ (Purchase Order) และการแก้ไขเวอร์ชัน การติดตามสถานะและการส่งมอบแยกหลายรอบหลายสาขา การประสานงานติดตามผลการตรวจรับสินค้าและการตรวจรับงานบริการ/ครุภัณฑ์ การตรวจรับใบแจ้งหนี้ผู้จำหน่ายและการกระทบยอด 3 ทาง (3-Way Matching) ตามเกณฑ์ Tolerance พร้อมส่งต่อข้อมูลเจ้าหนี้ให้ฝ่ายบัญชี การจัดการเคลม คืนสินค้า และใบลดหนี้ผู้จำหน่าย ไปจนถึงการประเมินและวิเคราะห์ประสิทธิภาพผู้จำหน่าย

ทั้งนี้ Domain 09 ยึดหลัก **Single Source of Truth (SSOT)** โดยเป็นเจ้าของข้อมูลทะเบียนผู้จำหน่าย ประเภทผู้จำหน่าย ที่อยู่/ผู้ติดต่อ/เอกสารผู้จำหน่าย เงื่อนไขชำระเงิน แค็ตตาล็อกสินค้าจัดซื้อของแต่ละผู้จำหน่าย ราคาซื้อและช่วงราคา สัญญาผู้จำหน่าย คำขอความต้องการจัดซื้อ แผนจัดซื้อและงบประมาณจัดซื้อ ใบขอซื้อ (Purchase Requisition) นโยบายและประวัติการอนุมัติจัดซื้อ คำขอใบเสนอราคา (RFQ) ใบเสนอราคาผู้จำหน่าย การเปรียบเทียบและคัดเลือกผู้จำหน่าย ใบสั่งซื้อ (Purchase Order) ประวัติการแก้ไขและสถานะ PO การติดตามการจัดส่ง (ASN/Delivery Tracking) ใบตรวจรับงานบริการ/ครุภัณฑ์นอกสต็อก ใบแจ้งหนี้ผู้จำหน่ายและผลการทำ 3-Way Matching การเคลม/คืนสินค้า/ใบลดหนี้ผู้จำหน่าย และผลการประเมินผู้จำหน่าย ส่วนข้อมูลสาขาและทะเบียนบริการกลางอยู่ที่ Domain 00 (`core`), ทะเบียนสินค้ากลาง บริษัทผู้ผลิต หน่วยนับ คลังยา การตรวจรับสินค้าเข้าคลังทางกายภาพ (`pharmacy.goods_receipts`) ล็อต วันหมดอายุ ยอดคงเหลือ การกักกัน การตัดจำหน่าย และการส่งคำขอเติมสต็อก (`pharmacy.replenishment_requests`) อยู่ที่ Domain 04 (`pharmacy`), รายการตรวจแล็บ ใบส่งตรวจแล็บภายนอก (`laboratory.external_lab_referrals`) และทะเบียนเครื่องมือแล็บ (`laboratory.laboratory_equipment`) อยู่ที่ Domain 05 (`laboratory`), ข้อมูลสกุลเงิน อัตราแลกเปลี่ยน และอัตราภาษีมาตรฐานอยู่ที่ Domain 07 (`billing` — โดยไม่ปะปนกับใบแจ้งหนี้ลูกค้า), ข้อมูลพนักงานและผู้อนุมัติอยู่ที่ Domain 10 (`hr`), และการบันทึกบัญชีแยกประเภท การตั้งเจ้าหนี้ทางการเงิน และการจ่ายชำระเงินผู้จำหน่ายจริงอยู่ที่ระบบ `Finance & Accounting`

## กลุ่ม Governance Config, Document Sequences, Supplier Categories & Master Profiles

### ตาราง `procurement.document_sequences`

**หน้าที่**: บริหารรูปแบบการออกเลขที่เอกสารจัดซื้อและการตรวจรับฝั่งซัพพลายเออร์แยกตามสาขาและงวดเวลา (เช่น `PR`, `RFQ`, `PO`, `DLV`, `SAC`, `SIV`, `MCH`, `CLM`, `RTV`, `SCN`, `CTR`, `EVL`, `APH`) เพื่อรับประกันว่าเลขที่เอกสารจัดซื้อทุกประเภทไม่ซ้ำซ้อนและตรวจสอบลำดับย้อนหลังได้

#### โครงสร้าง Field:

| Column | Data Type | Constraint |
| --- | --- | --- |
| `sequence_id` | UUID | PK, NOT NULL |
| `branch_id` | UUID | FK → core.branches, NOT NULL |
| `document_type` | ENUM | NOT NULL |
| `document_prefix` | VARCHAR(20) | NOT NULL |
| `number_format_pattern` | VARCHAR(100) | NOT NULL |
| `reset_frequency` | ENUM | NOT NULL |
| `current_period_key` | VARCHAR(20) | NOT NULL |
| `last_running_number` | INTEGER | NOT NULL DEFAULT 0 |
| `padding_length` | SMALLINT | NOT NULL DEFAULT 4 |
| `effective_from` | DATE | NOT NULL |
| `effective_to` | DATE | NULL |
| `status` | ENUM | NOT NULL |
| `created_at` | TIMESTAMPTZ | NOT NULL |
| `created_by` | UUID | FK → hr.employees, NOT NULL |
| `updated_at` | TIMESTAMPTZ | NULL |
| `updated_by` | UUID | FK → hr.employees, NULL |

#### ข้อกำหนด:

- `sequence_id`: รหัสประจำชุดรันเลขที่เอกสารจัดซื้อ ใช้เป็น Primary Key
- `branch_id`: สาขาเจ้าของชุดเลขที่เอกสาร อ้างอิง `core.branches`
- `document_type`: ประเภทเอกสารจัดซื้อ (`PURCHASE_DEMAND`, `PURCHASE_PLAN`, `PURCHASE_BUDGET`, `PURCHASE_REQUISITION`, `APPROVAL_REQUEST`, `RFQ`, `SUPPLIER_QUOTATION`, `QUOTATION_COMPARISON`, `SUPPLIER_CONTRACT`, `PURCHASE_ORDER`, `SUPPLIER_DELIVERY`, `SERVICE_ACCEPTANCE`, `SUPPLIER_INVOICE`, `MATCHING`, `AP_HANDOFF_BATCH`, `SUPPLIER_CLAIM`, `SUPPLIER_RETURN`, `SUPPLIER_CREDIT_NOTE`, `SUPPLIER_EVALUATION`)
- `document_prefix`: คำนำหน้าเลขที่เอกสาร เช่น `DMD`, `PR`, `RFQ`, `PO`, `DLV`, `SAC`, `SIV`, `MCH`, `CLM`, `RTV`, `SCN`, `CTR`, `EVL`, `APH`
- `number_format_pattern`: รูปแบบ Template เช่น `{PREFIX}-{BRANCH}-{YYYY}{MM}{DD}-{NNNN}`
- `reset_frequency`: รอบการรีเซ็ตเลขที่รัน (`DAILY`, `MONTHLY`, `YEARLY`, `FISCAL_YEAR`, `NEVER`)
- `current_period_key`: คีย์งวดเวลาปัจจุบัน (เช่น `202611` หรือ `20261120`)
- `last_running_number`: เลขลำดับล่าสุดที่ถูกใช้งานแล้ว (ใช้ Transaction Lock `SELECT ... FOR UPDATE` ขณะออกเลข)
- `padding_length`: จำนวนหลักของเลขลำดับ (เช่น `4` -> `0001`)
- `effective_from` / `effective_to` / `status`: ช่วงวันที่มีผลบังคับใช้และสถานะ (`ACTIVE`, `INACTIVE`)
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit อ้างอิง `hr.employees`

#### หมายเหตุ:

1. กำหนด Unique Constraint `(branch_id, document_type, current_period_key)` สำหรับชุดที่ `status = 'ACTIVE'`
2. การออกเลขที่เอกสารจัดซื้อทุกฉบับต้องทำใน Database Transaction เดียวกับการบันทึกเอกสารเพื่อป้องกันเลขซ้ำหรือขาดตอน

### ตาราง `procurement.supplier_categories`

**หน้าที่**: จัดเก็บประเภทและหมวดหมู่ของผู้จำหน่ายแบบลำดับชั้น (Hierarchical Classification) เพื่อจำแนกผู้จำหน่ายยา วัคซีน เวชภัณฑ์ น้ำยาตรวจแล็บ แล็บภายนอก ครุภัณฑ์การแพทย์ งานบริการ/สอบเทียบ และวัสดุทั่วไป พร้อมกำหนดข้อกำหนดด้านเอกสารใบอนุญาตบังคับตามประเภท (§3.2, §3.19)

#### โครงสร้าง Field:

| Column | Data Type | Constraint |
| --- | --- | --- |
| `category_id` | UUID | PK, NOT NULL |
| `parent_category_id` | UUID | FK → procurement.supplier_categories, NULL |
| `category_code` | VARCHAR(30) | UNIQUE, NOT NULL |
| `category_name` | VARCHAR(150) | NOT NULL |
| `supplier_domain_type` | ENUM | NOT NULL |
| `requires_fda_license` | BOOLEAN | NOT NULL DEFAULT FALSE |
| `requires_tax_certificate` | BOOLEAN | NOT NULL DEFAULT TRUE |
| `description` | TEXT | NULL |
| `status` | ENUM | NOT NULL |
| `created_at` | TIMESTAMPTZ | NOT NULL |
| `created_by` | UUID | FK → hr.employees, NOT NULL |
| `updated_at` | TIMESTAMPTZ | NULL |
| `updated_by` | UUID | FK → hr.employees, NULL |

#### ข้อกำหนด:

- `category_id`: รหัสประจำประเภทผู้จำหน่าย ใช้เป็น Primary Key
- `parent_category_id`: หมวดหมู่แม่กรณีจัดกลุ่มย่อย (Self-referencing `procurement.supplier_categories`)
- `category_code`: รหัสหมวดหมู่ผู้จำหน่ายที่ไม่ซ้ำกัน (เช่น `SC-PHARMA`, `SC-VACCINE`, `SC-EXTLAB`, `SC-EQUIP`)
- `category_name`: ชื่อหมวดหมู่ผู้จำหน่าย
- `supplier_domain_type`: กลุ่มบทบาทหลักทางธุรกิจ (`PHARMACY_DISTRIBUTOR`, `MANUFACTURER_DIRECT`, `MEDICAL_CONSUMABLES`, `LAB_REAGENT_SUPPLIER`, `EXTERNAL_REFERENCE_LAB`, `MEDICAL_EQUIPMENT_VENDOR`, `MAINTENANCE_CALIBRATION_VENDOR`, `GENERAL_SUPPLIES_IT`, `COURIER_LOGISTICS`, `OTHER`)
- `requires_fda_license`: ระบุว่าผู้จำหน่ายในหมวดนี้ต้องแนบใบอนุญาตขายยา/เครื่องมือแพทย์ (อย.) ที่ยังไม่หมดอายุหรือไม่
- `requires_tax_certificate`: ระบุว่าต้องมีใบทะเบียนภาษีมูลค่าเพิ่ม (ภ.พ.20) หรือหนังสือรับรองนิติบุคคลประกอบการอนุมัติคู่ค้าหรือไม่
- `description`: คำอธิบายขอบเขตหมวดหมู่
- `status`: สถานะใช้งาน (`ACTIVE`, `INACTIVE`)
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit

#### หมายเหตุ:

1. ห้ามลบหมวดหมู่ที่มีผู้จำหน่ายหรือนโยบายอนุมัติอ้างอิงอยู่ ให้เปลี่ยน `status = 'INACTIVE'`
2. กรณี `requires_fda_license = TRUE` ระบบต้องแจ้งเตือนหรือไม่อนุญาตให้ออก PO สินค้าควบคุมหากไม่มี `supplier_documents` ที่ผ่านการตรวจรับและยังไม่หมดอายุ

### ตาราง `procurement.supplier_payment_terms`

**หน้าที่**: จัดเก็บมาตรฐานเงื่อนไขการชำระเงินและเครดิตการค้ากับผู้จำหน่าย (เช่น เงินสด/ชำระทันที, มัดจำล่วงหน้า, เครดิต 30/45/60 วัน, ส่วนลดชำระเร็ว) สำหรับกำหนดค่าเริ่มต้นที่ผู้จำหน่าย สัญญา ใบเสนอราคา ใบสั่งซื้อ และใบแจ้งหนี้ (§3.4)

#### โครงสร้าง Field:

| Column | Data Type | Constraint |
| --- | --- | --- |
| `payment_term_id` | UUID | PK, NOT NULL |
| `term_code` | VARCHAR(30) | UNIQUE, NOT NULL |
| `term_name` | VARCHAR(150) | NOT NULL |
| `payment_timing` | ENUM | NOT NULL |
| `credit_days` | INTEGER | NOT NULL DEFAULT 0 |
| `early_payment_discount_percent` | NUMERIC(5,2) | NOT NULL DEFAULT 0 |
| `early_payment_discount_days` | INTEGER | NULL |
| `requires_deposit_percent` | NUMERIC(5,2) | NOT NULL DEFAULT 0 |
| `description` | TEXT | NULL |
| `status` | ENUM | NOT NULL |
| `created_at` | TIMESTAMPTZ | NOT NULL |
| `created_by` | UUID | FK → hr.employees, NOT NULL |
| `updated_at` | TIMESTAMPTZ | NULL |
| `updated_by` | UUID | FK → hr.employees, NULL |

#### ข้อกำหนด:

- `payment_term_id`: รหัสประจำเงื่อนไขการชำระเงิน ใช้เป็น Primary Key
- `term_code` / `term_name`: รหัสและชื่อเงื่อนไข (เช่น `NET30`, `COD`, `PREPAID_100`, `DEP30_NET30`)
- `payment_timing`: รูปแบบจังหวะการชำระ (`PREPAID`, `CASH_ON_DELIVERY`, `CREDIT_NET_DAYS`, `END_OF_MONTH_PLUS_DAYS`, `MILESTONE_INSTALLMENT`)
- `credit_days`: จำนวนวันเครดิตหลังวางบิล/รับของ (`0` สำหรับชำระทันที)
- `early_payment_discount_percent` / `early_payment_discount_days`: อัตราส่วนลดกรณีชำระก่อนกำหนด (เช่น 2% ภายใน 10 วัน)
- `requires_deposit_percent`: สัดส่วนเงินมัดจำที่ต้องชำระก่อนส่งมอบ (ร้อยละ `0`–`100`)
- `description` / `status`: รายละเอียดเพิ่มเติมและสถานะ (`ACTIVE`, `INACTIVE`)
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit

#### หมายเหตุ:

1. `credit_days >= 0`, `early_payment_discount_percent >= 0`, และ `requires_deposit_percent BETWEEN 0 AND 100`

- `branch_name_tax` / `tax_id`: ชื่อสาขาในทางภาษี (เช่น `สำนักงานใหญ่`, `สาขาที่ 00001`) และเลขประจำตัวผู้เสียภาษี 13 หลัก
- `supplier_type`: ประเภทนิติบุคคล/ลักษณะคู่ค้า (`COMPANY_LIMITED`, `PARTNERSHIP`, `SOLE_PROPRIETOR`, `GOVERNMENT_AGENCY`, `FOREIGN_VENDOR`, `UNIVERSITY_LAB`)
- `primary_category_id`: หมวดหมู่หลักของผู้จำหน่าย อ้างอิง `procurement.supplier_categories`
- `manufacturer_id`: เชื่อมโยงกับทะเบียนบริษัทผู้ผลิต (`pharmacy.manufacturers`) เฉพาะกรณีผู้ผลิตเป็นผู้จัดจำหน่ายให้คลินิกโดยตรง (โดยยังคงแยกแนวคิดผู้ผลิตกับผู้จำหน่ายตามหลัก Domain 04 ข้อ 3.1)
- `payment_term_id`: เงื่อนไขเครดิตและการชำระเงินเริ่มต้น อ้างอิง `procurement.supplier_payment_terms`
- `default_currency_id`: สกุลเงินซื้อขายเริ่มต้น อ้างอิง `billing.currencies`
- `default_credit_limit`: วงเงินเครดิตที่ผู้จำหน่ายเปิดให้คลินิก
- `wht_applicable` / `default_wht_tax_rate_id`: ระบุว่าธุรกรรมของผู้จำหน่ายรายนี้เข้าข่ายหักภาษี ณ ที่จ่ายเริ่มต้นหรือไม่ และอ้างอิงอัตราจาก `billing.tax_rates`
- `website_url` / `email` / `phone`: ข้อมูลติดต่อกลางขององค์กรผู้จำหน่าย
- `is_approved_vendor` / `approved_at` / `approved_by`: สถานะผ่านการคัดเลือกเป็นผู้จำหน่ายที่อนุมัติ (Approved Vendor List — AVL) วันเวลาและผู้อนุมัติ
- `supplier_status`: สถานะคู่ค้า (`PENDING_REVIEW`, `ACTIVE`, `SUSPENDED`, `BLACKLISTED`, `INACTIVE`)
- `current_rating_score` / `current_performance_tier`: คะแนนประเมินล่าสุด (0–100) และระดับคู่ค้า (`STRATEGIC_A`, `PREFERRED_B`, `STANDARD_C`, `PROBATION_D`, `UNRATED`) ที่อัปเดตจากการประเมินใน `supplier_evaluations`
- `blacklist_reason` / `blacklisted_at` / `blacklisted_by`: เหตุผล วันเวลา และผู้สั่งระงับ/ขึ้นบัญชีดำ
- `notes` / `created_at` / `created_by` / `updated_at` / `updated_by`: หมายเหตุและข้อมูล Audit

#### หมายเหตุ:

1. ห้ามออก `purchase_orders` ใหม่ให้ผู้จำหน่ายที่มี `supplier_status IN ('SUSPENDED', 'BLACKLISTED', 'INACTIVE', 'PENDING_REVIEW')` หรือ `is_approved_vendor = FALSE`

3. สำหรับการสร้าง SQL DDL จริง ควรเพิ่ม FK `source_quotation_item_id → procurement.supplier_quotation_items` ด้วยคำสั่ง `ALTER TABLE` หลังจากสร้างตาราง `supplier_quotation_items` แล้ว

- `budget_status`: สถานะงบประมาณ (`DRAFT`, `ACTIVE`, `FROZEN`, `CLOSED`)

- `notes` / `created_at` / `created_by` / `updated_at` / `updated_by`: หมายเหตุและข้อมูล Audit

1. ยอดงบประมาณคงเหลือพร้อมใช้คำนวณจาก `allocated_amount - (reserved_amount + committed_amount + actual_spent_amount)`

- `po_status`: สถานะใบสั่งซื้อ (`DRAFT`, `PENDING_APPROVAL`, `APPROVED`, `ISSUED_TO_SUPPLIER`, `ACKNOWLEDGED`, `PARTIALLY_DELIVERED`, `PARTIALLY_RECEIVED`, `FULLY_RECEIVED`, `CLOSED`, `CANCELLED`)
- `supplier_acknowledged_at` / `supplier_ack_ref`: วันเวลาและเลขยืนยันรับคำสั่งซื้อจากผู้จำหน่าย

- `buyer_employee_id` / `approved_by` / `approved_at`: เจ้าหน้าที่จัดซื้อผู้จัดทำและผู้อนุมัติใบสั่งซื้อ (ต้องผ่านหลัก SoD ห้ามผู้ออกใบสั่งซื้ออนุมัติเอง)
- `shipping_address_text` / `terms_and_conditions` / `notes`: Snapshot ที่อยู่จัดส่ง เงื่อนไขสั่งซื้อ และหมายเหตุ

2. การส่งมอบบางส่วนต้องเปลี่ยนสถานะเป็น `PARTIALLY_DELIVERED` หรือ `PARTIALLY_RECEIVED` เท่านั้น ห้ามปิดเป็น `CLOSED` โดยอัตโนมัติจนกว่าจะรับครบหรือมีการอนุมัติ Short Close
