# Domain 04 — Pharmacy & Inventory Management

เจ้าของข้อมูล: Domain 04

รับผิดชอบกระบวนการบริหารจัดการยา เวชภัณฑ์ วัคซีน วัสดุสิ้นเปลือง และสินค้าจำหน่ายของคลินิกสัตวแพทย์อย่างครบวงจร ตั้งแต่การบริหารทะเบียนสินค้า ข้อมูลทางเภสัชกรรมและยาควบคุมพิเศษ หน่วยนับหลายระดับ คลังและตำแหน่งจัดเก็บ การบันทึกอุณหภูมิ Cold-Chain ล็อตและวันหมดอายุ ยอดคงเหลือและการจองสินค้า บัญชีความเคลื่อนไหวสินค้า (Immutable Ledger) การวางแผนและขอเติมสินค้า การตรวจรับสินค้าจากผู้จำหน่าย การจัดเก็บเข้าตำแหน่ง การรับและตรวจสอบคำสั่งยาจากคลินิก การจ่ายยาและขายปลีกหน้าร้าน การจัดทำฉลากยา การจ่ายบางส่วนและติดตาม Backorder การรับคืนยาและการตรวจ QC การเบิกใช้ภายในหน่วยงาน การโอนสินค้าระหว่างคลังและสาขา การตรวจนับและปรับปรุงยอด ไปจนถึงการกักกัน การเรียกคืนสินค้า และการตัดจำหน่าย

ทั้งนี้ Domain 04 ยึดหลัก **Single Source of Truth (SSOT)** โดยเป็นเจ้าของทะเบียนสินค้า ล็อต วันหมดอายุ ยอดคงคลัง การตรวจรับสินค้าเข้าคลัง และการจ่ายยาจริง ส่วนการตัดสินใจสั่งใช้ยาและประวัติแพ้ยายังคงอยู่ที่ Domain 03 (`clinical`), การจัดซื้อจัดจ้างและใบสั่งซื้ออยู่ที่ Domain 09 (`procurement`), และการกำหนดราคาขายปลีกและการเรียกเก็บเงินอยู่ที่ Domain 07 (`billing`)

## กลุ่ม Product Master, Pharmaceutical Information & Multi-UOM

### ตาราง `pharmacy.product_categories`

**หน้าที่**: จัดเก็บหมวดหมู่ของยา วัคซีน เวชภัณฑ์ วัสดุสิ้นเปลือง และสินค้าสำหรับจำหน่าย รองรับโครงสร้างหมวดหมู่หลัก-หมวดหมู่ย่อยเพื่อใช้จัดกลุ่ม ค้นหา วางแผนเติมสินค้า และวิเคราะห์ต้นทุนการใช้สินค้า

#### โครงสร้าง Field:

| Column               | Data Type    | Constraint                              |
| -------------------- | ------------ | --------------------------------------- |
| `category_id`        | UUID         | PK, NOT NULL                            |
| `parent_category_id` | UUID         | FK → pharmacy.product_categories, NULL  |
| `category_code`      | VARCHAR(30)  | UNIQUE, NOT NULL                        |
| `category_name`      | VARCHAR(150) | NOT NULL                                |
| `category_name_en`   | VARCHAR(150) | NULL                                    |
| `category_type`      | ENUM         | NOT NULL                                |
| `description`        | TEXT         | NULL                                    |
| `display_order`      | SMALLINT     | NOT NULL DEFAULT 0                      |
| `status`             | ENUM         | NOT NULL                                |
| `created_at`         | TIMESTAMPTZ  | NOT NULL                                |
| `created_by`         | UUID         | FK → hr.employees, NOT NULL             |
| `updated_at`         | TIMESTAMPTZ  | NULL                                    |
| `updated_by`         | UUID         | FK → hr.employees, NULL                 |

#### ข้อกำหนด:

- `category_id`: รหัสประจำหมวดหมู่สินค้า ใช้เป็น Primary Key
- `parent_category_id`: รหัสหมวดหมู่หลัก อ้างอิงจาก `pharmacy.product_categories` (เป็น `NULL` เมื่อเป็นหมวดหมู่ระดับบนสุด)
- `category_code`: รหัสหมวดหมู่ทางธุรกิจ เช่น `CAT-ABX`, `CAT-VAC-CANINE`, `CAT-SUP-WOUND`
- `category_name`: ชื่อหมวดหมู่สินค้าภาษาไทย
- `category_name_en`: ชื่อหมวดหมู่สินค้าภาษาอังกฤษ
- `category_type`: กลุ่มประเภทใหญ่ของหมวดหมู่สินค้า ค่าที่เป็นไปได้ คือ
  - `MEDICATION`: ยาสำหรับสัตว์เลี้ยง (ยาปฏิชีวนะ ยาแก้ปวด ยาลดอักเสบ ยาโรคเรื้อรัง ฯลฯ)
  - `VACCINE`: วัคซีนป้องกันโรคสำหรับสัตว์ชนิดต่าง ๆ
  - `MEDICAL_SUPPLY`: เวชภัณฑ์ทางการแพทย์ (เข็ม ไซริงค์ สายน้ำเกลือ ผ้าก๊อซ วัสดุทำแผล)
  - `LAB_REAGENT`: น้ำยาและวัสดุตรวจทางห้องปฏิบัติการ
  - `CONSUMABLE`: วัสดุสิ้นเปลืองทางการแพทย์ (น้ำยาฆ่าเชื้อ ถุงมือ ภาชนะเก็บตัวอย่าง)
  - `RETAIL_FOOD`: อาหารสัตว์และอาหารประกอบการรักษาโรค
  - `SUPPLEMENT`: อาหารเสริมและวิตามิน
  - `PET_CARE`: ผลิตภัณฑ์ทำความสะอาดและอุปกรณ์ดูแลสัตว์เลี้ยง
- `description`: คำอธิบายขอบเขตสินค้าในหมวดหมู่นี้
- `display_order`: ลำดับการแสดงผลในรายการเลือก
- `status`: สถานะหมวดหมู่ ค่าที่เป็นไปได้ คือ `ACTIVE` (เปิดใช้งาน) และ `INACTIVE` (ปิดใช้งาน)
- `created_at` / `created_by` / `updated_at` / `updated_by`: วันเวลาและพนักงานผู้สร้างและแก้ไขล่าสุด อ้างอิง `hr.employees`

#### หมายเหตุ:

1. `category_code` ต้องไม่ซ้ำกันทั้งระบบ
2. ห้ามกำหนด `parent_category_id` ให้ชี้มาที่ `category_id` ของตนเอง (`parent_category_id <> category_id`)
3. หมวดหมู่ที่ยังมีรายการสินค้าใช้งานอยู่ไม่ควรลบข้อมูลจริง ให้เปลี่ยน `status` เป็น `INACTIVE` แทน

### ตาราง `pharmacy.manufacturers`

**หน้าที่**: จัดเก็บทะเบียนบริษัทผู้ผลิตยา วัคซีน เวชภัณฑ์ และสินค้า โดยแยกออกจากข้อมูลผู้จำหน่าย (Supplier/Distributor) ใน Domain 09 เพื่อรองรับกรณีสินค้าชนิดหนึ่งผลิตโดยผู้ผลิตรายเดียวแต่สั่งซื้อจากผู้จัดจำหน่ายได้หลายราย

#### โครงสร้าง Field:

| Column               | Data Type    | Constraint                  |
| -------------------- | ------------ | --------------------------- |
| `manufacturer_id`    | UUID         | PK, NOT NULL                |
| `manufacturer_code`  | VARCHAR(30)  | UNIQUE, NOT NULL            |
| `manufacturer_name`  | VARCHAR(200) | NOT NULL                    |
| `manufacturer_name_en` | VARCHAR(200) | NULL                      |
| `country_code`       | CHAR(2)      | NULL                        |
| `fda_license_number` | VARCHAR(100) | NULL                        |
| `contact_email`      | VARCHAR(255) | NULL                        |
| `contact_phone`      | VARCHAR(30)  | NULL                        |
| `website_url`        | TEXT         | NULL                        |
| `status`             | ENUM         | NOT NULL                    |
| `notes`              | TEXT         | NULL                        |
| `created_at`         | TIMESTAMPTZ  | NOT NULL                    |
| `created_by`         | UUID         | FK → hr.employees, NOT NULL |
| `updated_at`         | TIMESTAMPTZ  | NULL                        |
| `updated_by`         | UUID         | FK → hr.employees, NULL     |

#### ข้อกำหนด:

- `manufacturer_id`: รหัสประจำบริษัทผู้ผลิต
- `manufacturer_code`: รหัสอ้างอิงผู้ผลิตในระบบ เช่น `MFG-0001`
- `manufacturer_name`: ชื่อบริษัทผู้ผลิตภาษาไทยหรือชื่อทางการค้าหลัก
- `manufacturer_name_en`: ชื่อบริษัทผู้ผลิตภาษาอังกฤษ
- `country_code`: รหัสประเทศต้นทางตามมาตรฐาน ISO 3166-1 alpha-2 (เช่น `TH`, `US`, `DE`, `FR`)
- `fda_license_number`: เลขที่ใบอนุญาตผลิตหรือทะเบียนผู้ผลิตจากหน่วยงานกำกับดูแล (อย./กรมปศุสัตว์)
- `contact_email` / `contact_phone` / `website_url`: ช่องทางติดต่อผู้ผลิต (ใช้ประกอบการประสานงาน Recall หรือแจ้งอาการไม่พึงประสงค์)
- `status`: สถานะผู้ผลิต (`ACTIVE`, `INACTIVE`)
- `notes`: หมายเหตุเพิ่มเติมเกี่ยวกับผู้ผลิต
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit ผู้สร้างและผู้แก้ไขล่าสุด

#### หมายเหตุ:

1. ต้องแยกข้อมูลบริษัทผู้ผลิตในตารางนี้กับข้อมูลผู้จัดจำหน่าย (`procurement.suppliers` ใน Domain 09) ตามหลักธุรกิจข้อ 3.1
2. ผู้ผลิตที่ถูกอ้างอิงใน `products` หรือ `inventory_lots` แล้วห้ามลบข้อมูลจริง

### ตาราง `pharmacy.products`

**หน้าที่**: ทะเบียนสินค้ากลางทั้งหมดของคลินิกสัตวแพทย์ ทั้งยา วัคซีน เวชภัณฑ์ วัสดุสิ้นเปลือง น้ำยาแล็บ และสินค้าปลีกสำหรับจำหน่าย เป็นตารางหลักที่ Domain 03 (`clinical`), Domain 05 (`laboratory`), Domain 06 (`surgery`), Domain 07 (`billing`) และ Domain 09 (`procurement`) ใช้อ้างอิงร่วมกันเป็น Single Source of Truth

#### โครงสร้าง Field:

| Column                            | Data Type    | Constraint                             |
| --------------------------------- | ------------ | -------------------------------------- |
| `product_id`                      | UUID         | PK, NOT NULL                           |
| `product_code`                    | VARCHAR(50)  | UNIQUE, NOT NULL                       |
| `barcode`                         | VARCHAR(100) | NULL                                   |
| `product_name`                    | VARCHAR(200) | NOT NULL                               |
| `product_name_en`                 | VARCHAR(200) | NULL                                   |
| `generic_name_summary`            | VARCHAR(200) | NULL                                   |
| `product_type`                    | ENUM         | NOT NULL                               |
| `category_id`                     | UUID         | FK → pharmacy.product_categories, NOT NULL |
| `manufacturer_id`                 | UUID         | FK → pharmacy.manufacturers, NULL      |
| `base_uom_id`                     | UUID         | FK → pharmacy.units_of_measure, NOT NULL |
| `dosage_form`                     | VARCHAR(100) | NULL                                   |
| `strength_text`                   | VARCHAR(100) | NULL                                   |
| `pack_size_description`           | VARCHAR(150) | NULL                                   |
| `is_divisible`                    | BOOLEAN      | NOT NULL DEFAULT TRUE                  |
| `requires_lot_tracking`           | BOOLEAN      | NOT NULL DEFAULT TRUE                  |
| `requires_expiry_tracking`        | BOOLEAN      | NOT NULL DEFAULT TRUE                  |
| `requires_cold_chain`             | BOOLEAN      | NOT NULL DEFAULT FALSE                 |
| `is_prescription_required`        | BOOLEAN      | NOT NULL DEFAULT FALSE                 |
| `is_dispensable_to_owner`         | BOOLEAN      | NOT NULL DEFAULT TRUE                  |
| `is_internal_use_only`            | BOOLEAN      | NOT NULL DEFAULT FALSE                 |
| `default_shelf_life_warning_days` | SMALLINT     | NULL DEFAULT 90                        |
| `description`                     | TEXT         | NULL                                   |
| `status`                          | ENUM         | NOT NULL                               |
| `created_at`                      | TIMESTAMPTZ  | NOT NULL                               |
| `created_by`                      | UUID         | FK → hr.employees, NOT NULL            |
| `updated_at`                      | TIMESTAMPTZ  | NULL                                   |
| `updated_by`                      | UUID         | FK → hr.employees, NULL                |

#### ข้อกำหนด:

- `product_id`: รหัสประจำสินค้าภายในระบบ ใช้เป็น Primary Key
- `product_code`: รหัสสินค้าทางธุรกิจที่ห้ามซ้ำกัน เช่น `PRD-{YYYY}{MM}{DD}-{NNNN}` หรือรหัส SKU มาตรฐานของคลินิก
- `barcode`: บาร์โค้ดมาตรฐานบนบรรจุภัณฑ์หลักสำหรับสแกนรับเข้าและหยิบจ่าย (กำหนด Partial UNIQUE Index เฉพาะแถวที่ `barcode IS NOT NULL`)
- `product_name`: ชื่อสินค้าหรือชื่อทางการค้าภาษาไทย/ที่ใช้แสดงในระบบ
- `product_name_en`: ชื่อสินค้าภาษาอังกฤษ
- `generic_name_summary`: ชื่อสามัญโดยย่อสำหรับช่วยค้นหาและแสดงผลอย่างรวดเร็ว (รายละเอียดเชิงเภสัชกรรมฉบับเต็มเก็บใน `pharmacy.medication_profiles`)
- `product_type`: ประเภทสินค้า ค่าที่เป็นไปได้ คือ `MEDICATION`, `VACCINE`, `MEDICAL_SUPPLY`, `LAB_REAGENT`, `CONSUMABLE`, `RETAIL_FOOD`, `SUPPLEMENT`, `PET_CARE`
- `category_id`: หมวดหมู่สินค้า อ้างอิงจาก `pharmacy.product_categories`
- `manufacturer_id`: บริษัทผู้ผลิต อ้างอิงจาก `pharmacy.manufacturers`
- `base_uom_id`: หน่วยนับพื้นฐาน (Smallest Tracking Unit) สำหรับควบคุมสต็อกทั้งหมดในระบบ อ้างอิง `pharmacy.units_of_measure` เช่น เม็ด (`TAB`), มิลลิลิตร (`ML`), ชิ้น (`PIECE`)
- `dosage_form`: รูปแบบสินค้า/ยาโดยสรุป เช่น เม็ด แคปซูล ยาน้ำ ยาฉีด แผ่นทดสอบ
- `strength_text`: ความแรงหรือความเข้มข้นโดยสรุป เช่น `250 mg`, `100 mg/5 mL`, `1 mL/dose`
- `pack_size_description`: คำอธิบายขนาดบรรจุ เช่น `10 เม็ด/แผง, 10 แผง/กล่อง`
- `is_divisible`: ระบุว่าสินค้าสามารถแบ่งหน่วยจ่ายจากบรรจุภัณฑ์ได้หรือไม่ (`FALSE` สำหรับสินค้าที่ห้ามแบ่งบรรจุ เช่น ยาหยอดตา 1 ขวด หรือหลอดวัคซีน 1 โดส)
- `requires_lot_tracking`: ระบุว่าสินค้านี้ต้องระบุเลขล็อตทุกครั้งที่รับเข้าและเคลื่อนไหวหรือไม่
- `requires_expiry_tracking`: ระบุว่าสินค้านี้ต้องบันทึกและตรวจสอบวันหมดอายุทุกครั้งหรือไม่
- `requires_cold_chain`: ระบุว่าสินค้านี้ต้องจัดเก็บและขนส่งแบบควบคุมอุณหภูมิ (เช่น ตู้เย็นวัคซีน 2–8°C) หรือไม่
- `is_prescription_required`: ระบุว่าเป็นสินค้าที่ต้องมีใบสั่งยาจากสัตวแพทย์ (`clinical.prescriptions`) ก่อนจ่ายออกเสมอหรือไม่
- `is_dispensable_to_owner`: ระบุว่าสามารถจ่ายหรือจำหน่ายให้เจ้าของสัตว์เลี้ยงนำกลับได้หรือไม่
- `is_internal_use_only`: ระบุว่าเป็นเวชภัณฑ์/น้ำยา/ยาที่ใช้เฉพาะภายในคลินิกเท่านั้น (ห้ามจ่ายกลับบ้านหรือขายปลีก)
- `default_shelf_life_warning_days`: จำนวนวันล่วงหน้าสำหรับแจ้งเตือนสินค้าใกล้หมดอายุ (เช่น 90 วันก่อนวันหมดอายุ)
- `description`: รายละเอียดเพิ่มเติมของสินค้า
- `status`: สถานะการใช้งานสินค้า ค่าที่เป็นไปได้ คือ
  - `DRAFT`: สร้างรายการแล้ว รอตรวจสอบก่อนเปิดใช้งาน
  - `ACTIVE`: เปิดใช้งานปกติ สามารถสั่งใช้ สั่งซื้อ รับเข้า และจ่ายออกได้
  - `SUSPENDED`: ระงับชั่วคราว ห้ามสร้างคำสั่งใหม่
  - `DISCONTINUED`: เลิกใช้ถาวร คงประวัติเดิมไว้ทั้งหมด
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit ผู้สร้างและแก้ไขล่าสุด

#### หมายเหตุ:

1. ยาชนิดเดียวกันที่มี **ความแรง** หรือ **รูปแบบ** ต่างกัน ต้องสร้างเป็นคนละ `product_id` เพื่อป้องกันความผิดพลาดในการจ่ายยาและคำนวณสต็อก
2. สินค้าที่มีประวัติใน `clinical.prescription_items`, `inventory_lots` หรือ `stock_movements` แล้ว ห้ามลบข้อมูลจริง
3. หาก `is_internal_use_only = TRUE` ต้องตั้ง `is_dispensable_to_owner = FALSE`
4. การเปลี่ยนชื่อสินค้าต้องไม่ไปแก้ Snapshot ชื่อสินค้าที่บันทึกไว้แล้วใน `clinical.prescription_items`, `medication_labels` หรือ `billing`
5. สำหรับการสร้าง SQL DDL จริง ควรสร้าง `pharmacy.units_of_measure` ก่อน `pharmacy.products` (หรือเพิ่ม FK `base_uom_id` ภายหลัง)

### ตาราง `pharmacy.medication_profiles`

**หน้าที่**: จัดเก็บข้อมูลเชิงลึกทางเภสัชกรรมของยาและวัคซีนแต่ละรายการ (1:1 กับ `pharmacy.products`) รวมถึงประเภทยาควบคุมพิเศษ/วัตถุออกฤทธิ์/ยาเสพติด เพื่อใช้ประกอบการตรวจสอบความปลอดภัยก่อนจ่ายยา การพิมพ์เอกสารคำแนะนำ และแยกข้อมูลตามเอกสารผู้ผลิตออกจากบันทึกเพิ่มเติมของคลินิก

#### โครงสร้าง Field:

| Column                        | Data Type    | Constraint                               |
| ----------------------------- | ------------ | ---------------------------------------- |
| `medication_profile_id`       | UUID         | PK, NOT NULL                             |

| `strength_unit`               | VARCHAR(50)  | NULL                                     |

| `default_route`               | ENUM         | NOT NULL                                 |
| `controlled_drug_schedule`    | ENUM         | NOT NULL DEFAULT 'NONE'                  |

#### ข้อกำหนด:

- `medication_profile_id`: รหัสประจำข้อมูลทางเภสัชกรรม
- `product_id`: รหัสสินค้าที่เกี่ยวข้อง อ้างอิง `pharmacy.products` (กำหนด `UNIQUE` เพื่อเป็นความสัมพันธ์แบบ 1:1 สำหรับสินค้าประเภท `MEDICATION` และ `VACCINE`)
- `generic_name`: ชื่อสามัญทางยา (INN/Generic Name)
- `brand_name`: ชื่อทางการค้า/ยี่ห้อ
- `active_ingredients`: รายการตัวยาสำคัญและปริมาณต่อหน่วย (JSON Array เช่น `[{"name": "Amoxicillin", "amount": 200, "unit": "mg"}, {"name": "Clavulanic acid", "amount": 50, "unit": "mg"}]`)
- `therapeutic_class`: กลุ่มฤทธิ์ทางเภสัชวิทยา (เช่น `BETA_LACTAM_ANTIBIOTIC`, `NSAID`, `ANTIPARASITIC`)
- `strength_value` / `strength_unit`: ค่าความแรงเชิงตัวเลขและหน่วย (เช่น `250` และ `mg/tablet` หรือ `10` และ `mg/mL`)
- `dosage_form`: รูปแบบยา ค่าที่เป็นไปได้ คือ `TABLET`, `CAPSULE`, `CHEWABLE`, `ORAL_LIQUID`, `SUSPENSION`, `INJECTION_SOLUTION`, `INJECTION_POWDER`, `TOPICAL_CREAM`, `OINTMENT`, `EYE_DROPS`, `EAR_DROPS`, `SPOT_ON`, `SPRAY`, `POWDER`, `SHAMPOO_MEDICATED`, `IV_FLUID`, `OTHER`
- `default_route`: ช่องทางการให้ยาหลักตามเอกสารกำกับยา ค่าที่เป็นไปได้ คือ `ORAL`, `SUBCUTANEOUS`, `INTRAMUSCULAR`, `INTRAVENOUS`, `TOPICAL`, `OPHTHALMIC`, `OTIC`, `INHALATION`, `RECTAL`, `OTHER`
- `controlled_drug_schedule`: ระดับการควบคุมตามกฎหมายยา/วัตถุออกฤทธิ์/ยาเสพติด ค่าที่เป็นไปได้ คือ
  - `NONE`: ยาทั่วไปหรือสินค้าที่ไม่จัดเป็นยาควบคุมพิเศษ
  - `DANGEROUS_DRUG`: ยาอันตราย (ต้องควบคุมการจ่ายโดยสัตวแพทย์/เภสัชกร)
  - `SPECIAL_CONTROL`: ยาควบคุมพิเศษ (ต้องมีใบสั่งยาและจัดทำบัญชีขาย/จ่ายยา)
  - `PSYCHOTROPIC_CAT_2`: วัตถุออกฤทธิ์ต่อจิตและประสาท ประเภท 2 (เช่น Ketamine, Diazepam, Midazolam)
  - `PSYCHOTROPIC_CAT_3_4`: วัตถุออกฤทธิ์ต่อจิตและประสาท ประเภท 3 หรือ 4
  - `NARCOTIC_CAT_2`: ยาเสพติดให้โทษ ประเภท 2 (เช่น Morphine, Fentanyl, Methadone, Pethidine)
- `requires_witness_verification`: ระบุว่าทุกครั้งที่จ่าย ตัดใช้ หรือทำลายยาที่เหลือต้องมีพยาน (`witnessed_by`) ร่วมลงนามยืนยันหรือไม่
- `storage_condition_summary`: เงื่อนไขการจัดเก็บตามเอกสารกำกับยา (เช่น เก็บที่อุณหภูมิ 2–8°C พ้นแสงแดด)
- `storage_temp_min_c` / `storage_temp_max_c`: ช่วงอุณหภูมิจัดเก็บที่แนะนำเป็นองศาเซลเซียส
- `warnings` / `contraindications` / `side_effects`: คำเตือน ข้อห้ามใช้ และผลข้างเคียงตามเอกสารอ้างอิง
- `reference_document_url`: ลิงก์หรือไฟล์อ้างอิงเอกสารกำกับยา (Package Insert / Monograph)
- `source_type`: แหล่งที่มาของข้อมูลทางเภสัชกรรม (`MANUFACTURER_INSERT`, `CLINIC_PHARMACY_NOTE`, `REGULATORY_MONOGRAPH`)
- `clinic_custom_notes`: บันทึกและคำแนะนำเพิ่มเติมภายในคลินิก (แยกออกจากข้อมูลผู้ผลิตอย่างชัดเจน)
- `reviewed_at` / `reviewed_by`: วันเวลาและเภสัชกร/สัตวแพทย์ผู้ทบทวนข้อมูลล่าสุด
- `status`: สถานะข้อมูลทางเภสัชกรรม (`ACTIVE`, `INACTIVE`)
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit

#### หมายเหตุ:

1. ต้องแยกข้อมูลทางเภสัชกรรมออกจากตารางสินค้าหลัก (`pharmacy.products`) และข้อมูลเชิงพาณิชย์ เพื่อไม่ปะปนกับข้อมูลคลังและราคา
2. ข้อมูล `warnings` และ `contraindications` ในตารางนี้ใช้เป็นข้อมูลอ้างอิงประกอบการตรวจสอบก่อนจ่ายยา ห้ามนำไปใช้แทนคำสั่งการรักษาหรือ `clinical.prescriptions` ของสัตวแพทย์
3. เมื่อ `controlled_drug_schedule` เป็น `PSYCHOTROPIC_CAT_2` หรือ `NARCOTIC_CAT_2` แนะนำให้ตั้ง `requires_witness_verification = TRUE` และจัดเก็บใน `NARCOTIC_CABINET` เสมอ

### ตาราง `pharmacy.units_of_measure`

**หน้าที่**: ทะเบียนหน่วยนับมาตรฐานทั้งหมดที่ใช้ในการสั่งซื้อ จัดเก็บ เบิกใช้ และจ่ายสินค้าของระบบ (เช่น เม็ด แผง กล่อง ขวด มิลลิลิตร หลอด) เพื่อให้ Domain 03, 04, 05, 06, 07 และ 09 ใช้รหัสหน่วยนับมาตรฐานชุดเดียวกัน

#### โครงสร้าง Field:

| Column          | Data Type    | Constraint                  |
| --------------- | ------------ | --------------------------- |
| `uom_id`        | UUID         | PK, NOT NULL                |
| `uom_code`      | VARCHAR(30)  | UNIQUE, NOT NULL            |
| `uom_name`      | VARCHAR(100) | NOT NULL                    |
| `uom_name_en`   | VARCHAR(100) | NULL                        |
| `uom_type`      | ENUM         | NOT NULL                    |
| `allow_decimal` | BOOLEAN      | NOT NULL DEFAULT FALSE      |
| `description`   | TEXT         | NULL                        |
| `status`        | ENUM         | NOT NULL                    |
| `created_at`    | TIMESTAMPTZ  | NOT NULL                    |
| `created_by`    | UUID         | FK → hr.employees, NOT NULL |
| `updated_at`    | TIMESTAMPTZ  | NULL                        |
| `updated_by`    | UUID         | FK → hr.employees, NULL     |

#### ข้อกำหนด:

- `uom_id`: รหัสประจำหน่วยนับ
- `uom_code`: รหัสหน่วยนับมาตรฐาน (เช่น `TAB`, `CAP`, `AMP`, `VIAL`, `ML`, `MG`, `G`, `KG`, `BOX`, `STRIP`, `BTL`, `TUBE`, `PACK`, `SACHET`, `PAIR`, `PIECE`, `DOSE`)
- `uom_name`: ชื่อหน่วยนับภาษาไทย (เช่น เม็ด, แผง, กล่อง, ขวด, มิลลิลิตร)
- `uom_name_en`: ชื่อหน่วยนับภาษาอังกฤษ
- `uom_type`: หมวดประเภทของหน่วยนับ ค่าที่เป็นไปได้ คือ `COUNT` (นับชิ้น/เม็ด), `VOLUME` (ปริมาตร), `WEIGHT` (น้ำหนัก), `PACKAGE` (บรรจุภัณฑ์รวม), `OTHER`
- `allow_decimal`: ระบุว่าหน่วยนับนี้อนุญาตให้ระบุจำนวนเป็นทศนิยมได้หรือไม่ (เช่น `TRUE` สำหรับ `ML`, `G` หรือ `TAB` แบบแบ่งครึ่งเม็ด, `FALSE` สำหรับ `BOX`, `BOTTLE`, `VIAL`)
- `description`: คำอธิบายเพิ่มเติมของหน่วยนับ
- `status`: สถานะการใช้งาน (`ACTIVE`, `INACTIVE`)
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit

#### หมายเหตุ:

1. `uom_code` ต้องไม่ซ้ำกันทั้งระบบ
2. หน่วยนับที่มีการผูกไว้ใน `pharmacy.products`, `pharmacy.product_units` หรือถูกอ้างอิงในธุรกรรมแล้วห้ามลบจริง

### ตาราง `pharmacy.product_units`

**หน้าที่**: กำหนดโครงสร้างหน่วยนับหลายระดับและอัตราการแปลงหน่วยของสินค้าแต่ละรายการ (เช่น 1 กล่อง = 10 แผง, 1 แผง = 10 เม็ด, 1 กล่อง = 100 เม็ด) รวมถึงกำหนดสิทธิ์ว่าแต่ละหน่วยใช้สำหรับซื้อ จัดเก็บ เบิก หรือจ่าย และสามารถแบ่งบรรจุได้หรือไม่

#### โครงสร้าง Field:

| Column                        | Data Type     | Constraint                             |
| ----------------------------- | ------------- | -------------------------------------- |
| `product_unit_id`             | UUID          | PK, NOT NULL                           |
| `product_id`                  | UUID          | FK → pharmacy.products, NOT NULL       |
| `uom_id`                      | UUID          | FK → pharmacy.units_of_measure, NOT NULL |
| `parent_uom_id`               | UUID          | FK → pharmacy.units_of_measure, NULL   |
| `conversion_factor_to_base`   | NUMERIC(14,6) | NOT NULL                               |
| `conversion_factor_to_parent` | NUMERIC(14,6) | NULL                                   |
| `barcode`                     | VARCHAR(100)  | NULL                                   |
| `is_base_uom`                 | BOOLEAN       | NOT NULL DEFAULT FALSE                 |
| `is_purchase_uom`             | BOOLEAN       | NOT NULL DEFAULT FALSE                 |
| `is_storage_uom`              | BOOLEAN       | NOT NULL DEFAULT FALSE                 |
| `is_issue_uom`                | BOOLEAN       | NOT NULL DEFAULT FALSE                 |
| `is_dispense_uom`             | BOOLEAN       | NOT NULL DEFAULT FALSE                 |
| `is_splittable`               | BOOLEAN       | NOT NULL DEFAULT TRUE                  |
| `rounding_precision`          | SMALLINT      | NOT NULL DEFAULT 0                     |
| `effective_from`              | TIMESTAMPTZ   | NOT NULL                               |
| `effective_to`                | TIMESTAMPTZ   | NULL                                   |
| `status`                      | ENUM          | NOT NULL                               |
| `created_at`                  | TIMESTAMPTZ   | NOT NULL                               |
| `created_by`                  | UUID          | FK → hr.employees, NOT NULL            |
| `updated_at`                  | TIMESTAMPTZ   | NULL                                   |
| `updated_by`                  | UUID          | FK → hr.employees, NULL                |

#### ข้อกำหนด:

- `product_unit_id`: รหัสประจำการตั้งค่าหน่วยนับของสินค้า
- `product_id`: สินค้าเจ้าของหน่วยนับ อ้างอิง `pharmacy.products`
- `uom_id`: หน่วยนับ อ้างอิง `pharmacy.units_of_measure`
- `parent_uom_id`: หน่วยนับระดับใหญ่กว่าถัดไปในลำดับชั้นบรรจุภัณฑ์ (เช่น ของ `TAB` คือ `STRIP`, ของ `STRIP` คือ `BOX`)
- `conversion_factor_to_base`: ตัวคูณเพื่อแปลงจาก `uom_id` นี้เป็นหน่วยหลัก (`base_uom_id` ของสินค้า) เช่น `BOX` มีค่า `100.000000`, `STRIP` มีค่า `10.000000`, `TAB` มีค่า `1.000000`
- `conversion_factor_to_parent`: จำนวนหน่วยย่อยนี้ที่ประกอบเป็น 1 `parent_uom_id` (เช่น `10` แผงต่อกล่อง)
- `barcode`: บาร์โค้ดเฉพาะของบรรจุภัณฑ์ระดับนี้ (เช่น บาร์โค้ดข้างกล่อง vs บาร์โค้ดแผง)
- `is_base_uom` / `is_purchase_uom` / `is_storage_uom` / `is_issue_uom` / `is_dispense_uom`: ธงระบุบทบาทของหน่วยนับนี้ว่าอนุญาตให้ใช้เป็นหน่วยฐาน, หน่วยสั่งซื้อ, หน่วยจัดเก็บ, หน่วยเบิกใช้ภายใน และหน่วยจ่ายยาให้ลูกค้าหรือไม่
- `is_splittable`: ระบุว่าหน่วยนี้สามารถแตกย่อยลงไปเป็นหน่วยที่เล็กกว่าได้หรือไม่ (`FALSE` สำหรับแพ็กเกจปิดผนึกที่ต้องจ่ายยกชิ้น)
- `rounding_precision`: จำนวนตำแหน่งทศนิยมที่อนุญาตสำหรับหน่วยนี้ (0–4)
- `effective_from` / `effective_to`: ช่วงวันเวลาที่มีผลบังคับใช้อัตราแปลงหน่วยนี้
- `status`: สถานะ (`ACTIVE`, `INACTIVE`)
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit

#### หมายเหตุ:

1. สินค้า 1 รายการต้องมีแถวที่ `is_base_uom = TRUE` และ `conversion_factor_to_base = 1.000000` เพียง 1 รายการที่ `ACTIVE` อยู่และ `uom_id` ต้องตรงกับ `products.base_uom_id`
2. `conversion_factor_to_base` ต้องมากกว่า 0 เสมอ
3. การเปลี่ยนอัตราแปลงหน่วยในอนาคตต้องปิดรายการเดิมด้วย `effective_to` และ `status = INACTIVE` แล้วเพิ่มแถวใหม่ เพื่อไม่ให้ข้อมูลประวัติใน `stock_movements` ที่บันทึก `conversion_factor_used` ไว้แล้วผิดเพี้ยน

- `product_id`: สินค้าเจ้าของล็อต อ้างอิง `pharmacy.products`
- `manufacturer_lot_number`: หมายเลขล็อตที่พิมพ์บนบรรจุภัณฑ์จากบริษัทผู้ผลิต
- `manufacturer_id`: บริษัทผู้ผลิต อ้างอิง `pharmacy.manufacturers`
- `supplier_id`: ผู้จำหน่ายที่ส่งมอบล็อตนี้ อ้างอิง `procurement.suppliers` (Domain 09)
- `goods_receipt_item_id`: รายการตรวจรับสินค้าต้นทางที่นำเข้าล็อตนี้ อ้างอิง `pharmacy.goods_receipt_items` (เป็น `NULL` ได้สำหรับยอดยกมาตั้งต้นระบบ `OPENING_STOCK`)
- `manufacture_date`: วันที่ผลิต
- `expiry_date`: วันหมดอายุ (บังคับ NOT NULL เมื่อ `products.requires_expiry_tracking = TRUE`)
- `received_at`: วันและเวลาที่รับเข้าคลัง
- `initial_quantity_base`: จำนวนรวมตั้งต้นของล็อตนี้ในหน่วยหลัก (`base_uom_id`)
- `remaining_quantity_base`: ยอดคงเหลือรวมของล็อตนี้ในทุกคลัง (ในหน่วยหลัก)
- `unit_cost_base`: ต้นทุนรับเข้าต่อ 1 หน่วยหลัก (Base UOM) ใช้สำหรับคำนวณมูลค่าสินค้าคงคลังและส่งต่อ Finance & Accounting (Domain 04 ข้อ 4.6)
- `lot_status`: สถานะคุณภาพและการใช้งานของล็อต ค่าที่เป็นไปได้ คือ
  - `ACTIVE`: ล็อตปกติ พร้อมใช้งานและจ่ายออกได้
  - `NEAR_EXPIRY`: ใกล้หมดอายุ (ยังจ่ายได้ตามเงื่อนไข FEFO พร้อมคำเตือน)
  - `QUARANTINED`: ถูกกักกันเพื่อรอตรวจสอบคุณภาพ (ห้ามหยิบจ่าย)
  - `EXPIRED`: หมดอายุแล้ว (ห้ามจ่ายออกโดยเด็ดขาด)
  - `RECALLED`: ถูกเรียกคืนโดยผู้ผลิตหรือหน่วยงานกำกับ (ห้ามจ่ายและต้องไล่ตรวจย้อนกลับผู้ป่วย)
  - `DEPLETED`: จ่ายออกหมดล็อตแล้ว (`remaining_quantity_base = 0`)
- `notes`: หมายเหตุเพิ่มเติมของล็อต
- `created_at` / `created_by` / `updated_at` / `updated_by`: ข้อมูล Audit

#### หมายเหตุ:

1. หาก `products.requires_expiry_tracking = TRUE` ต้องระบุ `expiry_date` และหากระบุ `manufacture_date` ด้วย ต้องตรวจสอบว่า `expiry_date > manufacture_date`
2. ล็อตที่ `lot_status` เป็น `QUARANTINED`, `EXPIRED` หรือ `RECALLED` ต้องถูกป้องกันระดับธุรกิจไม่ให้นำมาจ่ายใน `dispensings`, `internal_stock_issues` หรือ `inventory_transfers`
3. การจัดลำดับ FEFO ในการหยิบจ่ายให้เรียงตาม `expiry_date ASC` (ล็อตที่หมดอายุก่อนออกก่อน) โดยข้ามล็อตที่ไม่พร้อมใช้งาน
4. สำหรับการสร้าง SQL DDL จริง ควรเพิ่ม FK `goods_receipt_item_id → pharmacy.goods_receipt_items` ด้วยคำสั่ง `ALTER TABLE` หลังจากสร้างตาราง `goods_receipt_items` แล้ว

- `branch_id` / `warehouse_id` / `storage_location_id`: สาขา คลัง และตำแหน่งจัดเก็บสินค้า
- `product_id`: สินค้า อ้างอิง `pharmacy.products`
- `lot_id`: ล็อตสินค้า อ้างอิง `pharmacy.inventory_lots` (เป็น `NULL` เฉพาะกรณีสินค้าที่ `requires_lot_tracking = FALSE`)
- `base_uom_id`: หน่วยหลักที่ใช้เก็บจำนวน อ้างอิง `pharmacy.units_of_measure` (ต้องตรงกับ `products.base_uom_id`)
- `on_hand_qty`: จำนวนสินค้าที่มีอยู่จริงทางกายภาพในตำแหน่งจัดเก็บนี้ (On-hand Quantity)
- `reserved_qty`: จำนวนที่ถูกจองไว้ตาม `pharmacy.stock_reservations` ที่มีสถานะ `ACTIVE` หรือ `PARTIALLY_FULFILLED`
- `quarantined_qty`: จำนวนสินค้าที่ถูกกักกันรอตรวจสอบ (ไม่สามารถหยิบจ่ายได้)
- `in_transit_qty`: จำนวนสินค้าที่กำลังรอโอนรับเข้าคลังปลายทางจากการโอนระหว่างคลัง (`IN_TRANSIT`)
- `expired_qty`: จำนวนสินค้าที่หมดอายุแล้วในตำแหน่งจัดเก็บนี้ (รอตัดจำหน่าย)
- `available_qty`: จำนวนสินค้าที่ **พร้อมใช้งานและจ่ายออกได้จริง** (`available_qty = on_hand_qty - reserved_qty - quarantined_qty - expired_qty`)
- `last_movement_at`: วันและเวลาของความเคลื่อนไหวล่าสุดจาก `stock_movements`
- `updated_at`: วันและเวลาที่ปรับปรุงยอดสรุปล่าสุด

#### หมายเหตุ:

1. กำหนด Unique Constraint แบบรองรับ `NULL` (`COALESCE(lot_id, '00000000-0000-0000-0000-000000000000')`) บน `(warehouse_id, storage_location_id, product_id, lot_id)`
2. ห้ามแก้ไขค่าในตารางนี้โดยตรงจาก UI หรือ API ภายนอก ต้องปรับปรุงผ่าน Transaction เดียวกันกับการบันทึกรายการใน `pharmacy.stock_movements` หรือ `pharmacy.stock_reservations` เท่านั้น (ตามกฎ §3.6 และ §9.2)
3. กรณีคลังกำหนด `allow_negative_stock = FALSE` ต้องตรวจสอบว่า `available_qty >= 0` และ `on_hand_qty >= 0`

  - `FULFILLED`: ตัดจ่ายครบตามจำนวนจองแล้ว
  - `RELEASED`: ปล่อยยอดจองคืนเข้า `available_qty` แล้ว
  - `EXPIRED`: หมดเวลาจองและระบบคืนยอดอัตโนมัติ

1. ต้องกำหนด CHECK Constraint ให้สอดคล้องตาม `reservation_type` (เช่น `PRESCRIPTION` ต้องระบุ `prescription_item_id`, `TRANSFER_OUT` ต้องระบุ `transfer_item_id`, `INTERNAL_ISSUE` ต้องระบุ `internal_issue_item_id`)
2. `fulfilled_qty_base <= reserved_qty_base` และ `fulfilled_qty_base >= 0`
3. เมื่อเกิดการจ่ายยาจริงหรือยกเลิกใบสั่งยา ต้องปรับยอด `fulfilled_qty_base` หรือเปลี่ยนสถานะเป็น `FULFILLED`/`RELEASED` พร้อมปรับ `inventory_balances.reserved_qty` ภายใน Transaction เดียวกัน
4. สำหรับการสร้าง SQL DDL จริง ควรเพิ่ม FK `transfer_item_id` และ `internal_issue_item_id` ภายหลังด้วย `ALTER TABLE` เนื่องจากตารางดังกล่าวนิยามในหมวดถัดไป

- `product_id` / `lot_id`: สินค้าและล็อตที่เกิดการเคลื่อนไหว

  - `DISPENSE_OUT`: จ่ายยาให้เจ้าของสัตว์ ขายปลีกหน้าร้าน หรือตัดใช้ในคลินิก/ห้องผ่าตัด (-)
  - `INTERNAL_ISSUE_OUT`: เบิกใช้ภายในหน่วยงาน (-)
  - `TRANSFER_OUT`: โอนสินค้าออกจากคลังต้นทาง (-)
  - `TRANSFER_IN`: รับสินค้าเข้าคลังปลายทาง (+)
  - `DISPENSE_RETURN_IN`: รับคืนสินค้ากลับเข้าสต็อกพร้อมใช้หลังผ่าน QC (+)
  - `INTERNAL_RETURN_IN`: รับคืนวัสดุ/ยาจากหน่วยงานภายในกลับเข้าคลัง (+)
  - `STOCK_COUNT_ADJUST_IN`: ปรับเพิ่มสต็อกจากผลตรวจนับ (+)
  - `STOCK_COUNT_ADJUST_OUT`: ปรับลดสต็อกจากผลตรวจนับ (-)
  - `MANUAL_ADJUST_IN`: ปรับเพิ่มสต็อกตามคำขออนุมัติ (+)
  - `MANUAL_ADJUST_OUT`: ปรับลดสต็อกตามคำขออนุมัติ (-)
  - `WRITE_OFF_OUT`: ตัดจำหน่ายสินค้าหมดอายุ/ชำรุด/ถูกทำลาย (-)
  - `QUARANTINE_LOCK`: ย้ายยอดจากพร้อมใช้เป็นกักกัน (เปลี่ยนหมวดยอดภายใน)
  - `QUARANTINE_RELEASE`: ปลดล็อกยอดกักกันกลับเป็นพร้อมใช้หลังตรวจสอบผ่าน
  - `OPENING_BALANCE`: ยอดยกมาตั้งต้นระบบ (+)
- `quantity_entered` / `entered_uom_id` / `conversion_factor_used`: จำนวนและหน่วยที่ผู้ใช้งานกรอกจริง ณ จุดทำรายการ พร้อม Snapshot อัตราแปลงหน่วยที่ใช้ในขณะนั้น
- `quantity_delta_base`: การเปลี่ยนแปลงสุทธิในหน่วยหลัก (ค่าบวกเมื่อเพิ่มสต็อก ค่าลบเมื่อตัดสต็อก)
- `balance_before_base` / `balance_after_base`: ยอดคงเหลือในตำแหน่งจัดเก็บ/คลังนั้นก่อนและหลังธุรกรรม (`balance_after_base = balance_before_base + quantity_delta_base`)
- `unit_cost_base` / `total_cost`: ต้นทุนต่อหน่วยหลักและมูลค่าต้นทุนรวมของรายการนี้ (`ABS(quantity_delta_base) * unit_cost_base`) เพื่อส่งต่อ Finance & Accounting (Domain 04 ข้อ 4.6)
- `reference_type`: ประเภทเอกสารต้นทาง ได้แก่ `GOODS_RECEIPT`, `DISPENSING`, `MEDICATION_RETURN`, `INTERNAL_ISSUE`, `INVENTORY_TRANSFER`, `STOCK_ADJUSTMENT`, `STOCK_WRITE_OFF`, `QUARANTINE`, `OPENING_BALANCE`, `REVERSAL`
- คอลัมน์ Typed Foreign Key อ้างอิงเอกสารต้นทาง (`goods_receipt_item_id`, `dispensing_item_id`, `return_item_id`, `internal_issue_item_id`, `transfer_item_id`, `adjustment_item_id`, `write_off_item_id`, `quarantine_id`): ระบุเฉพาะคอลัมน์ที่ตรงกับ `reference_type`
- `performed_by` / `performed_at`: พนักงานผู้ยืนยันธุรกรรมและวันเวลาที่เกิดเหตุการณ์จริง
- `reason` / `notes` / `created_at`: เหตุผล หมายเหตุ และเวลาที่บันทึกลงฐานข้อมูล

#### หมายเหตุ:

1. ตารางนี้เป็น **Append-only Ledger** ห้าม `UPDATE` หรือ `DELETE` แถวที่ยืนยันแล้ว หากต้องการแก้ไขต้องสร้างรายการย้อนกลับหรือปรับปรุงเอกสารใหม่ตามหลักบัญชีคลังสินค้า (ข้อ 3.11)
2. ทุกธุรกรรมต้องตรวจสอบ `balance_after_base = balance_before_base + quantity_delta_base` และต้องอัปเดต `pharmacy.inventory_balances` ภายใน Transaction เดียวกัน
3. สำหรับการสร้าง SQL DDL จริง ควรเพิ่ม FK อ้างอิงเอกสารต้นทางในหมวดที่ 4–7 ภายหลังด้วยคำสั่ง `ALTER TABLE`

3. หากสินค้ากำหนด `requires_lot_tracking = TRUE` ต้องระบุ `manufacturer_lot_number` และหาก `requires_expiry_tracking = TRUE` ต้องระบุ `expiry_date` ก่อนยืนยันรับเข้าสต็อก

- `witnessed_by`: พยานผู้ร่วมยืนยัน (บังคับระบุหากรายการใดในเอกสารนี้เป็นยาควบคุมพิเศษที่มี `requires_witness_verification = TRUE`)
- `dispensed_at`: วันและเวลาที่ยืนยันการจ่ายจริง
- `dispensing_status`: สถานะการจ่าย ค่าที่เป็นไปได้ คือ `PREPARING`, `VERIFIED`, `DISPENSED`, `PARTIALLY_RETURNED`, `FULLY_RETURNED`, `CANCELLED`
- `notes` / `created_at` / `created_by` / `updated_at` / `updated_by`: หมายเหตุและข้อมูล Audit

#### หมายเหตุ:

1. หาก `dispensing_type = 'PRESCRIPTION'` ต้องกำหนด CHECK Constraint ให้ `prescription_id IS NOT NULL`
2. หนึ่ง `prescription_id` สามารถมี `dispensings` ได้หลายใบเพื่อรองรับการทยอยจ่ายหรือจ่ายซ้ำส่วนที่ค้างจ่าย (Partial Dispensing) แต่รวมจำนวนที่จ่ายแล้วต้องไม่เกินจำนวนที่สั่ง
3. ต้องไม่ตัดยอดสต็อกจริง (`stock_movements`) จนกว่าสถานะจะยืนยันเปลี่ยนเป็น `DISPENSED` (กฎ §3.14)
4. ตารางนี้ไม่เก็บยอดเงินหรือสถานะการรับชำระเงินของผู้ป่วย แต่ส่งจำนวนที่จ่ายจริงใน `dispensing_items` ไปให้ Domain 07 (`billing`) ออกรายการเรียกเก็บเงิน (กฎ §9.6)

- `replenishment_request_item_id`: คำขอเติมสินค้าหรือโอนสินค้าที่เปิดขึ้นเพื่อรองรับยอดค้างจ่ายนี้ (ถ้ามี)

- `notes` / `created_at` / `created_by` / `updated_at` / `updated_by`: หมายเหตุและข้อมูล Audit

#### หมายเหตุ:

1. `remaining_qty >= 0` และต้องไม่เกิน `ordered_qty`
2. เมื่อมีการจ่ายส่วนที่เหลือเพิ่มเติมผ่าน `pharmacy.dispensings` ต้องอัปเดต `dispensed_qty_cumulative` และ `remaining_qty` โดยป้องกันไม่ให้จ่ายเกินจำนวนที่ค้างอยู่

#### หมายเหตุ:

1. เมื่อสร้างกักกัน ระบบต้องบันทึกรายการ `QUARANTINE_LOCK` ใน `stock_movements` และย้ายยอดจาก `available_qty` ไปยัง `quarantined_qty` ใน `inventory_balances` (และเปลี่ยน `inventory_lots.lot_status` เป็น `QUARANTINED` หากกักกันทั้งล็อต)
2. สำหรับการสร้าง SQL DDL จริง ควรเพิ่ม FK `recall_id → pharmacy.product_recalls` ภายหลังด้วยคำสั่ง `ALTER TABLE` หรือสร้าง `product_recalls` ก่อน

- `initiated_by` / `closed_by` / `closed_at`: ผู้เปิดเหตุการณ์และผู้ปิดเคสเมื่อดำเนินการครบถ้วน

### ตาราง `pharmacy.stock_write_offs`

**หน้าที่**: จัดเก็บเอกสารขออนุมัติตัดจำหน่ายสินค้าที่ไม่สามารถนำกลับมาใช้งานได้ (เช่น หมดอายุ ชำรุด ปนเปื้อน สูญเสียจาก Cold-Chain ล้มเหลว หรือการทำลายซากยาควบคุมพิเศษที่เหลือใช้) โดยแยกจากการปรับปรุงผลต่างตรวจนับและบันทึกลายเซ็นพยานและหลักฐานการทำลายตามข้อ 3.21

#### ข้อกำหนด:

- `write_off_id`: รหัสประจำเอกสารตัดจำหน่ายสินค้า
- `write_off_number`: เลขที่ใบตัดจำหน่าย รูปแบบ `WOF-{YYYY}{MM}{DD}-{NNNN}`
- `branch_id` / `warehouse_id`: สาขาและคลังสินค้าที่ทำการตัดจำหน่าย
- `write_off_type`: ประเภทการตัดจำหน่าย ค่าที่เป็นไปได้ คือ `EXPIRED` (สินค้าหมดอายุ), `DAMAGED` (สินค้าชำรุดเสียหาย), `CONTAMINATED` (ปนเปื้อนระหว่างใช้งาน), `COLD_CHAIN_SPOILAGE` (เสื่อมสภาพจากอุณหภูมิเกินเกณฑ์), `RECALL_DESTRUCTION` (ทำลายตามคำสั่งเรียกคืน), `CONTROLLED_DRUG_WASTE` (ทำลายเศษยาควบคุมพิเศษ/วัตถุออกฤทธิ์)
- `reason`: เหตุผลประกอบการขออนุมัติตัดจำหน่าย
- `requested_by` / `requested_at` / `approved_by` / `approved_at`: ผู้ขอตัดจำหน่ายและผู้อนุมัติตามวงเงินหรือสิทธิ์

- `total_cost_value`: มูลค่าต้นทุนรวมของสินค้าที่ตัดจำหน่าย (ใช้ส่งต่อ Finance & Accounting ตามข้อ 4.6)

- `notes` / `created_at` / `created_by` / `updated_at` / `updated_by`: หมายเหตุและข้อมูล Audit

#### หมายเหตุ:
