# Domain 0: การตั้งค่าหลักของระบบ

## Shared Database — ตารางกลางที่ใช้ร่วมกัน

ศูนย์กลางข้อมูลพื้นฐานและข้อมูลอ้างอิงร่วมของระบบ ทำหน้าที่จัดเก็บข้อมูลที่หลาย Business Domains ต้องเรียกใช้งานร่วมกัน โดยไม่ต้องสร้างข้อมูลชุดเดียวกันซ้ำในแต่ละ Domain

### ตาราง `core.branches`

ทะเบียนสาขาของคลินิก เก็บข้อมูลสาขาทั้งหมดของคลินิกสัตวแพทย์ เป็นข้อมูลอ้างอิงหลักที่แทบทุก Domain (appointment, clinical, pharmacy, billing, procurement, hr) นำ `branch_id` ไปใช้งานร่วมกัน

#### โครงสร้าง Field:

| Column           | Data Type    | Constraint       |
| ---------------- | ------------ | ---------------- |
| `branch_id`      | UUID         | PK, NOT NULL     |
| `branch_code`    | VARCHAR(20)  | UNIQUE, NOT NULL |
| `branch_name`    | VARCHAR(150) | NOT NULL         |
| `branch_name_en` | VARCHAR(150) | NULL             |
| `branch_type`    | ENUM         | NOT NULL         |
| `phone_number`   | VARCHAR(30)  | NULL             |
| `email`          | VARCHAR(255) | NULL             |
| `website_url`    | TEXT         | NULL             |
| `address_line1`  | VARCHAR(255) | NOT NULL         |
| `address_line2`  | VARCHAR(255) | NULL             |
| `subdistrict`    | VARCHAR(100) | NULL             |
| `district`        | VARCHAR(100) | NULL                               |
| `province`        | VARCHAR(100) | NULL                               |
| `postal_code`     | VARCHAR(10)  | NULL                               |
| `timezone`        | VARCHAR(64)  | NOT NULL DEFAULT 'Asia/Bangkok'    |
| `tax_branch_code` | VARCHAR(10)  | NULL                               |
| `opened_on`       | DATE         | NULL                               |
| `closed_on`       | DATE         | NULL                               |
| `status`          | ENUM         | NOT NULL                           |
| `metadata`       | JSONB        | NULL             |
| `created_at`     | TIMESTAMPTZ  | NOT NULL         |
| `created_by`     | UUID         | NULL             |
| `updated_at`     | TIMESTAMPTZ  | NULL             |
| `updated_by`     | UUID         | NULL             |

#### ข้อกำหนด:

- `branch_id`: รหัสประจำสาขาภายในระบบ
- `branch_code`: รหัสสาขาที่ใช้ในทางธุรกิจ
- `branch_name`: ชื่อสาขาคลินิก
- `branch_name_en`: ชื่อสาขาคลินิกภาษาอังกฤษ
- `branch_type`: ประเภทของสาขา ค่าที่เป็นไปได้
  - `HEADQUARTERS`: สำนักงานใหญ่ สาขาหลักที่ใช้บริหารกิจการ
  - `VETERINARY_CLINIC`: คลินิกสัตวแพทย์ สาขาที่ให้บริการตรวจรักษาสัตว์
  - `VETERINARY_HOSPITAL`: โรงพยาบาลสัตว์ สาขาที่ให้บริการรักษาและดูแลผู้ป่วยในตามขอบเขตที่กำหนด
- `phone_number`: เบอร์โทรศัพท์ประจำสาขา
- `email`: อีเมลติดต่อสาขา
- `website_url`: เว็บไซต์ของสาขา
- `address_line1`: ที่อยู่หลัก
- `address_line2`: ที่อยู่เพิ่มเติม
- `subdistrict`:แขวงหรือตำบล
- `district`: เขตหรืออำเภอ
- `province`: จังหวัด
- `postal_code`: รหัสไปรษณีย์
- `timezone`: เขตเวลาของสาขาในรูปแบบ IANA Timezone (เช่น `Asia/Bangkok`) ใช้กำหนดช่วงเวลาเปิด-ปิดสาขา วันทำการ ตารางนัดหมาย และการออกรายงานของสาขาได้อย่างถูกต้องแม้ขยายสู่สาขาข้ามเขตเวลา
- `tax_branch_code`: รหัสสาขาทางภาษีสำหรับออกใบกำกับภาษี (เช่น `00000` สำหรับสำนักงานใหญ่ หรือ `00001`, `00002` สำหรับสาขา) เพื่อเชื่อมต่อกับ Domain 07 (Billing & Payment)
- `opened_on`: วันที่เริ่มเปิดดำเนินกิจการ
- `closed_on`: วันที่ปิดสาขาถาวร
- `status`: สถานะการดำเนินงาน ค่าที่เป็นไปได้
  - `ACTIVE`: เปิดดำเนินงาน สาขาสามารถรับบริการและทำธุรกรรมได้
  - `TEMPORARILY_CLOSED`: ปิดชั่วคราว สาขาหยุดให้บริการชั่วคราว
  - `INACTIVE`: ระงับการใช้งาน สาขาไม่สามารถใช้สร้างธุรกรรมใหม่ตามปกติ
  - `PERMANENTLY_CLOSED`: ปิดถาวร สาขาสิ้นสุดการดำเนินกิจการ
- `metadata`: ข้อมูลเสริมของสาขา
- `created_at`: วันที่สร้างข้อมูล
- `created_by`: ผู้สร้างข้อมูล อ้างอิง `hr.employees` (`employee_id`)
- `updated_at`: วันที่แก้ไขล่าสุด
- `updated_by`: ผู้แก้ไขล่าสุด อ้างอิง `hr.employees` (`employee_id`)

#### หมายเหตุ

1. `branch_code` ต้องไม่ซ้ำกัน
2. สาขาที่มีประวัติธุรกรรมแล้วห้ามลบจริง
3. สาขาที่ปิดถาวรต้องไม่สามารถสร้างธุรกรรมใหม่ได้
4. สาขาที่ปิดชั่วคราวยังต้องคงข้อมูลเดิมไว้
5. `closed_on` ต้องไม่ก่อน `opened_on` (เมื่อมีการระบุ `closed_on`)
6. `tax_branch_code` ของสาขาที่ออกใบกำกับภาษีควรกำหนดรูปแบบรหัส 5 หลักให้สอดคล้องกับข้อกำหนดทางภาษีของแต่ละประเทศ/สาขา (เช่น `00000` สำหรับ `HEADQUARTERS`)

### ตาราง `core.branch_business_hours`

เก็บวันและเวลาเปิดให้บริการของแต่ละสาขา ต้องแยกจาก `branches` เพราะแต่ละสาขาอาจมีเวลาทำการแตกต่างกัน และเวลาเปิดให้บริการอาจเปลี่ยนแปลงตามวัน

#### โครงสร้าง Field:

| Column             | Data Type   | Constraint         |
| ------------------ | ----------- | ------------------ |
| `business_hour_id` | UUID        | PK, NOT NULL       |
| `branch_id`        | UUID        | FK → core.branches |
| `day_of_week`      | SMALLINT    | NOT NULL           |
| `session_number`   | SMALLINT    | NOT NULL           |
| `open_time`        | TIME        | NOT NULL           |
| `close_time`       | TIME        | NOT NULL           |
| `effective_from`   | DATE        | NOT NULL           |
| `effective_to`     | DATE        | NULL               |
| `status`           | ENUM        | NOT NULL           |
| `created_at`       | TIMESTAMPTZ | NOT NULL           |
| `created_by`       | UUID        | NULL               |
| `updated_at`       | TIMESTAMPTZ | NULL               |
| `updated_by`       | UUID        | NULL               |

#### ข้อกำหนด:

- `business_hour_id`: รหัสเวลาทำการ
- `branch_id`: สาขาที่เป็นเจ้าของเวลาทำการ
- `day_of_week`: วันในสัปดาห์ ใช้ค่าเป็น 1 ถึง 7 แทน วันที่เริ่ม 1 คือ วันจันทร์ 7 คือ วันอาทิตย์
- `session_number`: ลำดับช่วงเวลาเปิดบริการในวันนั้น
- `open_time`: เวลาเริ่มเปิดให้บริการ
- `close_time`: เวลาปิดให้บริการ
- `effective_from`: วันที่เริ่มมีผล
- `effective_to`: วันที่สิ้นสุดผลบังคับ
- `status`: สถานะการใช้งานของช่วงเวลาทำการ ค่าที่เป็นไปได้ คือ
  - `ACTIVE`: เปิดใช้งาน ช่วงเวลาทำการมีผลบังคับใช้อยู่
  - `INACTIVE`: ปิดใช้งาน ช่วงเวลาทำการถูกระงับหรือยกเลิกการใช้งาน
- `created_at`: วันที่สร้าง
- `created_by`: ผู้สร้าง
- `updated_at`: วันที่แก้ไข
- `updated_by`: ผู้แก้ไข

#### หมายเหตุ:

1. หนึ่งสาขาสามารถมีเวลาทำการได้หลายวัน
2. หนึ่งวันสามารถมีหลายช่วงเวลาเปิดบริการ
3. ต้องไม่กำหนดช่วงเวลาเปิดและปิดซ้อนกันในวันเดียวกันและช่วงวันที่มีผลเดียวกัน
4. `effective_to` ต้องไม่ก่อน `effective_from`
5. `close_time` ต้องมากกว่า `open_time` สำหรับช่วงเวลาที่อยู่ภายในวันเดียวกัน
6. หากคลินิกเปิดข้ามเที่ยงคืน ให้แบ่งช่วงเวลาออกเป็นช่วงของวันเปิดและวันถัดไป เพื่อให้การตรวจสอบเวลาทำการง่ายและชัดเจน

### ตาราง `core.branch_closures`

เก็บวันหยุดและช่วงเวลาที่สาขาไม่สามารถให้บริการได้ แม้ว่าจะเป็นวันที่ปกติเปิดทำการก็ตาม เช่น วันหยุดปีใหม่, วันหยุดสงกรานต์, วันหยุดนักขัตฤกษ์, ปิดปรับปรุงสถานที่, ปิดซ่อมแซมอุปกรณ์, ปิดให้บริการเฉพาะช่วงเวลา มีความสำคัญต่อ Appointment เพราะระบบต้องไม่เปิดให้ลูกค้าจองเวลาที่สาขาปิดให้บริการ

#### โครงสร้าง Field:

| Column            | Data Type    | Constraint             |
| ----------------- | ------------ | ---------------------- |
| `closure_id`      | UUID         | PK, NOT NULL           |
| `branch_id`       | UUID         | FK → core.branches     |
| `closure_type`    | ENUM         | NOT NULL               |
| `closure_name`    | VARCHAR(200) | NOT NULL               |
| `closure_reason`  | TEXT         | NULL                   |
| `start_at`        | TIMESTAMPTZ  | NOT NULL               |
| `end_at`          | TIMESTAMPTZ  | NOT NULL               |
| `is_recurring`    | BOOLEAN      | NOT NULL DEFAULT FALSE |
| `recurrence_rule` | JSONB        | NULL                   |
| `status`          | ENUM         | NOT NULL               |
| `created_by`      | UUID         | NULL                   |
| `created_at`      | TIMESTAMPTZ  | NOT NULL               |
| `updated_by`      | UUID         | NULL                   |
| `updated_at`      | TIMESTAMPTZ  | NULL                   |

#### ข้อกำหนด:

- `closure_id`: รหัสรายการปิดให้บริการ
- `branch_id`: สาขาที่ปิดให้บริการ
- `closure_type`: ประเภทการปิด ค่าที่เป็นไปได้
  - `PUBLIC_HOLIDAY`: วันหยุดนักขัตฤกษ์ ตามวันหยุดราชการหรือวันหยุดที่กิจการกำหนด
  - `ANNUAL_HOLIDAY`: วันหยุดประจำปี ตามปฏิทินประจำปีของคลินิก
  - `MAINTENANCE`: ปิดปรับปรุง ซ่อมแซมหรือปรับปรุงสถานที่
  - `EMERGENCY`: ปิดฉุกเฉิน เหตุการณ์ฉุกเฉินที่ทำให้ไม่สามารถให้บริการ
  - `SPECIAL_CLOSURE`: ปิดเป็นกรณีพิเศษ การปิดเฉพาะกิจตามการบริหารของคลินิก
- `closure_name`: ชื่อรายการปิด
- `closure_reason`: รายละเอียดเหตุผล
- `start_at`: วันและเวลาเริ่มปิด
- `end_at`: วันและเวลาสิ้นสุดการปิด
- `is_recurring`: เป็นวันหยุดที่เกิดซ้ำหรือไม่
- `recurrence_rule`: เงื่อนไขการเกิดซ้ำ
- `status`: สถานะรายการ ค่าที่เป็นไปได้
  - `SCHEDULED`: กำหนดวันปิดไว้แล้ว
  - `ACTIVE`: การปิดมีผลใช้งาน
  - `CANCELLED`: ยกเลิกรายการปิด
  - `COMPLETED`: สิ้นสุดช่วงเวลาปิดแล้ว
- `created_by`: ผู้สร้างรายการ
- `created_at`: วันที่สร้าง
- `updated_by`: ผู้แก้ไข
- `updated_at`: วันที่แก้ไข

#### หมายเหตุ:

1. `end_at` ต้องมากกว่า `start_at`
2. การปิดสาขาต้องไม่ทำให้ประวัตินัดหมายเดิมสูญหาย
3. ระบบ Appointment ต้องตรวจสอบรายการปิดก่อนอนุญาตให้สร้างนัดหมาย
4. การปิดสาขาไม่ควรลบข้อมูลเวลาทำการปกติ
5. หากเป็นรายการที่เกิดซ้ำ ต้องกำหนด `recurrence_rule` ให้มีโครงสร้างที่ตรวจสอบได้
6. หากมีการปิดเฉพาะช่วงเวลา ระบบต้องสามารถจองช่วงเวลานอกเหนือจากช่วงปิดได้

### ตาราง `core.service_categories`

ทะเบียนประเภทบริการของคลินิกสัตวแพทย์ ใช้จัดกลุ่มบริการมาตรฐาน เพื่อให้สามารถค้นหา จัดหมวดหมู่ กำหนดราคา และออกรายงาน

#### โครงสร้าง Field:

| Column                | Data Type    | Constraint                         |
| --------------------- | ------------ | ---------------------------------- |
| `service_category_id` | UUID         | PK, NOT NULL                       |
| `category_code`       | VARCHAR(30)  | UNIQUE, NOT NULL                   |
| `category_name`       | VARCHAR(150) | NOT NULL                           |
| `category_name_en`    | VARCHAR(150) | NULL                               |
| `description`         | TEXT         | NULL                               |
| `parent_category_id`  | UUID         | FK → core.service_categories, NULL |
| `display_order`       | SMALLINT     | NOT NULL DEFAULT 0                 |
| `status`              | ENUM         | NOT NULL                           |
| `created_at`          | TIMESTAMPTZ  | NOT NULL                           |
| `created_by`          | UUID         | NULL                               |
| `updated_at`          | TIMESTAMPTZ  | NULL                               |
| `updated_by`          | UUID         | NULL                               |

#### ข้อกำหนด:

- `service_category_id`: รหัสประเภทบริการ
- `category_code`: รหัสประเภทบริการสำหรับเจ้าหน้าที่ใช้ภายในคลีนิก ค่าที่เป็นไปได้
- `category_name`: ชื่อประเภทบริการภาษาไทย
- `category_name_en`: ชื่อประเภทบริการภาษาอังกฤษ
- `description`: รายละเอียดประเภทบริการ
- `parent_category_id`: ประเภทบริการหลัก
- `display_order`: ลำดับการแสดงผล
- `status`: สถานะประเภทบริการ ค่าที่เป็นไปได้
  - `ACTIVE`: ประเภทบริการเปิดใช้งาน
  - `INACTIVE`: ประเภทบริการปิดใช้งาน
- `created_at`: วันที่สร้าง
- `created_by`: ผู้สร้าง
- `updated_at`: วันที่แก้ไข
- `updated_by`: ผู้แก้ไข

#### ค่า Category ที่ต้องมีในระบบ

| category_code        | category_name               | category_name_en   |
| -------------------- | --------------------------- | ------------------ |
| `CONSULTATION`       | บริการตรวจและให้คำปรึกษา    | Consultation       |
| `HEALTH_CHECK`       | บริการตรวจสุขภาพ            | Health Check       |
| `VACCINATION`        | บริการฉีดวัคซีน             | Vaccination        |
| `MEDICAL_TREATMENT`  | บริการรักษาทางการแพทย์      | Medical Treatment  |
| `SURGERY`            | บริการผ่าตัด                | Surgery            |
| `DENTAL`             | บริการทันตกรรม              | Dental             |
| `LABORATORY`         | บริการตรวจทางห้องปฏิบัติการ | Laboratory         |
| `DIAGNOSTIC_IMAGING` | บริการตรวจวินิจฉัยด้วยภาพ   | Diagnostic Imaging |
| `PREVENTIVE_CARE`    | บริการป้องกันโรค            | Preventive Care    |
| `WOUND_CARE`         | บริการทำแผลและดูแลบาดแผล    | Wound Care         |
| `INPATIENT_CARE`     | บริการดูแลสัตว์ป่วยใน       | Inpatient Care     |
| `GROOMING`           | บริการอาบน้ำและตัดแต่งขน    | Grooming           |
| `OTHER_SERVICES`     | บริการอื่น ๆ                | Other Services     |

#### หมายเหตุ:

1. `category_code` ต้องไม่ซ้ำ
2. ประเภทบริการหนึ่งรายการสามารถมีประเภทบริการย่อยได้หลายรายการ
3. ห้ามกำหนดประเภทบริการให้เป็น Parent ของตัวเอง
4. ประเภทบริการที่มีรายการบริการใช้งานอยู่ไม่ควรถูกลบ
5. ประเภทที่ปิดใช้งานแล้วต้องไม่ถูกนำไปสร้างบริการใหม่
6. การเปลี่ยนชื่อประเภทต้องไม่กระทบข้อมูลธุรกรรมเก่า

### ตาราง `core.service_catalogs`

ทะเบียนบริการมาตรฐานทั้งหมดของคลินิกสัตวแพทย์ หลาย Domain จำเป็นต้องใช้ข้อมูลบริการเดียวกัน

#### โครงสร้าง Field:

| Column                     | Data Type    | Constraint                             |
| -------------------------- | ------------ | -------------------------------------- |
| `service_catalog_id`       | UUID         | PK, NOT NULL                           |
| `service_code`             | VARCHAR(50)  | UNIQUE, NOT NULL                       |
| `service_name`             | VARCHAR(200) | NOT NULL                               |
| `service_name_en`          | VARCHAR(200) | NULL                                   |
| `service_category_id`      | UUID         | FK → core.service_categories, NOT NULL |

#### ข้อกำหนด:

- `service_catalog_id`: รหัสบริการภายในระบบ
- `service_code`: รหัสบริการทางธุรกิจ
- `service_name`: ชื่อบริการภาษาไทย
- `service_name_en`: ชื่อบริการภาษาอังกฤษ
- `service_category_id`: ประเภทบริการ
- `description`: รายละเอียดบริการ
- `unit_of_service`: หน่วยในการคิดค่าบริการ ไม่ใช่หน่วยนับสินค้าคงคลัง
  - `PER_SERVICE`: ต่อบริการ คิดค่าบริการต่อหนึ่งรายการ
  - `PER_SESSION`: ต่อครั้ง คิดค่าบริการต่อรอบการให้บริการ
  - `PER_VISIT`: ต่อการเข้ารับบริการ คิดค่าบริการต่อการเข้าคลินิก
  - `PER_HOUR`: ต่อชั่วโมง คิดค่าบริการตามระยะเวลา
  - `PER_DAY`: ต่อวัน คิดค่าบริการรายวัน เช่น การดูแลสัตว์ป่วยใน
  - `PER_PROCEDURE`: ต่อหัตถการ คิดค่าบริการตามหัตถการ
- `default_duration_minutes`: ระยะเวลาบริการมาตรฐานสำหรับใช้วางแผนการให้บริการเป็นนาที เป็นค่าที่กำหนดในทะเบียนบริการของแต่ละคลินิก ไม่ใช่ค่าตายตัวของระบบ
- `pre_buffer_minutes`: เวลาเตรียมความพร้อมก่อนเริ่มให้บริการเป็นนาที (เช่น เตรียมเครื่องมือ เตรียมห้อง) ค่าเริ่มต้น 0 สำหรับใช้วางแผนการจองเวลาใน Domain 02
- `post_buffer_minutes`: เวลาหลังจบการให้บริการเป็นนาที (เช่น ทำความสะอาดและฆ่าเชื้อห้องตรวจ/ห้องผ่าตัด) ค่าเริ่มต้น 0 สำหรับใช้วางแผนการจองเวลาใน Domain 02
- `required_room_type`: ประเภทห้องมาตรฐานที่บริการนี้จำเป็นต้องใช้ (Nullable; หากไม่เจาะจงห้องเฉพาะให้เป็น NULL) ค่าที่เป็นไปได้สอดคล้องกับ `appointment.rooms.room_type` คือ
  - `GENERAL_EXAMINATION`: ห้องตรวจทั่วไป
  - `SPECIALIST_EXAMINATION`: ห้องตรวจเฉพาะทาง
  - `VACCINATION`: ห้องฉีดวัคซีน
  - `SURGERY`: ห้องผ่าตัด
  - `RECOVERY`: ห้องพักฟื้น
  - `DIAGNOSTIC`: ห้องตรวจวินิจฉัย
  - `TREATMENT`: ห้องทำหัตถการ
  - `GROOMING`: ห้องอาบน้ำและตัดแต่งขน
- `requires_appointment`: ต้องนัดหมายล่วงหน้าหรือไม่ มีประโยชน์ต่อ Appointment
- `requires_veterinarian`: ใช้กำหนดว่าการให้บริการนั้นต้องมีสัตวแพทย์เป็นผู้รับผิดชอบหรือไม่ มีประโยชน์ต่อ Workforce Scheduling
- `is_taxable`: ใช้ระบุว่าบริการนั้นต้องเข้าสู่กระบวนการคำนวณภาษีหรือไม่ โดยการคำนวณจริงและกฎภาษียังคงเป็นความรับผิดชอบของ Billing & Payment Management
- `is_commissionable`: บริการนี้เข้าเงื่อนไขคำนวณค่าตอบแทนหรือไม่
- `status`: สถานะบริการ ค่าที่เป็นไปได้
  - `DRAFT`: สร้างรายการแล้วแต่ยังไม่เปิดใช้งาน
  - `ACTIVE`: บริการเปิดให้ใช้งาน
  - `INACTIVE`: ระงับการให้บริการชั่วคราว
  - `DISCONTINUED`: ยกเลิกบริการอย่างถาวร
- `display_order`: ลำดับแสดงผล
- `metadata`: ข้อมูลเพิ่มเติม
- `created_at`: วันที่สร้าง
- `created_by`: ผู้สร้าง
- `updated_at`: วันที่แก้ไข
- `updated_by`: ผู้แก้ไข

#### หมายเหตุ:

1. service_code ต้องไม่ซ้ำ
2. ทุกบริการต้องอยู่ภายใต้ประเภทบริการ
3. บริการที่มีการใช้งานในธุรกรรมแล้วต้องไม่ถูกลบ
4. การเปลี่ยนชื่อบริการต้องไม่ทำให้ชื่อใน Invoice เดิมเปลี่ยนตาม
5. ราคาบริการต้องดึงจาก service_prices
6. การสร้างบริการใหม่ต้องไม่จำเป็นต้องสร้างราคาในทุกสาขาทันที แต่ต้องมีราคาที่ใช้งานได้ก่อนนำไปเรียกเก็บเงิน
7. บริการที่ปิดใช้งานแล้วต้องไม่สามารถเลือกสร้างธุรกรรมใหม่ได้ตามปกติ
8. `default_duration_minutes` (หากระบุ), `pre_buffer_minutes` และ `post_buffer_minutes` ต้องมากกว่าหรือเท่ากับ 0 และ Domain 02 สามารถกำหนดค่า Override เฉพาะสัตวแพทย์หรือเฉพาะห้องเพิ่มเติมได้ผ่านตารางของ Domain 02

### ตาราง `core.service_prices`

จัดเก็บราคามาตรฐานของบริการ โดยรองรับการกำหนดราคาแตกต่างกันตามสาขาและช่วงเวลาที่มีผล แยกจาก `service_catalogs` เพราะบริการหนึ่งรายการอาจมีราคาต่างกันในแต่ละสาขา และราคาอาจเปลี่ยนแปลงตามเวลา

#### โครงสร้าง Field:

| Column               | Data Type     | Constraint                           |
| -------------------- | ------------- | ------------------------------------ |
| `service_price_id`   | UUID          | PK, NOT NULL                         |
| `service_catalog_id` | UUID          | FK → core.service_catalogs, NOT NULL |
| `branch_id`          | UUID          | FK → core.branches, NOT NULL         |
| `currency_code`      | CHAR(3)       | NOT NULL                             |
| `unit_price`         | NUMERIC(14,2) | NOT NULL                             |
| `effective_from`     | TIMESTAMPTZ   | NOT NULL                             |
| `effective_to`       | TIMESTAMPTZ   | NULL                                 |
| `status`             | ENUM          | NOT NULL                             |
| `price_reason`       | TEXT          | NULL                                 |
| `approved_by`        | UUID          | NULL                                 |
| `approved_at`        | TIMESTAMPTZ   | NULL                                 |
| `created_at`         | TIMESTAMPTZ   | NOT NULL                             |
| `created_by`         | UUID          | NULL                                 |
| `updated_at`         | TIMESTAMPTZ   | NULL                                 |
| `updated_by`         | UUID          | NULL                                 |

#### ข้อกำหนด:

- `service_price_id`: รหัสรายการราคา
- `service_catalog_id`: บริการที่กำหนดราคา
- `branch_id`: สาขาที่ใช้ราคานี้
- `currency_code`: รหัสสกุลเงิน
- `unit_price`: ราคาต่อหน่วยบริการ
- `effective_from`: วันและเวลาเริ่มใช้ราคา
- `effective_to`: วันและเวลาสิ้นสุดการใช้ราคา
- `status`: สถานะราคา ค่าที่เป็นไปได้
  - `DRAFT` ร่างราคา กำหนดราคาแล้วแต่ยังไม่อนุมัติ
  - `PENDING_APPROVAL` รออนุมัติ ส่งราคาให้ผู้มีอำนาจพิจารณา
  - `ACTIVE` ราคาใช้งาน ราคาที่สามารถนำไปใช้ได้
  - `EXPIRED` หมดอายุ สิ้นสุดช่วงเวลาการใช้ราคา
  - `CANCELLED` ยกเลิกราคา ราคาที่ถูกยกเลิกก่อนหรือหลังการอนุมัติตามสิทธิ์
- `price_reason`: เหตุผลในการกำหนดหรือปรับราคา
- `approved_by`: ผู้อนุมัติราคา
- `approved_at`: วันที่อนุมัติ
- `created_at`: วันที่สร้าง
- `created_by`: ผู้สร้าง
- `updated_at`: วันที่แก้ไข
- `updated_by`: ผู้แก้ไข

#### หมายเหตุ:

1. ราคาแต่ละรายการต้องอ้างอิงบริการและสาขาที่ถูกต้อง
2. `unit_price` ต้องมากกว่าหรือเท่ากับ 0
3. `effective_to` ต้องมากกว่า `effective_from`
4. ราคาเดียวกันของบริการเดียวกันในสาขาเดียวกันและสกุลเงินเดียวกันต้องไม่ซ้อนช่วงเวลาที่มีผล
5. ราคาที่อนุมัติและเริ่มใช้งานแล้วต้องไม่แก้ไขทับโดยตรง
6. การปรับราคาให้สร้างรายการใหม่และกำหนดวันเริ่มมีผล
7. การสร้าง Invoice ต้อง Snapshot ราคาที่ใช้จริงไว้ใน `billing.invoice_items`
8. การเปลี่ยนราคาปัจจุบันต้องไม่ส่งผลต่อ Invoice ที่ออกไปแล้ว

### ตาราง `core.audit_logs`

จัดเก็บประวัติการเปลี่ยนแปลงข้อมูลภายในระบบ ERP เพื่อให้สามารถตรวจสอบได้ว่า

- ใครเป็นผู้สร้างข้อมูล
- ใครเป็นผู้แก้ไขข้อมูล
- มีการเปลี่ยนแปลงอะไร
- ข้อมูลเดิมเป็นอย่างไร
- ข้อมูลใหม่เป็นอย่างไร
- เปลี่ยนแปลงเมื่อใด
- เปลี่ยนจากระบบหรือช่องทางใด

#### โครงสร้าง Field:

| Column           | Data Type    | Constraint           |
| ---------------- | ------------ | -------------------- |
| `audit_log_id`   | UUID         | PK, NOT NULL |
| `schema_name`    | VARCHAR(100) | NOT NULL     |
| `table_name`     | VARCHAR(100) | NOT NULL     |
| `record_id`      | UUID         | NOT NULL     |
| `action_type`    | ENUM         | NOT NULL     |
| `old_values`     | JSONB        | NULL         |
| `new_values`     | JSONB        | NULL         |
| `changed_fields` | TEXT[]       | NULL         |
| `performed_by`   | UUID         | NULL         |
| `performed_at`   | TIMESTAMPTZ  | NOT NULL     |
| `ip_address`     | INET         | NULL         |
| `user_agent`     | TEXT         | NULL         |
| `request_id`     | UUID         | NULL         |
| `source_channel` | ENUM         | NOT NULL     |
| `reason`         | TEXT         | NULL                 |
| `metadata`       | JSONB        | NULL                 |

#### ข้อกำหนด:

- `audit_log_id`: รหัส Audit Log
- `schema_name`: ชื่อ Schema ที่เกิดการเปลี่ยนแปลง
- `table_name`: ชื่อตารางที่ถูกเปลี่ยนแปลง
- `record_id`: รหัส Primary Key (`UUID`) ของข้อมูลที่ถูกเปลี่ยนแปลง
- `action_type`: ประเภทการดำเนินการ ค่าที่เป็นไปได้
  - `INSERT`: สร้างข้อมูลใหม่
  - `UPDATE`: แก้ไขข้อมูล
  - `DELETE`: ลบข้อมูล
  - `SOFT_DELETE`: เปลี่ยนสถานะเป็นลบเชิงตรรกะ
  - `RESTORE`: กู้คืนข้อมูล
  - `APPROVE`: อนุมัติข้อมูลหรือรายการ
  - `REJECT`: ปฏิเสธข้อมูลหรือรายการ
  - `CANCEL`: ยกเลิกรายการ
  - `LOGIN`: เข้าสู่ระบบ
  - `LOGOUT`: ออกจากระบบ
  - `ACCESS_DENIED`: ถูกปฏิเสธการเข้าถึง
- `old_values`: ข้อมูลก่อนเปลี่ยนแปลง
- `new_values`: ข้อมูลหลังเปลี่ยนแปลง
- `changed_fields`: รายชื่อ Field ที่เปลี่ยนแปลง
- `performed_by`: ผู้ดำเนินการ
- `performed_at`: วันและเวลาที่เกิดเหตุการณ์
- `ip_address`: IP Address ต้นทาง
- `user_agent`: ข้อมูล Client หรือ Browser
- `request_id`: รหัสคำขอที่เชื่อมโยงธุรกรรม
- `source_channel`: ช่องทางที่เกิดการดำเนินการ
  - `WEB_APPLICATION`: ระบบผ่านเว็บ
  - `MOBILE_APPLICATION`: แอปพลิเคชันมือถือ
  - `API`: การเรียกผ่าน API
  - `BACKGROUND_JOB`: กระบวนการทำงานเบื้องหลัง
  - `SYSTEM_PROCESS`: การดำเนินการอัตโนมัติของระบบ
  - `IMPORT`: การนำเข้าข้อมูล
  - `INTEGRATION`: การเชื่อมต่อระบบภายนอก
- `reason`: เหตุผลในการเปลี่ยนแปลง
- `metadata`: ข้อมูลเพิ่มเติม

#### หมายเหตุ:

1. Audit Log ต้องเป็นข้อมูลแบบ Append-only
2. ผู้ใช้งานทั่วไปต้องไม่มีสิทธิ์แก้ไขหรือลบ Audit Log
3. ทุกการเปลี่ยนแปลงข้อมูลสำคัญต้องมีการบันทึก Audit
4. ต้องบันทึกเวลาเป็น TIMESTAMPTZ
5. ต้องไม่เก็บรหัสผ่าน Token หรือ Secret ลงใน `old_values` และ `new_values`
6. ข้อมูลส่วนบุคคลที่อ่อนไหวต้องผ่านการ Mask หรือ Redact ก่อนบันทึก
7. ต้องกำหนดระยะเวลาเก็บรักษาข้อมูลตามนโยบายขององค์กร
8. การเปลี่ยนแปลงหลายตารางภายในธุรกรรมเดียวกันควรบันทึกให้สอดคล้องกับผล Commit ของธุรกรรมนั้น
