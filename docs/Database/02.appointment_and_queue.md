# Domain 02 — Appointment & Queue Management

เจ้าของข้อมูล: Domain 02

รับผิดชอบกระบวนการตั้งแต่ลูกค้าต้องการจองนัดหมาย ไปจนถึงการลงทะเบียนเข้ารับบริการ การจัดคิว การคัดกรอง และการส่งต่อไปยังระบบตรวจรักษา

## กลุ่ม Appointment Management

### ตาราง `appointment.appointments`

**หน้าที่**: จัดเก็บข้อมูลหลักของการนัดหมายแต่ละรายการ โดยหนึ่งรายการนัดหมายจะเป็นตัวแทนการจองเข้ารับบริการของสัตว์เลี้ยงหนึ่งตัว ณ สาขาและช่วงเวลาที่กำหนด

| Column                          | Data Type   | Constraint                              |
| ------------------------------- | ----------- | --------------------------------------- |
| `appointment_id`                | UUID        | PK, NOT NULL                            |
| `appointment_number`            | VARCHAR(30) | UNIQUE, NOT NULL                        |
| `rescheduled_from_appointment_id`| UUID       | FK → appointment.appointments, NULL     |
| `branch_id`                     | UUID        | FK → core.branches, NOT NULL            |
| `owner_id`                      | UUID        | FK → owner.owners, NOT NULL             |
| `pet_id`                        | UUID        | FK → owner.pets, NOT NULL               |
| `appointment_type`              | ENUM        | NOT NULL                                |
| `appointment_date`              | DATE        | NOT NULL                                |
| `scheduled_start_at`            | TIMESTAMPTZ | NOT NULL                                |
| `scheduled_end_at`              | TIMESTAMPTZ | NOT NULL                                |
| `primary_veterinarian_id`       | UUID        | FK → hr.employees, NULL                 |
| `appointment_reason`      | TEXT        | NULL                   |
| `booking_channel`         | ENUM        | NOT NULL               |
| `booking_status`          | ENUM        | NOT NULL               |
| `confirmation_status`     | ENUM        | NOT NULL               |
| `internal_notes`          | TEXT        | NULL                   |
| `customer_notes`          | TEXT        | NULL                   |
| `created_at`              | TIMESTAMPTZ | NOT NULL               |
| `updated_at`              | TIMESTAMPTZ | NULL                   |
| `created_by`              | UUID        | NOT NULL               |
| `updated_by`              | UUID        | NULL                   |

#### ข้อกำหนด:

- `appointment_id`: รหัสประจำรายการนัดหมาย ใช้เป็น Primary Key
- `appointment_number`: เลขที่นัดหมายที่แสดงให้พนักงานและลูกค้า ใช้วิธีกำหนดเป็น `APT-{YYYY}{MM}{DD}-{NNNN}` โดยที่:
  - `{YYYY}{MM}{DD}` คือวันที่ตามปฏิทิน ค.ศ.
  - `{NNNN}` คือ ตัวเลขที่เพิ่มขึ้นอัตโนมัติ เช่น 0001 - 9999 และ Reset เป็น 0000 ทุกวันที่ 1 เที่ยงคืนของทุกเดือน
- `rescheduled_from_appointment_id`: รหัสนัดหมายเดิมที่ถูกเลื่อนนัดมาเป็นรายการนี้ อ้างอิง `appointment.appointments` (เป็น `NULL` หากเป็นการสร้างนัดหมายใหม่ที่ไม่ใช่การเลื่อนนัด)
- `branch_id`: รหัสสาขาที่ลูกค้าต้องการเข้ารับบริการ อ้างอิงจาก `core.branches`
- `owner_id`: รหัสลูกค้าที่เป็นเจ้าของสัตว์เลี้ยง อ้างอิงจาก `owner.owners`
- `pet_id`: รหัสสัตว์เลี้ยงที่ต้องการเข้ารับบริการ อ้างอิงจาก `owner.pets`
- `appointment_type`: ประเภทการนัดหมายที่คลินิกสัตวแพทย์ต้องรองรับ ค่าที่เป็นไปได้ คือ
  - `CONSULTATION`: นัดตรวจและปรึกษาสัตวแพทย์
  - `HEALTH_CHECK`: นัดตรวจสุขภาพ
  - `VACCINATION`: นัดฉีดวัคซีน
  - `FOLLOW_UP`: นัดติดตามผลการรักษา
  - `MEDICAL_TREATMENT`: นัดเข้ารับการรักษา
  - `SURGERY`: นัดผ่าตัด
  - `LABORATORY`: นัดตรวจทางห้องปฏิบัติการ
  - `DIAGNOSTIC_IMAGING`: นัดตรวจวินิจฉัยด้วยภาพ
  - `DENTAL`: นัดทำทันตกรรม
  - `WOUND_CARE`: นัดทำแผล
  - `GROOMING`: นัดอาบน้ำและตัดแต่งขน
  - `OTHER`: นัดรับบริการประเภทอื่น
- `appointment_date`: วันที่นัดหมายตามเวลาท้องถิ่นของสาขา
- `scheduled_start_at`: เวลาที่กำหนดให้เริ่มรับบริการ
- `scheduled_end_at`: เวลาสิ้นสุดที่คาดการณ์
- `primary_veterinarian_id`: สัตวแพทย์หลักที่ได้รับมอบหมาย อ้างอิง `hr.employees`
- `appointment_reason`: เหตุผลในการนัด วัตถุประสงค์หรืออาการเบื้องต้น
- `booking_channel`: ค่าที่เป็นไปได้ คือ
  - `COUNTER`: จองผ่านพนักงานหน้าเคาน์เตอร์
  - `CALL_CENTER`: จองผ่านเจ้าหน้าที่บริการลูกค้า
  - `LINE_OA`: จองผ่าน LINE Official Account
  - `WEBSITE`: จองผ่านเว็บไซต์
  - `SOCIAL_MEDIA`: จองผ่านสื่อสังคมออนไลน์
- `booking_status`: สถานะการนัดหมายล่าสุด ค่าที่เป็นไปได้ คือ
  - `PENDING_CONFIRMATION`: สร้างนัดหมายแล้ว รอการยืนยัน
  - `CONFIRMED`: ยืนยันนัดหมายแล้ว
  - `CHECKED_IN`: เจ้าของและสัตว์เลี้ยงมาถึงแล้ว
  - `IN_SERVICE`: กำลังรับบริการ
  - `COMPLETED`: รับบริการเสร็จสิ้น
  - `CANCELLED`: ยกเลิกนัดหมาย
  - `NO_SHOW`: ลูกค้าไม่มาตามนัด
  - `RESCHEDULED`: นัดหมายถูกเลื่อนหรือเปลี่ยนกำหนด
- `confirmation_status`: สถานะการยืนยันนัดหมายปัจจุบัน
  - `PENDING`: รอการยืนยัน
  - `CONFIRMED`: ลูกค้ายืนยันแล้ว
  - `DECLINED`: ลูกค้าปฏิเสธ
  - `NO_RESPONSE`: ไม่มีการตอบกลับ
  - `UNDELIVERABLE`: ไม่สามารถติดต่อเพื่อยืนยันได้
- `internal_notes`: หมายเหตุภายในสำหรับเจ้าหน้าที่
- `customer_notes`: ข้อความหรือคำขอจากเจ้าของ
- `created_at`: เวลา/วันที่ที่สร้าง
- `updated_at`: เวลา/วันที่ที่แก้ไขล่าสุด
- `created_by`: รหัสประจำตัวผู้สร้าง หากเจ้าหน้าที่หน้าเคาน์เตอร์จะใช้ `employee_id` หากมาจากเจ้าของจะใช้ `owner_id`
- `updated_by`: รหัสประจำตัวผู้แก้ไข หากเจ้าหน้าที่หน้าเคาน์เตอร์จะใช้ `employee_id` หากมาจากเจ้าของจะใช้ `owner_id`

#### หมายเหตุ:

1. สถานะ `RESCHEDULED` ใช้ระบุรายการเดิมที่ถูกเปลี่ยนวันหรือเวลา โดยรายการใหม่จะมี `appointment_id` ของตัวเอง และเชื่อมโยงกลับมายังรายการเดิมผ่าน `rescheduled_from_appointment_id` (และบันทึกคู่เดิม-ใหม่ใน `appointment_modifications.new_appointment_id`)
2. หนึ่งรายการนัดหมายต้องอ้างอิงเจ้าของและสัตว์เลี้ยงที่มีอยู่จริง
3. เจ้าของที่อ้างอิงต้องมีสิทธิ์เป็นเจ้าของหรือผู้ดูแลสัตว์เลี้ยงตามข้อมูลใน Domain 01
4. `scheduled_end_at` ต้องมากกว่า `scheduled_start_at`
5. ต้องตรวจสอบเวลาทำการจาก `core.branch_business_hours`
6. ต้องตรวจสอบวันปิดบริการจาก `core.branch_closures`
7. ต้องตรวจสอบตารางสัตวแพทย์และทรัพยากรก่อนยืนยันการจอง
8. ต้องรองรับการนัดหมายที่ยังไม่กำหนดสัตวแพทย์
9. การยืนยันนัดหมายต้องแยกจากสถานะการนัดหมาย
10. การแก้ไขรายการต้องสร้างประวัติใน `appointment_modifications`
11. การยกเลิกต้องสร้างประวัติใน `appointment_cancellations`

### ตาราง `appointment.appointment_services`

**หน้าที่**: เก็บรายการบริการที่เจ้าของต้องการในแต่ละนัดหมาย ต้องแยกตารางนี้ออกจาก `appointments` เพราะหนึ่งนัดหมายสามารถประกอบด้วยบริการมากกว่าหนึ่งรายการได้

| Column                     | Data Type    | Constraint                              |
| -------------------------- | ------------ | --------------------------------------- |
| `appointment_service_id`   | UUID         | PK, NOT NULL                            |
| `appointment_id`           | UUID         | FK → appointment.appointments, NOT NULL |
| `service_catalog_id`       | UUID         | FK → core.service_catalogs, NOT NULL    |
| `service_name_snapshot`    | VARCHAR(200) | NOT NULL                                |
| `service_code_snapshot`    | VARCHAR(50)  | NOT NULL                                |
| `duration_minutes`         | SMALLINT     | NOT NULL                                |
| `buffer_minutes`           | SMALLINT     | NOT NULL DEFAULT 0                      |
| `service_notes`            | TEXT         | NULL                                    |
| `assigned_veterinarian_id` | UUID         | FK → hr.employees, NULL                 |
| `service_status`           | ENUM         | NOT NULL                                |
| `created_at`               | TIMESTAMPTZ  | NOT NULL                                |
| `created_by`               | UUID         | NOT NULL                                |

#### ข้อกำหนด:

- `appointment_service_id`: รหัสรายการบริการ
- `appointment_id`: นัดหมายที่เป็นเจ้าของรายการ
- `service_catalog_id`: บริการจาก `core.service_catalogs` ไม่สร้างทะเบียนบริการใหม่ใน Appointment
- `service_name_snapshot`: ชื่อบริการ ณ วันที่สร้างนัด เพื่อไม่ให้ชื่อบริการเก่าเปลี่ยนตามการแก้ไข Master Data
- `service_code_snapshot`: รหัสบริการ ณ วันที่สร้างนัด
- `duration_minutes`: ระยะเวลาที่คาดว่าจะใช้ในการวางแผนการนัดหมาย อาจแตกต่างจาก `default_duration_minutes` ใน Core (หรือใช้ค่า Override จาก `appointment.veterinarian_service_capabilities` หากระบุ)
- `buffer_minutes`: เวลาสำรองระหว่างบริการสำหรับเตรียมอุปกรณ์ ทำความสะอาด หรือเตรียมห้อง (ค่าเริ่มต้นดึงจาก `pre_buffer_minutes + post_buffer_minutes` ใน `core.service_catalogs` หรือค่า Override จาก `appointment.veterinarian_service_capabilities`)
- `service_notes`: รายละเอียดเพิ่มเติม
- `assigned_veterinarian_id`: สัตวแพทย์ผู้รับผิดชอบบริการนี้ อ้างอิงจาก `hr.employees` รองรับกรณีหนึ่งนัดหมายมีหลายบริการและแต่ละบริการใช้สัตวแพทย์ต่างกัน
- `service_status`: สถานะบริการ ค่าที่เป็นไปได้ คือ
  - `SCHEDULED`: กำหนดบริการไว้แล้ว
  - `CONFIRMED` : ยืนยันบริการแล้ว
  - `IN_PROGRESS`: กำลังให้บริการ
  - `COMPLETED`: ให้บริการเสร็จสิ้น
  - `CANCELLED`: ยกเลิกบริการ
  - `NOT_PERFORMED`: ไม่ได้ดำเนินการ
- `created_at`: วันที่สร้าง
- `created_by`: ผู้สร้าง

#### หมายเหตุ:

1. หนึ่งนัดหมายมีบริการได้หลายรายการ
2. บริการต้องมีอยู่ใน `core.service_catalogs`
3. ต้องเก็บ Snapshot ของชื่อและรหัสบริการ
4. ระยะเวลาต้องมากกว่า 0
5. การยกเลิกนัดหมายไม่ควรลบรายละเอียดบริการเดิม
6. การกำหนดสัตวแพทย์สามารถทำระดับรายการบริการได้

## กลุ่ม Appointment History

### ตาราง `appointment.appointment_confirmations`

**หน้าที่**: บันทึกประวัติการยืนยันนัดหมายจากเจ้าของสัตว์เลี้ยง ต้องมีตารางนี้แยกต่างหาก เพราะการยืนยันอาจเกิดขึ้นหลายครั้ง และผ่านหลายช่องทาง

#### โครงสร้าง Field:

| Column                 | Data Type    | Constraint                              |
| ---------------------- | ------------ | --------------------------------------- |
| `confirmation_id`      | UUID         | PK                                      |
| `appointment_id`       | UUID         | FK → appointment.appointments, NOT NULL |
| `confirmation_channel` | VARCHAR(30)  | NOT NULL                                |
| `confirmation_status`  | VARCHAR(30)  | NOT NULL                                |
| `requested_at`         | TIMESTAMPTZ  | NOT NULL                                |
| `responded_at`         | TIMESTAMPTZ  | NULL                                    |
| `response_reference`   | VARCHAR(150) | NULL                                    |
| `handled_by`           | UUID         | NULL                                    |
| `response_notes`       | TEXT         | NULL                                    |
| `created_at`           | TIMESTAMPTZ  | NOT NULL                                |

#### ข้อกำหนด:

- `confirmation_id` : รหัสรายการยืนยัน
- `appointment_id` : นัดหมายที่ต้องการยืนยัน อ้างอิงจาก `appointment.appointments`
- `confirmation_channel` : ช่องทางที่ใช้ยืนยัน ใช้ค่าเดียวกับช่องทางการติดต่อที่ระบบรองรับ ได้แก่
  - `COUNTER`: ผ่านพนักงานหน้าเคาน์เตอร์
  - `CALL_CENTER`: ผ่านเจ้าหน้าที่บริการลูกค้า
  - `LINE_OA`: ผ่าน LINE Official Account
  - `WEBSITE`: ผ่านเว็บไซต์
  - `SOCIAL_MEDIA`: ผ่านสื่อสังคมออนไลน์
- `confirmation_status` : ผลการยืนยัน
  - `PENDING`: รอดำเนินการ
  - `CONFIRMED`: ยืนยันแล้ว
  - `DECLINED`: ปฏิเสษ
  - `NO_RESPONSE`: ไม่มีการตอบกลับ
  - `UNDELIVERABLE`: ไม่สามารถติดต่อเพื่อยืนยันได้
- `requested_at` : เวลาที่ส่งคำขอยืนยัน
- `responded_at` : เวลาที่เจ้าของตอบกลับ
- `response_reference` : รหัสอ้างอิงจากผู้ให้บริการข้อความ
- `handled_by` : พนักงานผู้ดำเนินการ
- `response_notes` : หมายเหตุ
- `created_at` : วันที่สร้าง

#### หมายเหตุ:

- หนึ่งนัดหมายสามารถมีประวัติการยืนยันได้หลายรายการ
- ทุกครั้งที่เจ้าของตอบกลับต้องเก็บประวัติ
- ห้ามลบประวัติการยืนยันเดิม
- `appointments.confirmation_status` เป็นสถานะปัจจุบัน ส่วนตารางนี้เป็นประวัติเหตุการณ์
- ไม่ควรยกเลิกนัดหมายโดยอัตโนมัติเพียงเพราะไม่มีการตอบกลับ เว้นแต่มีนโยบายกำหนดไว้

### ตาราง `appointment.appointment_modifications`

**หน้าที่**: บันทึกประวัติการเปลี่ยนแปลงนัดหมาย เช่น เปลี่ยนวันที่ เวลา สาขา สัตวแพทย์ หรือรายละเอียดบริการ

#### โครงสร้าง Field:

| Column                 | Data Type   | Constraint                              |
| ---------------------- | ----------- | --------------------------------------- |
| `modification_id`      | UUID        | PK                                      |
| `appointment_id`       | UUID        | FK → appointment.appointments, NOT NULL |
| `modification_type`    | ENUM        | NOT NULL                                |
| `old_branch_id`        | UUID        | FK → core.branches, NULL                |
| `new_branch_id`        | UUID        | FK → core.branches, NULL                |
| `old_appointment_date` | DATE        | NULL                                    |
| `new_appointment_date` | DATE        | NULL                                    |
| `old_start_at`         | TIMESTAMPTZ | NULL                                    |
| `new_start_at`         | TIMESTAMPTZ | NULL                                    |
| `old_end_at`           | TIMESTAMPTZ | NULL                                    |
| `new_end_at`           | TIMESTAMPTZ | NULL                                    |
| `old_veterinarian_id`  | UUID        | FK → hr.employees, NULL                 |
| `new_veterinarian_id`  | UUID        | FK → hr.employees, NULL                 |
| `old_booking_status`   | ENUM        | NULL                                    |
| `new_booking_status`   | ENUM        | NULL                                    |
| `new_appointment_id`   | UUID        | FK → appointment.appointments, NULL     |
| `modification_reason`  | TEXT        | NOT NULL                                |
| `requested_by_type`    | ENUM        | NOT NULL                                |
| `requested_by_id`      | UUID        | NULL                                    |
| `modified_by`          | UUID        | NOT NULL                                |
| `modified_at`          | TIMESTAMPTZ | NOT NULL                                |
| `metadata`             | JSONB       | NULL                                    |

#### ข้อกำหนด:

- `modification_id`: รหัสประวัติการเปลี่ยนแปลง
- `appointment_id`: นัดหมายที่ถูกเปลี่ยนแปลง อ้างอิงจาก `appointment.appointments`
- `modification_type`: ประเภทการเปลี่ยนแปลง ค่าที่เป็นไปได้
  - `RESCHEDULE` เปลี่ยนวันหรือเวลา
  - `BRANCH_CHANGE` เปลี่ยนสาขา
  - `VETERINARIAN_CHANGE` เปลี่ยนสัตวแพทย์
  - `SERVICE_CHANGE` เปลี่ยนรายการบริการ
  - `DETAIL_UPDATE` เปลี่ยนรายละเอียดอื่น
  - `STATUS_CHANGE` เปลี่ยนสถานะ
- `old_branch_id`: สาขาเดิม อ้างอิงจาก `core.branches`
- `new_branch_id`: สาขาใหม่ อ้างอิงจาก `core.branches`
- `old_appointment_date`: วันที่นัดเดิม
- `new_appointment_date`: วันที่นัดใหม่

- `room_code`: รหัสห้องที่ใช้ระบุและค้นหาภายในสาขา เช่น `EXAM-01`, `SURG-01` โดยต้องไม่ซ้ำกันภายในสาขาเดียวกัน
- `room_name`: ชื่อห้องที่แสดงให้พนักงานเห็น เช่น ห้องตรวจ 1 ห้องผ่าตัด ห้องพักฟื้น
- `room_type`: ประเภทของห้องที่คลินิกสัตวแพทย์ต้องรองรับ ค่าที่เป็นไปได้ คือ

  - `RECOVERY`: ห้องพักฟื้น ใช้สำหรับดูแลสัตว์หลังผ่าตัดหรือหลังทำหัตถการ
  - `DIAGNOSTIC`: ห้องตรวจวินิจฉัย ใช้สำหรับตรวจด้วยเครื่องมือหรืออุปกรณ์วินิจฉัย
  - `TREATMENT`: ห้องทำหัตถการ ใช้สำหรับทำแผล ฉีดยา ให้น้ำเกลือ และการรักษาทั่วไป
  - `GROOMING`: ห้องอาบน้ำและตัดแต่งขน ใช้สำหรับบริการ Grooming
- `floor_number`: ชั้นหรือพื้นที่ตั้งของห้อง ใช้ช่วยระบุตำแหน่งภายในอาคาร
- `capacity`: จำนวนสัตว์เลี้ยงสูงสุดที่สามารถรองรับได้พร้อมกัน ต้องมากกว่า 0
- `description`: รายละเอียดเพิ่มเติมเกี่ยวกับห้อง เช่น ข้อจำกัดการใช้งาน อุปกรณ์ประจำห้อง หรือคำแนะนำสำหรับเจ้าหน้าที่
- `status`: สถานะการใช้งานของห้อง ค่าที่เป็นไปได้ คือ
  - `ACTIVE`: เปิดใช้งาน ห้องพร้อมสำหรับการจองและจัดสรร
  - `INACTIVE`: ปิดใช้งาน ห้องไม่สามารถนำไปจัดสรรสำหรับรายการใหม่
  - `MAINTENANCE`: อยู่ระหว่างซ่อมบำรุง ห้องไม่พร้อมให้บริการชั่วคราว
  - `UNAVAILABLE`: ไม่สามารถใช้งานได้ เช่น ห้องชำรุดหรือมีเหตุขัดข้อง
- `created_at`: วันและเวลาที่สร้างข้อมูลห้อง
- `updated_at`: วันและเวลาที่แก้ไขข้อมูลล่าสุด
- `created_by`: รหัสผู้สร้างข้อมูล
- `updated_by`: รหัสผู้แก้ไขข้อมูลล่าสุด

#### หมายเหตุ:

1. `room_code` ต้องไม่ซ้ำกันภายในสาขาเดียวกัน โดยกำหนด Unique Constraint แบบ `(branch_id, room_code)`
2. หนึ่งสาขาสามารถมีห้องให้บริการได้หลายห้อง
3. ห้องหนึ่งห้องสามารถถูกจองได้หลายรายการ แต่ช่วงเวลาการจองต้องไม่ทับซ้อนกัน เว้นแต่ระบบจะรองรับการใช้ห้องร่วมกันตาม `capacity` และนโยบายของคลินิก
4. ห้องที่มีประวัติการจองแล้วห้ามลบข้อมูลจริง ให้เปลี่ยน `status` เป็น `INACTIVE` แทน
5. ห้องที่อยู่ในสถานะ `MAINTENANCE` หรือ `UNAVAILABLE` ต้องไม่สามารถสร้างการจองใหม่ในช่วงเวลาที่ไม่พร้อมใช้งานได้
6. การเปลี่ยนสถานะห้องต้องไม่ลบประวัติการจองเดิม
7. ตารางนี้เป็นทะเบียนห้องที่ใช้ในกระบวนการนัดหมาย ส่วนข้อมูลทรัพย์สิน อุปกรณ์ประจำห้อง และการบำรุงรักษาเชิงสินทรัพย์ควรเป็นความรับผิดชอบของ Domain ที่ดูแล Facility หรือ Asset Management หากมีการแยก Domain ดังกล่าว

### ตาราง `appointment.room_availabilities`

**หน้าที่**: จัดเก็บช่วงเวลาที่ห้องแต่ละห้องสามารถเปิดให้บริการได้ เพื่อให้ระบบตรวจสอบความพร้อมของห้องก่อนจองทรัพยากร โดยรองรับทั้งเวลาว่างตามตารางประจำสัปดาห์และเวลาว่างเฉพาะวันที่กำหนด

| Column                 | Data Type   | Constraint                       |
| ---------------------- | ----------- | -------------------------------- |
| `room_availability_id` | UUID        | PK, NOT NULL                     |
| `room_id`              | UUID        | FK → appointment.rooms, NOT NULL |
| `availability_type`    | ENUM        | NOT NULL                         |
| `day_of_week`          | SMALLINT    | NULL                             |
| `available_date`       | DATE        | NULL                             |
| `start_time`           | TIME        | NOT NULL                         |
| `end_time`             | TIME        | NOT NULL                         |
| `effective_from`       | DATE        | NULL                             |
| `effective_to`         | DATE        | NULL                             |
| `status`               | ENUM        | NOT NULL                         |
| `notes`                | TEXT        | NULL                             |
| `created_at`           | TIMESTAMPTZ | NOT NULL                         |
| `updated_at`           | TIMESTAMPTZ | NULL                             |
| `created_by`           | UUID        | NOT NULL                         |
| `updated_by`           | UUID        | NULL                             |

#### ข้อกำหนด:

- `room_availability_id`: รหัสประจำช่วงเวลาที่ห้องพร้อมให้บริการ
- `room_id`: ห้องที่กำหนดช่วงเวลาว่าง อ้างอิงจาก `appointment.rooms`
- `availability_type`: ประเภทการกำหนดเวลาว่าง ค่าที่เป็นไปได้ คือ
  - `RECURRING`: ตารางเวลาประจำ เกิดซ้ำตามวันในสัปดาห์ เช่น ห้องตรวจเปิดให้บริการทุกวันจันทร์ถึงวันเสาร์
  - `SPECIFIC_DATE`: ตารางเวลาเฉพาะวันที่ กำหนดช่วงเวลาว่างสำหรับวันใดวันหนึ่งโดยเฉพาะ
- `day_of_week`: วันในสัปดาห์ ใช้สำหรับ `RECURRING` โดยกำหนดค่า
  - `1`: วันจันทร์
  - `2`: วันอังคาร
  - `3`: วันพุธ
  - `4`: วันพฤหัสบดี
  - `5`: วันศุกร์
  - `6`: วันเสาร์
  - `7`: วันอาทิตย์
- `available_date`: วันที่กำหนดเวลาว่าง ใช้สำหรับ `SPECIFIC_DATE`
- `start_time`: เวลาเริ่มต้นที่ห้องพร้อมให้บริการ
- `end_time`: เวลาสิ้นสุดที่ห้องพร้อมให้บริการ
- `effective_from`: วันที่เริ่มมีผลของตารางเวลาประจำ ใช้สำหรับ `RECURRING`
- `effective_to`: วันที่สิ้นสุดผลบังคับของตารางเวลาประจำ ใช้สำหรับ `RECURRING` หากเป็น `NULL` หมายถึงยังไม่มีวันที่สิ้นสุด
- `status`: สถานะของช่วงเวลาว่าง ค่าที่เป็นไปได้ คือ
  - `ACTIVE`: เปิดใช้งานช่วงเวลาว่าง ระบบสามารถนำช่วงเวลาดังกล่าวไปใช้ตรวจสอบและจองห้องได้
  - `INACTIVE`: ปิดใช้งานช่วงเวลาว่าง ไม่อนุญาตให้นำไปใช้กับการจองใหม่
- `notes`: หมายเหตุเพิ่มเติม เช่น ห้องเปิดเฉพาะการตรวจสุขภาพ หรือห้องไม่รองรับสัตว์ขนาดใหญ่
- `created_at`: วันและเวลาที่สร้างข้อมูล
- `updated_at`: วันและเวลาที่แก้ไขล่าสุด
- `created_by`: ผู้สร้างข้อมูล
- `updated_by`: ผู้แก้ไขข้อมูลล่าสุด

#### หมายเหตุ:

1. หาก `availability_type` เป็น `RECURRING` ต้องกำหนด `day_of_week` และ `effective_from` โดย `available_date` ต้องเป็น `NULL`
2. หาก `availability_type` เป็น `SPECIFIC_DATE` ต้องกำหนด `available_date` โดย `day_of_week`, `effective_from` และ `effective_to` ต้องเป็น `NULL`
3. `end_time` ต้องมากกว่า `start_time`
4. `effective_to` ต้องไม่ก่อน `effective_from`
5. หนึ่งห้องสามารถมีช่วงเวลาว่างได้หลายช่วงในวันเดียวกัน แต่ช่วงเวลาที่เปิดให้บริการต้องไม่ซ้อนทับกันโดยไม่ตั้งใจ
6. ตารางนี้ระบุช่วงเวลาที่ห้องมีสิทธิ์เปิดให้ใช้งาน ไม่ได้หมายความว่าห้องว่างจริงในเวลานั้น ระบบต้องตรวจสอบ `resource_reservations` เพิ่มเติมก่อนยืนยันการจอง
7. หากห้องถูกปิดซ่อมบำรุงหรือไม่พร้อมใช้งาน ต้องปิดช่วงเวลาว่างที่เกี่ยวข้องหรือใช้การจองทรัพยากรเพื่อปิดกั้นช่วงเวลาดังกล่าวตามนโยบายของระบบ
8. การเปลี่ยนแปลงตารางเวลาต้องไม่กระทบการจองที่ได้รับการยืนยันไปแล้วโดยไม่มีการตรวจสอบผลกระทบ

### ตาราง `appointment.resource_reservations`

**หน้าที่**: จัดเก็บข้อมูลการจองทรัพยากรที่ใช้ในการให้บริการตามนัดหมาย เช่น ห้องตรวจและสัตวแพทย์ เพื่อป้องกันการจัดสรรทรัพยากรซ้ำซ้อนในช่วงเวลาเดียวกัน และใช้ตรวจสอบความพร้อมของทรัพยากรก่อนยืนยันหรือเปลี่ยนแปลงนัดหมาย

| Column                   | Data Type   | Constraint                                  |
| ------------------------ | ----------- | ------------------------------------------- |
| `reservation_id`         | UUID        | PK, NOT NULL                                |
| `appointment_id`         | UUID        | FK → appointment.appointments, NOT NULL     |
| `appointment_service_id` | UUID        | FK → appointment.appointment_services, NULL |
| `room_id`                | UUID        | FK → appointment.rooms, NULL                |
| `veterinarian_id`        | UUID        | FK → hr.employees, NULL                     |
| `reservation_type`       | ENUM        | NOT NULL                                    |
| `reserved_start_at`      | TIMESTAMPTZ | NOT NULL                                    |
| `reserved_end_at`        | TIMESTAMPTZ | NOT NULL                                    |
| `reservation_status`     | ENUM        | NOT NULL                                    |
| `released_at`            | TIMESTAMPTZ | NULL                                        |
| `release_reason`         | TEXT        | NULL                                        |
| `notes`                  | TEXT        | NULL                                        |
| `created_at`             | TIMESTAMPTZ | NOT NULL                                    |
| `created_by`             | UUID        | NOT NULL                                    |
| `updated_at`             | TIMESTAMPTZ | NULL                                        |
| `updated_by`             | UUID        | NULL                                        |

#### ข้อกำหนด:

- `reservation_id`: รหัสประจำรายการจองทรัพยากร
- `appointment_id`: นัดหมายที่ต้องการใช้ทรัพยากร อ้างอิงจาก `appointment.appointments`
- `appointment_service_id`: รายการบริการที่ต้องใช้ทรัพยากร อ้างอิงจาก `appointment.appointment_services` หากเป็นการจองทรัพยากรในระดับนัดหมายโดยรวมสามารถเป็น `NULL` ได้
- `room_id`: ห้องที่ถูกจอง อ้างอิงจาก `appointment.rooms` หากรายการนี้เป็นการจองสัตวแพทย์โดยไม่ต้องจองห้องให้เป็น `NULL`
- `veterinarian_id`: สัตวแพทย์ที่ถูกจอง อ้างอิงจาก `hr.employees` หากรายการนี้เป็นการจองห้องโดยไม่ต้องกำหนดสัตวแพทย์ให้เป็น `NULL`
- `reservation_type`: ประเภททรัพยากรที่ถูกจอง ค่าที่เป็นไปได้ คือ
  - `ROOM`: การจองห้องให้บริการ โดยต้องกำหนด `room_id` และ `veterinarian_id` ต้องเป็น `NULL`
  - `VETERINARIAN`: การจองเวลาของสัตวแพทย์ โดยต้องกำหนด `veterinarian_id` และ `room_id` ต้องเป็น `NULL`
- `reserved_start_at`: วันและเวลาเริ่มต้นที่ทรัพยากรถูกจอง
- `reserved_end_at`: วันและเวลาสิ้นสุดที่ทรัพยากรถูกจอง ต้องมากกว่า `reserved_start_at`
- `reservation_status`: สถานะการจองทรัพยากร ค่าที่เป็นไปได้ คือ
  - `TENTATIVE`: จองชั่วคราวเพื่อรอตรวจสอบหรือยืนยันนัดหมาย
  - `CONFIRMED`: ยืนยันการจองทรัพยากรแล้ว
  - `IN_USE`: ทรัพยากรกำลังถูกใช้งาน
  - `COMPLETED`: ใช้ทรัพยากรเสร็จสิ้น
  - `RELEASED`: คืนทรัพยากรแล้ว สามารถนำไปจัดสรรให้รายการอื่นได้
  - `CANCELLED`: ยกเลิกการจองทรัพยากร
- `released_at`: วันและเวลาที่คืนหรือปล่อยทรัพยากร
- `release_reason`: เหตุผลในการคืนทรัพยากร เช่น ยกเลิกนัดหมาย เปลี่ยนห้อง หรือสัตวแพทย์ไม่สามารถปฏิบัติงานได้
- `notes`: หมายเหตุเพิ่มเติม
- `created_at`: วันและเวลาที่สร้างรายการจอง
- `created_by`: ผู้สร้างรายการจอง
- `updated_at`: วันและเวลาที่แก้ไขล่าสุด
- `updated_by`: ผู้แก้ไขล่าสุด

#### หมายเหตุ:

1. หนึ่งนัดหมายสามารถมีการจองทรัพยากรได้หลายรายการ
2. หนึ่งรายการบริการสามารถใช้ทรัพยากรได้มากกว่าหนึ่งประเภท เช่น ใช้ทั้งห้องตรวจและสัตวแพทย์
3. ต้องกำหนด `CHECK` Constraint ให้มีการระบุทรัพยากรเพียงชนิดเดียวตาม `reservation_type` ดังนี้
   - `ROOM` ต้องมี `room_id` และไม่มี `veterinarian_id`
   - `VETERINARIAN` ต้องมี `veterinarian_id` และไม่มี `room_id`
4. ต้องตรวจสอบช่วงเวลาซ้อนทับของทรัพยากร โดยเฉพาะรายการที่มีสถานะ `TENTATIVE`, `CONFIRMED` และ `IN_USE`
5. รายการที่มีสถานะ `RELEASED`, `CANCELLED` หรือ `COMPLETED` ไม่ควรถูกนับเป็นการจองที่กีดกันช่วงเวลาใหม่
6. เมื่อมีการยืนยันนัดหมาย ต้องเปลี่ยนรายการจองที่เกี่ยวข้องเป็น `CONFIRMED` ภายใน Transaction เดียวกัน
7. เมื่อยกเลิกหรือเลื่อนนัดหมาย ต้องจัดการการจองทรัพยากรเดิมและสร้างรายการจองใหม่ภายในกระบวนการที่ตรวจสอบความถูกต้องได้
8. ตารางนี้กำหนดให้จองเฉพาะห้องและสัตวแพทย์ หากต้องการจองเครื่องมือแพทย์หรืออุปกรณ์เฉพาะทาง ควรเพิ่มทะเบียนทรัพยากรประเภทอุปกรณ์และความสัมพันธ์แบบ Foreign Key ที่ชัดเจน ไม่ควรใช้ `resource_type` คู่กับ `resource_id` แบบ Polymorphic โดยไม่มี Foreign Key ตรวจสอบ

### ตาราง `appointment.veterinarian_schedule_exceptions`

- `exception_type`: ประเภทการกันเวลาหรือข้อยกเว้นตารางนัดหมาย ค่าที่เป็นไปได้ คือ
  - `EMERGENCY_BUFFER`: ช่วงเวลาสำรองสำหรับกรณีฉุกเฉิน/Walk-in เร่งด่วน (ห้ามจองออนไลน์ทั่วไป)
  - `SURGERY_BLOCK`: ช่วงเวลาที่กันไว้สำหรับงานผ่าตัดหรืองานหัตถการเฉพาะ
  - `MEETING_BLOCK`: ช่วงเวลาประชุม อบรม หรือประสานงานภายในคลินิก
  - `BREAK`: ช่วงพักเบรกหรือพักกลางวันนอกเหนือจากกะมาตรฐาน
  - `NO_BOOKING_SLOT`: ช่วงเวลาที่ปิดรับการจองล่วงหน้า
  - `UNAVAILABLE`: ไม่พร้อมรับบริการเฉพาะกิจในช่วงเวลาที่กำหนด
  - `EXTRA_OPEN_SLOT`: การเปิดสล็อตเวลาพิเศษเพิ่มเติมให้นัดหมายได้
- `exception_date`: วันที่ที่มีผลตามเวลาท้องถิ่นของสาขา
- `start_at`: วันและเวลาเริ่มต้นของข้อยกเว้น
- `end_at`: วันและเวลาสิ้นสุดของข้อยกเว้น (ต้องมากกว่า `start_at`)
- `max_concurrent_slots`: จำนวนนัดหมายสูงสุดที่อนุญาตในช่วงเวลานี้ (กำหนดเป็น `0` เมื่อต้องการบล็อกหรือปิดรับนัดหมายโดยสมบูรณ์ และมากกว่า `0` เมื่อใช้จำกัด/เปิดสล็อตเฉพาะกิจ)
- `reason`: เหตุผลหรือคำอธิบายเพิ่มเติมสำหรับเจ้าหน้าที่
- `status`: สถานะของข้อยกเว้น ค่าที่เป็นไปได้คือ `ACTIVE` (มีผลบังคับใช้อยู่) และ `CANCELLED` (ยกเลิกข้อยกเว้นแล้ว)
- `created_at`: วันและเวลาที่สร้างรายการ
- `created_by`: ผู้สร้างรายการ อ้างอิง `hr.employees`
- `updated_at`: วันและเวลาที่แก้ไขล่าสุด
- `updated_by`: ผู้แก้ไขล่าสุด อ้างอิง `hr.employees`

#### หมายเหตุ:

1. กะการทำงานปกติ วันหยุด และใบลาของพนักงานยังคงอยู่ในความรับผิดชอบของ Domain 10 (HR & Workforce) โดยระบบจองเวลาของ Domain 02 ต้องตรวจสอบ HR Base Schedule ร่วมกับตารางนี้ และ `appointment.resource_reservations`
2. `end_at` ต้องมากกว่า `start_at` และ `max_concurrent_slots` ต้องมากกว่าหรือเท่ากับ 0
3. ช่วงเวลาที่เป็น `EMERGENCY_BUFFER` หรือ `NO_BOOKING_SLOT` ที่ `ACTIVE` และ `max_concurrent_slots = 0` ต้องถูกปิดกั้นไม่ให้ลูกค้าจองผ่านช่องทาง Online/Self-service

## กลุ่ม Waiting List Management

### ตาราง `appointment.appointment_waitlists`

**หน้าที่**: จัดเก็บรายการลูกค้าและสัตว์เลี้ยงที่ต้องการเข้ารับบริการ แต่ยังไม่สามารถกำหนดวันหรือเวลานัดหมายได้ตามความต้องการ เช่น ตารางสัตวแพทย์เต็ม ห้องตรวจไม่ว่าง หรือเจ้าของต้องการรอคิวที่เร็วกว่าเวลานัดหมายปัจจุบัน

| Column                      | Data Type    | Constraint                          |
| --------------------------- | ------------ | ----------------------------------- |
| `waitlist_id`               | UUID         | PK, NOT NULL                        |
| `waitlist_number`           | VARCHAR(30)  | UNIQUE, NOT NULL                    |
| `branch_id`                 | UUID         | FK → core.branches, NOT NULL        |
| `owner_id`                  | UUID         | FK → owner.owners, NOT NULL         |
| `pet_id`                    | UUID         | FK → owner.pets, NOT NULL           |
| `service_catalog_id`        | UUID         | FK → core.service_catalogs, NULL    |
| `preferred_veterinarian_id` | UUID         | FK → hr.employees, NULL             |
| `preferred_start_date`      | DATE         | NOT NULL                            |
| `preferred_end_date`        | DATE         | NOT NULL                            |
| `preferred_time_period`     | ENUM         | NOT NULL                            |
| `priority_level`            | ENUM         | NOT NULL                            |
| `waitlist_status`           | ENUM         | NOT NULL                            |
| `contact_channel`           | ENUM         | NOT NULL                            |
| `contact_recipient`         | VARCHAR(255) | NOT NULL                            |
| `request_reason`            | TEXT         | NULL                                |
| `expires_at`                | TIMESTAMPTZ  | NOT NULL                            |
| `converted_appointment_id`  | UUID         | FK → appointment.appointments, NULL |
| `created_at`                | TIMESTAMPTZ  | NOT NULL                            |
| `created_by`                | UUID         | NOT NULL                            |
| `updated_at`                | TIMESTAMPTZ  | NULL                                |
| `updated_by`                | UUID         | NULL                                |

#### ข้อกำหนด:

- `waitlist_id`: รหัสประจำรายการ Waiting List ใช้เป็น Primary Key
- `waitlist_number`: เลขที่รายการรอคิว ใช้สำหรับค้นหาและติดตามรายการ โดยกำหนดรูปแบบ `WLT-{YYYY}{MM}{DD}-{NNNN}` โดย `{YYYY}{MM}{DD}` คือวันที่สร้างรายการตามปฏิทิน ค.ศ. และ `{NNNN}` คือลำดับรายการในวันนั้น
- `branch_id`: สาขาที่เจ้าของต้องการเข้ารับบริการ อ้างอิงจาก `core.branches`
- `owner_id`: เจ้าของสัตว์เลี้ยง อ้างอิงจาก `owner.owners`
- `pet_id`: สัตว์เลี้ยงที่ต้องการเข้ารับบริการ อ้างอิงจาก `owner.pets`
- `service_catalog_id`: บริการที่ต้องการเข้ารับบริการ อ้างอิงจาก `core.service_catalogs` หากยังไม่สามารถระบุบริการได้สามารถเป็น `NULL`
- `preferred_veterinarian_id`: สัตวแพทย์ที่เจ้าของต้องการเข้ารับบริการ อ้างอิงจาก `hr.employees` หากไม่ระบุ หมายถึงยอมรับสัตวแพทย์ที่มีความพร้อม
- `preferred_start_date`: วันที่เริ่มต้นที่เจ้าของสะดวกเข้ารับบริการ
- `preferred_end_date`: วันที่สิ้นสุดของช่วงวันที่เจ้าของสะดวกเข้ารับบริการ
- `preferred_time_period`: ช่วงเวลาที่เจ้าของสะดวกเข้ารับบริการ ค่าที่เป็นไปได้ คือ
  - `MORNING`: ช่วงเช้า
  - `AFTERNOON`: ช่วงบ่าย
  - `EVENING`: ช่วงเย็น
  - `ANYTIME`: เวลาใดก็ได้ภายในเวลาทำการของสาขา
- `priority_level`: ระดับความสำคัญของรายการรอคิว ค่าที่เป็นไปได้ คือ
  - `LOW`: ความสำคัญต่ำ เจ้าของสามารถรอได้โดยไม่มีข้อจำกัดด้านเวลา
  - `NORMAL`: ความสำคัญปกติ ใช้เป็นระดับมาตรฐานของรายการ Waiting List
  - `HIGH`: ความสำคัญสูง เจ้าของต้องการเข้ารับบริการโดยเร็ว
  - `URGENT`: เร่งด่วน ต้องได้รับการพิจารณาเพื่อจัดเวลานัดหมายโดยเร็วตามความเหมาะสม
- `waitlist_status`: สถานะรายการ Waiting List ค่าที่เป็นไปได้ คือ
  - `WAITING`: กำลังรอช่วงเวลาว่างที่ตรงกับความต้องการ
  - `NOTIFIED`: แจ้งเจ้าของแล้วว่ามีช่วงเวลาว่างที่สามารถเข้ารับบริการได้
  - `ACCEPTED`: เจ้าของตอบรับช่วงเวลาที่เสนอแล้ว อยู่ระหว่างดำเนินการสร้างนัดหมาย
  - `DECLINED`: เจ้าของปฏิเสธช่วงเวลาที่เสนอ
  - `EXPIRED`: รายการหมดอายุเนื่องจากพ้นกำหนดเวลาที่กำหนด
  - `CONVERTED`: เปลี่ยนรายการ Waiting List เป็นนัดหมายเรียบร้อยแล้ว
  - `CANCELLED`: เจ้าของหรือเจ้าหน้าที่ขอยกเลิกรายการ Waiting List
- `contact_channel`: ช่องทางหลักที่ใช้ติดต่อเจ้าของ ค่าที่เป็นไปได้ คือ
  - `PHONE`: ติดต่อทางโทรศัพท์
  - `SMS`: ติดต่อผ่านข้อความ SMS
  - `LINE_OA`: ติดต่อผ่าน LINE Official Account
  - `EMAIL`: ติดต่อผ่านอีเมล
- `contact_recipient`: หมายเลขโทรศัพท์ บัญชี LINE หรืออีเมลที่ใช้ติดต่อเจ้าของ
- `request_reason`: เหตุผลที่ต้องการเข้ารายการ Waiting List
- `expires_at`: วันและเวลาที่รายการ Waiting List หมดอายุ หากถึงเวลานี้แล้วยังไม่มีการเปลี่ยนเป็นนัดหมาย ระบบต้องจัดการสถานะเป็น `EXPIRED`
- `converted_appointment_id`: รหัสนัดหมายที่สร้างจากรายการ Waiting List อ้างอิงจาก `appointment.appointments`
- `created_at`: วันและเวลาที่สร้างรายการ
- `created_by`: ผู้สร้างรายการ
- `updated_at`: วันและเวลาที่แก้ไขล่าสุด
- `updated_by`: ผู้แก้ไขล่าสุด

#### หมายเหตุ:

1. หนึ่งรายการ Waiting List ต้องอ้างอิงเจ้าของและสัตว์เลี้ยงที่มีอยู่จริง
2. เจ้าของที่อ้างอิงต้องมีสิทธิ์เป็นเจ้าของหรือผู้ดูแลสัตว์เลี้ยงตาม `owner.pet_ownerships`
3. `preferred_end_date` ต้องไม่ก่อน `preferred_start_date`
4. ระบบต้องตรวจสอบตารางนัดหมายและทรัพยากรเมื่อมีช่วงเวลาว่างเกิดขึ้น
5. การแจ้งว่ามีเวลาว่างต้องสร้างประวัติใน `appointment.waitlist_notifications`
6. เจ้าของต้องตอบรับช่วงเวลาที่เสนอภายในระยะเวลาที่กำหนด มิฉะนั้นรายการแจ้งเตือนอาจหมดอายุและระบบสามารถเสนอช่วงเวลานั้นให้ลูกค้ารายอื่นได้
7. เมื่อสร้างนัดหมายสำเร็จ ต้องบันทึก `converted_appointment_id` และเปลี่ยน `waitlist_status` เป็น `CONVERTED`
8. รายการที่มีสถานะ `CONVERTED`, `CANCELLED` หรือ `EXPIRED` ต้องไม่ถูกนำกลับไปเสนอช่วงเวลาว่างใหม่โดยอัตโนมัติ
9. ระดับ `URGENT` ใน Waiting List เป็นเพียงระดับความต้องการจัดนัดหมาย ไม่ใช่ระดับความฉุกเฉินทางการแพทย์ หากสัตว์มีอาการฉุกเฉินต้องเข้าสู่กระบวนการ Triage แยกต่างหาก

- `proposed_start_at`: วันและเวลาเริ่มต้นของช่วงเวลาที่เสนอให้เจ้าของ
- `proposed_end_at`: วันและเวลาสิ้นสุดของช่วงเวลาที่เสนอ
- `proposed_veterinarian_id`: สัตวแพทย์ที่สามารถให้บริการในช่วงเวลาที่เสนอ อ้างอิงจาก `hr.employees`
- `proposed_room_id`: ห้องที่สามารถใช้ให้บริการในช่วงเวลาที่เสนอ อ้างอิงจาก `appointment.rooms`
- `notification_channel`: ช่องทางที่ใช้แจ้งเจ้าของ ค่าที่เป็นไปได้ คือ
  - `PHONE`: ติดต่อทางโทรศัพท์
  - `SMS`: ส่งข้อความ SMS
  - `LINE_OA`: ส่งข้อความผ่าน LINE Official Account
  - `EMAIL`: ส่งอีเมล
- `recipient`: หมายเลขโทรศัพท์ บัญชี LINE หรืออีเมลที่ใช้แจ้งเตือน
- `message_content`: เนื้อหาข้อความที่ส่งให้เจ้าของ โดยควรระบุวัน เวลา สาขา และวิธีตอบรับ
- `sent_at`: วันและเวลาที่ส่งข้อความจริง หากยังไม่ได้ส่งให้เป็น `NULL`
- `response_status`: สถานะการตอบกลับของเจ้าของ ค่าที่เป็นไปได้ คือ
  - `PENDING`: ส่งคำเสนอแล้วและกำลังรอคำตอบ
  - `ACCEPTED`: เจ้าของตอบรับช่วงเวลาที่เสนอ
  - `DECLINED`: เจ้าของปฏิเสธช่วงเวลาที่เสนอ
  - `NO_RESPONSE`: เจ้าของไม่ตอบกลับภายในระยะเวลาที่กำหนด
  - `EXPIRED`: คำเสนอหมดอายุตามเวลาที่กำหนด
  - `FAILED`: ไม่สามารถส่งการแจ้งเตือนไปยังเจ้าของได้
  - `CANCELLED`: ยกเลิกคำเสนอ เนื่องจากช่วงเวลาที่เสนอไม่สามารถใช้งานได้แล้ว
- `responded_at`: วันและเวลาที่เจ้าของตอบกลับ
- `response_notes`: รายละเอียดเพิ่มเติมจากการตอบกลับ
- `expires_at`: วันและเวลาสิ้นสุดการตอบรับคำเสนอ
- `provider_reference`: รหัสอ้างอิงจากผู้ให้บริการข้อความหรือระบบสื่อสาร
- `created_at`: วันและเวลาที่สร้างรายการแจ้งเตือน

#### หมายเหตุ:

1. หนึ่งรายการ Waiting List สามารถมีประวัติการแจ้งเตือนได้หลายรายการ
2. `notification_number` ต้องไม่ซ้ำกันภายใน `waitlist_id` เดียวกัน โดยกำหนด Unique Constraint `(waitlist_id, notification_number)`
3. ช่วงเวลาที่เสนอจะต้องผ่านการตรวจสอบความพร้อมของห้องและสัตวแพทย์ก่อนส่งให้เจ้าของ
4. เมื่อเจ้าของตอบรับ ต้องตรวจสอบทรัพยากรอีกครั้งก่อนสร้างนัดหมาย เพราะช่วงเวลาอาจถูกจองโดยรายการอื่นไปแล้ว
5. การตอบรับคำเสนอไม่ได้หมายความว่านัดหมายถูกสร้างสำเร็จแล้ว จนกว่าระบบจะสร้าง `appointment.appointments` และบันทึก `converted_appointment_id`
6. หากเจ้าของไม่ตอบกลับภายใน `expires_at` ให้เปลี่ยนสถานะเป็น `NO_RESPONSE` หรือ `EXPIRED` ตามผลการดำเนินงาน และอนุญาตให้เสนอช่วงเวลาแก่รายการ Waiting List อื่นได้
7. ห้ามเขียนทับประวัติการแจ้งเตือนเดิมเมื่อมีการเสนอช่วงเวลาใหม่

## กลุ่ม Registration & Check-in Management

### ตาราง `appointment.service_registrations`

**หน้าที่**: จัดเก็บข้อมูลการลงทะเบียนเข้ารับบริการของเจ้าของและสัตว์เลี้ยง ณ สาขาคลินิก ใช้เป็นจุดเริ่มต้นของกระบวนการให้บริการจริง รองรับทั้งลูกค้าที่มีนัดหมายล่วงหน้าและลูกค้าที่เดินเข้ามารับบริการโดยไม่มีนัดหมาย (Walk-in)

| Column                   | Data Type   | Constraint                                  |
| ------------------------ | ----------- | ------------------------------------------- |
| `registration_id`        | UUID        | PK, NOT NULL                                |
| `registration_number`    | VARCHAR(30) | UNIQUE, NOT NULL                            |
| `registration_type`      | ENUM        | NOT NULL                                    |
| `appointment_id`         | UUID        | FK → appointment.appointments, NULL         |
| `appointment_service_id` | UUID        | FK → appointment.appointment_services, NULL |
| `branch_id`              | UUID        | FK → core.branches, NOT NULL                |
| `owner_id`               | UUID        | FK → owner.owners, NOT NULL                 |
| `pet_id`                 | UUID        | FK → owner.pets, NOT NULL                   |
| `chief_complaint`        | TEXT        | NULL                                        |
| `arrival_at`             | TIMESTAMPTZ | NOT NULL                                    |
| `registered_at`          | TIMESTAMPTZ | NOT NULL                                    |
| `registered_by`          | UUID        | NOT NULL                                    |
| `urgency_level`          | ENUM        | NOT NULL                                    |
| `registration_status`    | ENUM        | NOT NULL                                    |
| `notes`                  | TEXT        | NULL                                        |
| `created_at`             | TIMESTAMPTZ | NOT NULL                                    |
| `updated_at`             | TIMESTAMPTZ | NULL                                        |

#### ข้อกำหนด:

- `registration_id`: รหัสประจำรายการลงทะเบียนเข้ารับบริการ
- `registration_number`: เลขที่ลงทะเบียน ใช้ระบุรายการให้บริการ โดยกำหนดรูปแบบ `REG-{YYYY}{MM}{DD}-{NNNN}` โดย `{YYYY}{MM}{DD}` คือวันที่ลงทะเบียนตามปฏิทิน ค.ศ. และ `{NNNN}` คือลำดับรายการในวันนั้น
- `registration_type`: ประเภทการลงทะเบียน ค่าที่เป็นไปได้ คือ
  - `APPOINTMENT`: ลงทะเบียนจากนัดหมายที่มีอยู่ในระบบ
  - `WALK_IN`: ลงทะเบียนโดยไม่มีนัดหมายล่วงหน้า
- `appointment_id`: นัดหมายต้นทาง อ้างอิงจาก `appointment.appointments` กรณีเป็น `APPOINTMENT` ต้องระบุค่า ส่วน `WALK_IN` ให้เป็น `NULL`
- `appointment_service_id`: รายการบริการที่กำลังลงทะเบียน อ้างอิงจาก `appointment.appointment_services` ใช้เมื่อการลงทะเบียนมาจากบริการเฉพาะในนัดหมาย หากเป็น Walk-in หรือเป็นการลงทะเบียนภาพรวมของนัดหมายให้เป็น `NULL`
- `branch_id`: สาขาที่ลูกค้าเข้ารับบริการ อ้างอิงจาก `core.branches`
- `owner_id`: เจ้าของสัตว์เลี้ยง อ้างอิงจาก `owner.owners`
- `pet_id`: สัตว์เลี้ยงที่เข้ารับบริการ อ้างอิงจาก `owner.pets`
- `chief_complaint`: อาการสำคัญหรือเหตุผลหลักที่เจ้าของนำสัตว์เลี้ยงมารับบริการ
- `arrival_at`: วันและเวลาที่เจ้าของและสัตว์เลี้ยงมาถึงสาขา
- `registered_at`: วันและเวลาที่เจ้าหน้าที่ดำเนินการลงทะเบียนเสร็จสิ้น
- `registered_by`: รหัสเจ้าหน้าที่ผู้ดำเนินการลงทะเบียน
- `urgency_level`: ระดับความเร่งด่วนเบื้องต้น ค่าที่เป็นไปได้ คือ
  - `NOT_ASSESSED`: ยังไม่ได้ประเมินระดับความเร่งด่วน
  - `ROUTINE`: อาการทั่วไป สามารถรอรับบริการตามลำดับคิวได้
  - `URGENT`: มีอาการที่ควรได้รับการประเมินหรือดูแลโดยเร็ว
  - `EMERGENCY`: มีภาวะฉุกเฉิน ต้องส่งเข้าสู่กระบวนการคัดกรองเร่งด่วนทันที
  - `CRITICAL`: ภาวะวิกฤตที่อาจเป็นอันตรายต่อชีวิต ต้องเข้าห้องฉุกเฉิน/พบสัตวแพทย์ทันที (สอดคล้องกับ `triage_assessments.urgency_level`)
- `registration_status`: สถานะการลงทะเบียน ค่าที่เป็นไปได้ คือ
  - `REGISTERED`: ลงทะเบียนเรียบร้อยแล้ว
  - `WAITING_TRIAGE`: รอการคัดกรองอาการ
  - `TRIAGE_IN_PROGRESS`: อยู่ระหว่างการคัดกรอง
  - `WAITING_SERVICE`: ผ่านการคัดกรองแล้วและรอรับบริการ
  - `IN_SERVICE`: กำลังรับบริการ
  - `COMPLETED`: กระบวนการให้บริการเสร็จสิ้น
  - `CANCELLED`: ยกเลิกการลงทะเบียน
- `notes`: หมายเหตุเพิ่มเติมสำหรับเจ้าหน้าที่
- `created_at`: วันและเวลาที่สร้างรายการ
- `updated_at`: วันและเวลาที่แก้ไขรายการล่าสุด

#### หมายเหตุ:

1. หนึ่งรายการลงทะเบียนต้องอ้างอิงเจ้าของและสัตว์เลี้ยงที่มีอยู่จริง
2. เจ้าของต้องมีสิทธิ์เป็นเจ้าของหรือผู้ดูแลสัตว์เลี้ยงตาม `owner.pet_ownerships`
3. หาก `registration_type` เป็น `APPOINTMENT` ต้องมี `appointment_id` และหากเป็น `WALK_IN` ต้องไม่มี `appointment_id`
4. ต้องตรวจสอบว่าสัตว์เลี้ยงใน `appointment_id` ตรงกับ `pet_id` และเจ้าของที่ลงทะเบียน
5. หนึ่งนัดหมายสามารถมีการลงทะเบียนได้ตามนโยบายของคลินิก หากนัดหนึ่งรายการประกอบด้วยหลายบริการ ต้องกำหนดให้ชัดเจนว่าจะลงทะเบียนระดับนัดหมายหนึ่งครั้งแล้วแยกบริการ หรือสร้างการลงทะเบียนแยกตามบริการ
6. การลงทะเบียน Walk-in ต้องไม่สร้างข้อมูลนัดหมายย้อนหลังโดยอัตโนมัติ
7. หากมีการประเมินว่าเป็น `CRITICAL` หรือ `EMERGENCY` ต้องเข้าสู่กระบวนการ Triage และส่งพบสัตวแพทย์โดยไม่รอคิวปกติ
8. `urgency_level` เป็นค่าคัดกรองเบื้องต้น ไม่ใช่ผลการวินิจฉัยทางการแพทย์
9. การเปลี่ยนสถานะสำคัญควรบันทึกในตาราง `appointment.service_status_histories`

### ตาราง `appointment.registration_services`

**หน้าที่**: จัดเก็บรายการบริการที่เจ้าของเลือกหรือต้องการรับบริการ ณ จุดลงทะเบียน/Check-in (อ้างอิง `core.service_catalogs`) เพื่อรองรับทั้งลูกค้า Walk-in ที่ไม่มี `appointment_services` มาก่อน และการยืนยัน/เพิ่มรายการบริการในวันที่มาตามนัดหมาย ก่อนส่งต่อไปยังคิว ห้องตรวจ (`clinical.clinical_encounters`) และระบบคิดเงิน (Domain 07)

#### โครงสร้าง Field:

| Column                     | Data Type    | Constraint                                       |
| -------------------------- | ------------ | ------------------------------------------------ |
| `registration_service_id`  | UUID         | PK, NOT NULL                                     |
| `registration_id`          | UUID         | FK → appointment.service_registrations, NOT NULL |
| `appointment_service_id`   | UUID         | FK → appointment.appointment_services, NULL      |
| `service_catalog_id`       | UUID         | FK → core.service_catalogs, NOT NULL             |
| `service_name_snapshot`    | VARCHAR(200) | NOT NULL                                         |
| `service_code_snapshot`    | VARCHAR(50)  | NOT NULL                                         |
| `quantity`                 | SMALLINT     | NOT NULL DEFAULT 1                               |
| `assigned_veterinarian_id` | UUID         | FK → hr.employees, NULL                          |
| `service_status`           | ENUM         | NOT NULL                                         |
| `notes`                    | TEXT         | NULL                                             |
| `created_at`               | TIMESTAMPTZ  | NOT NULL                                         |
| `created_by`               | UUID         | NOT NULL                                         |
| `updated_at`               | TIMESTAMPTZ  | NULL                                             |
| `updated_by`               | UUID         | NULL                                             |

#### ข้อกำหนด:

- `registration_service_id`: รหัสประจำรายการบริการของการลงทะเบียน
- `registration_id`: รหัสการลงทะเบียนที่เป็นเจ้าของรายการ อ้างอิง `appointment.service_registrations`
- `appointment_service_id`: รหัสรายการบริการจากนัดหมายต้นทาง อ้างอิง `appointment.appointment_services` (ระบุเมื่อบริการนี้ดึงมาจากนัดหมายเดิม และเป็น `NULL` สำหรับ Walk-in หรือบริการที่ขอเพิ่มหน้าเคาน์เตอร์)
- `service_catalog_id`: รหัสบริการมาตรฐาน อ้างอิง `core.service_catalogs`
- `service_name_snapshot`: ชื่อบริการ ณ เวลาลงทะเบียนเข้ารับบริการ
- `service_code_snapshot`: รหัสบริการ ณ เวลาลงทะเบียนเข้ารับบริการ
- `quantity`: จำนวนหน่วยบริการที่ขอรับบริการ (ต้องมากกว่า 0)
- `assigned_veterinarian_id`: สัตวแพทย์ที่มอบหมายให้ดูแลบริการนี้ (ถ้ามี) อ้างอิง `hr.employees`
- `service_status`: สถานะการรับบริการ ณ จุดต้อนรับ/คิว ค่าที่เป็นไปได้คือ
  - `REQUESTED`: ลงทะเบียนแจ้งความประสงค์ขอรับบริการแล้ว
  - `IN_PROGRESS`: ส่งต่อเข้าสู่การให้บริการแล้ว (เช่น เริ่ม Encounter ในห้องตรวจ)
  - `COMPLETED`: ให้บริการตามรายการเสร็จสิ้น
  - `CANCELLED`: ยกเลิกก่อนรับบริการ
  - `NOT_PERFORMED`: ไม่ได้ดำเนินการ (เช่น สัตวแพทย์ประเมินแล้วให้งดให้บริการ)
- `notes`: หมายเหตุเพิ่มเติม ณ จุดลงทะเบียน
- `created_at`: วันและเวลาที่สร้างรายการ
- `created_by`: ผู้สร้างรายการ
- `updated_at`: วันและเวลาที่แก้ไขล่าสุด
- `updated_by`: ผู้แก้ไขล่าสุด

#### หมายเหตุ:

1. ช่วยแก้ช่องว่างกรณี Walk-in (ไม่มี `appointment_id`) ให้สามารถเลือกรายการจาก `core.service_catalogs` ได้ชัดเจนตั้งแต่จุดลงทะเบียน
2. รายการบริการที่เกิดขึ้นจริงในห้องตรวจ (เช่น การตรวจรักษา เพิ่ม/ลดบริการ หรือค่าตรวจ OPD) จะถูกบันทึกและยืนยันต่อใน `clinical.encounter_services` ของ Domain 03 โดยไม่เขียนทับประวัติความตั้งใจเริ่มต้นตอนลงทะเบียนในตารางนี้
3. `quantity` ต้องมากกว่า 0

### ตาราง `appointment.check_ins`

**หน้าที่**: บันทึกเหตุการณ์ที่เจ้าของและสัตว์เลี้ยงมาถึงคลินิกและดำเนินการ Check-in เพื่อยืนยันการมาถึงจริง ใช้เป็นหลักฐานเวลาที่มาถึงและเป็นจุดเริ่มต้นของกระบวนการรอคิวหรือเข้ารับบริการ

| Column              | Data Type   | Constraint                                               |
| ------------------- | ----------- | -------------------------------------------------------- |
| `check_in_id`       | UUID        | PK, NOT NULL                                             |
| `registration_id`   | UUID        | FK → appointment.service_registrations, UNIQUE, NOT NULL |
| `check_in_type`     | ENUM        | NOT NULL                                                 |
| `actual_arrival_at` | TIMESTAMPTZ | NOT NULL                                                 |
| `checked_in_at`     | TIMESTAMPTZ | NOT NULL                                                 |
| `checked_in_by`     | UUID        | NULL                                                     |
| `check_in_status`   | ENUM        | NOT NULL                                                 |
| `notes`             | TEXT        | NULL                                                     |
| `created_at`        | TIMESTAMPTZ | NOT NULL                                                 |

#### ข้อกำหนด:

- `check_in_id`: รหัสประจำเหตุการณ์ Check-in
- `registration_id`: รายการลงทะเบียนที่ดำเนินการ Check-in อ้างอิงจาก `appointment.service_registrations` และต้องไม่ซ้ำกัน เพื่อป้องกันการ Check-in รายการเดิมหลายครั้ง
- `check_in_type`: ช่องทางการ Check-in ค่าที่เป็นไปได้ คือ
  - `COUNTER`: Check-in ผ่านเจ้าหน้าที่หน้าเคาน์เตอร์
  - `SELF_SERVICE`: Check-in ผ่านเครื่องบริการตนเองภายในคลินิก
  - `MOBILE_APP`: Check-in ผ่านแอปพลิเคชันของคลินิก
  - `QR_CODE`: Check-in ผ่านการสแกน QR Code
- `actual_arrival_at`: วันและเวลาที่เจ้าของและสัตว์เลี้ยงมาถึงสาขาจริง
- `checked_in_at`: วันและเวลาที่ระบบบันทึกการ Check-in เสร็จสิ้น
- `checked_in_by`: รหัสเจ้าหน้าที่ผู้ดำเนินการ หากเป็น Self-service, Mobile App หรือ QR Code ที่ทำงานอัตโนมัติสามารถเป็น `NULL`
- `check_in_status`: สถานะ Check-in ค่าที่เป็นไปได้ คือ
  - `COMPLETED`: Check-in สำเร็จ
  - `REJECTED`: ไม่อนุญาตให้ Check-in เช่น ไม่พบรายการลงทะเบียนหรือข้อมูลไม่ตรงกัน
  - `CANCELLED`: ยกเลิกเหตุการณ์ Check-in
- `notes`: หมายเหตุ เช่น ลูกค้ามาถึงก่อนเวลานัดหมาย หรือมีข้อมูลที่ต้องตรวจสอบเพิ่มเติม
- `created_at`: วันและเวลาที่สร้างข้อมูล Check-in

#### หมายเหตุ:

1. หนึ่งรายการลงทะเบียนสามารถมีเหตุการณ์ Check-in ที่สำเร็จได้เพียงหนึ่งรายการ
2. ต้องมี `service_registrations` ก่อนจึงจะดำเนินการ Check-in ได้
3. เมื่อ Check-in สำเร็จ ต้องปรับสถานะของ Registration ให้สอดคล้องกับกระบวนการ เช่น `WAITING_TRIAGE` หรือ `WAITING_SERVICE`
4. กรณีลูกค้ามาถึงก่อนเวลานัดหมาย ต้องเก็บเวลามาถึงจริงแยกจากเวลาที่กำหนดนัดหมาย
5. กรณีลูกค้าไม่มาตามนัด ต้องไม่สร้าง Check-in ปลอมเพื่อให้สถานะนัดหมายสมบูรณ์
6. การ Check-in ไม่ได้หมายความว่าสัตว์เลี้ยงเริ่มรับบริการแล้ว แต่เป็นการยืนยันการมาถึงของลูกค้าเท่านั้น

### ตาราง `appointment.check_outs`

**หน้าที่**: บันทึกเหตุการณ์สิ้นสุดการเข้ารับบริการของเจ้าของและสัตว์เลี้ยงในกระบวนการลงทะเบียน เพื่อระบุว่าการรับบริการสิ้นสุดลงอย่างไร และต้องดำเนินการต่อในขั้นตอนใด เช่น ชำระเงิน รับยา กลับบ้าน หรือส่งต่อไปยังระบบผู้ป่วยใน

| Column              | Data Type   | Constraint                                               |
| ------------------- | ----------- | -------------------------------------------------------- |
| `check_out_id`      | UUID        | PK, NOT NULL                                             |
| `registration_id`   | UUID        | FK → appointment.service_registrations, UNIQUE, NOT NULL |
| `queue_ticket_id`   | UUID        | FK → appointment.queue_tickets, NULL                     |
| `check_out_at`      | TIMESTAMPTZ | NOT NULL                                                 |
| `check_out_by`      | UUID        | NOT NULL                                                 |
| `service_outcome`   | ENUM        | NOT NULL                                                 |
| `next_action`       | ENUM        | NOT NULL                                                 |
| `next_action_notes` | TEXT        | NULL                                                     |
| `notes`             | TEXT        | NULL                                                     |
| `created_at`        | TIMESTAMPTZ | NOT NULL                                                 |

#### ข้อกำหนด:

- `check_out_id`: รหัสประจำเหตุการณ์ Check-out
- `registration_id`: รายการลงทะเบียนที่สิ้นสุดกระบวนการรับบริการ อ้างอิงจาก `appointment.service_registrations` และต้องไม่ซ้ำกัน
- `queue_ticket_id`: หมายเลขคิวที่เกี่ยวข้อง อ้างอิงจาก `appointment.queue_tickets` หากรายการลงทะเบียนไม่ได้ผ่านระบบคิวสามารถเป็น `NULL`
- `check_out_at`: วันและเวลาที่ดำเนินการ Check-out
- `check_out_by`: รหัสเจ้าหน้าที่ผู้ดำเนินการ
- `service_outcome`: ผลลัพธ์ของการเข้ารับบริการ ค่าที่เป็นไปได้ คือ
  - `COMPLETED`: รับบริการเสร็จสิ้นตามแผน
  - `REFERRED`: ส่งต่อไปยังสัตวแพทย์หรือสถานพยาบาลอื่น
  - `ADMITTED`: รับสัตว์เลี้ยงไว้เป็นผู้ป่วยใน
  - `TRANSFERRED`: ส่งต่อไปยังแผนกหรือกระบวนการอื่นภายในกิจการ
  - `LEFT_WITHOUT_COMPLETION`: เจ้าของนำสัตว์เลี้ยงออกจากคลินิกก่อนเสร็จสิ้นกระบวนการ
- `next_action`: ขั้นตอนถัดไปหลังสิ้นสุดการให้บริการ ค่าที่เป็นไปได้ คือ
  - `PAYMENT`: ไปดำเนินการชำระเงินกับ Billing
  - `PHARMACY`: ไปดำเนินการรับยากับ Pharmacy
  - `FOLLOW_UP`: นัดหมายติดตามผลการรักษา
  - `HOME`: กลับบ้าน
  - `INPATIENT`: ส่งเข้าสู่กระบวนการผู้ป่วยใน
  - `REFERRAL`: ดำเนินการส่งต่อไปยังสถานพยาบาลอื่น
- `next_action_notes`: รายละเอียดขั้นตอนถัดไป เช่น นัดติดตามผลภายใน 7 วัน หรือรอรับยาที่ห้องยา
- `notes`: หมายเหตุเพิ่มเติม
- `created_at`: วันและเวลาที่สร้างข้อมูล

#### หมายเหตุ:

1. หนึ่ง Registration สามารถมี Check-out ที่เสร็จสมบูรณ์ได้เพียงหนึ่งรายการ
2. ต้องตรวจสอบสถานะของ Registration ก่อนดำเนินการ Check-out
3. การ Check-out ไม่ควรถูกใช้แทนการชำระเงิน เพราะการชำระเงินเป็นความรับผิดชอบของ Billing Domain
4. หาก `service_outcome` เป็น `ADMITTED` ต้องส่งข้อมูลไปยัง Inpatient Domain เพื่อดำเนินการรับผู้ป่วยใน
5. หาก `service_outcome` เป็น `REFERRED` ต้องเก็บข้อมูลการส่งต่อใน Clinical หรือ Referral Domain ตามขอบเขตที่กำหนด
6. หาก `service_outcome` เป็น `LEFT_WITHOUT_COMPLETION` ต้องบันทึกเหตุผลและแจ้งผู้รับผิดชอบ
7. การสร้าง Check-out ต้องปรับสถานะ Registration ให้เป็น `COMPLETED` หรือสถานะสิ้นสุดที่สอดคล้องกับผลการดำเนินงาน
8. ตารางนี้บันทึกการสิ้นสุดกระบวนการลงทะเบียนและรับบริการ ไม่ได้หมายความว่าเจ้าของชำระเงินเสร็จสิ้นหรือออกจากอาคารแล้วเสมอไป

## กลุ่ม Queue Management

### ตาราง `appointment.queues`

**หน้าที่**: จัดเก็บข้อมูลหลักของชุดคิวให้บริการในแต่ละสาขาและแต่ละวัน เพื่อใช้บริหารลำดับการเข้ารับบริการของสัตว์เลี้ยง รองรับการแยกคิวตามประเภทบริการ เช่น คิวตรวจทั่วไป คิวฉีดวัคซีน คิวตรวจสุขภาพ และคิวฉุกเฉิน

| Column               | Data Type    | Constraint                   |
| -------------------- | ------------ | ---------------------------- |
| `queue_id`           | UUID         | PK, NOT NULL                 |
| `branch_id`          | UUID         | FK → core.branches, NOT NULL |
| `queue_date`         | DATE         | NOT NULL                     |
| `queue_code`         | VARCHAR(30)  | NOT NULL                     |
| `queue_name`         | VARCHAR(150) | NOT NULL                     |
| `queue_type`         | ENUM         | NOT NULL                     |
| `ticket_prefix`      | VARCHAR(10)  | NOT NULL                     |
| `last_ticket_number` | INTEGER      | NOT NULL DEFAULT 0           |
| `queue_status`       | ENUM         | NOT NULL                     |
| `opened_at`          | TIMESTAMPTZ  | NULL                         |
| `closed_at`          | TIMESTAMPTZ  | NULL                         |
| `created_at`         | TIMESTAMPTZ  | NOT NULL                     |
| `created_by`         | UUID         | NOT NULL                     |
| `updated_at`         | TIMESTAMPTZ  | NULL                         |
| `updated_by`         | UUID         | NULL                         |

#### ข้อกำหนด:

- `queue_id`: รหัสประจำชุดคิว ใช้เป็น Primary Key
- `branch_id`: สาขาที่เป็นเจ้าของชุดคิว อ้างอิงจาก `core.branches`
- `queue_date`: วันที่ให้บริการของชุดคิว ใช้วันที่ตามเวลาท้องถิ่นของสาขา
- `queue_code`: รหัสชุดคิวภายในสาขา เช่น `GENERAL`, `VACCINE`, `EMERGENCY` ต้องไม่ซ้ำกันภายในสาขาและวันที่เดียวกัน
- `queue_name`: ชื่อชุดคิวที่แสดงให้พนักงานและลูกค้าเห็น เช่น คิวตรวจทั่วไป คิวฉีดวัคซีน
- `queue_type`: ประเภทของชุดคิว ค่าที่เป็นไปได้ คือ
  - `GENERAL`: คิวตรวจและรับบริการทั่วไป
  - `VACCINATION`: คิวฉีดวัคซีน
  - `HEALTH_CHECK`: คิวตรวจสุขภาพ
  - `FOLLOW_UP`: คิวติดตามผลการรักษา
  - `TREATMENT`: คิวเข้ารับการรักษาและทำหัตถการ
  - `EMERGENCY`: คิวผู้ป่วยฉุกเฉิน
  - `SPECIALIST`: คิวตรวจโดยสัตวแพทย์เฉพาะทาง
  - `PROCEDURE`: คิวทำหัตถการเฉพาะ
  - `GROOMING`: คิวอาบน้ำและตัดแต่งขน
- `ticket_prefix`: ตัวอักษรนำหน้าหมายเลขคิว เช่น `A`, `V`, `E` ใช้แยกประเภทคิวเมื่อแสดงบนจอ
- `last_ticket_number`: หมายเลขคิวล่าสุดที่ออกให้ในชุดคิวนี้ เริ่มต้นจาก `0` และเพิ่มขึ้นทีละ 1 เมื่อมีการออกบัตรคิว
- `queue_status`: สถานะของชุดคิว ค่าที่เป็นไปได้ คือ
  - `OPEN`: เปิดให้รับคิวใหม่และเรียกคิวได้ตามปกติ
  - `PAUSED`: หยุดเรียกคิวชั่วคราว แต่ยังคงเก็บรายการคิวเดิมไว้
  - `CLOSED`: ปิดชุดคิว ไม่รับคิวใหม่และไม่เรียกคิวเพิ่มเติม
  - `CANCELLED`: ยกเลิกชุดคิว เนื่องจากเหตุผลทางธุรกิจหรือเหตุการณ์ที่ทำให้ไม่สามารถให้บริการได้
- `opened_at`: วันและเวลาที่เปิดใช้งานชุดคิว
- `closed_at`: วันและเวลาที่ปิดชุดคิว
- `created_at`: วันและเวลาที่สร้างชุดคิว
- `created_by`: ผู้สร้างชุดคิว
- `updated_at`: วันและเวลาที่แก้ไขล่าสุด
- `updated_by`: ผู้แก้ไขล่าสุด

#### หมายเหตุ:

1. หนึ่งสาขาสามารถมีชุดคิวได้หลายประเภทในวันเดียวกัน
2. `queue_code` ต้องไม่ซ้ำกันภายในสาขาและวันที่เดียวกัน โดยกำหนด Unique Constraint `(branch_id, queue_date, queue_code)`
3. หมายเลขคิวต้องเพิ่มขึ้นตามลำดับภายในชุดคิวเดียวกัน
4. การสร้างหมายเลขคิวต้องทำภายใต้ Transaction หรือกลไกที่ป้องกันการออกหมายเลขซ้ำเมื่อมีผู้ลงทะเบียนพร้อมกันหลายรายการ
5. เมื่อ `queue_status` เป็น `PAUSED` ระบบต้องไม่เรียกคิวใหม่ แต่ยังคงรักษารายการคิวที่รออยู่
6. เมื่อ `queue_status` เป็น `CLOSED` ต้องไม่อนุญาตให้สร้าง Ticket ใหม่ในชุดคิวดังกล่าว
7. ชุดคิวที่มีประวัติการให้บริการแล้วห้ามลบจริง
8. คิวประเภท `EMERGENCY` ต้องรองรับการจัดลำดับตามผลการคัดกรอง ไม่ควรใช้เพียงลำดับเวลาที่ออกบัตรคิว
9. การปิดชุดคิวไม่ควรทำให้ Ticket ที่ยังค้างอยู่สูญหาย ต้องมีขั้นตอนจัดการคิวที่เหลือ เช่น ย้ายคิว ยกเลิกคิว หรือส่งต่อ

### ตาราง `appointment.queue_tickets`

**หน้าที่**: จัดเก็บบัตรคิวของเจ้าของและสัตว์เลี้ยงที่ลงทะเบียนเข้ารับบริการ ใช้แสดงลำดับการรอรับบริการ ติดตามสถานะคิว และเชื่อมโยงกับ Registration ที่เป็นต้นทางของการรับบริการ

| Column                     | Data Type   | Constraint                                       |
| -------------------------- | ----------- | ------------------------------------------------ |
| `queue_ticket_id`          | UUID        | PK, NOT NULL                                     |
| `queue_id`                 | UUID        | FK → appointment.queues, NOT NULL                |
| `registration_id`          | UUID        | FK → appointment.service_registrations, NOT NULL |
| `ticket_number`            | VARCHAR(20) | NOT NULL                                         |
| `sequence_number`          | INTEGER     | NOT NULL                                         |
| `priority_level`           | ENUM        | NOT NULL                                         |
| `queue_position`           | INTEGER     | NULL                                             |
| `ticket_status`            | ENUM        | NOT NULL                                         |
| `issued_at`                | TIMESTAMPTZ | NOT NULL                                         |
| `first_called_at`          | TIMESTAMPTZ | NULL                                             |
| `service_started_at`       | TIMESTAMPTZ | NULL                                             |
| `completed_at`             | TIMESTAMPTZ | NULL                                             |
| `assigned_veterinarian_id` | UUID        | FK → hr.employees, NULL                          |
| `assigned_room_id`         | UUID        | FK → appointment.rooms, NULL                     |
| `created_at`               | TIMESTAMPTZ | NOT NULL                                         |
| `updated_at`               | TIMESTAMPTZ | NULL                                             |

#### ข้อกำหนด:

- `queue_ticket_id`: รหัสประจำบัตรคิว ใช้เป็น Primary Key
- `queue_id`: ชุดคิวที่บัตรคิวนี้สังกัด อ้างอิงจาก `appointment.queues`
- `registration_id`: รายการลงทะเบียนที่เป็นเจ้าของบัตรคิว อ้างอิงจาก `appointment.service_registrations`
- `ticket_number`: หมายเลขคิวที่แสดงให้ลูกค้า เช่น `A001`, `V002`, `E003` ต้องไม่ซ้ำกันภายในชุดคิวเดียวกัน
- `sequence_number`: ลำดับการออกบัตรคิวภายในชุดคิว ใช้เก็บลำดับที่เกิดขึ้นจริงและไม่เปลี่ยนแปลง แม้ตำแหน่งรอคิวจะเปลี่ยน
- `priority_level`: ระดับความสำคัญในการจัดลำดับคิว ค่าที่เป็นไปได้ คือ
  - `CRITICAL`: วิกฤต ต้องได้รับการช่วยเหลือทันทีตามการประเมินของสัตวแพทย์
  - `EMERGENCY`: ฉุกเฉิน ต้องได้รับการประเมินและดูแลโดยเร็ว
  - `URGENT`: เร่งด่วน ควรได้รับบริการก่อนคิวปกติ
  - `ROUTINE`: คิวปกติตามลำดับการลงทะเบียน (เทียบเท่าความเร่งด่วนระดับ `ROUTINE`)
  - `SCHEDULED`: คิวตามนัดหมาย ใช้สำหรับรายการที่มีการจองเวลาล่วงหน้า
- `queue_position`: ตำแหน่งปัจจุบันของคิวในลำดับรอ หากเริ่มให้บริการแล้วหรือไม่มีตำแหน่งรอสามารถเป็น `NULL`
- `ticket_status`: สถานะของบัตรคิว ค่าที่เป็นไปได้ คือ
  - `WAITING`: รอเรียกคิว
  - `CALLED`: ถูกเรียกคิวแล้วและกำลังรอเจ้าของเข้าพบเจ้าหน้าที่
  - `IN_SERVICE`: สัตว์เลี้ยงกำลังรับบริการ
  - `ON_HOLD`: พักคิวชั่วคราว เช่น เจ้าของยังไม่พร้อมหรือรอผลตรวจ
  - `COMPLETED`: รับบริการเสร็จสิ้น
  - `SKIPPED`: ถูกข้ามคิว เนื่องจากเรียกแล้วไม่มีผู้มาติดต่อหรือมีเหตุผลที่กำหนด
  - `CANCELLED`: ยกเลิกคิว
  - `NO_SHOW`: เจ้าของไม่มาตามการเรียกคิวภายในเวลาที่กำหนด
- `issued_at`: วันและเวลาที่ออกบัตรคิว
- `first_called_at`: วันและเวลาที่เรียกคิวครั้งแรก
- `service_started_at`: วันและเวลาที่เริ่มรับบริการจริง
- `completed_at`: วันและเวลาที่รับบริการเสร็จสิ้น
- `assigned_veterinarian_id`: สัตวแพทย์ที่ได้รับมอบหมายให้ดูแลคิวนี้ อ้างอิงจาก `hr.employees`
- `assigned_room_id`: ห้องที่กำหนดให้เข้ารับบริการ อ้างอิงจาก `appointment.rooms`
- `created_at`: วันและเวลาที่สร้างบัตรคิว
- `updated_at`: วันและเวลาที่แก้ไขข้อมูลล่าสุด

#### หมายเหตุ:

1. หนึ่งบัตรคิวต้องอ้างอิง Registration ที่มีอยู่จริง
2. ต้องกำหนด Unique Constraint `(queue_id, ticket_number)` และ `(queue_id, sequence_number)` เพื่อป้องกันหมายเลขและลำดับซ้ำ
3. `queue_position` เป็นตำแหน่งรอคิวปัจจุบัน ไม่ใช่ลำดับการออกบัตรคิว จึงสามารถเปลี่ยนแปลงได้ตามการเรียกคิวและการจัดลำดับความเร่งด่วน
4. การจัดลำดับคิวต้องพิจารณา `priority_level` ร่วมกับเวลาที่ลงทะเบียน ไม่ใช่ใช้ `sequence_number` เพียงอย่างเดียว
5. คิว `CRITICAL` และ `EMERGENCY` ต้องสามารถแทรกเข้าสู่กระบวนการให้บริการได้ตามผลการคัดกรอง โดยไม่ต้องรอตามลำดับปกติ
6. หนึ่ง Registration ต้องมีจำนวน Ticket ตามนโยบายที่กำหนด หากระบบกำหนดให้หนึ่ง Registration มีหนึ่ง Ticket ให้เพิ่ม Unique Constraint ที่ `registration_id`
7. หากหนึ่ง Registration มีหลายบริการและต้องการแยกคิวตามบริการ อาจอนุญาตให้มีหลาย Ticket โดยต้องกำหนดความสัมพันธ์กับ `appointment_service_id` เพิ่มเติมในโครงสร้างตามนโยบายของคลินิก
8. เมื่อเรียกคิว ต้องสร้างประวัติใน `appointment.queue_calls`
9. เมื่อสถานะ Ticket เปลี่ยนแปลง ต้องบันทึกประวัติใน `appointment.queue_status_histories`
10. การเปลี่ยนสถานะเป็น `COMPLETED` ต้องบันทึก `completed_at` และปรับสถานะ Registration ให้สอดคล้องกัน

### ตาราง `appointment.queue_calls`

**หน้าที่**: บันทึกประวัติการเรียกบัตรคิวแต่ละครั้ง เพื่อให้ตรวจสอบได้ว่ามีการเรียกคิวเมื่อใด เรียกโดยใคร เรียกผ่านช่องทางใด และเจ้าของตอบสนองต่อการเรียกคิวหรือไม่

| Column            | Data Type   | Constraint                               |
| ----------------- | ----------- | ---------------------------------------- |
| `queue_call_id`   | UUID        | PK, NOT NULL                             |
| `queue_ticket_id` | UUID        | FK → appointment.queue_tickets, NOT NULL |
| `call_sequence`   | SMALLINT    | NOT NULL                                 |
| `called_at`       | TIMESTAMPTZ | NOT NULL                                 |
| `called_by`       | UUID        | NOT NULL                                 |
| `room_id`         | UUID        | FK → appointment.rooms, NULL             |
| `call_channel`    | ENUM        | NOT NULL                                 |
| `call_result`     | ENUM        | NOT NULL                                 |
| `response_at`     | TIMESTAMPTZ | NULL                                     |
| `notes`           | TEXT        | NULL                                     |
| `created_at`      | TIMESTAMPTZ | NOT NULL                                 |

#### ข้อกำหนด:

- `queue_call_id`: รหัสประจำเหตุการณ์เรียกคิว
- `queue_ticket_id`: บัตรคิวที่ถูกเรียก อ้างอิงจาก `appointment.queue_tickets`
- `call_sequence`: ลำดับครั้งที่เรียกบัตรคิวเดียวกัน เช่น เรียกครั้งที่ 1, 2 หรือ 3
- `called_at`: วันและเวลาที่เรียกคิว
- `called_by`: รหัสเจ้าหน้าที่ผู้เรียกคิว
- `room_id`: ห้องที่ให้เจ้าของและสัตว์เลี้ยงเข้ารับบริการ อ้างอิงจาก `appointment.rooms`
- `call_channel`: ช่องทางที่ใช้เรียกคิว ค่าที่เป็นไปได้ คือ
  - `DISPLAY_SCREEN`: แสดงหมายเลขคิวบนจอเรียกคิว
  - `VOICE`: ประกาศเรียกคิวด้วยเสียง
  - `COUNTER`: เรียกคิวโดยเจ้าหน้าที่หน้าเคาน์เตอร์
  - `MOBILE_NOTIFICATION`: ส่งการแจ้งเตือนผ่านแอปพลิเคชันหรืออุปกรณ์มือถือ
- `call_result`: ผลการเรียกคิว ค่าที่เป็นไปได้ คือ
  - `ANSWERED`: เจ้าของตอบสนองต่อการเรียกและมารับบริการ
  - `NO_RESPONSE`: เรียกแล้วไม่มีผู้ตอบสนอง
  - `SKIPPED`: ข้ามคิวตามขั้นตอนที่กำหนด
  - `RECALLED`: เรียกคิวซ้ำหลังจากการเรียกครั้งก่อน
- `response_at`: วันและเวลาที่เจ้าของตอบสนองต่อการเรียกคิว
- `notes`: หมายเหตุเพิ่มเติม เช่น เรียกแล้วเจ้าของยังไม่พร้อม หรือขอเวลาจัดเตรียมสัตว์เลี้ยง
- `created_at`: วันและเวลาที่สร้างประวัติการเรียกคิว

#### หมายเหตุ:

1. หนึ่งบัตรคิวสามารถมีประวัติการเรียกได้หลายครั้ง
2. `call_sequence` ต้องไม่ซ้ำกันภายใน `queue_ticket_id` เดียวกัน โดยกำหนด Unique Constraint `(queue_ticket_id, call_sequence)`
3. ทุกครั้งที่เรียกคิวต้องสร้างข้อมูลใหม่ ห้ามเขียนทับประวัติการเรียกครั้งก่อน
4. หากเรียกแล้วไม่มีผู้ตอบสนอง ต้องบันทึก `NO_RESPONSE` และดำเนินการตามนโยบายการเรียกซ้ำหรือข้ามคิว
5. หากเรียกซ้ำ ต้องสร้างประวัติใหม่โดยเพิ่ม `call_sequence`
6. หาก `call_result` เป็น `ANSWERED` ควรบันทึก `response_at` และปรับสถานะ Ticket ตามขั้นตอนการให้บริการ
7. ตารางนี้เป็นประวัติการเรียกคิว ไม่ใช่ประวัติการเปลี่ยนสถานะทั้งหมดของบัตรคิว ซึ่งต้องเก็บใน `queue_status_histories`

### ตาราง `appointment.queue_status_histories`

**หน้าที่**: บันทึกประวัติการเปลี่ยนแปลงสถานะของบัตรคิว เพื่อให้สามารถตรวจสอบย้อนหลังได้ว่าคิวเปลี่ยนจากสถานะใดไปเป็นสถานะใด เปลี่ยนเมื่อใด และใครเป็นผู้ดำเนินการ

| Column                    | Data Type   | Constraint                               |
| ------------------------- | ----------- | ---------------------------------------- |
| `queue_status_history_id` | UUID        | PK, NOT NULL                             |
| `queue_ticket_id`         | UUID        | FK → appointment.queue_tickets, NOT NULL |
| `previous_status`         | ENUM        | NULL                                     |
| `new_status`              | ENUM        | NOT NULL                                 |
| `changed_at`              | TIMESTAMPTZ | NOT NULL                                 |
| `changed_by`              | UUID        | NULL                                     |
| `change_reason`           | TEXT        | NULL                                     |
| `metadata`                | JSONB       | NULL                                     |
| `created_at`              | TIMESTAMPTZ | NOT NULL                                 |

#### ข้อกำหนด:

- `queue_status_history_id`: รหัสประจำประวัติการเปลี่ยนสถานะ
- `queue_ticket_id`: บัตรคิวที่มีการเปลี่ยนสถานะ อ้างอิงจาก `appointment.queue_tickets`
- `previous_status`: สถานะก่อนการเปลี่ยนแปลง หากเป็นประวัติแรกของบัตรคิว ให้เป็น `NULL` ใช้ชุดค่าเดียวกับ `queue_tickets.ticket_status` ได้แก่
  - `WAITING`
  - `CALLED`
  - `IN_SERVICE`
  - `ON_HOLD`
  - `COMPLETED`
  - `SKIPPED`
  - `CANCELLED`
  - `NO_SHOW`
- `new_status`: สถานะใหม่ของบัตรคิว ใช้ชุดค่าเดียวกับ `queue_tickets.ticket_status` ได้แก่
  - `WAITING`
  - `CALLED`
  - `IN_SERVICE`
  - `ON_HOLD`
  - `COMPLETED`
  - `SKIPPED`
  - `CANCELLED`
  - `NO_SHOW`
- `changed_at`: วันและเวลาที่สถานะเปลี่ยนแปลง
- `changed_by`: รหัสเจ้าหน้าที่หรือผู้ดำเนินการ หากเป็นการเปลี่ยนสถานะโดยระบบอัตโนมัติสามารถเป็น `NULL`
- `change_reason`: เหตุผลในการเปลี่ยนสถานะ เช่น เรียกคิวแล้วไม่มีผู้ตอบสนอง พักคิวเพื่อรอผลตรวจ หรือยกเลิกคิว
- `metadata`: รายละเอียดเพิ่มเติมของการเปลี่ยนสถานะ เช่น ตำแหน่งคิวเดิมและใหม่ หรือข้อมูลที่เกี่ยวข้องกับเหตุการณ์
- `created_at`: วันและเวลาที่สร้างประวัติ

#### หมายเหตุ:

1. ทุกครั้งที่สถานะ Ticket เปลี่ยนแปลง ต้องสร้างประวัติใหม่
2. ห้ามลบหรือแก้ไขประวัติเดิมโดยไม่มีเหตุผลและกระบวนการ Audit
3. `previous_status` ต้องตรงกับสถานะก่อนหน้าที่บันทึกไว้ใน `queue_tickets`
4. `new_status` ต้องตรงกับสถานะปัจจุบันใน `queue_tickets` หลังการเปลี่ยนแปลง
5. การปรับปรุง `queue_tickets.ticket_status` และการเพิ่ม `queue_status_histories` ต้องเกิดใน Transaction เดียวกัน
6. ต้องกำหนดกฎการเปลี่ยนสถานะที่อนุญาต เช่น
   - `WAITING` → `CALLED`, `CANCELLED`, `NO_SHOW`
   - `CALLED` → `IN_SERVICE`, `WAITING`, `SKIPPED`, `CANCELLED`, `NO_SHOW`
   - `IN_SERVICE` → `ON_HOLD`, `COMPLETED`, `CANCELLED`
   - `ON_HOLD` → `WAITING`, `CALLED`, `IN_SERVICE`, `CANCELLED`
   - `SKIPPED` → `WAITING`, หากอนุญาตให้กลับเข้าคิว
7. ไม่ควรอนุญาตให้เปลี่ยนจาก `COMPLETED` กลับเป็น `WAITING` โดยตรง หากจำเป็นต้องรับบริการใหม่ควรสร้างกระบวนการหรือลงทะเบียนใหม่

## กลุ่ม Emergency Triage Management

#### ข้อกำหนด:

- `triage_assessment_id`: รหัสประจำรายการประเมินและคัดกรอง
- `registration_id`: รายการลงทะเบียนที่เข้าสู่กระบวนการ Triage อ้างอิงจาก `appointment.service_registrations`
- `pet_id`: สัตว์เลี้ยงที่ได้รับการประเมิน อ้างอิงจาก `owner.pets`
- `assessment_number`: ลำดับครั้งที่ประเมินภายใน Registration เดียวกัน รองรับกรณีที่ต้องประเมินซ้ำ
- `urgency_level`: ระดับความเร่งด่วนจากการคัดกรอง ค่าที่เป็นไปได้ คือ
  - `CRITICAL`: ภาวะวิกฤต สัตว์เลี้ยงมีอาการที่อาจเป็นอันตรายต่อชีวิต ต้องได้รับการช่วยเหลือทันที
  - `EMERGENCY`: ภาวะฉุกเฉิน มีความเสี่ยงสูงและต้องได้รับการประเมินโดยสัตวแพทย์โดยเร็ว
  - `URGENT`: ภาวะเร่งด่วน มีอาการผิดปกติที่ควรได้รับการดูแลก่อนผู้ป่วยทั่วไป
  - `ROUTINE`: ภาวะทั่วไป สามารถรอรับบริการตามลำดับคิวปกติได้
  - `SCHEDULED`: ผู้ป่วยที่มารับบริการตามนัดหมายและไม่มีข้อบ่งชี้ว่าต้องเร่งด่วน
- `chief_complaint`: อาการสำคัญหรือเหตุผลหลักที่นำสัตว์เลี้ยงเข้ารับการคัดกรอง
- `clinical_observations`: รายละเอียดการสังเกตอาการเบื้องต้น เช่น การหายใจ ระดับความรู้สึกตัว อาการเจ็บปวด หรืออาการผิดปกติที่พบ
- `assessed_by`: รหัสเจ้าหน้าที่หรือบุคลากรทางการแพทย์ผู้ดำเนินการประเมิน อ้างอิงจาก `hr.employees`
- `assessed_at`: วันและเวลาที่ดำเนินการประเมิน
- `immediate_action`: การดำเนินการเบื้องต้นหลังการคัดกรอง เช่น แจ้งสัตวแพทย์ เตรียมอุปกรณ์ช่วยเหลือ หรือส่งเข้าห้องฉุกเฉิน
- `referred_veterinarian_id`: สัตวแพทย์ที่ได้รับการส่งต่อเพื่อประเมินหรือรักษาต่อ อ้างอิงจาก `hr.employees`
- `triage_status`: สถานะของการคัดกรอง ค่าที่เป็นไปได้ คือ
  - `IN_PROGRESS`: อยู่ระหว่างประเมินและรวบรวมข้อมูล
  - `COMPLETED`: ประเมินเสร็จสิ้นและกำหนดระดับความเร่งด่วนแล้ว
  - `REASSESSED`: มีการประเมินซ้ำเพื่อปรับระดับความเร่งด่วนหรือทบทวนอาการ
  - `REFERRED`: ส่งต่อให้สัตวแพทย์หรือผู้รับผิดชอบดำเนินการต่อแล้ว
- `created_at`: วันและเวลาที่สร้างข้อมูลการประเมิน

#### หมายเหตุ:

1. หนึ่ง Registration สามารถมีการประเมิน Triage ได้หลายครั้ง เพื่อรองรับการประเมินซ้ำเมื่ออาการเปลี่ยนแปลง
2. ต้องกำหนด Unique Constraint `(registration_id, assessment_number)`
3. `pet_id` ต้องตรงกับสัตว์เลี้ยงที่อ้างอิงใน `service_registrations`
4. ทุกการประเมินต้องบันทึกผู้ประเมินและเวลาที่ประเมิน
5. หากประเมินได้ระดับ `CRITICAL` หรือ `EMERGENCY` ต้องส่งสัญญาณให้ระบบ Queue จัดลำดับความสำคัญโดยไม่ต้องรอคิวปกติ
6. หากมีการประเมินซ้ำ ต้องสร้าง `triage_assessments` รายการใหม่ ห้ามเขียนทับผลการประเมินเดิม
7. การประเมิน Triage เป็นการคัดกรองความเร่งด่วน ไม่ใช่การวินิจฉัยโรคหรือบันทึกเวชระเบียนฉบับสมบูรณ์
8. รายละเอียดค่าทางสรีรวิทยาที่วัดได้ควรบันทึกใน `appointment.triage_observations`
9. เมื่อส่งต่อให้สัตวแพทย์แล้ว ต้องปรับสถานะ Registration และ Queue ให้สอดคล้องกับการดำเนินงานจริง

### ตาราง `appointment.triage_observations`

**หน้าที่**: จัดเก็บค่าที่ตรวจวัดหรือสังเกตได้ระหว่างกระบวนการ Triage เช่น อุณหภูมิร่างกาย อัตราการเต้นของหัวใจ อัตราการหายใจ ระดับความเจ็บปวด และสีของเยื่อเมือก เพื่อใช้ประกอบการประเมินความเร่งด่วนของสัตว์เลี้ยง

| Column                  | Data Type     | Constraint                                    |
| ----------------------- | ------------- | --------------------------------------------- |
| `triage_observation_id` | UUID          | PK, NOT NULL                                  |
| `triage_assessment_id`  | UUID          | FK → appointment.triage_assessments, NOT NULL |
| `observation_type`      | ENUM          | NOT NULL                                      |
| `numeric_value`         | NUMERIC(12,3) | NULL                                          |
| `text_value`            | VARCHAR(255)  | NULL                                          |
| `unit`                  | VARCHAR(30)   | NULL                                          |
| `observed_at`           | TIMESTAMPTZ   | NOT NULL                                      |
| `observed_by`           | UUID          | FK → hr.employees, NOT NULL                   |
| `notes`                 | TEXT          | NULL                                          |
| `created_at`            | TIMESTAMPTZ   | NOT NULL                                      |

#### ข้อกำหนด:

- `triage_observation_id`: รหัสประจำรายการค่าที่ตรวจวัดหรือสังเกต
- `triage_assessment_id`: รายการประเมิน Triage ที่เป็นเจ้าของข้อมูล อ้างอิงจาก `appointment.triage_assessments`
- `observation_type`: ประเภทข้อมูลที่ตรวจวัดหรือสังเกต ค่าที่เป็นไปได้ คือ
  - `BODY_TEMPERATURE`: อุณหภูมิร่างกาย โดยทั่วไปบันทึกเป็นองศาเซลเซียส (`°C`)
  - `HEART_RATE`: อัตราการเต้นของหัวใจ โดยทั่วไปบันทึกเป็นครั้งต่อนาที (`bpm`)
  - `RESPIRATORY_RATE`: อัตราการหายใจ โดยทั่วไปบันทึกเป็นครั้งต่อนาที (`breaths/min`)
  - `CAPILLARY_REFILL_TIME`: ระยะเวลาการคืนสีของหลอดเลือดฝอย โดยทั่วไปบันทึกเป็นวินาที (`sec`)
  - `MUCOUS_MEMBRANE_COLOR`: สีของเยื่อเมือก เช่น สีชมพู ซีด หรือเขียวคล้ำ
  - `CONSCIOUSNESS_LEVEL`: ระดับความรู้สึกตัว เช่น ปกติ ซึม หรือไม่รู้สึกตัว
  - `PAIN_SCORE`: คะแนนประเมินความเจ็บปวดตามแบบประเมินที่คลินิกกำหนด
  - `BODY_WEIGHT`: น้ำหนักตัวสัตว์เลี้ยง โดยทั่วไปบันทึกเป็นกิโลกรัม (`kg`)
  - `OTHER`: ข้อมูลการตรวจวัดหรือสังเกตประเภทอื่นที่ไม่ได้อยู่ในรายการมาตรฐาน
- `numeric_value`: ค่าตัวเลขที่ตรวจวัดได้ เช่น อุณหภูมิ 39.2 หรืออัตราการเต้นของหัวใจ 120
- `text_value`: ข้อความที่ใช้บันทึกผลการสังเกต เช่น เยื่อเมือกสีซีด หรือมีอาการซึม
- `unit`: หน่วยของค่าที่ตรวจวัด เช่น `°C`, `bpm`, `breaths/min`, `sec`, `kg`
- `observed_at`: วันและเวลาที่ตรวจวัดหรือสังเกต
- `observed_by`: รหัสเจ้าหน้าที่หรือบุคลากรทางการแพทย์ผู้ตรวจวัด อ้างอิงจาก `hr.employees`
- `notes`: รายละเอียดเพิ่มเติม เช่น สภาพสัตว์ขณะตรวจวัด หรือข้อจำกัดของการวัด
- `created_at`: วันและเวลาที่สร้างข้อมูล

#### หมายเหตุ:

1. หนึ่ง Triage Assessment สามารถมี Observation ได้หลายรายการ
2. ค่าที่เป็นตัวเลขต้องเก็บใน `numeric_value` และค่าที่เป็นข้อความต้องเก็บใน `text_value`
3. หนึ่ง Observation ต้องกำหนดค่าใน `numeric_value` หรือ `text_value` อย่างใดอย่างหนึ่งตามลักษณะข้อมูล ไม่ควรกรอกทั้งสองช่องโดยไม่มีเหตุผล
4. `unit` ต้องสอดคล้องกับ `observation_type` เช่น อุณหภูมิใช้ `°C` น้ำหนักใช้ `kg` และอัตราการเต้นหัวใจใช้ `bpm`
5. ค่าที่ตรวจวัดได้ต้องเก็บพร้อมเวลาและผู้ตรวจวัด เพื่อให้สามารถตรวจสอบย้อนหลังได้
6. ค่าทางสรีรวิทยาต้องไม่ถูกนำไปใช้แทนข้อมูลเวชระเบียนหลักของ Clinical Domain
7. หากมีการตรวจวัดค่าเดิมหลายครั้ง ต้องสร้าง Observation ใหม่ทุกครั้ง ไม่เขียนทับค่าเก่า
8. การกำหนดช่วงค่าปกติและการแจ้งเตือนความผิดปกติควรแยกตามชนิดสัตว์ อายุ และบริบททางคลินิก ไม่ควรใช้ค่าขีดจำกัดชุดเดียวกับสัตว์ทุกชนิด

## กลุ่ม Service Status History

### ตาราง `appointment.service_status_histories`

**หน้าที่**: จัดเก็บประวัติการเปลี่ยนแปลงสถานะของรายการลงทะเบียนเข้ารับบริการ เพื่อให้สามารถตรวจสอบขั้นตอนการดำเนินงานตั้งแต่ลงทะเบียน รอคัดกรอง รอรับบริการ เริ่มรับบริการ จนถึงสิ้นสุดกระบวนการได้อย่างครบถ้วน

| Column                      | Data Type   | Constraint                                       |
| --------------------------- | ----------- | ------------------------------------------------ |
| `service_status_history_id` | UUID        | PK, NOT NULL                                     |
| `registration_id`           | UUID        | FK → appointment.service_registrations, NOT NULL |
| `previous_status`           | ENUM        | NULL                                             |
| `new_status`                | ENUM        | NOT NULL                                         |
| `changed_at`                | TIMESTAMPTZ | NOT NULL                                         |
| `changed_by`                | UUID        | NULL                                             |
| `change_reason`             | TEXT        | NULL                                             |
| `notes`                     | TEXT        | NULL                                             |
| `created_at`                | TIMESTAMPTZ | NOT NULL                                         |

#### ข้อกำหนด:

- `service_status_history_id`: รหัสประจำประวัติการเปลี่ยนแปลงสถานะการให้บริการ
- `registration_id`: รายการลงทะเบียนที่มีการเปลี่ยนสถานะ อ้างอิงจาก `appointment.service_registrations`
- `previous_status`: สถานะก่อนการเปลี่ยนแปลง ใช้ชุดค่าเดียวกับ `service_registrations.registration_status` ได้แก่
  - `REGISTERED`: ลงทะเบียนเรียบร้อยแล้ว
  - `WAITING_TRIAGE`: รอการคัดกรองอาการ
  - `TRIAGE_IN_PROGRESS`: อยู่ระหว่างการคัดกรอง
  - `WAITING_SERVICE`: ผ่านการคัดกรองแล้วและรอรับบริการ
  - `IN_SERVICE`: กำลังรับบริการ
  - `COMPLETED`: กระบวนการให้บริการเสร็จสิ้น
  - `CANCELLED`: ยกเลิกการลงทะเบียน

หากเป็นประวัติแรกของ Registration ให้เป็น `NULL`

- `new_status`: สถานะใหม่ของรายการลงทะเบียน ใช้ชุดค่าเดียวกับ `service_registrations.registration_status` ได้แก่
  - `REGISTERED`
  - `WAITING_TRIAGE`
  - `TRIAGE_IN_PROGRESS`
  - `WAITING_SERVICE`
  - `IN_SERVICE`
  - `COMPLETED`
  - `CANCELLED`
- `changed_at`: วันและเวลาที่สถานะเปลี่ยนแปลง
- `changed_by`: รหัสผู้ดำเนินการเปลี่ยนสถานะ หากเป็นการเปลี่ยนสถานะโดยระบบอัตโนมัติสามารถเป็น `NULL`
- `change_reason`: เหตุผลในการเปลี่ยนสถานะ เช่น ผ่านการคัดกรองแล้ว เริ่มรับบริการ หรือยกเลิกการลงทะเบียน
- `notes`: หมายเหตุเพิ่มเติมเกี่ยวกับการเปลี่ยนสถานะ
- `created_at`: วันและเวลาที่สร้างประวัติ

#### หมายเหตุ:

1. หนึ่ง Registration สามารถมีประวัติการเปลี่ยนสถานะได้หลายรายการ
2. ทุกครั้งที่ `registration_status` เปลี่ยนแปลง ต้องสร้างประวัติใหม่ในตารางนี้
3. `previous_status` ต้องตรงกับสถานะเดิมก่อนการเปลี่ยนแปลง
4. `new_status` ต้องตรงกับสถานะปัจจุบันใน `service_registrations` หลังการเปลี่ยนแปลง
5. การปรับปรุงสถานะ Registration และการเพิ่ม History ต้องเกิดภายใน Transaction เดียวกัน
6. ห้ามลบประวัติเดิมเพื่อแก้ไขข้อผิดพลาดโดยไม่มีขั้นตอน Audit ที่ตรวจสอบได้
7. ต้องกำหนดลำดับการเปลี่ยนสถานะที่อนุญาต เช่น
   - `REGISTERED` → `WAITING_TRIAGE`, `WAITING_SERVICE`, `CANCELLED`
   - `WAITING_TRIAGE` → `TRIAGE_IN_PROGRESS`, `CANCELLED`
   - `TRIAGE_IN_PROGRESS` → `WAITING_SERVICE`, `CANCELLED`
   - `WAITING_SERVICE` → `IN_SERVICE`, `CANCELLED`
   - `IN_SERVICE` → `COMPLETED`, `CANCELLED` (รองรับกรณีสัตว์เลี้ยงออกจากการรักษากลางคัน / `LEFT_WITHOUT_COMPLETION` หรือยกเลิกกลางกระบวนการ โดยต้องบันทึกเหตุผลใน `change_reason` และซิงค์กับ `clinical.clinical_encounters` และ `appointment.queue_status_histories`)
8. หากสัตว์เลี้ยงต้องกลับไปประเมิน Triage ซ้ำ ต้องบันทึกประวัติการประเมินใหม่ใน `triage_assessments` และกำหนดกระบวนการเปลี่ยนสถานะให้สอดคล้องกัน
9. สถานะ `COMPLETED` และ `CANCELLED` เป็นสถานะสิ้นสุดของ Registration ตามกระบวนการปกติ หากต้องรับบริการใหม่ควรสร้าง Registration ใหม่
