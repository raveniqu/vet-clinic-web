# Development Roadmap (Part 2): ฝั่ง Command (`POST` / `PUT` / `DELETE`) สำหรับโมดูล Owners

เอกสารนี้เป็นส่วนต่อยอดของ [docs/owners/1.md](./1.md) โดยอิงจาก **โค้ดเบสจริงปัจจุบันใน `src/`** และ **OpenAPI Specification ล่าสุดจาก MCP `apidog_vet_clinic`** (`x-download-time: 2026-11-25T07:58:17.337Z`) เพื่อออกแบบและพัฒนาฝั่ง Command ทั้ง 3 Operations:
1. `POST /api/v1/owners` (`registerOwnerFn` — ลงทะเบียนเจ้าของสัตว์รายใหม่)
2. `PUT /api/v1/owners/{id}` (`updateOwnerFn` — แก้ไขข้อมูลเจ้าของสัตว์ ที่อยู่ และความยินยอม PDPA)
3. `DELETE /api/v1/owners/{id}` (`deleteOwnerFn` — Soft-delete เจ้าของสัตว์แบบ Idempotent)

> **กติกาที่รักษาไว้ทุกบรรทัด:**
> - ยึด **Domain-First (Tactical DDD + Clean Architecture + ACL)** ตาม [architecture.md](../../.agents/rules/architecture.md), [globals.md](../../.agents/rules/globals.md) และ [server.md](../../.agents/rules/server.md)

> - เนื้อหาสลับระหว่าง **คำอธิบายสถาปัตยกรรม/เหตุผล** กับ **โค้ดฉบับสมบูรณ์ทุกไฟล์ที่เกี่ยวข้อง**

### 0.1 สรุปสัญญาฝั่ง Command จาก MCP OpenAPI

| Operation | Endpoint & HTTP Status | กฎธุรกิจและข้อจำกัดจาก MCP Spec |
| --- | --- | --- |
| **Create (`createOwner`)** | `POST /api/v1/owners`<br>สำเร็จ: `201 Created` (+ `Location` header)<br>ผิดพลาด: `400`, `401`, `403`, **`409`**, `500` | - Payload แยกด้วย `type` (`INDIVIDUAL` vs `JURISTIC`, `additionalProperties: false`)<br>- `INDIVIDUAL`: บังคับ `prefix` (`MR`/`MRS`/`MS`), `last_name` (`1..100`), `date_of_birth`, `gender` (`MALE`/`FEMALE`/`OTHER`)<br>- `JURISTIC`: บังคับ `prefix` (`COMMERCIAL`/`NON_PROFIT`/`OTHER`) และ **ห้ามส่ง** `last_name`, `date_of_birth`, `gender`<br>- `addresses.residential` **บังคับ**, `addresses.billing` optional/nullable, `is_default: true` ได้ไม่เกิน 1 ที่อยู่<br>- `consents.privacy_policy` **ต้องเป็น `true`**<br>- `owner_code` ถูกสร้างอัตโนมัติใน DB (`OWN-YYYYMMDD-NNNN`)<br>- ซ้ำใน `tax_id`, `phone_no`, `email`, `line_id` คืน `409 Conflict` |

### 0.2 ประเด็นวิกฤตเชิงสถาปัตยกรรม 5 ข้อที่แก้ใน Roadmap นี้

1. **`ownerCode` ตอนสร้างใหม่ (`Owner.create`) ยังไม่มีค่าจนกว่า Backend จะสร้างให้:**
   ในโค้ดเดิม `CreateOwnerParams` บังคับส่ง `ownerCode: OwnerCode` แต่ฝั่ง Client ไม่ได้เป็นผู้กำหนด `owner_code` (Backend เป็นคนรัน sequence ใน transaction) ดังนั้น `Owner` Aggregate ต้องรองรับ `ownerCode: OwnerCode | null` ในสถานะ Transient (`Owner.create`) และบังคับ `ownerCode !== null` เมื่อ `Owner.reconstitute` และก่อน `OwnerMapper.toDto`
2. **ความต่างของ `gender` ระหว่าง Domain (`NOT_SPECIFIED`) กับ API (`OTHER`):**
   Domain ใช้ `"MALE" | "FEMALE" | "NOT_SPECIFIED"` ตาม Database Schema Doc ส่วน API Command ใช้ `"MALE" | "FEMALE" | "OTHER"` เราคง Domain เป็น `"NOT_SPECIFIED"` และให้ ACL ใน `owner-api.repository.ts` แปลง `"NOT_SPECIFIED"` → `"OTHER"` ตอนส่ง `POST`/`PUT` (และ `"OTHER"` → `"NOT_SPECIFIED"` ตอนอ่านกลับ)
3. **ข้อบกพร่องใน Apidog Component Schema ของ `201 Created`:**
   ใน MCP Spec ล่าสุด `OwnerIndividualResponse.json` และ `OwnerJuristicResponse.json` มีเฉพาะ `{ id }` (`additionalProperties: false`) ซึ่งขัดกับ Pseudocode ข้อ 12 ที่บอกให้คืน Payload เต็ม ดังนั้นใน Infrastructure `create()` จะรองรับทั้ง **Full Detail Payload** (1 HTTP call) และ **Minimal `{ id }` Fallback** (ยิง `findById(id)` ต่ออัตโนมัติถ้า Mock ส่งแค่ `{ id }`) เพื่อไม่ให้พังกับ Apidog Cloud Mock
4. **กลยุทธ์ Aggregate Loading ของ `UpdateOwnerUseCase` vs `DeleteOwnerUseCase`:**
   - `UpdateOwnerUseCase`: โหลด `Owner` ผ่าน `findById(ownerId)` → สั่ง `owner.updateProfile(...)` เพื่อตรวจ Invariant สำคัญใน Domain (เช่น ห้ามเปลี่ยน `ownerType`, รักษา `ownerCode` และ `createdAt`) → บันทึกด้วย `ownerRepository.update(owner)` (และคืน `204` / `void` โดยไม่ยิง `GET` ซ้ำอีกรอบ)
   - `DeleteOwnerUseCase`: ตาม [server.md ข้อ 14](../../.agents/rules/server.md#L91-L95) **ห้ามทำ `SELECT`/`findById` ก่อนลบ** เพราะ `DELETE /api/v1/owners/{id}` เป็น Idempotent `204` การยิง `findById` ก่อนจะทำให้เสีย Round-trip และทำลายความหมาย Idempotent ของ Backend
5. **TanStack Start `createServerFn` รองรับเฉพาะ `method: "GET" | "POST"`:**
   ใน `@tanstack/react-start@1.169.7` ไม่สามารถระบุ `method: "PUT"` หรือ `method: "DELETE"` ใน `createServerFn()` ได้ (TypeScript อนุญาตเฉพาะ `"GET" | "POST"`) ดังนั้น Gateway ทั้ง `registerOwnerFn`, `updateOwnerFn` และ `deleteOwnerFn` ต้องใช้ `createServerFn({ method: "POST" })` แล้วปล่อยให้ Infrastructure `ApiOwnerRepository` ส่ง HTTP `POST`, `PUT`, `DELETE` ไปยัง Backend ERP API ตามลำดับ

## 1. Phase 1 — อัปเดต Shared Schemas สำหรับ Command (`src/shared/schemas/owners.schema.ts`)

### คำอธิบายเชิงสถาปัตยกรรม
- ใน Zod v4 (`zod@4.6.7`) ไม่สามารถเรียก `.omit()` บน `z.discriminatedUnion()` ได้ตรงๆ จึงออกแบบ `ownerWritePayloadSchema` เป็น Discriminated Union กลางที่ใช้ร่วมกันระหว่าง `registerOwnerInputSchema` และ `updateOwnerInputSchema` (ซึ่งครอบด้วย `z.object({ ownerId, payload })`)
- แยกความเข้มงวดระหว่าง **Read DTO (`ownerDetailsResponseSchema`)** กับ **Write Input (`ownerWritePayloadSchema`)**:
  - ฝั่ง Write (`INDIVIDUAL`) บังคับ `lastName` (`1..100`), `dateOfBirth`, `gender`, `acquisitionChannel` ไม่เป็น `null` ตามสัญญาจริงของ `POST`/`PUT`
  - ฝั่ง Write (`JURISTIC`) **ไม่มีฟิลด์** `lastName`, `dateOfBirth`, `gender` ใน Contract เพื่อไม่ให้ UI ส่งข้อมูลที่ไม่เกี่ยวข้องเข้ามา
  - `consents.privacyPolicy` ใช้ `z.literal(true)` เพื่อบังคับรับทราบ Privacy Policy ตั้งแต่ Boundary
  - เพิ่ม `.superRefine()` ใน `ownerWriteAddressesSchema` ตรวจว่า `residential.isDefault` และ `billing?.isDefault` ห้ามเป็น `true` พร้อมกัน

## 2. Phase 2 — อัปเดต Domain Aggregate & Repository Interface

### คำอธิบายเชิงสถาปัตยกรรม
1. **`OwnerProps.ownerCode` เปลี่ยนเป็น `OwnerCode | null`:**
   - ใน `Owner.create(...)` (Transient ก่อนส่งไปสร้างที่ ERP) กำหนด `ownerCode: null`
   - ใน `Owner.reconstitute(...)` (โหลดกลับจาก ERP) บังคับ `ownerCode !== null`
2. **เพิ่ม Domain Method `updateProfile(params: UpdateOwnerProfileParams)` ใน `owner.entity.ts`:**
   - **Invariant 1 (Immutable `ownerType`):** หาก `params.classification.ownerType !== this.props.classification.ownerType` ให้โยน `ValidationDomainError` ทันที
   - **Invariant 2 (Preserve Identity & Sequence):** รักษา `ownerCode` และ `createdAt` เดิมไว้ ห้ามทับ
   - **Invariant 3 (Command Completeness):** ทั้ง `Owner.create` และ `owner.updateProfile` ต้องมี `residential !== null`, `consents.privacyPolicy === true`, `acquisitionChannel !== null`, และถ้าเป็น `INDIVIDUAL` ต้องมี `lastName` (`1..100`) และ `dateOfBirth !== null`
   - **Domain Event:** เพิ่ม `OwnerUpdated` เมื่อ `updateProfile` สำเร็จ
3. **ปรับ `owner.entity.ts` บรรทัดที่ Biome เตือน:** เปลี่ยน `!billing || !billing.isDefault` เป็น `!billing?.isDefault` เพื่อให้ `biome check` เป็น `0 warnings`
4. **อัปเดต `IOwnerRepository` ([owner.interface.ts](../../src/server/domain/owners/interfaces/owner.interface.ts)):** เพิ่ม `create`, `update`, `deleteById` โดยรับ/คืนเฉพาะ `Owner` และ `number` (Pure Domain Contract)

function normalizeAndValidateClassification(
	classification: OwnerClassification,
): OwnerClassification {
	const lastName = normalizeOptionalString(
		classification.lastName,
		"lastName",
		150,
	);

	if (classification.ownerType === "INDIVIDUAL") {
		if (!isIndividualPrefix(classification.prefix)) {
			throw new ValidationDomainError(
				`คำนำหน้า "${classification.prefix}" ไม่ถูกต้องสำหรับเจ้าของที่เป็นบุคคลธรรมดา`,
			);
		}
		return {
			ownerType: "INDIVIDUAL",
			prefix: classification.prefix,
			lastName,
			dateOfBirth: classification.dateOfBirth,
			gender: classification.gender,
		};
	}

	if (!isJuristicPrefix(classification.prefix)) {
		throw new ValidationDomainError(
			`คำนำหน้า "${classification.prefix}" ไม่ถูกต้องสำหรับเจ้าของประเภทนิติบุคคล`,
		);
	}
	if (classification.dateOfBirth !== null) {
		throw new ValidationDomainError("เจ้าของประเภทนิติบุคคลไม่สามารถมีวันเกิดได้");
	}
	if (classification.gender !== "NOT_SPECIFIED") {
		throw new ValidationDomainError(
			'เจ้าของประเภทนิติบุคคลต้องระบุเพศเป็น "NOT_SPECIFIED" เท่านั้น',
		);
	}

	return {
		ownerType: "JURISTIC",
		prefix: classification.prefix,
		lastName,
		dateOfBirth: null,
		gender: "NOT_SPECIFIED",
	};
}

function normalizeWriteClassification(
	classification: OwnerWriteClassification,
): OwnerClassification {
	if (classification.ownerType === "INDIVIDUAL") {
		return {
			ownerType: "INDIVIDUAL",
			prefix: classification.prefix,
			lastName: normalizeRequiredString(
				classification.lastName,
				"lastName",
				100,
			),
			dateOfBirth: classification.dateOfBirth,
			gender: classification.gender,
		};
	}

	return {
		ownerType: "JURISTIC",
		prefix: classification.prefix,
		lastName: null,
		dateOfBirth: null,
		gender: "NOT_SPECIFIED",
	};
}

function assertWriteInvariants(
	params: CreateOwnerParams | UpdateOwnerProfileParams,
): void {
	if (!params.consents.privacyPolicy) {
		throw new ValidationDomainError(
			"ต้องให้ความยินยอมนโยบายความเป็นส่วนตัว (privacyPolicy) ก่อนบันทึกข้อมูล",
		);
	}
	if (!params.addresses.residential) {
		throw new ValidationDomainError(
			"ต้องระบุที่อยู่ปัจจุบัน (residential) อย่างน้อย 1 รายการ",
		);
	}
}

function normalizeAndValidateAddresses(
	addresses: OwnerAddresses,
): OwnerAddresses {
	const residential = addresses.residential;
	const billing = addresses.billing;

	if (residential?.isDefault && billing?.isDefault) {
		throw new ValidationDomainError(
			"สามารถกำหนดเป็นที่อยู่หลัก (isDefault) ได้เพียง 1 รายการเท่านั้น",
		);
	}

	if (residential && !residential.isDefault && !billing?.isDefault) {
		return Object.freeze({
			residential: residential.withDefault(true),
			billing,
		});
	}

	return Object.freeze({
		residential,
		billing,
	});
}

function validateAndNormalizeProps(props: OwnerProps): OwnerProps {
	if (
		Number.isNaN(props.createdAt.getTime()) ||
		Number.isNaN(props.updatedAt.getTime())
	) {
		throw new ValidationDomainError("วันที่สร้างและวันที่แก้ไขข้อมูลเจ้าของสัตว์ต้องถูกต้อง");
	}
	if (props.updatedAt.getTime() < props.createdAt.getTime()) {
		throw new ValidationDomainError(
			"วันที่อัปเดตข้อมูลเจ้าของสัตว์ต้องไม่เก่ากว่าวันที่สร้างข้อมูล",
		);
	}

	return {
		ownerCode: props.ownerCode,
		classification: normalizeAndValidateClassification(props.classification),
		firstName: normalizeRequiredString(props.firstName, "firstName", 255),
		taxId: props.taxId,
		phoneNumber: normalizeRequiredString(props.phoneNumber, "phoneNumber", 30),
		lineId: normalizeOptionalString(props.lineId, "lineId", 100),
		email: normalizeEmail(props.email),
		acquisitionChannel: props.acquisitionChannel,
		addresses: normalizeAndValidateAddresses(props.addresses),
		consents: props.consents,
		createdAt: new Date(props.createdAt.getTime()),
		updatedAt: new Date(props.updatedAt.getTime()),
	};
}

export class Owner extends AggregateRoot<OwnerProps, number> {
	private constructor(ownerId: number, props: OwnerProps) {
		super(ownerId, props);
	}

	static create(params: CreateOwnerParams): Owner {
		assertWriteInvariants(params);
		const now = new Date();
		const validated = validateAndNormalizeProps({
			ownerCode: null,
			classification: normalizeWriteClassification(params.classification),
			firstName: params.firstName,
			taxId: params.taxId,
			phoneNumber: params.phoneNumber,
			lineId: params.lineId,
			email: params.email,
			acquisitionChannel: params.acquisitionChannel,
			addresses: params.addresses,
			consents: params.consents,
			createdAt: now,
			updatedAt: now,
		});

		const owner = new Owner(TRANSIENT_OWNER_ID, validated);
		owner.addDomainEvent({
			eventName: "OwnerCreated",
			occurredAt: now,
		});
		return owner;
	}

	static reconstitute(ownerId: number, props: OwnerProps): Owner {
		if (!Number.isInteger(ownerId) || ownerId <= 0) {
			throw new ValidationDomainError("รหัสเจ้าของสัตว์ที่บันทึกไว้ต้องเป็นจำนวนเต็มบวก");
		}
		if (props.ownerCode === null) {
			throw new ValidationDomainError("ข้อมูลเจ้าของสัตว์ที่บันทึกไว้ต้องมี ownerCode");
		}
		return new Owner(ownerId, validateAndNormalizeProps(props));
	}

	updateProfile(params: UpdateOwnerProfileParams): void {
		if (
			params.classification.ownerType !== this.props.classification.ownerType
		) {
			throw new ValidationDomainError(
				"ไม่สามารถเปลี่ยนประเภทเจ้าของสัตว์ (ownerType) ได้",
			);
		}
		assertWriteInvariants(params);

		const now = new Date();
		this.props = validateAndNormalizeProps({
			ownerCode: this.props.ownerCode,
			classification: normalizeWriteClassification(params.classification),
			firstName: params.firstName,
			taxId: params.taxId,
			phoneNumber: params.phoneNumber,
			lineId: params.lineId,
			email: params.email,
			acquisitionChannel: params.acquisitionChannel,
			addresses: params.addresses,
			consents: params.consents,
			createdAt: this.props.createdAt,
			updatedAt: now,
		});

		this.addDomainEvent({
			eventName: "OwnerUpdated",
			occurredAt: now,
		});
	}

	updateContact(params: UpdateOwnerContactParams): void {
		this.props = validateAndNormalizeProps({
			...this.props,
			phoneNumber: params.phoneNumber,
			lineId: params.lineId,
			email: params.email,
			updatedAt: new Date(),
		});
	}

	updateAddresses(addresses: OwnerAddresses): void {
		this.props = validateAndNormalizeProps({
			...this.props,
			addresses,
			updatedAt: new Date(),
		});
	}

	updateConsents(partial: Partial<OwnerConsentsProps>): void {
		this.props = validateAndNormalizeProps({
			...this.props,
			consents: this.props.consents.withUpdates(partial),
			updatedAt: new Date(),
		});
	}

	get ownerCode(): OwnerCode | null {
		return this.props.ownerCode;
	}

	get classification(): OwnerClassification {
		return this.props.classification;
	}

	get ownerType(): OwnerType {
		return this.props.classification.ownerType;
	}

	get prefix(): OwnerPrefix {
		return this.props.classification.prefix;
	}

	get firstName(): string {
		return this.props.firstName;
	}

	get lastName(): string | null {
		return this.props.classification.lastName;
	}

	get taxId(): TaxId {
		return this.props.taxId;
	}

	get dateOfBirth(): CalendarDate | null {
		return this.props.classification.dateOfBirth;
	}

	get gender(): OwnerGender {
		return this.props.classification.gender;
	}

	get phoneNumber(): string {
		return this.props.phoneNumber;
	}

	get lineId(): string | null {
		return this.props.lineId;
	}

	get email(): string | null {
		return this.props.email;
	}

	get acquisitionChannel(): AcquisitionChannel | null {
		return this.props.acquisitionChannel;
	}

	get residentialAddress(): OwnerAddress | null {
		return this.props.addresses.residential;
	}

	get billingAddress(): OwnerAddress | null {
		return this.props.addresses.billing;
	}

	get consents(): OwnerConsents {
		return this.props.consents;
	}

	get createdAt(): Date {

	}

}

## 3. Phase 3 — Application Layer: Mapper & 3 Command Use Cases

### คำอธิบายเชิงสถาปัตยกรรม
- **รวมศูนย์การแปลง DTO ↔ Domain Params ไว้ใน [owner.mapper.ts](../../src/server/application/mappers/owner.mapper.ts):** เพิ่ม `toCreateParams` และ `toUpdateProfileParams` เพื่อไม่ให้ `RegisterOwnerUseCase` และ `UpdateOwnerUseCase` เขียนโค้ดสร้าง `TaxId`, `CalendarDate`, `OwnerAddress`, `OwnerConsents` ซ้ำซ้อนกัน (DRY)
- **Guard `ownerCode` ใน `OwnerMapper.toDto(owner)`:** หากเผลอส่ง Transient `Owner` ที่ยังไม่ได้บันทึก (`ownerCode === null`) มาแปลงเป็น `OwnerDetailsResponse` จะโยน `ValidationDomainError` ชัดเจน
- **แยก 1 Use Case ต่อ 1 ไฟล์ (`register-owner`, `update-owner`, `delete-owner`):**
  - `RegisterOwnerUseCase`: `Owner.create(...)` → `ownerRepository.create(owner)` → `OwnerMapper.toDto(created)` (คืนข้อมูลเต็มรวม `ownerId` และ `ownerCode` ที่ Backend สร้างให้)
  - `UpdateOwnerUseCase`: `findById(ownerId)` → `NotFoundDomainError` ถ้าไม่พบ → `existing.updateProfile(...)` → `ownerRepository.update(existing)` → `void`
  - `DeleteOwnerUseCase`: เรียก `ownerRepository.deleteById(ownerId)` ตรงใน Single Round-trip แบบ Idempotent (ไม่เรียก `findById` ก่อนตาม `server.md` ข้อ 14)

			...base,
			ownerType: "JURISTIC",
			prefix: classification.prefix,
			dateOfBirth: null,
			gender: "NOT_SPECIFIED",
		};
	}

## 4. Phase 4 — Infrastructure & Anti-Corruption Layer (`src/server/infrastructure/`)

### คำอธิบายเชิงสถาปัตยกรรม
1. **ขยาย `ApiClient` ([api-client.ts](../../src/server/infrastructure/http/api-client.ts)) รองรับ Command HTTP Methods:**
   - สกัด `executeRequest(method, path, options)` เป็นเมธอดร่วม ไม่ให้โค้ด timeout, `AbortSignal.any`, headers และ network error handling ซ้ำกันระหว่าง `GET`, `POST`, `PUT`, `DELETE`
   - ใส่ Header `Content-Type: application/json` เฉพาะเมื่อมี body (`POST` / `PUT`)
   - เมธอด `putNoContent` และ `deleteNoContent` ไม่เรียก `response.json()` เมื่อสำเร็จ เพื่อรองรับ `204 No Content` (Empty Body) อย่างปลอดภัย
   - เพิ่มการ Map `409 Conflict` → `ConflictDomainError` (ที่รองรับอยู่แล้ว) สำหรับความซ้ำซ้อนของ `tax_id`, `phone_no`, `email`, `line_id`
2. **เพิ่ม Write Wire Schemas ใน `owner-api.schemas.ts`:**
   - `ownerApiWriteRequestSchema` (`z.discriminatedUnion("type", ...)`): ฝั่ง `JURISTIC` **ไม่มี** `last_name`, `date_of_birth`, `gender` (`strict` เทียบเท่า `additionalProperties: false` ใน OpenAPI) และฝั่ง `INDIVIDUAL` ใช้ `gender: z.enum(["MALE", "FEMALE", "OTHER"])` พร้อม `consents.privacy_policy: z.literal(true)`
   - `ownerApiCreatedResponseSchema`: ใช้ `z.union([ownerApiDetailResponseSchema, z.strictObject({ id: z.int().positive() })])` เพื่อรองรับทั้ง Backend จริงที่คืนรายละเอียดครบ และ Apidog Mock ที่อิง Component Schema `{ id }` (ใช้ `strictObject` เพื่อป้องกัน payload พังๆ ตกไปเข้า branch `{ id }`)
3. **แปล Domain → Wire Request ใน `owner-api.repository.ts` (`toWriteRequest`):**
   - ตรวจสอบและแปลง `"NOT_SPECIFIED"` → `"OTHER"` สำหรับ `INDIVIDUAL`
   - ตัด `last_name`, `date_of_birth`, `gender` ออกอัตโนมัติสำหรับ `JURISTIC`

import { z } from "zod";
import {
	ConflictDomainError,
	ForbiddenDomainError,
	NotFoundDomainError,
	UnauthorizedDomainError,
	ValidationDomainError,
} from "#/server/domain/common/errors";
import { UpstreamServiceError } from "./errors";
import { getApiRequestContext } from "./request-context";

const apiErrorResponseSchema = z.object({
	error_message: z.string().min(1),
});

const SAFE_COOKIE_VALUE_PATTERN = /^[^\s;]+$/;

export interface ApiClientConfig {
	readonly baseUrl: string;
	readonly timeoutMs: number;
	readonly apidogToken?: string;
}

export type ApiQueryParams = Record<string, string | number | undefined>;
export type ApiHttpMethod = "GET" | "POST" | "PUT" | "DELETE";

export interface ApiGetOptions {
	readonly query?: ApiQueryParams;
}

export interface ApiRequestOptions {
	readonly query?: ApiQueryParams;
	readonly body?: unknown;
}

export class ApiClient {
	private readonly baseUrl: string;
	private readonly timeoutMs: number;
	private readonly apidogToken?: string;

	constructor(config: ApiClientConfig) {
		this.baseUrl = config.baseUrl.replace(/\/+$/, "");
		this.timeoutMs = config.timeoutMs;
		this.apidogToken = config.apidogToken;
	}

	async getJson<TOutput>(
		path: string,
		schema: z.ZodType<TOutput>,
		options?: ApiGetOptions,
	): Promise<TOutput> {
		const response = await this.executeRequest("GET", path, {
			query: options?.query,
		});
		if (!response.ok) {
			throw await this.mapHttpError(path, response);
		}
		return this.parseSuccessResponse(path, response, schema);
	}

	async getOptionalJson<TOutput>(
		path: string,
		schema: z.ZodType<TOutput>,
		options?: ApiGetOptions,
	): Promise<TOutput | null> {
		const response = await this.executeRequest("GET", path, {
			query: options?.query,
		});
		if (response.status === 404) {
			return null;
		}
		if (!response.ok) {
			throw await this.mapHttpError(path, response);
		}
		return this.parseSuccessResponse(path, response, schema);
	}

	async postJson<TOutput>(
		path: string,
		body: unknown,
		schema: z.ZodType<TOutput>,
		options?: ApiGetOptions,
	): Promise<TOutput> {
		const response = await this.executeRequest("POST", path, {
			query: options?.query,
			body,
		});
		if (!response.ok) {
			throw await this.mapHttpError(path, response);
		}
		return this.parseSuccessResponse(path, response, schema);
	}

	async putNoContent(
		path: string,
		body: unknown,
		options?: ApiGetOptions,
	): Promise<void> {
		const response = await this.executeRequest("PUT", path, {
			query: options?.query,
			body,
		});
		if (!response.ok) {
			throw await this.mapHttpError(path, response);
		}
	}

	async deleteNoContent(path: string, options?: ApiGetOptions): Promise<void> {
		const response = await this.executeRequest("DELETE", path, {
			query: options?.query,
		});
		if (!response.ok) {
			throw await this.mapHttpError(path, response);
		}
	}

	private async executeRequest(
		method: ApiHttpMethod,
		path: string,
		options?: ApiRequestOptions,
	): Promise<Response> {
		const url = this.buildUrl(path, options?.query);
		const requestContext = getApiRequestContext();
		const hasBody = options?.body !== undefined;
		const headers = this.buildHeaders(requestContext?.sessionId, hasBody);
		const timeoutSignal = AbortSignal.timeout(this.timeoutMs);
		const signal = requestContext?.signal
			? AbortSignal.any([requestContext.signal, timeoutSignal])
			: timeoutSignal;

		try {
			return await fetch(url, {
				method,
				headers,
				body: hasBody ? JSON.stringify(options.body) : undefined,
				signal,
			});
		} catch (error) {
			if (error instanceof DOMException && error.name === "TimeoutError") {
				throw new UpstreamServiceError(
					"Upstream API request timed out. Please try again.",
				);
			}
			if (error instanceof DOMException && error.name === "AbortError") {
				throw new UpstreamServiceError("Upstream API request was cancelled.");
			}
			const errorName =
				error instanceof Error ? error.name : "UnknownNetworkError";
			console.error("[ApiClient] Network failure", {
				method,
				path,
				errorName,
			});
			throw new UpstreamServiceError("Unable to reach upstream API service.");
		}
	}

	private buildUrl(path: string, query?: ApiQueryParams): URL {
		const normalizedPath = path.startsWith("/") ? path : `/${path}`;
		const url = new URL(`${this.baseUrl}${normalizedPath}`);

		if (!query) {
			return url;
		}

		for (const [key, value] of Object.entries(query)) {
			if (value === undefined) {
				continue;
			}
			if (typeof value === "string" && value.length === 0) {
				continue;
			}
			url.searchParams.set(key, String(value));
		}

		return url;
	}

	private buildHeaders(sessionId?: string, hasBody = false): Headers {
		const headers = new Headers({
			Accept: "application/json",
		});

		if (hasBody) {
			headers.set("Content-Type", "application/json");
		}

		if (sessionId) {
			if (!SAFE_COOKIE_VALUE_PATTERN.test(sessionId)) {
				throw new UnauthorizedDomainError("Invalid session identifier.");
			}
			headers.set("Cookie", `session_id=${sessionId}`);
		}

		if (this.apidogToken) {
			headers.set("apidogToken", this.apidogToken);
		}

		return headers;
	}

	private async parseSuccessResponse<TOutput>(
		path: string,
		response: Response,
		schema: z.ZodType<TOutput>,
	): Promise<TOutput> {
		let rawBody: unknown;
		try {
			rawBody = await response.json();
		} catch {
			console.error("[ApiClient] Invalid JSON response", {
				path,
				status: response.status,
			});
			throw new UpstreamServiceError(
				"Received malformed JSON from upstream API.",
			);
		}

		const parsed = schema.safeParse(rawBody);
		if (!parsed.success) {
			const issuePaths = parsed.error.issues
				.slice(0, 10)
				.map((issue) => issue.path.join(".") || "<root>");
			console.error("[ApiClient] Response contract validation failed", {
				path,
				issueCount: parsed.error.issues.length,
				issuePaths,
			});
			throw new UpstreamServiceError(
				"Upstream API returned an unexpected payload format.",
			);
		}

		return parsed.data;
	}

	private async mapHttpError(path: string, response: Response): Promise<Error> {
		const message = await this.readErrorMessage(response);

		switch (response.status) {
			case 400:
			case 422:
				return new ValidationDomainError(message);
			case 401:
				return new UnauthorizedDomainError(message);
			case 403:
				return new ForbiddenDomainError(message);
			case 404:
				return new NotFoundDomainError(message);
			case 409:
				return new ConflictDomainError(message);
			default:
				console.error("[ApiClient] Upstream HTTP error", {
					path,
					status: response.status,
				});
				return new UpstreamServiceError(
					"An unexpected upstream service error occurred.",
				);
		}
	}

	private async readErrorMessage(response: Response): Promise<string> {
		try {
			const rawBody: unknown = await response.json();
			const parsed = apiErrorResponseSchema.safeParse(rawBody);
			if (parsed.success) {
				return parsed.data.error_message;
			}
		} catch {
			// Fallback to HTTP status text when error body is not JSON.
		}

		return response.statusText || `HTTP ${response.status}`;
	}
}

## 6. Four Engineering Angles & Verification Plan (หลังนำไปใช้งานจริง)

### 6.1 การประเมิน 4 มิติ

| มิติ | สิ่งที่จัดการใน Roadmap นี้ | Trade-off / ความเสี่ยงที่เหลืออยู่ |
| --- | --- | --- |
| **Correctness** | แยก Write DTO ให้ซื่อสัตย์ต่อ API (`INDIVIDUAL` บังคับ `lastName` + `dateOfBirth`, `JURISTIC` ไม่ส่งฟิลด์บุคคล), รองรับ `ownerCode: null` ใน Transient Entity, ป้องกันเปลี่ยน `ownerType` ใน `updateProfile`, รองรับ `204` ไม่ parse JSON และรองรับ `{ id }` fallback ใน `POST` | `UpdateOwnerUseCase` ยิง `GET` ก่อน `PUT` หากเกิด race condition ถูกลบระหว่าง 2 call Backend จะคืน `404` ซึ่ง `ApiClient` จับเป็น `NotFoundDomainError` ให้อยู่แล้ว |
| **Performance** | `DeleteOwnerUseCase` ยิง `DELETE` ครั้งเดียว (Single Round-trip, Idempotent) และ `UpdateOwnerUseCase` คืน `void` ไม่ยิง `GET` หลัง `204`; ส่วน `create()` ใช้ 1 call หาก Backend คืน payload เต็ม | `UpdateOwnerUseCase` มีต้นทุนเพิ่ม 1 `GET` ก่อน `PUT` เพื่อโหลด `Owner` Aggregate มาตรวจ `ownerType` immutability (หากต้องการลดในอนาคต สามารถส่ง `expectedOwnerType` หรือให้ Backend ตรวจอย่างเดียวได้ แต่จะสูญเสีย Domain protection ใน BFF) |
| **Security** | ใช้ `Cache-Control: no-store`, บังคับ `REQUIRE_SESSION_COOKIE`, ตรวจ `SAFE_COOKIE_VALUE_PATTERN`, ไม่ log plaintext `tax_id`/`body` ใน `ApiClient`, บังคับ `privacyPolicy: true` และใช้ `.strictObject()` ป้องกัน extra properties ใน request/minimal response | สำหรับ RPC ที่ใช้ `method: "POST"` ควรเพิ่ม Origin Check Middleware ใน `src/start.ts` หรือ `apiContextMiddleware` หาก deploy ข้าม subdomain |
| **Maintainability** | แยก 1 Use Case ต่อ 1 ไฟล์, รวมศูนย์ VO mapping ไว้ที่ `OwnerMapper`, ใช้ `executeRequest()` ร่วมกันใน `ApiClient`, และขัง quirks (`OTHER` ↔ `NOT_SPECIFIED`, omission of juristic fields) ไว้ใน `owner-api.repository.ts` | เมื่อทีม Backend แก้ `OwnerIndividualResponse.json` ใน Apidog ให้ครบ อย่าลืมคง/ตรวจสอบ contract test ของ `create()` |

2. **Contract & Domain Unit Tests ที่แนะนำ (ยังไม่รันในขั้นนี้):**
