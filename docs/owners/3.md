# แผนแก้ไข Blocker ฝั่ง Client Caches & App Wiring ก่อนเริ่มพัฒนา `client/features/**`

เอกสารนี้อธิบายสาเหตุต้นตอ (Root Cause), แนวทางแก้ไขแบบไม่กระทบสัญญาเดิม, โค้ดฉบับสมบูรณ์ทุกไฟล์, และการประเมินความเสี่ยงสำหรับ **3 กลุ่ม Blocker** ที่พบจากการตรวจ `src/client/caches/**`, `src/router.tsx`, `src/routes/__root.tsx` และ `src/client/shared/shadcn/components/ui/toast.tsx` (เทียบกับแพ็กเกจจริงใน `package.json`: `@tanstack/react-query@5.108.4`, `@tanstack/react-router-ssr-query@1.167.3`, `@tanstack/react-start@1.169.7`, `@base-ui/react@1.9.0`, `@biomejs/biome@2.6.8`)

---

## 1. Evidence & Causal Trace (หลักฐานและลูกโซ่สาเหตุ)

### Verified Facts (ตรวจพบจริงจากโค้ดและ `node_modules`)
1. `src/router.tsx` (บรรทัด 1–19) ยังสร้าง `createTanStackRouter` โดยไม่มี `queryClient`, ไม่มี `context: { queryClient }` และไม่ได้เรียก `setupRouterSsrQueryIntegration` จาก `@tanstack/react-router-ssr-query`
2. `src/routes/__root.tsx` (บรรทัด 7–54) ยังใช้ `createRootRoute` แทน `createRootRouteWithContext<RouterContext>()` และไม่ได้ mount `<Toaster>` จาก `src/client/shared/shadcn/components/ui/toast.tsx`
3. `node_modules/@tanstack/router-ssr-query-core/dist/esm/index.js` (บรรทัด 6–105) และ `node_modules/@tanstack/react-router-ssr-query/dist/esm/index.js` (บรรทัด 6–17) ผูก `queryClient` กับ SSR `dehydrate`/`hydrate` และ `QueryClientProvider` ต่อ 1 `router` instance — จึงต้องสร้าง `createQueryClient()` **ภายใน `getRouter()`** ไม่ใช่ตัวแปร global ระดับ module เพื่อป้องกันการปะปนของ cache ข้าม user request บน SSR
4. `src/client/caches/owners/mutates/delete-owner.mutate.ts` (บรรทัด 14–18) เรียกเฉพาะ `queryClient.removeQueries({ queryKey: ownersKeys.detail(variables.ownerId) })` โดยไม่ได้ invalidate `ownersKeys.lists()` และไม่ได้ป้องกัน race refetch กรณีลบจากหน้า Detail ที่ยังมี observer active อยู่
5. `src/client/caches/global.ts` (บรรทัด 35–48) fallback ไปใช้ `error.message` ตรงๆ ใน `toast.add(...)` ขณะที่ `src/server-functions/middlewares/api-context.middleware.ts` (บรรทัด 42, 47) โยน `new Error("[${error.code}] ${error.message}")` ทำให้ข้อความบน Toast แสดง prefix `[DOMAIN_VALIDATION_ERROR]`, `[CONFLICT]`, `[UPSTREAM_SERVICE_ERROR]` ให้ผู้ใช้เห็นตรงๆ
6. `node_modules/@tanstack/react-query/build/modern/types.d.ts` (บรรทัด 82–91) ยืนยันว่า `UseSuspenseQueryOptions` ตัด `enabled`, `throwOnError`, และ `placeholderData` ออก ดังนั้น `queryOptions(...)` ใน `client/caches/owners/queries/*.query.ts` ต้องไม่ใส่ `enabled` หรือ `placeholderData` ไว้ภายใน เพื่อให้ใช้ได้ทั้งกับ `useSuspenseQuery` / `ensureQueryData` และ `useQuery` (ส่วน `enabled` / `keepPreviousData` ให้ส่งเพิ่มเติมที่ hook ปลายทางเมื่อใช้ `useQuery`)
7. `bun run check` (`biome check`) ยังไม่ผ่าน (`Exit 1`, 12 errors) จากการเว้นวรรคแบบ 2 spaces และลำดับ import ใน 7 ไฟล์ใต้ `src/client/caches/**`

### Causal Chain ของปัญหาหลักทั้ง 3 จุด

```text
[Blocker 1: App Wiring ขาด]
  router.tsx ไม่มี QueryClient + setupRouterSsrQueryIntegration
  └──> useQueryClient() / useQuery() ไม่มี Provider ──> Crash ทันทีเมื่อรัน Feature UI
  __root.tsx ไม่มี <Toaster>
  └──> toast.add(...) ใน global.ts ไม่มี <ToastProvider>/<ToastViewport> รับ event ──> Toast ไม่แสดง

[Blocker 2: Cache Lifecycle & Error UX]
  delete-owner.mutate.ts ลืม invalidate ownersKeys.lists()
  └──> หน้าตาราง List ยังโชว์รายการที่ลบไปแล้ว (Stale Cache)
  register/update invalidate ownersKeys.all กว้างเกินไป
  └──> ดึง detail ของเจ้าของคนอื่นที่ไม่เกี่ยวข้องใหม่โดยไม่จำเป็น
  api-context.middleware.ts แนบ [CODE] มากับ error.message + global.ts แสดง error.message ตรงๆ
  └──> ผู้ใช้เห็นข้อความทางเทคนิค เช่น [UPSTREAM_SERVICE_ERROR] หรือ [CONFLICT] บน Toast

[Blocker 3: Tooling Baseline]
  ไฟล์ใหม่ใน client/caches/** ใช้ spaces และ import order ไม่ตรง biome.json
  └──> bun run check ล้มเหลว (แม้ tsc และ biome lint จะผ่าน)
```

#### 1.3 อัปเดตไฟล์: `src/router.tsx`
- เรียก `createQueryClient()` **ภายใน `getRouter()`** เพื่อไม่ให้ SSR request แชร์ `QueryClient` ข้าม session/user
- เรียก `setupRouterSsrQueryIntegration({ router, queryClient })` ซึ่งจะ:
  - ห่อ Root ด้วย `<QueryClientProvider client={queryClient}>` ให้อัตโนมัติ
  - จัดการ `dehydrate` (server) / `hydrate` (client) รวมถึง streaming queries และ `redirect()` handling

```tsx
import { createRouter as createTanStackRouter } from "@tanstack/react-router";
import { setupRouterSsrQueryIntegration } from "@tanstack/react-router-ssr-query";
import { createQueryClient } from "#/client/caches/global";
import { routeTree } from "./routeTree.gen";

export function getRouter() {
	const queryClient = createQueryClient();

	const router = createTanStackRouter({
		routeTree,
		context: { queryClient },
		scrollRestoration: true,
		defaultPreload: "intent",
		defaultPreloadStaleTime: 0,
	});

	setupRouterSsrQueryIntegration({
		router,
		queryClient,
	});

	return router;
}

declare module "@tanstack/react-router" {
	interface Register {
		router: ReturnType<typeof getRouter>;
	}
}
```

### ขั้นที่ 2: แก้ Bug ใน Cache Mutations, Error Toast UX และ Query Options (Blocker 2)

#### 2.1 สร้างไฟล์ใหม่: `src/client/shared/helpers/rpc-error.ts`
- แยกข้อความรูปแบบ `[CODE] detail` ที่ส่งมาจาก `src/server-functions/middlewares/api-context.middleware.ts`
- แปลงรหัสโครงสร้าง (`UNAUTHORIZED`, `FORBIDDEN`, `UPSTREAM_SERVICE_ERROR`, `NOT_FOUND`) เป็นภาษาไทยที่ผู้ใช้เข้าใจง่าย และดึง `detail` สำหรับ `CONFLICT` / `DOMAIN_VALIDATION_ERROR` / `INVALID_STATE_TRANSITION` ออกมาโดยไม่โชว์ `[CODE]` ดิบ
- เตรียม `parseRpcError` ไว้ให้ Feature Form Hooks (ในอนาคต) สามารถเช็ก `parsed?.code === "CONFLICT"` เพื่อแสดง error ในฟอร์มพร้อมส่ง `meta: { errorToast: false }` ได้สะดวก

```ts
const RPC_ERROR_PATTERN = /^\[([A-Z_]+)\]\s*(.*)$/;

export type RpcErrorCode =
	| "DOMAIN_VALIDATION_ERROR"
	| "UNAUTHORIZED"
	| "FORBIDDEN"
	| "NOT_FOUND"
	| "CONFLICT"
	| "INVALID_STATE_TRANSITION"
	| "UPSTREAM_SERVICE_ERROR";

export interface ParsedRpcError {
	readonly code: RpcErrorCode | string;
	readonly detail: string;
}

const DEFAULT_FALLBACK_MESSAGE =
	"เกิดข้อผิดพลาดที่ไม่คาดคิด กรุณาลองใหม่อีกครั้ง";

const ERROR_CODE_FRIENDLY_MESSAGES: Partial<Record<RpcErrorCode, string>> = {
	UNAUTHORIZED: "เซสชันหมดอายุหรือยังไม่ได้เข้าสู่ระบบ กรุณาเข้าสู่ระบบใหม่อีกครั้ง",
	FORBIDDEN: "คุณไม่มีสิทธิ์เข้าถึงหรือดำเนินการรายการนี้",
	NOT_FOUND: "ไม่พบข้อมูลที่ต้องการ หรือข้อมูลอาจถูกลบออกจากระบบแล้ว",
	UPSTREAM_SERVICE_ERROR:
		"ไม่สามารถเชื่อมต่อบริการหลักได้ชั่วคราว กรุณาลองใหม่อีกครั้ง",
};

export function parseRpcError(error: unknown): ParsedRpcError | null {
	if (!(error instanceof Error)) {
		return null;
	}

	const match = RPC_ERROR_PATTERN.exec(error.message.trim());
	if (!match) {
		return null;
	}

	return {
		code: match[1],
		detail: match[2].trim(),
	};
}

export function getUserFriendlyErrorMessage(error: unknown): string {
	const parsed = parseRpcError(error);
	if (parsed) {
		const mappedMessage =
			ERROR_CODE_FRIENDLY_MESSAGES[parsed.code as RpcErrorCode];
		if (mappedMessage) {
			return mappedMessage;
		}
		if (parsed.detail.length > 0) {
			return parsed.detail;
		}
		return DEFAULT_FALLBACK_MESSAGE;
	}

	if (error instanceof Error && error.message.trim().length > 0) {
		return error.message;
	}

	return DEFAULT_FALLBACK_MESSAGE;
}
```

#### 2.2 อัปเดตไฟล์: `src/client/caches/global.ts`
- ใช้ `getUserFriendlyErrorMessage(error)` เป็น fallback ใน `MutationCache.onError` แทนการส่ง `error.message` ที่มี `[CODE]` ไปยัง `toast.add(...)`

```ts
import { MutationCache, QueryClient } from "@tanstack/react-query";
import { getUserFriendlyErrorMessage } from "#/client/shared/helpers/rpc-error";
import { toast } from "#/client/shared/shadcn/components/ui/toast";

declare module "@tanstack/react-query" {
	interface Register {
		mutationMeta: {
			successToast?: string | ((data: unknown) => string);
			errorToast?: string | ((error: Error) => string) | false;
		};
	}
}

export function createQueryClient() {
	return new QueryClient({
		defaultOptions: {
			queries: {
				staleTime: 30_000,
			},
		},
		mutationCache: new MutationCache({
			onSuccess: (data, _variables, _context, mutation) => {
				const meta = mutation.meta;
				if (!meta?.successToast) return;

				const message =
					typeof meta.successToast === "function"
						? meta.successToast(data)
						: meta.successToast;

				toast.add({
					description: message,
					type: "success",
				});
			},
			onError: (error, _variables, _context, mutation) => {
				const meta = mutation.meta;
				if (meta?.errorToast === false) return;

				const message =
					typeof meta?.errorToast === "function"
						? meta.errorToast(error)
						: (meta?.errorToast ?? getUserFriendlyErrorMessage(error));

				toast.add({
					description: message,
					type: "error",
				});
			},
		}),
	});
}
```

#### 2.3 อัปเดตไฟล์: `src/client/caches/owners/mutates/delete-owner.mutate.ts`
**เหตุผลเชิงลึกของการแก้ Bug ใน `onSuccess`:**
1. เดิมลบแค่ `detail(ownerId)` แล้วไม่ invalidate `ownersKeys.lists()` ทำให้หน้าตาราง List แสดงข้อมูลผีที่ถูกลบไปแล้ว
2. หากสั่ง `removeQueries` โดยไม่จำกัด `type: "inactive"` ในขณะที่ผู้ใช้กดลบจาก **หน้า Detail (`/owners/:id`)** ตัว observer ที่ยัง mount อยู่จะยิง `GET /api/v1/owners/:id` ซ้ำทันทีและได้ `404` ก่อนที่โค้ด UI จะ `navigate()` ออก
3. การใช้ลำดับ 4 คำสั่งด้านล่างแก้ได้ครบทั้ง 2 สถานการณ์:
   - `cancelQueries` หยุด request ค้างของ detail
   - `removeQueries(..., { exact: true, type: "inactive" })` ล้าง cache ทิ้งทันทีถ้าไม่ได้เปิดหน้า detail ค้างอยู่ (เช่น ลบจากหน้า List)
   - `invalidateQueries(..., { exact: true, refetchType: "none" })` มาร์กให้ detail กลายเป็น stale โดยยังไม่ยิง refetch ทันทีถ้าหน้า detail ยัง mount อยู่ (กัน `404` race และกัน stale data หากกด Back กลับมา)
   - `invalidateQueries({ queryKey: ownersKeys.lists() })` ให้ตารางรายชื่อโหลดข้อมูลล่าสุดทันที

```ts
import { useMutation, useQueryClient } from "@tanstack/react-query";
import { deleteOwnerFn } from "#/server-functions/owners/delete-owner.fn";
import type { DeleteOwnerInput } from "#/shared/schemas/owners.schema";
import { ownersKeys } from "../keys";

export function useDeleteOwnerMutation() {
	const queryClient = useQueryClient();

	return useMutation({
		mutationFn: (input: DeleteOwnerInput) => deleteOwnerFn({ data: input }),
		meta: {
			successToast: "ลบข้อมูลเจ้าของสัตว์เรียบร้อยแล้ว",
		},
		onSuccess: async (_data, variables) => {
			const detailKey = ownersKeys.detail(variables.ownerId);
			await queryClient.cancelQueries({ queryKey: detailKey });
			queryClient.removeQueries({
				queryKey: detailKey,
				exact: true,
				type: "inactive",
			});
			await Promise.all([
				queryClient.invalidateQueries({
					queryKey: detailKey,
					exact: true,
					refetchType: "none",
				}),
				queryClient.invalidateQueries({ queryKey: ownersKeys.lists() }),
			]);
		},
	});
}
```

#### 2.4 อัปเดตไฟล์: `src/client/caches/owners/mutates/register-owner.mutate.ts`
- เก็บ `createdOwner` ที่ได้จาก `registerOwnerFn` ลง `ownersKeys.detail(createdOwner.ownerId)` ทันที (`setQueryData`) เพื่อลดการยิง `GET` ซ้ำเมื่อนำทางไปหน้า Detail หลังสร้างเสร็จ
- Invalidate เฉพาะ `ownersKeys.lists()` (ไม่กระทบ detail อื่นที่ cache ไว้) และนำ `Promise.all` ที่ห่อคำสั่งเดียวออก

```ts
import { useMutation, useQueryClient } from "@tanstack/react-query";
import { registerOwnerFn } from "#/server-functions/owners/register-owner.fn";
import type { RegisterOwnerInput } from "#/shared/schemas/owners.schema";
import { ownersKeys } from "../keys";

export function useRegisterOwnerMutation() {
	const queryClient = useQueryClient();

	return useMutation({
		mutationFn: (input: RegisterOwnerInput) => registerOwnerFn({ data: input }),
		meta: {
			successToast: "เพิ่มเจ้าของใหม่สำเร็จ",
		},
		onSuccess: async (createdOwner) => {
			queryClient.setQueryData(
				ownersKeys.detail(createdOwner.ownerId),
				createdOwner,
			);
			await queryClient.invalidateQueries({ queryKey: ownersKeys.lists() });
		},
	});
}
```

#### 2.5 อัปเดตไฟล์: `src/client/caches/owners/mutates/update-owner.mutate.ts`
- Invalidate เฉพาะ `ownersKeys.lists()` และ `ownersKeys.detail(variables.ownerId)` แบบเจาะจงแทน `ownersKeys.all`

```ts
import { useMutation, useQueryClient } from "@tanstack/react-query";
import { updateOwnerFn } from "#/server-functions/owners/update-owner.fn";
import type { UpdateOwnerInput } from "#/shared/schemas/owners.schema";
import { ownersKeys } from "../keys";

export function useUpdateOwnerMutation() {
	const queryClient = useQueryClient();

	return useMutation({
		mutationFn: (input: UpdateOwnerInput) => updateOwnerFn({ data: input }),
		meta: { successToast: "บันทึกการแก้ไขเจ้าของสำเร็จ" },
		onSuccess: async (_data, variables) => {
			await Promise.all([
				queryClient.invalidateQueries({ queryKey: ownersKeys.lists() }),
				queryClient.invalidateQueries({
					queryKey: ownersKeys.detail(variables.ownerId),
					exact: true,
				}),
			]);
		},
	});
}
```

#### 2.6 ปรับปรุงไฟล์ Query Options (`get-owners.query.ts`, `get-owner-by-id.query.ts`, `keys.ts`)
- ตัด `staleTime: 30_000` ที่ซ้ำซ้อนออก เพื่อให้ `createQueryClient()` ใน `global.ts` เป็น Single Source of Truth
- **คง `queryOptions(...)` ให้ไม่มี `enabled` หรือ `placeholderData`** เพื่อรองรับทั้ง `useSuspenseQuery` / `ensureQueryData` และ `useQuery` (หาก Feature Hook ใช้ `useQuery` และต้องการคงแถวเดิมตอนเปลี่ยนหน้า ให้ส่ง `{ ...ownersListQuery(params), placeholderData: keepPreviousData }` หรือ `{ ...getOwnerByIdQuery(ownerId), enabled: ownerId > 0 }` ที่ Hook ปลายทางใน `client/features/owners/hooks/`)

## 4. Risk & Safety Review

- **Regression & Compatibility:**
  - การคง `ownersListQuery` และ `getOwnerByIdQuery` โดยไม่ใส่ `enabled`/`placeholderData` ลงใน `queryOptions` ทำให้รองรับได้ทั้ง `context.queryClient.ensureQueryData(...)` ใน Route `loader`, `useSuspenseQuery`, และ `useQuery` โดยไม่เกิด Type Error
  - การลบ `staleTime` ที่ซ้ำซ้อนออกจาก query options ยังคงได้ `staleTime: 30_000` เท่าเดิมผ่าน `defaultOptions.queries` ใน `global.ts`
  - ข้อควรระวังตอนสร้างปุ่มลบในหน้า Detail (`client/features/owners/`): ควรเรียก `await deleteMutation.mutateAsync({ ownerId })` แล้ว `navigate({ to: "/owners" })` ทันที (ลำดับ `invalidateQueries(..., { refetchType: "none" })` ใน Roadmap นี้ช่วยป้องกันไม่ให้เกิด 404 refetch ขณะเปลี่ยนหน้า)
- **Performance:**
  - `useRegisterOwnerMutation` เติม `detail` cache ทันทีด้วย `setQueryData` ช่วยประหยัด 1 network round-trip เมื่อเปิดหน้า Detail ต่อ
  - `useUpdateOwnerMutation` และ `useRegisterOwnerMutation` ไม่ invalidate `ownersKeys.all` แบบเหมารวมอีกต่อไป จึงไม่ไป refetch ข้อมูลเจ้าของคนอื่นที่ค้างใน cache
  - `createQueryClient()` ทำงานเฉพาะตอนสร้าง Router (1 ครั้งต่อ request บน SSR, 1 ครั้งต่อ session บน browser) ไม่มี overhead ต่อ component render
- **Security:**
  - การสร้าง `QueryClient` ภายใน `getRouter()` แทน module-level singleton เป็นมาตรการสำคัญป้องกัน Cross-Request Cache Leak ของข้อมูล PII ลูกค้าบน SSR
  - `getUserFriendlyErrorMessage` ป้องกันการโชว์รายละเอียด internal/upstream message บน Toast (`UPSTREAM_SERVICE_ERROR`, `UNAUTHORIZED`, `FORBIDDEN`) ขณะที่ข้อความ validation/conflict ที่ปลอดภัยยังคงแสดงได้ชัดเจน
- **Out of Scope (แจ้งเพื่อทราบ ไม่รวมในแผนแก้ Blocker นี้):**
  - หน้า Global Not Found (`src/client/core/screens/not-found.tsx`), Shared Layout (`src/client/shared/components/`), และ `src/routes/index.tsx` (ที่ยังเป็นหน้า Starter) สามารถสร้างได้ทันทีในขั้นตอนถัดไปเมื่อเริ่ม `client/features/**`
