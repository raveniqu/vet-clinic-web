# Domain 02: การบริหารจัดการนัดหมายและคิวรับบริการ (Appointment & Queue Management)

Domain นี้เป็นหนึ่งในโดเมนหลักของธุรกิจคลินิกสัตวแพทย์ ทำหน้าที่บริหารจัดการกระบวนการนัดหมาย การจัดตารางเวลาการให้บริการ การจัดคิวลูกค้าและสัตว์เลี้ยง การลงทะเบียนเข้ารับบริการ ตลอดจนการติดตามสถานะของลูกค้าตั้งแต่เริ่มติดต่อคลินิกจนกระทั่งเข้าสู่กระบวนการตรวจรักษา

หากมองในมุมของการพัฒนาระบบบริหารจัดการคลินิกสัตวแพทย์ (Veterinary Clinic ERP) โดเมนนี้ถือเป็นส่วนสำคัญที่เชื่อมโยงระหว่างข้อมูลลูกค้าและสัตว์เลี้ยงกับกระบวนการให้บริการทางการแพทย์

โดยจะทำงานร่วมกับระบบอื่น ๆ เช่น

- ระบบบริหารจัดการลูกค้าและสัตว์เลี้ยง (Customer & Pet Management)
- ระบบตรวจรักษาและเวชระเบียนสัตว์ (Clinical & Medical Management)
- ระบบบริหารจัดการสัตวแพทย์และบุคลากร (Human Resources Management)
- ระบบบริหารห้องตรวจและสถานที่ (Facility Management)
- ระบบบริหารการรักษาและหัตถการ (Surgery & Treatment Management)
- ระบบคิดค่าบริการและรับชำระเงิน (Billing & Payment Management)
- ระบบบริหารความสัมพันธ์ลูกค้า (Customer Relationship Management)

ตัวอย่างเช่น ลูกค้าชื่อคุณสมชายต้องการพาสุนัขชื่อเจ้าดำมาตรวจรักษา เนื่องจากมีอาการเบื่ออาหาร ลูกค้าติดต่อคลินิกเพื่อขอนัดหมาย ระบบจะต้องสามารถตรวจสอบข้อมูลลูกค้าและสัตว์เลี้ยง เลือกประเภทบริการ เลือกวันและเวลาที่ต้องการ ตรวจสอบตารางสัตวแพทย์ จองเวลาตรวจ และสร้างรายการนัดหมายได้

เมื่อถึงวันนัด ลูกค้าพาเจ้าดำมาถึงคลินิก พนักงานต้อนรับจะดำเนินการลงทะเบียนเข้ารับบริการ ระบบจะเปลี่ยนสถานะนัดหมายและจัดลำดับคิวเพื่อรอพบสัตวแพทย์

หากมีสัตว์ป่วยฉุกเฉินเข้ามาระหว่างนั้น ระบบต้องสามารถรองรับการคัดกรองและจัดลำดับความเร่งด่วนตามการประเมินของบุคลากรทางสัตวแพทย์ได้ โดยไม่จำเป็นต้องเรียงคิวตามเวลาที่มาถึงเพียงอย่างเดียว

ดังนั้น Domain นี้ไม่ได้มีหน้าที่เพียงการจองวันและเวลา แต่ต้องบริหารทรัพยากรและสถานะการให้บริการทั้งหมดที่เกี่ยวข้องกับการนัดหมายและคิวอย่างเป็นระบบ

# 1. วัตถุประสงค์หลักของโดเมน

การบริหารจัดการนัดหมายและคิวรับบริการมีวัตถุประสงค์สำคัญ 15 ประการ

1. จัดการข้อมูลการนัดหมายของลูกค้าและสัตว์เลี้ยงอย่างเป็นระบบ
2. รองรับการจองนัดหมายผ่านหลายช่องทาง
3. จัดตารางเวลาการให้บริการของคลินิก
4. จัดตารางเวลาการทำงานของสัตวแพทย์
5. จัดสรรห้องตรวจและทรัพยากรที่จำเป็น
6. ป้องกันการจองเวลาซ้ำซ้อน
7. รองรับลูกค้าที่จองนัดหมายล่วงหน้า
8. รองรับลูกค้าที่เข้ารับบริการโดยไม่ได้นัดหมาย (Walk-in)
9. บริหารลำดับคิวและสถานะการรอรับบริการ
10. รองรับการคัดกรองสัตว์ป่วยฉุกเฉิน
11. แจ้งเตือนและยืนยันการนัดหมายกับลูกค้า
12. ติดตามลูกค้าที่ไม่มาตามนัดหรือยกเลิกนัดหมาย
13. บริหารระยะเวลาการให้บริการและเวลารอคอย
14. สนับสนุนการกระจายภาระงานของสัตวแพทย์และบุคลากร
15. สนับสนุนการวิเคราะห์ประสิทธิภาพการให้บริการของคลินิก

เป้าหมายสูงสุด: ทำให้คลินิกสามารถบริหารจัดการนัดหมายและคิวได้อย่างมีประสิทธิภาพ ลดระยะเวลารอคอย ลดความผิดพลาดในการจัดตาราง และใช้ทรัพยากรของคลินิกได้อย่างเหมาะสม โดยยังคงให้ความสำคัญกับความเร่งด่วนและความปลอดภัยของสัตว์ป่วย

# 3. รายละเอียดกลุ่มความสามารถทางธุรกิจ

## 3.1 การจองนัดหมาย (Appointment Booking)

เป็นกระบวนการรับคำขอจากลูกค้าที่ต้องการนำสัตว์เลี้ยงเข้ารับบริการในวันและเวลาที่กำหนดล่วงหน้า เพื่อให้คลินิกสามารถเตรียมความพร้อมด้านสัตวแพทย์ บุคลากร ห้องตรวจ และอุปกรณ์ที่เกี่ยวข้องได้

วัตถุประสงค์

- รองรับการจองนัดหมายล่วงหน้า
- ลดความแออัดของลูกค้าที่เข้ารับบริการพร้อมกัน
- ช่วยให้คลินิกวางแผนการทำงานได้
- จัดสรรสัตวแพทย์ให้เหมาะสมกับประเภทบริการ
- เตรียมข้อมูลสัตว์เลี้ยงก่อนเข้ารับบริการ
- ลดระยะเวลาการรอคอยของลูกค้า

ช่องทางการจองนัดหมาย

1. จองผ่านพนักงานต้อนรับที่คลินิก
2. จองผ่านโทรศัพท์
3. จองผ่าน LINE Official Account
4. จองผ่านเว็บไซต์คลินิก
5. จองผ่านระบบลูกค้าออนไลน์
6. จองผ่านแอปพลิเคชันของคลินิก
7. จองผ่านช่องทางสื่อสังคมออนไลน์
8. จองผ่านพนักงานบริการลูกค้า

รายละเอียดข้อมูลที่ต้องจัดเก็บ

| รายการข้อมูล    | รายละเอียด                              |
| --------------- | --------------------------------------- |
| รหัสนัดหมาย     | รหัสประจำรายการนัดหมาย                  |
| รหัสลูกค้า      | ลูกค้าที่เป็นผู้ขอนัด                   |
| รหัสสัตว์เลี้ยง | สัตว์เลี้ยงที่ต้องการนำมาตรวจ           |
| ประเภทบริการ    | ตรวจทั่วไป ฉีดวัคซีน ตรวจสุขภาพ เป็นต้น |
| วันที่นัดหมาย   | วันที่ต้องการเข้ารับบริการ              |
| เวลาเริ่มต้น    | เวลาที่กำหนดให้เริ่มรับบริการ           |
| เวลาสิ้นสุด     | เวลาสิ้นสุดที่คาดการณ์                  |
| สัตวแพทย์       | สัตวแพทย์ที่ได้รับมอบหมาย               |
| สาขา            | สาขาที่ต้องการเข้ารับบริการ             |
| เหตุผลในการนัด  | วัตถุประสงค์หรืออาการเบื้องต้น          |
| ช่องทางการจอง   | โทรศัพท์ เว็บไซต์ LINE หรือช่องทางอื่น  |
| ผู้บันทึก       | ผู้ที่สร้างรายการนัดหมาย                |
| สถานะนัดหมาย    | สถานะปัจจุบันของรายการนัด               |

กระบวนการทำงาน

1. ลูกค้าติดต่อคลินิกเพื่อขอนัดหมาย
2. พนักงานค้นหาข้อมูลลูกค้า
3. เลือกสัตว์เลี้ยงที่ต้องการนำเข้ารับบริการ
4. เลือกประเภทบริการ
5. ระบุเหตุผลหรืออาการเบื้องต้น
6. เลือกสาขาที่ต้องการเข้ารับบริการ
7. ตรวจสอบวันและเวลาที่สามารถให้บริการได้
8. ตรวจสอบตารางสัตวแพทย์
9. เลือกวันและเวลาที่เหมาะสม
10. ตรวจสอบความพร้อมของทรัพยากรที่จำเป็น
11. บันทึกรายการนัดหมาย
12. ระบบสร้างรหัสนัดหมาย
13. ส่งรายละเอียดการนัดหมายให้ลูกค้า
14. รอการยืนยันตามกระบวนการของคลินิก

กฎทางธุรกิจที่ควรกำหนด

- การนัดหมายแต่ละรายการต้องมีรหัสไม่ซ้ำกัน
- การนัดหมายต้องอ้างอิงลูกค้าและสัตว์เลี้ยงที่ถูกต้อง
- ต้องระบุประเภทบริการที่ต้องการเข้ารับบริการ
- ต้องตรวจสอบช่วงเวลาทำการของคลินิกก่อนสร้างนัด
- ต้องตรวจสอบความพร้อมของสัตวแพทย์ก่อนจอง
- ต้องตรวจสอบทรัพยากรที่จำเป็นสำหรับบริการนั้น
- ต้องรองรับการนัดหมายที่ยังไม่ระบุสัตวแพทย์
- ต้องรองรับการจองจากหลายช่องทาง
- ต้องป้องกันการสร้างรายการนัดหมายซ้ำจากคำขอเดียวกัน
- ต้องจัดเก็บผู้สร้างรายการและวันเวลาที่สร้างรายการ

ตัวอย่างสถานการณ์

คุณสมชายต้องการนำสุนัขชื่อเจ้าดำมาตรวจสุขภาพประจำปี จึงโทรศัพท์มาที่คลินิก พนักงานตรวจสอบข้อมูลลูกค้าและสัตว์เลี้ยง จากนั้นเลือกบริการตรวจสุขภาพประจำปี และจองเวลาวันที่ 15 พฤศจิกายน เวลา 10:00 น.

ระบบสร้างรหัสนัดหมายเป็น `APT-000001` และบันทึกข้อมูลไว้ในระบบนัดหมาย

เมื่อลูกค้าติดต่อกลับมาในภายหลัง พนักงานสามารถค้นหารายการนัดหมายจากรหัสนัดหมาย เบอร์โทรศัพท์ หรือข้อมูลสัตว์เลี้ยงได้

## 3.2 การจัดตารางนัดหมาย (Appointment Scheduling)

เป็นการบริหารช่วงเวลาที่คลินิกเปิดให้ลูกค้าจองบริการ โดยต้องคำนึงถึงวันทำการ เวลาทำการ จำนวนสัตวแพทย์ จำนวนห้องตรวจ และระยะเวลาที่ใช้ในบริการแต่ละประเภท

วัตถุประสงค์

- จัดสรรเวลาการให้บริการอย่างเหมาะสม
- ลดปัญหาการนัดหมายซ้อนทับ
- กระจายจำนวนลูกค้าในแต่ละช่วงเวลา
- ป้องกันการใช้ทรัพยากรเกินความสามารถ
- รองรับบริการที่ใช้เวลาต่างกัน

องค์ประกอบของตารางนัดหมาย

1. วันทำการของคลินิก
2. เวลาเปิดและปิดคลินิก
3. ช่วงเวลาพักของสัตวแพทย์
4. ช่วงเวลาที่สัตวแพทย์ปฏิบัติงาน
5. ช่วงเวลาที่สัตวแพทย์ไม่รับนัด
6. ช่วงเวลาที่ห้องตรวจพร้อมใช้งาน
7. ช่วงเวลาที่ห้องผ่าตัดถูกใช้งาน
8. ช่วงเวลาสำรองสำหรับสัตว์ป่วยฉุกเฉิน
9. จำนวนลูกค้าที่รับได้ต่อช่วงเวลา
10. ระยะเวลาของบริการแต่ละประเภท

- ไม่สามารถจองห้องตรวจที่ถูกใช้งานอยู่ในช่วงเวลาเดียวกันได้
- ต้องรองรับการกำหนดระยะเวลาตามประเภทบริการ
- ต้องรองรับเวลาสำรองระหว่างบริการเพื่อเตรียมห้องหรืออุปกรณ์
- การเปลี่ยนแปลงตารางทำงานต้องไม่ทำให้รายการนัดหมายเดิมสูญหาย
- ต้องแจ้งเตือนเมื่อการเปลี่ยนตารางส่งผลกระทบต่อนัดหมายเดิม

## 3.3 การเปลี่ยนแปลงนัดหมาย (Appointment Modification)

เป็นกระบวนการเปลี่ยนแปลงรายละเอียดของรายการนัดหมายที่สร้างไว้แล้ว โดยอาจเกิดจากความต้องการของลูกค้าหรือเหตุผลด้านการดำเนินงานของคลินิก

ตัวอย่างการเปลี่ยนแปลง

- เปลี่ยนวันที่นัดหมาย
- เปลี่ยนเวลานัดหมาย
- เปลี่ยนสัตวแพทย์
- เปลี่ยนประเภทบริการ
- เปลี่ยนสาขา
- เปลี่ยนห้องตรวจ
- เปลี่ยนรายละเอียดอาการเบื้องต้น
- เพิ่มข้อมูลหรือคำแนะนำก่อนเข้ารับบริการ

กระบวนการทำงาน

1. ลูกค้าติดต่อเพื่อขอเปลี่ยนแปลงนัดหมาย
2. พนักงานค้นหารายการนัดหมายเดิม
3. ตรวจสอบสถานะของนัดหมาย
4. เลือกรายการที่ต้องการเปลี่ยนแปลง
5. ระบุรายละเอียดใหม่
6. ตรวจสอบตารางเวลาที่ว่าง
7. ตรวจสอบความพร้อมของสัตวแพทย์
8. ตรวจสอบทรัพยากรที่เกี่ยวข้อง
9. บันทึกการเปลี่ยนแปลง
10. จัดเก็บข้อมูลก่อนและหลังเปลี่ยนแปลง
11. แจ้งรายละเอียดใหม่ให้ลูกค้าทราบ

ข้อมูลที่ควรจัดเก็บ

- รหัสประวัติการเปลี่ยนแปลง
- รหัสนัดหมาย
- ประเภทการเปลี่ยนแปลง
- ค่าเดิม
- ค่าใหม่
- เหตุผลในการเปลี่ยนแปลง
- ผู้ร้องขอ
- ผู้ดำเนินการ
- วันและเวลาที่เปลี่ยนแปลง

กฎทางธุรกิจ

- ต้องเก็บประวัติการเปลี่ยนแปลงทุกครั้ง
- ต้องไม่เขียนทับข้อมูลเดิมโดยไม่มีประวัติ
- ต้องตรวจสอบสถานะนัดหมายก่อนอนุญาตให้แก้ไข
- ต้องตรวจสอบเวลาว่างใหม่ก่อนยืนยันการเปลี่ยนแปลง
- ต้องแจ้งลูกค้าเมื่อรายละเอียดสำคัญเปลี่ยนแปลง
- ต้องรองรับการเปลี่ยนแปลงโดยพนักงานที่ได้รับอนุญาตเท่านั้น

ตัวอย่างเช่น คุณสมชายต้องการเปลี่ยนนัดหมายจากวันที่ 15 พฤศจิกายน เวลา 10:00 น. เป็นวันที่ 16 พฤศจิกายน เวลา 14:00 น.

ระบบต้องบันทึกทั้งวันและเวลาเดิมและวันเวลาใหม่ เพื่อให้สามารถตรวจสอบย้อนหลังได้

## 3.4 การยกเลิกนัดหมาย (Appointment Cancellation)

เป็นกระบวนการยกเลิกรายการนัดหมายที่สร้างไว้แล้ว โดยอาจเกิดจากลูกค้าไม่สะดวกเข้ารับบริการ สัตวแพทย์ไม่สามารถปฏิบัติงานได้ หรือคลินิกจำเป็นต้องหยุดให้บริการในช่วงเวลานั้น

ประเภทการยกเลิก

1. ลูกค้าขอยกเลิก
2. สัตวแพทย์ขอยกเลิก
3. คลินิกยกเลิก
4. สาขาหยุดให้บริการ
5. เกิดเหตุฉุกเฉินที่กระทบต่อการให้บริการ
6. ทรัพยากรหรืออุปกรณ์ที่จำเป็นไม่พร้อมใช้งาน

ข้อมูลที่ต้องจัดเก็บ

- รหัสนัดหมาย
- วันที่ยกเลิก
- เวลาที่ยกเลิก
- ผู้ร้องขอยกเลิก
- ผู้ดำเนินการยกเลิก
- เหตุผลการยกเลิก
- ประเภทการยกเลิก
- สถานะก่อนยกเลิก
- สถานะหลังยกเลิก
- รายละเอียดการแจ้งลูกค้า

ความสามารถของระบบ

- ยกเลิกนัดหมาย
- ระบุเหตุผลการยกเลิก
- บันทึกประวัติการยกเลิก
- คืนช่วงเวลาที่จองไว้ให้ระบบ
- แจ้งเตือนลูกค้า
- แสดงรายงานการยกเลิก
- วิเคราะห์อัตราการยกเลิก
- รองรับการนัดหมายใหม่หลังยกเลิก

กฎทางธุรกิจ

- ต้องเก็บประวัติรายการนัดหมายที่ยกเลิก
- ต้องระบุเหตุผลการยกเลิก
- ต้องไม่ลบรายการนัดหมายออกจากฐานข้อมูล
- ต้องคืนทรัพยากรที่ถูกจองไว้เมื่อยกเลิกสำเร็จ
- ต้องป้องกันการยกเลิกรายการที่ดำเนินการเสร็จสิ้นแล้วโดยไม่ได้รับอนุญาต
- หากมีเงินมัดจำหรือค่าใช้จ่ายล่วงหน้า ต้องส่งข้อมูลไปยังระบบการเงินเพื่อดำเนินการตามนโยบาย

ตัวอย่างเช่น ลูกค้ายกเลิกนัดหมายเวลา 10:00 น. ระบบจะเปลี่ยนสถานะเป็นยกเลิก และนำช่วงเวลาดังกล่าวกลับมาเปิดให้ลูกค้ารายอื่นจองได้ตามเงื่อนไขของคลินิก

## 3.5 การรับลูกค้าแบบไม่ได้นัดหมาย (Walk-in Registration)

เป็นกระบวนการรับลูกค้าที่นำสัตว์เลี้ยงเข้ามาใช้บริการโดยไม่ได้จองนัดหมายล่วงหน้า

เป็นความสามารถที่จำเป็นสำหรับคลินิกสัตวแพทย์ทั่วไป เนื่องจากอาการเจ็บป่วยของสัตว์อาจเกิดขึ้นโดยไม่สามารถคาดการณ์ล่วงหน้าได้

วัตถุประสงค์

- รองรับลูกค้าที่เข้ามาใช้บริการทันที
- ลดความยุ่งยากในการลงทะเบียน
- จัดลำดับคิวให้เหมาะสม
- ตรวจสอบความพร้อมของสัตวแพทย์
- ป้องกันการแทรกคิวโดยไม่มีหลักเกณฑ์

ข้อมูลที่ต้องจัดเก็บ

- รหัสรายการรับบริการ
- รหัสลูกค้า
- รหัสสัตว์เลี้ยง
- วันที่และเวลามาถึง
- ประเภทบริการที่ต้องการ
- อาการเบื้องต้น
- สาขาที่เข้ารับบริการ
- ระดับความเร่งด่วนเบื้องต้น
- ผู้ลงทะเบียน
- สถานะการรับบริการ

กระบวนการทำงาน

1. ลูกค้านำสัตว์เลี้ยงมาที่คลินิก
2. พนักงานต้อนรับสอบถามวัตถุประสงค์
3. ค้นหาข้อมูลลูกค้าเดิม
4. หากไม่พบ ให้ลงทะเบียนลูกค้าใหม่
5. เลือกสัตว์เลี้ยงที่เกี่ยวข้อง
6. บันทึกอาการเบื้องต้น
7. ลงทะเบียนรายการเข้ารับบริการ
8. ประเมินความจำเป็นในการคัดกรองเบื้องต้น
9. ตรวจสอบคิวปัจจุบัน
10. สร้างหมายเลขคิว
11. แจ้งลูกค้าเกี่ยวกับสถานะการรอ
12. ส่งรายการไปยังขั้นตอนคัดกรองหรือรอตรวจตามความเหมาะสม

กฎทางธุรกิจ

- ลูกค้าแบบไม่ได้นัดต้องสามารถเข้าสู่ระบบคิวได้
- ต้องระบุเวลาที่มาถึงจริง
- ต้องแยกรายการ Walk-in ออกจากรายการนัดหมายล่วงหน้า
- ต้องรองรับการตรวจสอบลูกค้าเดิม
- ต้องรองรับการสร้างข้อมูลลูกค้าและสัตว์เลี้ยงใหม่
- ต้องไม่จัดลำดับสัตว์ป่วยฉุกเฉินตามเวลามาถึงเพียงอย่างเดียว
- ต้องบันทึกผู้ลงทะเบียนและผู้ดำเนินการ

## 3.6 การบริหารคิว (Queue Management)

เป็นกระบวนการจัดลำดับสัตว์เลี้ยงที่รอเข้ารับบริการ โดยพิจารณาจากเวลามาถึง ประเภทบริการ ระดับความเร่งด่วน และความพร้อมของสัตวแพทย์

เมื่อสัตวแพทย์ตรวจคิว Q001 เสร็จ ระบบจะเปลี่ยนสถานะเป็นเสร็จสิ้น และสามารถเรียกคิวถัดไปตามหลักเกณฑ์ที่คลินิกกำหนด

อย่างไรก็ตาม หาก Q005 มีอาการฉุกเฉินที่ได้รับการประเมินว่าต้องได้รับการดูแลเร่งด่วน ก็สามารถจัดลำดับให้ได้รับการดูแลก่อนคิวทั่วไปได้

## 3.7 การบริหารรายชื่อรอคิว (Waiting List Management)

เป็นการจัดการรายชื่อลูกค้าที่ต้องการเข้ารับบริการ แต่ยังไม่มีช่วงเวลาว่างที่เหมาะสม หรือยังไม่สามารถยืนยันเวลานัดหมายได้

สถานการณ์ที่ต้องใช้

- สัตวแพทย์ที่ลูกค้าต้องการไม่ว่าง
- ลูกค้าต้องการนัดหมายในช่วงเวลาที่เต็มแล้ว
- ห้องตรวจหรืออุปกรณ์ไม่พร้อม
- ลูกค้าต้องการเข้ารับบริการในวันหรือเวลาที่เฉพาะเจาะจง
- มีลูกค้ายกเลิกนัดหมายและเกิดช่วงเวลาว่าง

ข้อมูลที่ควรจัดเก็บ

- รหัสรายการรอคิว
- รหัสลูกค้า
- รหัสสัตว์เลี้ยง
- ประเภทบริการ
- ช่วงวันที่ต้องการ
- ช่วงเวลาที่ต้องการ
- สัตวแพทย์ที่ต้องการ
- สาขาที่ต้องการ
- วันที่เริ่มรอ
- ลำดับความต้องการ
- สถานะรายการ
- วันหมดอายุของรายการรอ
- ประวัติการติดต่อ

กระบวนการทำงาน

1. ลูกค้าขอนัดหมาย
2. ระบบตรวจสอบตารางเวลาว่าง
3. หากไม่มีเวลาที่ตรงกับความต้องการ
4. เสนอให้ลูกค้าเข้ารายชื่อรอคิว
5. บันทึกเงื่อนไขและช่วงเวลาที่ต้องการ
6. เมื่อเกิดช่วงเวลาว่าง ระบบค้นหารายชื่อที่ตรงตามเงื่อนไข
7. แจ้งลูกค้าเกี่ยวกับช่วงเวลาที่ว่าง
8. ลูกค้าตอบรับหรือปฏิเสธ
9. หากตอบรับ ให้สร้างรายการนัดหมาย
10. หากไม่ตอบรับ ให้ดำเนินการตามนโยบายและติดต่อรายชื่อถัดไป

กฎทางธุรกิจ

- รายการรอคิวต้องมีรหัสอ้างอิง
- ต้องระบุช่วงเวลาที่ลูกค้าสะดวก
- ต้องไม่ถือว่ารายชื่อรอคิวเป็นรายการนัดหมายที่ยืนยันแล้ว
- ต้องสามารถกำหนดวันหมดอายุของการรอคิวได้
- ต้องเก็บประวัติการแจ้งเตือนและการตอบกลับ
- ต้องป้องกันการสร้างนัดหมายซ้ำจากรายการรอคิวเดียวกัน
- ต้องมีเงื่อนไขการจัดลำดับที่ชัดเจน

## 3.8 การจัดตารางสัตวแพทย์ (Doctor Scheduling)

เป็นการบริหารตารางเวลาปฏิบัติงานของสัตวแพทย์แต่ละคน เพื่อให้สามารถจัดสรรสัตวแพทย์ให้เหมาะสมกับประเภทบริการและจำนวนสัตว์ป่วยที่เข้ารับบริการ

ข้อมูลที่ต้องบริหาร

1. รหัสสัตวแพทย์
2. สาขาที่ปฏิบัติงาน
3. วันทำงาน
4. เวลาเริ่มงาน
5. เวลาสิ้นสุดงาน
6. เวลาพัก
7. วันหยุด
8. วันลา
9. เวลาที่ไม่รับนัดหมาย
10. ความเชี่ยวชาญหรือประเภทบริการที่รับผิดชอบ
11. จำนวนการนัดหมายสูงสุด
12. ตารางการทำงานพิเศษ

ความสามารถของระบบ

- กำหนดตารางทำงานรายวัน
- กำหนดตารางทำงานรายสัปดาห์
- กำหนดตารางทำงานรายเดือน
- กำหนดวันหยุด
- กำหนดเวลาพัก
- กำหนดช่วงเวลาที่ไม่รับนัด
- กำหนดสาขาที่ปฏิบัติงาน
- กำหนดความสามารถในการให้บริการ
- ตรวจสอบเวลาว่าง
- แสดงจำนวนงานที่ได้รับมอบหมาย
- รองรับการเปลี่ยนตารางกะ
- แจ้งเตือนเมื่อมีนัดหมายที่ได้รับผลกระทบ

กฎทางธุรกิจ

- ไม่สามารถจัดนัดหมายในช่วงที่สัตวแพทย์ไม่ได้ปฏิบัติงานได้ตามปกติ
- ต้องตรวจสอบวันลาและวันหยุด
- ต้องรองรับสัตวแพทย์ที่ทำงานหลายสาขา
- ต้องรองรับสัตวแพทย์ที่ให้บริการหลายประเภท
- ต้องป้องกันการมอบหมายงานที่ซ้อนทับกัน
- การเปลี่ยนแปลงตารางสัตวแพทย์ต้องตรวจสอบนัดหมายที่มีอยู่ก่อน
- ต้องมีประวัติการเปลี่ยนแปลงตาราง

ข้อสำคัญคือ ข้อมูลตารางเวลาทำงานควรมีแหล่งข้อมูลหลักอยู่ในระบบบริหารทรัพยากรบุคคล ส่วน Domain นัดหมายควรนำข้อมูลดังกล่าวมาใช้ตรวจสอบความพร้อม ไม่ควรสร้างข้อมูลตารางพนักงานซ้ำอีกชุดหนึ่งโดยไม่มีการเชื่อมโยง

## 3.9 การจัดตารางห้องตรวจ (Room Scheduling)

เป็นการบริหารและจัดสรรห้องตรวจหรือพื้นที่ให้บริการให้เหมาะสมกับประเภทการรักษาและความต้องการของสัตว์ป่วย

ประเภทห้องหรือพื้นที่

1. ห้องตรวจทั่วไป
2. ห้องตรวจเฉพาะทาง

4. ห้องผ่าตัด

7. ห้องปฏิบัติการ
8. พื้นที่พักรอสัตว์ป่วย

ข้อมูลที่ต้องจัดเก็บ

- รหัสห้อง
- ชื่อห้อง
- ประเภทห้อง
- สาขา
- จำนวนสัตว์ที่รองรับ
- อุปกรณ์ประจำห้อง

- ประวัติการใช้งาน

ความสามารถของระบบ

- จัดสรรห้องให้กับรายการนัดหมาย

- กำหนดประเภทห้องที่รองรับบริการ
- ตรวจสอบความพร้อมของอุปกรณ์
- ป้องกันการจองห้องซ้ำซ้อน
- กำหนดเวลาทำความสะอาดห้อง
- จัดการกรณีห้องไม่พร้อมใช้งาน
- แสดงตารางการใช้งานห้อง

กฎทางธุรกิจ

- ห้องตรวจต้องรองรับประเภทบริการที่กำหนด
- ห้องหนึ่งห้องไม่ควรถูกจัดสรรให้บริการที่ซ้อนทับกัน
- ต้องรองรับการปิดห้องชั่วคราว
- ต้องตรวจสอบความพร้อมของอุปกรณ์ที่จำเป็น
- การเปลี่ยนห้องต้องบันทึกประวัติ
- ต้องรองรับการจัดสรรห้องให้กับบริการที่ไม่ได้กำหนดห้องล่วงหน้า

## 3.10 การบริหารระยะเวลาบริการ (Service Duration Management)

เป็นการกำหนดและบริหารระยะเวลาที่คาดว่าจะใช้ในการให้บริการแต่ละประเภท เพื่อช่วยวางแผนตารางนัดหมายและคำนวณจำนวนลูกค้าที่สามารถรับได้ในแต่ละวัน

ตัวอย่างประเภทบริการและระยะเวลา

| ประเภทบริการ     | ระยะเวลาโดยประมาณ |
| ---------------- | ----------------- |
| ตรวจสุขภาพทั่วไป | 20–30 นาที        |
| ฉีดวัคซีน        | 15–20 นาที        |
| ตรวจติดตามผล     | 15–30 นาที        |
| ตรวจผิวหนัง      | 20–40 นาที        |
| ตรวจเลือด        | 15–30 นาที        |
| อาบน้ำและตัดขน   | 60–120 นาที       |
| ทำแผล            | 15–30 นาที        |

ตัวเลขข้างต้นเป็นเพียงตัวอย่างสำหรับออกแบบระบบ คลินิกต้องกำหนดเวลาจริงตามประเภทบริการ ความซับซ้อน และแนวทางปฏิบัติของตนเอง

ข้อมูลที่ควรจัดเก็บ

- รหัสบริการ
- ชื่อบริการ
- ระยะเวลาเริ่มต้น
- ระยะเวลาสิ้นสุด
- เวลาที่ใช้ในการเตรียมการ
- เวลาที่ใช้ในการทำความสะอาด
- เวลาสำรองระหว่างบริการ
- ประเภทห้องที่ต้องใช้
- ประเภทบุคลากรที่ต้องใช้
- จำนวนบุคลากรที่ต้องใช้

ความสามารถของระบบ

- กำหนดระยะเวลามาตรฐานของบริการ
- กำหนดระยะเวลาตามประเภทสัตว์
- กำหนดระยะเวลาตามความซับซ้อน
- กำหนดเวลาสำรอง
- ปรับระยะเวลาตามเงื่อนไขพิเศษ
- คำนวณช่วงเวลาที่สามารถเปิดรับนัด
- วิเคราะห์ระยะเวลาการให้บริการจริง
- เปรียบเทียบเวลามาตรฐานกับเวลาที่ใช้จริง

กฎทางธุรกิจ

- บริการแต่ละประเภทสามารถกำหนดระยะเวลาต่างกันได้
- ต้องรองรับการปรับระยะเวลาเฉพาะรายการ
- การเปลี่ยนแปลงระยะเวลาต้องไม่กระทบรายการนัดหมายเดิมโดยไม่มีการตรวจสอบ
- ต้องแยกระยะเวลาการให้บริการออกจากระยะเวลาการเตรียมห้อง
- ต้องสามารถบันทึกระยะเวลาจริงเพื่อใช้วิเคราะห์ประสิทธิภาพได้

## 3.11 การแจ้งเตือนนัดหมาย (Appointment Reminder)

เป็นการแจ้งเตือนลูกค้าก่อนถึงวันและเวลานัดหมาย เพื่อช่วยลดปัญหาการลืมนัดหมายและเพิ่มโอกาสที่ลูกค้าจะมาตามนัด

ประเภทการแจ้งเตือน

1. แจ้งเตือนเมื่อสร้างนัดหมายสำเร็จ
2. แจ้งเตือนก่อนวันนัด
3. แจ้งเตือนก่อนเวลานัด
4. แจ้งเตือนเมื่อมีการเปลี่ยนแปลงนัด
5. แจ้งเตือนเมื่อมีการยกเลิกนัด
6. แจ้งเตือนเมื่อใกล้ถึงคิว
7. แจ้งเตือนเมื่อมีช่วงเวลาว่างจากรายชื่อรอคิว

ช่องทางการแจ้งเตือน

- SMS
- LINE
- อีเมล
- โทรศัพท์
- การแจ้งเตือนผ่านแอปพลิเคชัน

ข้อมูลที่ต้องจัดเก็บ

- รหัสการแจ้งเตือน
- รหัสนัดหมาย
- รหัสลูกค้า
- ช่องทางการแจ้งเตือน
- เนื้อหาข้อความ
- วันและเวลาที่กำหนดส่ง
- วันและเวลาที่ส่งจริง
- สถานะการส่ง
- ผลการส่ง
- จำนวนครั้งที่พยายามส่ง

ความสามารถของระบบ

- กำหนดช่วงเวลาแจ้งเตือน
- สร้างข้อความอัตโนมัติ
- เลือกช่องทางติดต่อ
- ส่งข้อความอัตโนมัติ
- ตรวจสอบสถานะการส่ง
- ส่งซ้ำเมื่อเกิดข้อผิดพลาดตามนโยบาย
- บันทึกประวัติการแจ้งเตือน
- ยกเลิกการแจ้งเตือนเมื่อยกเลิกนัดหมาย

กฎทางธุรกิจ

- ต้องใช้ช่องทางติดต่อที่ถูกต้อง
- ต้องตรวจสอบความต้องการและสิทธิในการติดต่อของลูกค้า
- ต้องไม่ส่งการแจ้งเตือนนัดหมายที่ถูกยกเลิกแล้ว
- ต้องไม่ส่งข้อความซ้ำโดยไม่มีความจำเป็น
- ต้องจัดเก็บประวัติการส่งข้อความ
- ต้องแยกข้อความแจ้งเตือนบริการออกจากข้อความประชาสัมพันธ์

ตัวอย่างเช่น คลินิกกำหนดให้ส่งข้อความเตือนก่อนวันนัด 1 วัน และก่อนเวลานัด 2 ชั่วโมง โดยลูกค้าสามารถตรวจสอบวัน เวลา สาขา และประเภทบริการได้จากข้อความ

## 3.12 การยืนยันนัดหมาย (Appointment Confirmation)

เป็นกระบวนการตรวจสอบว่าลูกค้าได้รับทราบและยอมรับรายละเอียดของนัดหมายแล้วหรือไม่

การสร้างนัดหมายสำเร็จไม่ได้หมายความว่าลูกค้ายืนยันว่าจะมาใช้บริการเสมอไป จึงควรแยกสถานะการยืนยันออกจากสถานะของนัดหมาย

รูปแบบการยืนยัน

1. ลูกค้ายืนยันกับพนักงานโดยตรง
2. ลูกค้ายืนยันผ่านโทรศัพท์
3. ลูกค้ายืนยันผ่าน LINE
4. ลูกค้ายืนยันผ่านเว็บไซต์
5. ลูกค้ายืนยันผ่านแอปพลิเคชัน
6. ลูกค้ายืนยันผ่านลิงก์ในข้อความแจ้งเตือน

สถานะการยืนยันที่ควรรองรับ

- รอการยืนยัน
- ยืนยันแล้ว
- ปฏิเสธการยืนยัน
- ไม่ได้รับการตอบกลับ
- ยืนยันไม่ได้เนื่องจากข้อมูลติดต่อไม่ถูกต้อง

ข้อมูลที่ต้องจัดเก็บ

- รหัสการยืนยัน
- รหัสนัดหมาย
- วันและเวลาที่ส่งคำขอยืนยัน
- วันและเวลาที่ตอบกลับ
- ช่องทางการยืนยัน
- ผลการยืนยัน
- ผู้ดำเนินการ
- หมายเหตุ

กฎทางธุรกิจ

- ต้องแยกสถานะการยืนยันออกจากสถานะนัดหมาย
- ต้องสามารถตั้งกำหนดเวลารอการยืนยันได้
- ต้องเก็บประวัติการยืนยัน
- ต้องรองรับการยืนยันโดยพนักงาน
- ต้องรองรับกรณีลูกค้าไม่ตอบกลับ
- ต้องไม่ยกเลิกนัดหมายอัตโนมัติเพียงเพราะไม่มีการตอบกลับ เว้นแต่มีนโยบายที่กำหนดไว้อย่างชัดเจน

ตัวอย่างเช่น รายการนัดหมายของเจ้าดำอาจมีสถานะนัดหมายเป็นรอยืนยัน แต่มีสถานะการยืนยันเป็นยืนยันแล้ว เมื่อเจ้าของตอบกลับข้อความยืนยันนัดหมาย

## 3.13 การลงทะเบียนเข้ารับบริการ (Check-in Management)

เป็นกระบวนการบันทึกว่าลูกค้าและสัตว์เลี้ยงเดินทางมาถึงคลินิกแล้ว และพร้อมเข้าสู่กระบวนการรับบริการ

เป็นขั้นตอนเชื่อมต่อระหว่างระบบนัดหมายกับระบบคิวและระบบตรวจรักษา

วัตถุประสงค์

- บันทึกเวลามาถึงจริง
- ตรวจสอบรายการนัดหมาย
- ยืนยันตัวตนลูกค้าและสัตว์เลี้ยง
- ตรวจสอบความพร้อมก่อนรับบริการ
- สร้างรายการรับบริการ
- จัดคิวให้กับสัตว์เลี้ยง

ข้อมูลที่ต้องจัดเก็บ

- รหัสการลงทะเบียนเข้ารับบริการ
- รหัสนัดหมาย
- รหัสลูกค้า
- รหัสสัตว์เลี้ยง
- วันเวลาที่มาถึง
- วันเวลาที่ลงทะเบียน
- ผู้ลงทะเบียน
- ประเภทการเข้ารับบริการ
- อาการเพิ่มเติม
- เอกสารประกอบ
- สถานะการลงทะเบียน

กระบวนการทำงาน

1. ลูกค้าเดินทางมาถึงคลินิก
2. พนักงานต้อนรับตรวจสอบข้อมูลลูกค้า
3. ตรวจสอบข้อมูลสัตว์เลี้ยง
4. ค้นหารายการนัดหมาย
5. ตรวจสอบรายละเอียดบริการ
6. ยืนยันว่ามาถึงแล้ว
7. บันทึกเวลามาถึงจริง
8. สอบถามอาการเพิ่มเติม
9. ตรวจสอบว่ามีข้อมูลที่ต้องปรับปรุงหรือไม่
10. สร้างรายการเข้ารับบริการ
11. สร้างหรือเชื่อมโยงรายการคิว
12. ส่งต่อไปยังขั้นตอนคัดกรองหรือรอพบสัตวแพทย์

กฎทางธุรกิจ

- ต้องบันทึกเวลามาถึงจริง
- ต้องตรวจสอบลูกค้าและสัตว์เลี้ยงให้ถูกต้อง
- ต้องรองรับลูกค้าที่มาตามนัด
- ต้องรองรับลูกค้าที่มาก่อนหรือหลังเวลานัด
- ต้องรองรับ Walk-in
- ต้องป้องกันการ Check-in ซ้ำโดยไม่ได้ตั้งใจ
- ต้องเก็บประวัติการลงทะเบียน
- ต้องสามารถเชื่อมโยงกับรายการนัดหมายเดิมได้

## 3.14 การลงทะเบียนออกจากกระบวนการรับบริการ (Check-out Management)

เป็นการบันทึกว่าสัตว์เลี้ยงได้ดำเนินการในขั้นตอนการรับบริการตามขอบเขตที่กำหนดเสร็จสิ้นแล้ว และพร้อมเข้าสู่กระบวนการถัดไป เช่น การชำระเงิน การรับยา หรือการกลับบ้าน

อย่างไรก็ตาม ควรแยกความหมายระหว่างการสิ้นสุดคิว การสิ้นสุดการตรวจรักษา และการชำระเงิน เพราะเป็นคนละเหตุการณ์ทางธุรกิจ

ข้อมูลที่ควรจัดเก็บ

- รหัสรายการรับบริการ
- รหัสนัดหมาย
- รหัสคิว
- วันเวลาที่สิ้นสุดขั้นตอน
- ผู้ดำเนินการ
- ผลการให้บริการ
- หมายเหตุ
- สถานะการรับบริการ

ความสามารถของระบบ

- บันทึกการสิ้นสุดขั้นตอนรับบริการ
- ตรวจสอบรายการบริการที่ดำเนินการแล้ว
- ส่งต่อข้อมูลไปยังระบบ Billing
- เชื่อมโยงกับเวชระเบียน
- บันทึกเวลาที่ใช้จริง
- แสดงรายการที่ยังไม่เสร็จสิ้น
- ตรวจสอบรายการที่ต้องติดตามต่อ

กฎทางธุรกิจ

- ต้องไม่ถือว่าการออกจากคิวเท่ากับการชำระเงินเสร็จสิ้น
- ต้องแยกสถานะการให้บริการออกจากสถานะการชำระเงิน
- ต้องตรวจสอบรายการที่ยังดำเนินการไม่เสร็จ
- ต้องเก็บผู้ดำเนินการและเวลาที่เปลี่ยนสถานะ
- ต้องรองรับกรณีที่สัตว์เลี้ยงต้องเข้ารับบริการหลายขั้นตอน

## 3.15 การคัดกรองสัตว์ป่วยฉุกเฉิน (Emergency Triage)

เป็นกระบวนการประเมินอาการเบื้องต้นของสัตว์ป่วยเพื่อจัดระดับความเร่งด่วนในการได้รับการดูแล

เป็นความสามารถที่มีความสำคัญอย่างยิ่ง เพราะการจัดลำดับคิวของคลินิกสัตวแพทย์ไม่ควรใช้หลักมาก่อนได้รับบริการก่อนในทุกสถานการณ์

วัตถุประสงค์

- ค้นหาสัตว์ป่วยที่ต้องได้รับการดูแลเร่งด่วน
- ลดความเสี่ยงจากการรอคิว
- จัดลำดับความสำคัญของการให้บริการ
- สนับสนุนการตัดสินใจของบุคลากรทางสัตวแพทย์
- บันทึกข้อมูลการคัดกรองอย่างเป็นระบบ

ตัวอย่างอาการที่ต้องให้ความสำคัญ

- หายใจลำบาก
- หมดสติหรือไม่ตอบสนอง
- เลือดออกมาก
- ชักต่อเนื่องหรือชักซ้ำ
- ได้รับอุบัติเหตุรุนแรง
- สงสัยได้รับสารพิษ
- มีอาการทรุดลงอย่างรวดเร็ว

ตัวอย่างเหล่านี้ใช้ประกอบการออกแบบระบบเท่านั้น การประเมินระดับความเร่งด่วนและการรักษาต้องเป็นหน้าที่ของบุคลากรที่มีความรู้และอำนาจหน้าที่เหมาะสม

ข้อมูลที่ต้องจัดเก็บ

| รายการ                | รายละเอียด                   |
| --------------------- | ---------------------------- |
| รหัสการคัดกรอง        | รหัสประจำรายการ              |
| รหัสสัตว์เลี้ยง       | สัตว์ป่วยที่ได้รับการคัดกรอง |
| รหัสการเข้ารับบริการ  | รายการรับบริการที่เกี่ยวข้อง |
| เวลาที่เริ่มคัดกรอง   | เวลาเริ่มประเมิน             |
| อาการเบื้องต้น        | อาการที่พบ                   |
| ระดับความเร่งด่วน     | ผลการประเมิน                 |
| ผู้ประเมิน            | บุคลากรผู้คัดกรอง            |
| สัญญาณชีพ             | ข้อมูลที่ตรวจวัด             |
| การดำเนินการเบื้องต้น | สิ่งที่ดำเนินการ             |
| เวลาส่งต่อ            | เวลาที่ส่งต่อให้สัตวแพทย์    |
| หมายเหตุ              | รายละเอียดเพิ่มเติม          |

ตัวอย่างระดับความเร่งด่วนที่สามารถนำมาใช้ในการออกแบบ

- ระดับวิกฤต: ต้องได้รับการช่วยเหลือทันที
- ระดับฉุกเฉิน: ต้องได้รับการประเมินและดูแลอย่างเร่งด่วน
- ระดับเร่งด่วน: ควรได้รับการตรวจโดยเร็ว
- ระดับทั่วไป: สามารถรอตามลำดับคิวได้
- ระดับนัดหมาย: เข้ารับบริการตามเวลานัดหมาย

การแบ่งระดับข้างต้นเป็นตัวอย่างสำหรับออกแบบระบบ ไม่ใช่มาตรฐานการคัดกรองทางสัตวแพทย์ที่กำหนดใช้กับทุกคลินิก

ความสามารถของระบบ

- บันทึกผลการคัดกรอง
- บันทึกสัญญาณชีพ
- กำหนดระดับความเร่งด่วน
- แจ้งเตือนกรณีวิกฤต
- เปลี่ยนลำดับคิวตามผลการประเมิน
- ส่งต่อสัตวแพทย์
- บันทึกประวัติการประเมิน
- ติดตามเวลาตั้งแต่มาถึงจนได้รับการประเมิน
- ตรวจสอบผู้ประเมิน
- รองรับการประเมินซ้ำเมื่ออาการเปลี่ยนแปลง

กฎทางธุรกิจ

- ต้องสามารถคัดกรองสัตว์ป่วยได้ทั้งกลุ่มนัดหมายและ Walk-in
- สัตว์ป่วยฉุกเฉินต้องไม่ถูกบังคับให้รอคิวทั่วไป
- การจัดระดับความเร่งด่วนต้องมีผู้รับผิดชอบ
- ต้องบันทึกวันและเวลาการประเมิน
- ต้องรองรับการเปลี่ยนระดับความเร่งด่วน
- ต้องเก็บประวัติการเปลี่ยนแปลงระดับความเร่งด่วน
- ระบบต้องไม่ตัดสินระดับความฉุกเฉินจากข้อมูลอัตโนมัติเพียงอย่างเดียว

## 3.16 การจัดการกรณีไม่มาตามนัด (No-show Management)

เป็นการบริหารจัดการกรณีที่ลูกค้าไม่ได้เดินทางมาเข้ารับบริการตามวันและเวลาที่กำหนด โดยไม่มีการยกเลิกหรือแจ้งเปลี่ยนแปลงนัดหมายล่วงหน้าตามเงื่อนไขของคลินิก

สาเหตุที่อาจเกิดขึ้น

1. ลูกค้าลืมวันนัด
2. ลูกค้าไม่สะดวกเดินทาง
3. ลูกค้าไม่สามารถติดต่อได้
4. สัตว์เลี้ยงมีอาการดีขึ้น
5. ลูกค้าเปลี่ยนไปใช้บริการที่อื่น
6. เกิดเหตุการณ์ที่ไม่คาดคิด

ข้อมูลที่ควรจัดเก็บ

- รหัสนัดหมาย
- รหัสลูกค้า
- รหัสสัตว์เลี้ยง
- วันและเวลานัดหมาย
- เวลาที่คาดว่าจะมาถึง
- เวลาที่ตรวจพบว่าไม่มาตามนัด
- ผู้ตรวจสอบ
- สาเหตุของการไม่มาตามนัด
- ผลการติดต่อ
- สถานะการติดตาม

กระบวนการทำงาน

1. ระบบตรวจสอบรายการนัดหมายประจำวัน
2. เมื่อเลยเวลานัดตามระยะเวลาผ่อนผันที่กำหนด
3. ตรวจสอบว่าลูกค้า Check-in แล้วหรือไม่
4. หากยังไม่มาถึง ให้แจ้งเตือนพนักงาน
5. พนักงานติดต่อสอบถามลูกค้า
6. บันทึกผลการติดต่อ
7. กำหนดสถานะ No-show หากเข้าเงื่อนไข
8. พิจารณาการนัดหมายใหม่
9. เก็บประวัติการไม่มาตามนัด

ความสามารถของระบบ

- ตรวจจับรายการนัดหมายที่ไม่มาตามนัด
- กำหนดระยะเวลาผ่อนผัน
- แจ้งเตือนพนักงาน
- บันทึกเหตุผล
- บันทึกผลการติดต่อลูกค้า
- แสดงประวัติ No-show
- วิเคราะห์อัตราการไม่มาตามนัด
- รองรับการนัดหมายใหม่

กฎทางธุรกิจ

- ต้องไม่กำหนด No-show ทันทีเมื่อเลยเวลานัดเพียงเล็กน้อย
- ต้องมีระยะเวลาผ่อนผันที่กำหนดไว้
- ต้องตรวจสอบสถานะ Check-in ก่อน
- ต้องแยก No-show ออกจากการยกเลิกนัด
- ต้องบันทึกประวัติทุกครั้ง
- ต้องไม่เปลี่ยนแปลงประวัตินัดหมายเดิม
- การกำหนดค่าปรับหรือเงินมัดจำต้องเป็นไปตามนโยบายที่แจ้งลูกค้าไว้

## 3.17 การติดตามสถานะการให้บริการ (Service Status Tracking)

เป็นการติดตามความคืบหน้าของลูกค้าและสัตว์เลี้ยงในแต่ละขั้นตอน ตั้งแต่ลงทะเบียนเข้ารับบริการจนถึงการส่งต่อเข้าสู่ระบบตรวจรักษา

สถานะที่ควรรองรับ

1. รอการลงทะเบียน
2. ลงทะเบียนแล้ว
3. รอคัดกรอง
4. กำลังคัดกรอง
5. รอพบสัตวแพทย์
6. เรียกเข้าห้องตรวจ
7. กำลังตรวจรักษา
8. รอผลตรวจเพิ่มเติม
9. รอรับการรักษาขั้นต่อไป
10. เสร็จสิ้นขั้นตอนบริการ
11. ยกเลิกการรับบริการ

สถานะจริงอาจแตกต่างกันตามประเภทบริการ เช่น การฉีดวัคซีนอาจไม่มีขั้นตอนส่งตรวจทางห้องปฏิบัติการ

ข้อมูลที่ต้องจัดเก็บ

- รหัสรายการรับบริการ
- รหัสคิว
- สถานะปัจจุบัน
- สถานะก่อนหน้า
- วันเวลาที่เปลี่ยนสถานะ
- ผู้เปลี่ยนสถานะ
- เหตุผลการเปลี่ยนสถานะ
- หมายเหตุ

ความสามารถของระบบ

- แสดงสถานะปัจจุบัน
- แสดงประวัติสถานะ
- แสดงเวลาที่ใช้ในแต่ละขั้นตอน
- แจ้งเตือนเมื่อมีความล่าช้า
- แสดงรายการที่ค้างอยู่
- แสดงรายการที่ต้องติดตาม
- เชื่อมโยงกับระบบตรวจรักษา
- วิเคราะห์จุดที่เกิดความล่าช้า

กฎทางธุรกิจ

- ต้องกำหนดสถานะที่สามารถเปลี่ยนไปหากันได้
- ต้องบันทึกเวลาทุกครั้งที่เปลี่ยนสถานะ
- ต้องระบุผู้ดำเนินการ
- ต้องไม่อนุญาตให้ข้ามสถานะสำคัญโดยไม่มีเงื่อนไข
- ต้องรองรับการส่งต่อระหว่างขั้นตอน

3. หากเป็นลูกค้าใหม่ ให้ลงทะเบียนลูกค้า
4. เลือกสัตว์เลี้ยงที่ต้องการเข้ารับบริการ
5. หากเป็นสัตว์เลี้ยงใหม่ ให้ลงทะเบียนสัตว์เลี้ยง
6. สอบถามประเภทบริการที่ต้องการ
7. บันทึกอาการหรือเหตุผลในการนัดหมาย
8. ตรวจสอบตารางทำงานของสัตวแพทย์
9. ตรวจสอบตารางห้องตรวจ
10. ตรวจสอบระยะเวลาที่ต้องใช้ในบริการ
11. ตรวจสอบช่วงเวลาว่าง
12. เสนอวันและเวลาให้ลูกค้า
13. ลูกค้าเลือกวันและเวลา
14. บันทึกการนัดหมาย
15. ระบบสร้างรหัสนัดหมาย
16. กำหนดสถานะนัดหมาย
17. ส่งรายละเอียดนัดหมายให้ลูกค้า
18. สร้างรายการแจ้งเตือนก่อนถึงวันนัด

## 4.2 กระบวนการรับลูกค้าตามนัดหมาย

1. ลูกค้าเดินทางมาถึงคลินิก
2. พนักงานตรวจสอบข้อมูลลูกค้า

4. ตรวจสอบสัตว์เลี้ยง

7. ตรวจสอบอาการเพิ่มเติม
8. หากพบสัญญาณที่ต้องคัดกรองเร่งด่วน ให้ดำเนินการคัดกรอง

10. แจ้งหมายเลขคิวให้ลูกค้า
11. ลูกค้ารอรับบริการ
12. ระบบเรียกคิวเมื่อถึงลำดับ
13. ลูกค้าเข้าสู่กระบวนการตรวจรักษา

## 4.3 กระบวนการรับลูกค้าแบบ Walk-in

1. ลูกค้าเดินทางมาถึงคลินิกโดยไม่ได้นัด
2. พนักงานสอบถามข้อมูลเบื้องต้น
3. ค้นหาข้อมูลลูกค้า
4. ตรวจสอบข้อมูลสัตว์เลี้ยง
5. บันทึกอาการเบื้องต้น
6. สร้างรายการ Walk-in
7. ตรวจสอบว่ามีอาการที่ต้องคัดกรองเร่งด่วนหรือไม่
8. หากมี ให้ส่งเข้ากระบวนการคัดกรอง
9. หากไม่มี ให้ตรวจสอบคิวปัจจุบัน
10. สร้างหมายเลขคิว
11. แจ้งลูกค้าเกี่ยวกับเวลารอโดยประมาณ
12. รอเรียกเข้ารับบริการ
13. ส่งต่อเข้าสู่ระบบตรวจรักษา

## 4.4 กระบวนการจัดการกรณียกเลิกนัดหมาย

1. ลูกค้าแจ้งความประสงค์ยกเลิก
2. พนักงานค้นหารายการนัดหมาย
3. ตรวจสอบสถานะนัดหมาย
4. บันทึกเหตุผลการยกเลิก
5. ตรวจสอบเงินมัดจำหรือเงื่อนไขที่เกี่ยวข้อง หากมี
6. ยืนยันการยกเลิก
7. เปลี่ยนสถานะนัดหมาย
8. คืนช่วงเวลาที่จองไว้
9. ตรวจสอบรายชื่อรอคิว
10. ติดต่อผู้ที่ต้องการช่วงเวลาว่าง
11. แจ้งผลการยกเลิกให้ลูกค้าทราบ
12. จัดเก็บประวัติการดำเนินการ

## 4.5 กระบวนการจัดการสัตว์ป่วยฉุกเฉิน

1. ลูกค้านำสัตว์ป่วยเข้ามาที่คลินิก
2. พนักงานรับแจ้งอาการเบื้องต้น
3. แจ้งบุคลากรที่รับผิดชอบการคัดกรอง
4. ดำเนินการประเมินความเร่งด่วน
5. บันทึกผลการคัดกรอง
6. หากเป็นกรณีวิกฤต ให้แจ้งสัตวแพทย์ทันที
7. จัดสรรพื้นที่และทรัพยากรที่จำเป็น
8. ส่งต่อสัตว์ป่วยเพื่อรับการดูแล
9. บันทึกเวลาที่เริ่มได้รับการดูแล
10. เชื่อมโยงรายการเข้ารับบริการกับเวชระเบียน

กระบวนการนี้ต้องให้ความสำคัญกับความปลอดภัยของสัตว์ป่วยมากกว่าลำดับคิวปกติ

## 4.6 กระบวนการจัดการรายชื่อรอคิว

1. ลูกค้าต้องการนัดหมาย
2. ระบบตรวจสอบช่วงเวลาว่าง
3. ไม่พบช่วงเวลาที่เหมาะสม
4. เสนอให้ลูกค้าเข้ารายชื่อรอคิว
5. บันทึกช่วงเวลาที่ต้องการ
6. รอจนมีช่วงเวลาว่าง
7. ระบบค้นหารายชื่อที่ตรงกับเงื่อนไข
8. แจ้งลูกค้าที่มีคุณสมบัติตรงตามช่วงเวลาว่าง
9. ลูกค้าตอบรับ
10. สร้างรายการนัดหมาย
11. เปลี่ยนสถานะรายการรอคิวเป็นดำเนินการแล้ว

## 4.7 กระบวนการจัดการกรณีสัตวแพทย์ไม่สามารถปฏิบัติงานได้

เป็นกรณีสำคัญที่ระบบต้องรองรับ เช่น สัตวแพทย์ลาป่วย ติดภารกิจ หรือมีเหตุฉุกเฉิน

1. ผู้ดูแลตารางงานได้รับแจ้งว่าสัตวแพทย์ไม่สามารถปฏิบัติงานได้
2. ตรวจสอบตารางนัดหมายที่ได้รับผลกระทบ
3. ค้นหาสัตวแพทย์ทดแทน
4. ตรวจสอบความสามารถในการให้บริการ
5. ตรวจสอบเวลาว่าง
6. จัดสรรสัตวแพทย์ทดแทน
7. หากไม่สามารถจัดสรรได้ ให้ค้นหาช่วงเวลาใหม่
8. ติดต่อแจ้งลูกค้า
9. บันทึกผลการเปลี่ยนแปลง
10. ปรับปรุงตารางนัดหมาย
11. ตรวจสอบว่ารายการนัดหมายทั้งหมดได้รับการจัดการแล้ว

ข้อควรระวัง: ไม่ควรเปลี่ยนสัตวแพทย์ในรายการนัดหมายทั้งหมดโดยอัตโนมัติโดยไม่ตรวจสอบประเภทบริการและความเหมาะสมของผู้ให้บริการ

## 6.1 ความสัมพันธ์ระหว่าง Appointment กับ Queue

จุดนี้เป็นเรื่องสำคัญในการออกแบบฐานข้อมูล

ไม่ควรรวมข้อมูลนัดหมายและข้อมูลคิวไว้ในตารางเดียวกัน เพราะมีวัตถุประสงค์ต่างกัน

Appointment คือการจองช่วงเวลาในอนาคต

Queue คือการจัดลำดับการเข้ารับบริการตามสถานการณ์จริง

# 7. ผู้ใช้งานที่เกี่ยวข้องกับโดเมนนี้

การออกแบบระบบต้องกำหนดบทบาทและสิทธิ์ของผู้ใช้งานแต่ละประเภท

| ผู้ใช้งาน               | หน้าที่และสิทธิ์                             |
| ----------------------- | -------------------------------------------- |
| ผู้ดูแลระบบ             | ตั้งค่าระบบนัดหมายและคิว                     |
| ผู้จัดการคลินิก         | ตรวจสอบและบริหารภาพรวม                       |
| พนักงานต้อนรับ          | จองนัดหมายและลงทะเบียนลูกค้า                 |
| เจ้าหน้าที่จัดคิว       | เรียกคิวและจัดการคิว                         |
| สัตวแพทย์               | ตรวจสอบตารางงานและรับรายการตรวจ              |
| ผู้ช่วยสัตวแพทย์        | ตรวจสอบรายการคิวและช่วยประสานงาน             |
| ผู้คัดกรอง              | บันทึกและจัดการผลการคัดกรองตามหน้าที่        |
| ผู้ดูแลสถานที่          | จัดการตารางห้องและทรัพยากร                   |
| เจ้าหน้าที่บริการลูกค้า | ติดต่อและติดตามการนัดหมาย                    |
| ลูกค้า                  | จองนัดหมาย ตรวจสอบและเปลี่ยนแปลงนัดตามสิทธิ์ |

ตัวอย่างการกำหนดสิทธิ์

- พนักงานต้อนรับสามารถสร้างและเปลี่ยนแปลงนัดหมายได้
- พนักงานต้อนรับสามารถลงทะเบียน Walk-in ได้
- เจ้าหน้าที่จัดคิวสามารถเรียกและข้ามคิวได้ตามสิทธิ์
- สัตวแพทย์สามารถตรวจสอบตารางนัดหมายของตนเองได้
- ผู้จัดการสามารถตรวจสอบตารางนัดหมายของทุกสาขาตามสิทธิ์
- ลูกค้าสามารถดูนัดหมายของตนเองและสัตว์เลี้ยงที่มีสิทธิ์ดูแลได้
- การเปลี่ยนระดับความเร่งด่วนต้องจำกัดสิทธิ์ให้ผู้ที่ได้รับมอบหมาย

การกำหนดสิทธิ์ควรแยกตามบทบาท สาขา และขอบเขตหน้าที่ ไม่ควรให้ผู้ใช้งานทุกคนแก้ไขข้อมูลนัดหมายและคิวได้ทั้งหมด

# 9. ข้อกำหนดที่สำคัญในการพัฒนาระบบ

ผมขอเน้นข้อกำหนดทางธุรกิจและเทคนิค 15 ประการที่ควรให้ความสำคัญเป็นพิเศษ

1. Appointment เป็นข้อมูลหลัก: ต้องมีรหัสนัดหมายที่ไม่ซ้ำกัน
2. แยก Appointment กับ Queue: ต้องแยกข้อมูลการจองนัดหมายออกจากข้อมูลคิว
3. รองรับ Walk-in: ต้องรองรับลูกค้าที่ไม่ได้จองนัดหมาย
4. รองรับหลายสาขา: ต้องแยกตารางนัดหมายและคิวตามสาขา
5. ป้องกันการจองซ้ำ: ต้องตรวจสอบช่วงเวลาของสัตวแพทย์และทรัพยากร
6. รองรับหลายประเภทบริการ: แต่ละบริการอาจใช้เวลาและทรัพยากรต่างกัน
7. รองรับการเปลี่ยนแปลงนัด: ต้องเก็บประวัติการแก้ไข
8. รองรับการยกเลิกนัด: ต้องเก็บประวัติและคืนทรัพยากรที่จองไว้
9. รองรับ Emergency Triage: ต้องจัดการสัตว์ป่วยฉุกเฉินแยกจากคิวทั่วไป
10. รองรับการแจ้งเตือน: ต้องสามารถแจ้งเตือนผ่านหลายช่องทาง
11. รองรับ No-show: ต้องตรวจจับและติดตามลูกค้าที่ไม่มาตามนัด
12. ติดตามสถานะได้: ต้องทราบว่าสัตว์เลี้ยงอยู่ในขั้นตอนใด
13. ตรวจสอบย้อนหลังได้: การเปลี่ยนแปลงสำคัญต้องมีประวัติ
14. รองรับการทำงานพร้อมกัน: ต้องป้องกันปัญหาการจองทรัพยากรซ้ำจากผู้ใช้งานหลายคน
15. รองรับการเชื่อมต่อ: ต้องเชื่อมโยงกับระบบลูกค้า เวชระเบียน บุคลากร และการเงินได้

## ข้อสรุปของ Domain นี้

Domain Appointment & Queue Management ควรทำหน้าที่เป็นศูนย์กลางการบริหารนัดหมาย ตารางเวลา และคิวรับบริการของคลินิกสัตวแพทย์

ต้องสามารถตอบคำถามสำคัญในการดำเนินงานได้ เช่น

- วันนี้มีลูกค้านัดหมายกี่ราย?
- วันนี้มีสัตว์เลี้ยงเข้ารับบริการกี่ตัว?
- สัตวแพทย์แต่ละคนมีนัดหมายกี่รายการ?
- ช่วงเวลาใดมีนัดหมายหนาแน่นที่สุด?
- ห้องตรวจใดกำลังถูกใช้งาน?
- มีลูกค้ารอรับบริการกี่ราย?
- คิวใดกำลังรอเรียก?
- มีสัตว์ป่วยฉุกเฉินหรือไม่?
- ลูกค้ารายใดยังไม่มาตามนัด?
- มีนัดหมายใดที่ต้องเปลี่ยนแปลง?
- ระยะเวลารอคอยเฉลี่ยของลูกค้าเป็นเท่าใด?

สิ่งสำคัญที่สุดคือ ต้องแยกการจองนัดหมาย การลงทะเบียนเข้ารับบริการ การจัดคิว และการตรวจรักษาออกจากกันอย่างชัดเจน แม้ว่าทั้งหมดจะเป็นกระบวนการที่เชื่อมโยงกันก็ตาม

# 12. ลำดับการออกแบบขั้นต่อไป

หากจะนำ Domain นี้ไปพัฒนาระบบ ERP สำหรับคลินิกสัตวแพทย์ ผมแนะนำให้ลงรายละเอียดต่ออีก 4 ระดับ โดยใช้แนวทางเดียวกับ Domain 01: Customer & Pet Management

ขั้นที่ 1

Business Capability Breakdown

แตกความสามารถทั้ง 18 กลุ่มออกเป็นความสามารถย่อย พร้อมกำหนดขอบเขต หน้าที่ และผู้รับผิดชอบ

ขั้นที่ 2

Business Process & Business Rules

ออกแบบขั้นตอนปฏิบัติงานจริง เงื่อนไข กฎทางธุรกิจ และกรณีผิดปกติ

ขั้นที่ 3

Database Architecture & Complete ERD

ออกแบบตารางทั้งหมด พร้อม Primary Key, Foreign Key, Data Types, Index, Relationships และ Data Dictionary

ขั้นที่ 4

Application Architecture & API Specification

ออกแบบหน้าจอ โมดูลระบบ API และการเชื่อมต่อกับ Domain อื่น

## ข้อเสนอแนะเพิ่มเติมสำหรับการพัฒนาระบบ

ผมแนะนำให้ให้ความสำคัญกับ 5 เรื่องนี้เป็นพิเศษก่อนเริ่มพัฒนาฐานข้อมูล

1. การออกแบบสถานะนัดหมาย (Appointment Status Lifecycle)
2. การออกแบบสถานะคิว (Queue Status Lifecycle)
3. การออกแบบการจัดสรรสัตวแพทย์ ห้องตรวจ และทรัพยากร (Resource Scheduling)
4. การออกแบบกระบวนการคัดกรองสัตว์ป่วยฉุกเฉิน (Emergency Triage Workflow)
5. การออกแบบการป้องกันการจองซ้ำและการทำงานพร้อมกัน (Concurrency Control)

เพราะทั้ง 5 เรื่องนี้จะส่งผลโดยตรงต่อโครงสร้างฐานข้อมูล กฎทางธุรกิจ และการออกแบบ API ของระบบในอนาคต

เป้าหมายคือการสร้างระบบ Appointment & Queue Management ที่สามารถใช้งานได้จริงในคลินิกสัตวแพทย์ ตั้งแต่คลินิกขนาดเล็กที่มีสัตวแพทย์ 1–2 คน ไปจนถึงโรงพยาบาลสัตว์หรือธุรกิจคลินิกหลายสาขา โดยไม่จำเป็นต้องรื้อโครงสร้างระบบใหม่เมื่อธุรกิจเติบโตขึ้นครับ
