# Domain 06: การบริหารจัดการการผ่าตัดและหัตถการรักษา (Surgery & Treatment Management)

Domain นี้เป็นหนึ่งในโดเมนสำคัญของธุรกิจคลินิกสัตวแพทย์และโรงพยาบาลสัตว์ ทำหน้าที่บริหารจัดการกระบวนการผ่าตัด การทำหัตถการทางการแพทย์ การเตรียมความพร้อมก่อนการรักษา การระงับความรู้สึก การดำเนินการรักษาจริง การดูแลระหว่างทำหัตถการ ตลอดจนการติดตามและดูแลสัตว์เลี้ยงหลังการรักษา

หากมองในมุมของการพัฒนาระบบบริหารจัดการคลินิกสัตวแพทย์ (Veterinary Clinic ERP) Domain นี้จะเป็นศูนย์กลางในการควบคุมกระบวนการรักษาที่ต้องมีการปฏิบัติงานเฉพาะทาง ซึ่งมีความซับซ้อนมากกว่าการตรวจรักษาทั่วไป

ตัวอย่างบริการที่อยู่ในขอบเขตของ Domain นี้ ได้แก่

- การผ่าตัดทำหมันสุนัขและแมว
- การผ่าตัดทำหมันสัตว์เพศผู้และเพศเมีย
- การผ่าตัดนำสิ่งแปลกปลอมออกจากร่างกาย
- การผ่าตัดก้อนเนื้อและเนื้องอก
- การผ่าตัดกระดูกและข้อ
- การผ่าตัดช่องท้อง
- การผ่าตัดเนื้อเยื่ออ่อน
- การผ่าตัดฉุกเฉิน
- การทำแผลและเย็บแผล
- การล้างแผลและตัดไหม
- การใส่สายสวนปัสสาวะ
- การให้สารน้ำทางหลอดเลือดดำ
- การระบายของเหลวหรือหนอง
- การทำหัตถการทางทันตกรรม
- การระงับความรู้สึกและการเฝ้าระวังระหว่างผ่าตัด
- การดูแลและติดตามอาการหลังผ่าตัด

วัตถุประสงค์หลักของ Domain นี้ คือ ทำให้คลินิกสามารถควบคุมกระบวนการผ่าตัดและหัตถการได้อย่างเป็นระบบ ตั้งแต่ได้รับคำสั่งรักษาจากสัตวแพทย์ การประเมินความพร้อม การจัดเตรียมบุคลากรและอุปกรณ์ การดำเนินการรักษาจริง การบันทึกผล ไปจนถึงการติดตามผลหลังการรักษา โดยทุกขั้นตอนสามารถตรวจสอบย้อนหลังได้

## 1. วัตถุประสงค์หลักของโดเมน

การบริหารจัดการการผ่าตัดและหัตถการมีวัตถุประสงค์สำคัญ 12 ประการ

1. บริหารรายการผ่าตัดและหัตถการ: จัดเก็บรายการบริการและประเภทการรักษาที่คลินิกสามารถดำเนินการได้
2. บริหารคำขอรับการผ่าตัด: รับคำสั่งหรือแผนการรักษาที่ส่งมาจาก Clinical & Medical Management
3. บริหารการประเมินก่อนผ่าตัด: ตรวจสอบความพร้อมของสัตว์เลี้ยงก่อนเข้ารับการผ่าตัดหรือหัตถการ
4. บริหารการยินยอมให้รักษา: จัดเก็บหลักฐานการยินยอมจากเจ้าของสัตว์เลี้ยง
5. บริหารตารางผ่าตัด: จัดสรรวันเวลา ห้องผ่าตัด สัตวแพทย์ และบุคลากรที่เกี่ยวข้อง
6. บริหารการเตรียมผ่าตัด: ตรวจสอบความพร้อมของสถานที่ เครื่องมือ ยา และเวชภัณฑ์
7. บริหารการระงับความรู้สึก: บันทึกข้อมูลการวางยาสลบหรือการระงับความรู้สึกตามแผนการรักษา
8. บริหารกระบวนการผ่าตัด: ควบคุมขั้นตอนการผ่าตัดและการทำหัตถการจริง
9. บริหารการบันทึกผลการรักษา: บันทึกผลการผ่าตัด รายละเอียดหัตถการ และเหตุการณ์สำคัญ
10. บริหารการดูแลหลังผ่าตัด: ติดตามอาการและเฝ้าระวังภาวะแทรกซ้อน
11. บริหารการส่งต่อและติดตามผล: เชื่อมโยงการรักษากับเวชระเบียนและการนัดติดตาม
12. บริหารคุณภาพและความปลอดภัย: ตรวจสอบความครบถ้วนของกระบวนการและวิเคราะห์เหตุการณ์ไม่พึงประสงค์

เป้าหมายสูงสุดคือ ทำให้การผ่าตัดและหัตถการทุกครั้งมีข้อมูลครบถ้วน สามารถระบุผู้รับผิดชอบ ทรัพยากรที่ใช้ ขั้นตอนที่ดำเนินการ ผลลัพธ์ และประวัติการติดตามได้อย่างชัดเจน

## 3. รายละเอียดกลุ่มความสามารถทางธุรกิจ

### 3.1 การบริหารทะเบียนผ่าตัดและหัตถการ (Surgery & Procedure Catalog Management)

เป็นการจัดการทะเบียนรายการผ่าตัดและหัตถการทั้งหมดที่คลินิกเปิดให้บริการ เพื่อให้สามารถกำหนดมาตรฐานของบริการและนำไปใช้ในกระบวนการทำงานได้อย่างเป็นระบบ

ตัวอย่างรายการผ่าตัด

- การผ่าตัดทำหมันสุนัข
- การผ่าตัดทำหมันแมว
- การผ่าตัดนำก้อนเนื้อออก
- การผ่าตัดนำสิ่งแปลกปลอมออก
- การผ่าตัดแก้ไขกระดูกหัก
- การผ่าตัดกระเพาะปัสสาวะ
- การผ่าตัดช่องท้อง
- การผ่าตัดเนื้อเยื่ออ่อน

ตัวอย่างรายการหัตถการ

- การทำแผล
- การเย็บแผล
- การตัดไหม
- การล้างแผล
- การใส่สายสวนปัสสาวะ
- การระบายหนอง
- การเจาะระบายของเหลว
- การทำความสะอาดช่องปากและฟัน
- การขูดหินปูน
- การถอนฟัน

ข้อมูลที่ควรจัดเก็บ

| รายการข้อมูล             | รายละเอียด                          |
| ------------------------ | ----------------------------------- |
| รหัสรายการ               | รหัสผ่าตัดหรือหัตถการ               |
| ชื่อรายการ               | ชื่อบริการ                          |
| ประเภท                   | ผ่าตัด หัตถการ หรือการรักษาเฉพาะทาง |
| คำอธิบาย                 | รายละเอียดของบริการ                 |
| กลุ่มอวัยวะ              | เช่น ช่องท้อง กระดูก ผิวหนัง        |
| ระดับความซับซ้อน         | ระดับความยากของการรักษา             |
| ระยะเวลาประมาณ           | ระยะเวลาที่ใช้                      |
| ประเภทการระงับความรู้สึก | ไม่ใช้ เฉพาะที่ หรือทั่วร่างกาย     |
| คุณสมบัติผู้ดำเนินการ    | ประเภทหรือระดับความเชี่ยวชาญ        |
| ห้องที่ต้องใช้           | ห้องตรวจ ห้องผ่าตัด หรือห้องหัตถการ |
| อุปกรณ์ที่ต้องใช้        | รายการอุปกรณ์ที่จำเป็น              |
| สถานะ                    | เปิดใช้งานหรือปิดใช้งาน             |

ความสามารถของระบบ

- สร้างและแก้ไขทะเบียนรายการผ่าตัด
- สร้างและแก้ไขทะเบียนหัตถการ
- แบ่งประเภทบริการ
- กำหนดระยะเวลามาตรฐาน
- กำหนดข้อกำหนดก่อนการรักษา
- กำหนดรายการอุปกรณ์ที่ต้องเตรียม
- กำหนดบุคลากรที่มีคุณสมบัติเหมาะสม
- เชื่อมโยงรายการบริการกับระบบ Billing

กฎทางธุรกิจ

- รายการผ่าตัดและหัตถการต้องมีรหัสเฉพาะ
- รายการที่ปิดใช้งานแล้วต้องไม่ถูกเลือกสร้างรายการใหม่
- การแก้ไขรายละเอียดบริการต้องไม่เปลี่ยนแปลงข้อมูลประวัติการรักษาที่เกิดขึ้นแล้ว
- ต้องแยกประเภทผ่าตัดออกจากหัตถการทั่วไป
- ต้องรองรับบริการที่มีหลายขั้นตอน
- ต้องรองรับบริการที่ต้องใช้บุคลากรและเครื่องมือเฉพาะทาง

### 3.2 การบริหารคำขอผ่าตัดและหัตถการ (Surgery Request Management)

เป็นกระบวนการรับคำสั่งหรือคำขอให้ดำเนินการผ่าตัดและหัตถการจากสัตวแพทย์ผู้ตรวจรักษา

ส่วนนี้มีความสำคัญมาก เพราะการผ่าตัดหรือหัตถการไม่ควรเกิดขึ้นโดยไม่มีข้อมูลอ้างอิงว่ามีความจำเป็นทางการแพทย์และได้รับการวางแผนจากผู้รับผิดชอบแล้ว

ข้อมูลที่ควรจัดเก็บ

- รหัสคำขอผ่าตัด
- รหัสรายการตรวจรักษา (Clinical Encounter)
- รหัสสัตว์เลี้ยง
- รหัสรายการผ่าตัดหรือหัตถการ
- ข้อบ่งชี้ทางการแพทย์
- การวินิจฉัยที่เกี่ยวข้อง
- รายละเอียดการรักษาที่ต้องการ
- สัตวแพทย์ผู้สั่ง
- ระดับความเร่งด่วน
- วันที่สร้างคำขอ
- วันที่ต้องการดำเนินการ
- สถานะคำขอ
- หมายเหตุ

ความสามารถของระบบ

1. รับคำขอผ่าตัดจาก Clinical
2. รับคำขอทำหัตถการจาก Clinical
3. ตรวจสอบข้อมูลสัตว์เลี้ยง
4. ตรวจสอบการวินิจฉัยและข้อบ่งชี้
5. ตรวจสอบประเภทบริการ
6. กำหนดระดับความเร่งด่วน
7. มอบหมายสัตวแพทย์ผู้รับผิดชอบ
8. ส่งคำขอเข้าสู่กระบวนการประเมินก่อนผ่าตัด
9. ติดตามสถานะคำขอ
10. บันทึกเหตุผลกรณีปฏิเสธหรือยกเลิก

กฎทางธุรกิจ

- คำขอผ่าตัดต้องอ้างอิงสัตว์เลี้ยงและรายการตรวจรักษาที่ถูกต้อง
- ต้องระบุสัตวแพทย์ผู้สั่ง
- ต้องระบุเหตุผลหรือข้อบ่งชี้ในการรักษา
- คำขอหนึ่งรายการอาจมีหลายรายการผ่าตัดหรือหัตถการ
- การเปลี่ยนแปลงคำขอต้องเก็บประวัติ
- ต้องแยกคำขอผ่าตัดออกจากการผ่าตัดที่เกิดขึ้นจริง
- การยกเลิกต้องระบุเหตุผลและผู้ดำเนินการ

### 3.3 การประเมินความพร้อมก่อนผ่าตัด (Preoperative Assessment Management)

เป็นกระบวนการประเมินสภาพร่างกายและความพร้อมของสัตว์เลี้ยงก่อนเข้ารับการผ่าตัดหรือหัตถการ

วัตถุประสงค์สำคัญคือ ลดความเสี่ยงที่อาจเกิดขึ้นระหว่างการผ่าตัดและการระงับความรู้สึก

องค์ประกอบของการประเมิน

1. การประเมินสภาพร่างกายทั่วไป
2. การประเมินสัญญาณชีพ
3. การประเมินระบบหัวใจและหลอดเลือด
4. การประเมินระบบทางเดินหายใจ
5. การประเมินระบบประสาท
6. การประเมินภาวะขาดน้ำ
7. การตรวจสอบประวัติการแพ้ยา
8. การตรวจสอบโรคประจำตัว
9. การตรวจสอบประวัติการใช้ยา
10. การประเมินผลตรวจทางห้องปฏิบัติการ
11. การประเมินความเสี่ยงจากการระงับความรู้สึก
12. การกำหนดความพร้อมก่อนเข้ารับการผ่าตัด

| รายการข้อมูล      | รายละเอียด                            |
| ----------------- | ------------------------------------- |
| รหัสการประเมิน    | รหัสประจำรายการ                       |
| รหัสคำขอผ่าตัด    | อ้างอิงคำขอ                           |
| น้ำหนัก           | น้ำหนักสัตว์ ณ วันที่ประเมิน          |
| อุณหภูมิ          | อุณหภูมิร่างกาย                       |

ความสามารถของระบบ

- บันทึกผลประเมินก่อนผ่าตัด
- เรียกดูประวัติสุขภาพ
- เรียกดูประวัติแพ้ยา
- เชื่อมโยงผลตรวจเลือด
- บันทึกผลการประเมินความเสี่ยง
- บันทึกข้อควรระวัง
- กำหนดความพร้อมก่อนผ่าตัด
- ส่งกลับเพื่อประเมินเพิ่มเติม
- บันทึกผู้รับรองผลการประเมิน

กฎทางธุรกิจ

- การประเมินต้องอ้างอิงสัตว์เลี้ยงและคำขอผ่าตัด
- ต้องบันทึกวันเวลาและผู้ประเมิน
- ต้องไม่อนุญาตให้ข้ามขั้นตอนประเมินตามข้อกำหนดของบริการ
- กรณีมีความเสี่ยงต้องระบุแนวทางจัดการ
- ผลประเมินต้องไม่ถูกเขียนทับโดยไม่มีประวัติ
- ผลประเมินสามารถเปลี่ยนแปลงได้เมื่อสภาพร่างกายของสัตว์เปลี่ยนแปลง

หมายเหตุ: การประเมินความพร้อมและระดับความเสี่ยงต้องเป็นไปตามดุลยพินิจและแนวทางวิชาชีพของสัตวแพทย์ ไม่ควรให้ระบบตัดสินความเหมาะสมในการผ่าตัดโดยอัตโนมัติเพียงอย่างเดียว

### 3.4 การบริหารความยินยอมก่อนรักษา (Treatment Consent Management)

เป็นการบริหารเอกสารและหลักฐานการยินยอมจากเจ้าของสัตว์เลี้ยงก่อนการผ่าตัดหรือหัตถการ

เนื่องจากการผ่าตัดบางประเภทมีความเสี่ยงและอาจเกิดภาวะแทรกซ้อน จึงต้องมีการสื่อสารข้อมูลที่จำเป็นให้เจ้าของเข้าใจและจัดเก็บหลักฐานการตัดสินใจ

ข้อมูลที่ควรจัดเก็บ

- รหัสเอกสารความยินยอม
- รหัสลูกค้า
- รหัสสัตว์เลี้ยง
- รหัสคำขอผ่าตัด
- ประเภทการรักษา
- รายละเอียดการรักษาที่ได้รับความยินยอม
- รายละเอียดความเสี่ยงที่แจ้งให้ทราบ
- ค่าใช้จ่ายโดยประมาณ หากเกี่ยวข้อง
- ชื่อผู้ให้ความยินยอม
- ความสัมพันธ์กับสัตว์เลี้ยง
- วันเวลาที่ให้ความยินยอม
- ลายมือชื่อหรือหลักฐานอิเล็กทรอนิกส์
- ผู้รับรองเอกสาร
- สถานะเอกสาร

ความสามารถของระบบ

- สร้างเอกสารความยินยอมตามประเภทบริการ
- แสดงรายละเอียดการรักษา
- บันทึกความเสี่ยงที่แจ้งแก่เจ้าของ
- รองรับการลงลายมือชื่อ
- แนบเอกสารเพิ่มเติม
- จัดเก็บเอกสารฉบับที่ลงนามแล้ว
- ตรวจสอบสถานะความยินยอม
- รองรับการถอนความยินยอม
- บันทึกประวัติการเปลี่ยนแปลง

กฎทางธุรกิจ

- ต้องระบุว่าผู้ให้ความยินยอมเป็นใคร
- ต้องเชื่อมโยงเอกสารกับสัตว์เลี้ยงและรายการรักษาที่ถูกต้อง
- ต้องแยกเอกสารแต่ละประเภทการรักษา
- การเปลี่ยนแปลงรายละเอียดการรักษาที่มีสาระสำคัญอาจต้องขอความยินยอมใหม่
- ต้องจัดเก็บเอกสารที่ได้รับการยืนยันแล้วโดยไม่แก้ไขทับฉบับเดิม
- ต้องรองรับกรณีฉุกเฉินตามนโยบายและข้อกำหนดที่เกี่ยวข้อง โดยบันทึกเหตุผลและผู้มีอำนาจตัดสินใจ

### 3.5 การบริหารแผนการผ่าตัด (Surgical Planning Management)

เป็นกระบวนการกำหนดรายละเอียดการผ่าตัดล่วงหน้าก่อนเริ่มดำเนินการจริง

ตัวอย่างเช่น การผ่าตัดทำหมันสุนัขเพศเมีย อาจต้องกำหนดรายละเอียดดังนี้

- ประเภทการผ่าตัด
- ตำแหน่งที่ทำการผ่าตัด
- วิธีการผ่าตัด
- สัตวแพทย์ผู้ผ่าตัด
- ผู้ช่วยผ่าตัด
- วิธีการระงับความรู้สึก
- อุปกรณ์ที่ต้องเตรียม
- ยาที่ต้องใช้
- การเตรียมสัตว์ก่อนผ่าตัด
- แนวทางดูแลหลังผ่าตัด

ข้อมูลที่ควรจัดเก็บ

| รายการข้อมูล        | รายละเอียด                        |
| ------------------- | --------------------------------- |
| รหัสแผนผ่าตัด       | รหัสประจำแผน                      |
| รหัสคำขอ            | อ้างอิงคำขอผ่าตัด                 |

| สัตวแพทย์ผู้ผ่าตัด  | ผู้รับผิดชอบหลัก                  |
| ทีมผ่าตัด           | บุคลากรที่เกี่ยวข้อง              |
| วิธีระงับความรู้สึก | วิธีที่เลือกใช้                   |
| อุปกรณ์             | รายการอุปกรณ์ที่ต้องเตรียม        |

ความสามารถของระบบ

- สร้างแผนการผ่าตัด
- กำหนดเทคนิคการผ่าตัด
- กำหนดผู้รับผิดชอบ
- กำหนดทีมผ่าตัด
- กำหนดรายการเครื่องมือ
- กำหนดแผนระงับความรู้สึก
- กำหนดแผนการดูแลหลังผ่าตัด
- ส่งแผนให้ผู้เกี่ยวข้องตรวจสอบ
- บันทึกการเปลี่ยนแปลงแผน

กฎทางธุรกิจ

- แผนการผ่าตัดต้องอ้างอิงคำขอที่ถูกต้อง
- ต้องมีผู้รับผิดชอบแผนอย่างชัดเจน
- ต้องรองรับการแก้ไขแผนก่อนเริ่มผ่าตัด
- หากเปลี่ยนแผนระหว่างผ่าตัด ต้องบันทึกเหตุผลและผู้ตัดสินใจ
- ต้องแยกแผนการผ่าตัดออกจากผลการผ่าตัดจริง

### 3.6 การบริหารตารางผ่าตัด (Surgery Scheduling Management)

เป็นการจัดตารางเวลาการผ่าตัดและหัตถการ เพื่อให้สามารถใช้บุคลากร ห้องผ่าตัด และอุปกรณ์ได้อย่างมีประสิทธิภาพ

- รหัสคำขอผ่าตัด

- เวลาเริ่มต้นที่กำหนด
- เวลาสิ้นสุดโดยประมาณ
- ห้องผ่าตัด
- สัตวแพทย์ผู้ผ่าตัด
- ทีมผ่าตัด
- ระดับความเร่งด่วน
- ระยะเวลาเตรียมห้อง
- เวลาพักและทำความสะอาดห้อง
- สถานะการจอง

ความสามารถของระบบ

- สร้างตารางผ่าตัด
- แสดงตารางรายวันและรายสัปดาห์
- จัดสรรห้องผ่าตัด
- จัดสรรสัตวแพทย์
- จัดสรรทีมผ่าตัด
- ตรวจสอบเวลาว่าง
- ตรวจสอบการจองซ้ำ
- เลื่อนกำหนดผ่าตัด
- ยกเลิกกำหนดผ่าตัด
- รองรับกรณีผ่าตัดฉุกเฉิน
- แจ้งเตือนผู้เกี่ยวข้องก่อนถึงเวลาผ่าตัด

กฎทางธุรกิจ

- ห้องผ่าตัดหนึ่งห้องไม่ควรถูกจองให้กับงานที่ใช้เวลาทับซ้อนกัน
- บุคลากรต้องไม่ถูกจัดสรรให้กับงานที่ทับซ้อนกันโดยไม่ผ่านเงื่อนไข
- ต้องคำนึงถึงเวลาทำความสะอาดและเตรียมห้อง
- การเลื่อนตารางต้องบันทึกเหตุผล
- ต้องรองรับการแทรกคิวผ่าตัดฉุกเฉิน
- การเปลี่ยนแปลงตารางต้องแจ้งผู้เกี่ยวข้อง

### 3.7 การบริหารห้องผ่าตัด (Operating Room Management)

เป็นการจัดการห้องที่ใช้สำหรับการผ่าตัดและหัตถการ โดยตรวจสอบความพร้อมก่อนเริ่มใช้งาน

ข้อมูลที่ควรจัดเก็บ

- รหัสห้องผ่าตัด
- ชื่อห้อง
- ประเภทห้อง
- สาขาที่ตั้ง
- ความจุหรือข้อจำกัดการใช้งาน
- รายการอุปกรณ์ประจำห้อง
- สถานะห้อง
- วันที่ตรวจสอบความพร้อม
- ผู้รับผิดชอบห้อง

ความสามารถของระบบ

- ลงทะเบียนห้องผ่าตัด
- ตรวจสอบสถานะห้อง
- จัดสรรห้องให้กับรายการผ่าตัด
- บันทึกการใช้งานห้อง
- บันทึกการทำความสะอาด
- บันทึกการฆ่าเชื้อ
- บันทึกปัญหาของห้อง
- ระงับการใช้งานห้องเมื่อไม่พร้อม
- ตรวจสอบประวัติการใช้งาน

กฎทางธุรกิจ

- ห้องผ่าตัดต้องมีรหัสเฉพาะ
- ห้องที่อยู่ระหว่างซ่อมบำรุงต้องไม่ถูกจัดสรรให้ใช้งาน
- ต้องบันทึกสถานะห้องก่อนและหลังการผ่าตัด
- ต้องมีขั้นตอนตรวจสอบและเตรียมห้องก่อนใช้งาน
- ต้องสามารถตรวจสอบย้อนกลับได้ว่าการผ่าตัดแต่ละครั้งใช้ห้องใด

### 3.8 การบริหารบุคลากรผ่าตัด (Surgical Team Management)

เป็นการจัดสรรบุคลากรที่เกี่ยวข้องกับการผ่าตัดให้เหมาะสมกับประเภทและความซับซ้อนของการรักษา

- ผู้ช่วยสัตวแพทย์

- เจ้าหน้าที่ดูแลสัตว์หลังผ่าตัด

ความสามารถของระบบ

- กำหนดทีมผ่าตัด

- ตรวจสอบคุณสมบัติบุคลากร
- ตรวจสอบตารางการทำงาน
- เปลี่ยนตัวผู้ปฏิบัติงาน
- บันทึกผู้ปฏิบัติงานจริง
- เก็บประวัติการเข้าร่วมทีม

- ต้องระบุสัตวแพทย์ผู้รับผิดชอบหลัก
- ต้องตรวจสอบคุณสมบัติของผู้ปฏิบัติงานตามประเภทงาน
- ต้องแยกผู้วางแผนออกจากผู้ปฏิบัติงานจริงเมื่อเป็นคนละบุคคล
- การเปลี่ยนบุคลากรต้องมีประวัติ
- ต้องสามารถตรวจสอบผู้ปฏิบัติงานในแต่ละขั้นตอนได้

### 3.9 การเตรียมความพร้อมก่อนผ่าตัด (Preoperative Preparation Management)

เป็นการควบคุมขั้นตอนการเตรียมสัตว์เลี้ยง ห้องผ่าตัด เครื่องมือ และเวชภัณฑ์ก่อนเริ่มผ่าตัด

ตัวอย่างรายการตรวจสอบ

การเตรียมสัตว์เลี้ยง

- ตรวจสอบตัวตนสัตว์เลี้ยง
- ตรวจสอบรายการผ่าตัด
- ตรวจสอบการประเมินก่อนผ่าตัด
- ตรวจสอบเอกสารความยินยอม
- ตรวจสอบคำแนะนำเรื่องอาหารและน้ำ
- ตรวจสอบการเตรียมตำแหน่งผ่าตัด
- ตรวจสอบการให้ยาตามคำสั่ง

การเตรียมห้องและเครื่องมือ

- ตรวจสอบความสะอาดห้อง
- ตรวจสอบเครื่องมือผ่าตัด
- ตรวจสอบเครื่องระงับความรู้สึก
- ตรวจสอบเครื่องติดตามสัญญาณชีพ
- ตรวจสอบอุปกรณ์ช่วยชีวิต
- ตรวจสอบชุดผ่าตัด
- ตรวจสอบเวชภัณฑ์ที่จำเป็น

ข้อมูลที่ควรจัดเก็บ

- รหัสรายการเตรียมผ่าตัด
- รหัสรายการผ่าตัด
- รายการตรวจสอบ
- ผลการตรวจสอบแต่ละรายการ
- ผู้ตรวจสอบ
- วันเวลา
- หมายเหตุ
- สถานะความพร้อม

กฎทางธุรกิจ

- ต้องมีรายการตรวจสอบก่อนเริ่มผ่าตัด
- รายการสำคัญต้องได้รับการยืนยัน
- หากพบความไม่พร้อมต้องแจ้งเตือน
- ต้องระบุผู้ตรวจสอบ
- ต้องไม่อนุญาตให้เริ่มกระบวนการตามปกติหากเงื่อนไขสำคัญยังไม่ผ่าน เว้นแต่เป็นกรณีฉุกเฉินที่ได้รับการจัดการตามแนวทางที่กำหนด

- การบันทึกข้อมูลต้องอยู่ภายใต้ขอบเขตสิทธิ์ของบุคลากร

### 3.11 การเฝ้าระวังระหว่างระงับความรู้สึก (Intraoperative Monitoring Management)

เป็นกระบวนการติดตามและบันทึกสัญญาณชีพของสัตว์ระหว่างการระงับความรู้สึกและการผ่าตัด

ตัวอย่างข้อมูลที่ติดตาม

- อัตราการหายใจ

- อุณหภูมิร่างกาย
- ระดับก๊าซคาร์บอนไดออกไซด์ตามวิธีตรวจ
- ระดับความลึกของการระงับความรู้สึก
- การตอบสนองของสัตว์

ข้อมูลที่ควรจัดเก็บ

- รหัสรายการติดตาม

ความสามารถของระบบ

กฎทางธุรกิจ

- ต้องเก็บค่าที่วัดได้จริง ไม่ใช่เฉพาะค่าที่อยู่ในเกณฑ์ปกติ
- ต้องไม่แก้ไขข้อมูลเดิมโดยไม่มีประวัติ
- ระบบแจ้งเตือนต้องเป็นเครื่องมือสนับสนุน ไม่ใช่สิ่งทดแทนการเฝ้าระวังของบุคลากรทางการแพทย์

- ติดตามเครื่องมือที่นำไปใช้งาน
- บันทึกการคืนเครื่องมือ
- บันทึกเครื่องมือชำรุด
- ส่งข้อมูลการใช้สินค้าไปยัง Pharmacy & Inventory

กฎทางธุรกิจ

- วัสดุที่ใช้แล้วต้องบันทึกการตัดสต็อก
- ต้องสามารถตรวจสอบย้อนกลับถึงล็อตสินค้าได้
- เครื่องมือที่ต้องผ่านกระบวนการฆ่าเชื้อต้องมีสถานะที่ตรวจสอบได้
- เครื่องมือที่ไม่ผ่านเกณฑ์ความพร้อมต้องไม่ถูกนำไปใช้งาน
- ต้องแยกเครื่องมือที่ใช้ซ้ำได้ออกจากวัสดุสิ้นเปลือง
- จำนวนที่เบิกต้องไม่ถูกถือว่าเป็นจำนวนที่ใช้จริงโดยอัตโนมัติ

### 3.15 การบริหารบันทึกการผ่าตัด (Surgical Record Management)

เป็นการจัดเก็บข้อมูลการผ่าตัดที่เกิดขึ้นจริง เพื่อให้มีหลักฐานทางการแพทย์ที่ครบถ้วนและสามารถตรวจสอบย้อนหลังได้

ข้อมูลที่ควรจัดเก็บ

1. ข้อมูลสัตว์เลี้ยง
2. ข้อมูลรายการผ่าตัด
3. ข้อบ่งชี้ในการผ่าตัด
4. การวินิจฉัยที่เกี่ยวข้อง
5. เทคนิคการผ่าตัด
6. ตำแหน่งผ่าตัด
7. รายชื่อทีมผ่าตัด
8. รายละเอียดการระงับความรู้สึก
9. รายละเอียดการดำเนินการ
10. เครื่องมือและวัสดุที่ใช้
11. ปริมาณการเสียเลือดโดยประมาณ หากมีการบันทึก
12. เหตุการณ์ผิดปกติ
13. ผลการผ่าตัด
14. คำแนะนำหลังผ่าตัด

ความสามารถของระบบ

- สร้างบันทึกการผ่าตัด
- บันทึกข้อมูลระหว่างผ่าตัด
- บันทึกผลการผ่าตัด
- แนบภาพประกอบ
- แนบเอกสารทางการแพทย์
- บันทึกผู้ผ่าตัดและผู้ช่วย
- บันทึกเหตุการณ์สำคัญ
- ตรวจสอบความครบถ้วน
- ส่งบันทึกให้สัตวแพทย์รับรอง
- เชื่อมโยงกับเวชระเบียนหลัก

กฎทางธุรกิจ

- การผ่าตัดทุกครั้งต้องมีบันทึกการผ่าตัด
- ต้องระบุผู้จัดทำบันทึก
- ต้องระบุสัตวแพทย์ผู้รับผิดชอบ
- การแก้ไขบันทึกที่รับรองแล้วต้องมีประวัติและเหตุผล
- ต้องไม่ลบประวัติการผ่าตัดที่เกิดขึ้นแล้ว
- ต้องเชื่อมโยงข้อมูลกับ Clinical & Medical Management

### 3.16 การดูแลสัตว์หลังผ่าตัด (Postoperative Care Management)

เป็นการบริหารกระบวนการดูแลสัตว์เลี้ยงหลังสิ้นสุดการผ่าตัดหรือหัตถการ เพื่อประเมินการฟื้นตัวและเฝ้าระวังภาวะแทรกซ้อน

ตัวอย่างการดูแล

- ตรวจสอบระดับความรู้สึกตัว
- ตรวจสอบการหายใจ
- ตรวจสอบอัตราการเต้นหัวใจ
- ตรวจสอบอุณหภูมิ
- ตรวจสอบแผลผ่าตัด
- ตรวจสอบอาการปวด
- ตรวจสอบการตอบสนองต่อการรักษา
- ดูแลการให้สารน้ำ
- ดูแลการให้ยาตามคำสั่ง
- ประเมินความพร้อมก่อนส่งต่อ

ข้อมูลที่ควรจัดเก็บ

| รายการข้อมูล       | รายละเอียด          |
| ------------------ | ------------------- |
| รหัสการดูแล        | รหัสประจำรายการ     |
| รหัสผ่าตัด         | อ้างอิงการผ่าตัด    |
| วันเวลา            | เวลาที่ประเมิน      |
| สัญญาณชีพ          | ค่าที่ตรวจวัด       |
| ระดับความรู้สึกตัว | ผลการประเมิน        |
| อาการปวด           | ผลการประเมิน        |
| สภาพแผล            | รายละเอียด          |
| การให้ยา           | อ้างอิงคำสั่งยา     |
| การดูแลเพิ่มเติม   | รายละเอียด          |
| ผู้ดูแล            | บุคลากรผู้รับผิดชอบ |
| สถานะการฟื้นตัว    | ผลการประเมิน        |

ความสามารถของระบบ

- บันทึกผลการดูแลหลังผ่าตัด
- บันทึกสัญญาณชีพ
- ติดตามอาการปวด
- บันทึกการดูแลแผล
- ติดตามการให้ยา
- แจ้งเตือนการประเมินตามช่วงเวลา
- บันทึกความผิดปกติ
- ส่งต่อข้อมูลให้สัตวแพทย์
- ประเมินความพร้อมก่อนจำหน่าย

กฎทางธุรกิจ

- ต้องบันทึกการดูแลตามรอบเวลาที่กำหนด
- ต้องระบุผู้ดูแล
- ต้องบันทึกค่าที่ตรวจวัดจริง
- หากพบความผิดปกติต้องมีการแจ้งผู้รับผิดชอบ
- ต้องแยกการดูแลหลังผ่าตัดออกจากการบันทึกผลผ่าตัด
- ต้องรองรับการส่งต่อไปยัง Inpatient Care หากจำเป็นต้องพักรักษาต่อ

### 3.17 การบริหารภาวะแทรกซ้อน (Surgical Complication Management)

เป็นการบันทึกและบริหารเหตุการณ์ผิดปกติที่เกิดขึ้นก่อน ระหว่าง หรือหลังการผ่าตัด

ตัวอย่างเหตุการณ์

- ภาวะแทรกซ้อนจากการระงับความรู้สึก
- การเสียเลือดมากกว่าที่คาด
- การติดเชื้อบริเวณแผล
- แผลผ่าตัดแยก
- การฟื้นตัวล่าช้า
- การตอบสนองต่อยาไม่พึงประสงค์
- การผ่าตัดไม่สามารถดำเนินการได้ตามแผน
- เหตุการณ์ที่ต้องทำการรักษาเพิ่มเติม

ข้อมูลที่ควรจัดเก็บ

- รหัสเหตุการณ์
- รหัสการผ่าตัด
- ประเภทเหตุการณ์
- วันเวลาที่เกิดเหตุ
- รายละเอียดเหตุการณ์
- ระดับความรุนแรง
- ผู้พบเหตุการณ์
- ผู้รับผิดชอบ
- การแก้ไขเบื้องต้น
- การรักษาเพิ่มเติม
- ผลลัพธ์
- เอกสารประกอบ

ความสามารถของระบบ

- บันทึกเหตุการณ์ผิดปกติ
- จำแนกประเภทภาวะแทรกซ้อน
- กำหนดระดับความรุนแรง
- แจ้งเตือนสัตวแพทย์ผู้รับผิดชอบ
- บันทึกการดำเนินการแก้ไข
- ติดตามผลหลังแก้ไข
- สร้างรายงานภาวะแทรกซ้อน
- วิเคราะห์แนวโน้มของเหตุการณ์

กฎทางธุรกิจ

- ทุกเหตุการณ์ต้องมีวันเวลาและผู้รายงาน
- ต้องไม่ลบเหตุการณ์ที่เกิดขึ้นแล้ว
- ต้องบันทึกการดำเนินการแก้ไข
- เหตุการณ์รุนแรงต้องมีการตรวจสอบตามนโยบาย
- ต้องสามารถเชื่อมโยงเหตุการณ์กับบุคลากร เครื่องมือ ยา และล็อตวัสดุที่เกี่ยวข้องได้

### 3.18 การจำหน่ายสัตว์หลังผ่าตัด (Postoperative Discharge Management)

เป็นกระบวนการประเมินความพร้อมและส่งมอบสัตว์เลี้ยงกลับไปยังเจ้าของ หรือส่งต่อไปยังหน่วยงานที่รับผิดชอบการรักษาต่อ

ข้อมูลที่ควรจัดเก็บ

- รหัสรายการจำหน่าย
- รหัสการผ่าตัด
- รหัสสัตว์เลี้ยง
- ผลการประเมินก่อนจำหน่าย
- สภาพร่างกายล่าสุด
- สภาพแผล
- รายการยาที่ต้องใช้ต่อ
- คำแนะนำการดูแลที่บ้าน
- นัดหมายติดตาม
- ผู้อนุมัติการจำหน่าย
- ผู้รับมอบสัตว์เลี้ยง
- วันเวลาในการส่งมอบ
- สถานะการจำหน่าย

ความสามารถของระบบ

- ประเมินความพร้อมก่อนจำหน่าย
- บันทึกสรุปผลการผ่าตัด
- จัดทำคำแนะนำหลังผ่าตัด
- เชื่อมโยงใบสั่งยากับ Pharmacy
- สร้างนัดหมายติดตาม
- จัดทำเอกสารส่งมอบสัตว์เลี้ยง
- บันทึกผู้รับมอบ
- บันทึกวันเวลาจำหน่าย
- ส่งข้อมูลกลับไปยัง Clinical

กฎทางธุรกิจ

- การจำหน่ายต้องได้รับการประเมินและอนุมัติตามขอบเขตหน้าที่
- ต้องมีข้อมูลคำแนะนำหลังผ่าตัด
- ต้องระบุผู้รับมอบสัตว์เลี้ยง
- ต้องบันทึกวันเวลาที่ส่งมอบจริง
- การจำหน่ายสัตว์ไม่จำเป็นต้องหมายความว่าธุรกรรมทางการเงินเสร็จสมบูรณ์
- หากสัตว์ต้องพักรักษาต่อ ต้องส่งต่อไปยัง Inpatient Care

### 3.19 การติดตามผลหลังผ่าตัด (Postoperative Follow-up Management)

เป็นกระบวนการติดตามผลการรักษาหลังจากสัตว์เลี้ยงกลับบ้านหรือสิ้นสุดการดูแลในช่วงหลังผ่าตัด

ตัวอย่างการติดตาม

- ติดตามอาการหลังผ่าตัด
- ติดตามการรับประทานอาหาร
- ติดตามการขับถ่าย
- ติดตามอาการปวด
- ตรวจสอบแผลผ่าตัด
- นัดตัดไหม
- นัดตรวจแผล
- นัดตรวจซ้ำ
- ประเมินผลการฟื้นตัว

ข้อมูลที่ควรจัดเก็บ

- รหัสการติดตาม
- รหัสการผ่าตัด
- รหัสสัตว์เลี้ยง
- วันที่ต้องติดตาม
- ประเภทการติดตาม
- ช่องทางการติดตาม
- ผลการติดตาม
- อาการที่พบ
- ผู้รับผิดชอบ
- นัดหมายครั้งถัดไป
- สถานะการติดตาม

ความสามารถของระบบ

- สร้างแผนติดตามหลังผ่าตัด
- สร้างนัดหมายอัตโนมัติตามแผนที่กำหนด
- แจ้งเตือนเจ้าของสัตว์เลี้ยง
- บันทึกผลการติดตาม
- บันทึกอาการผิดปกติ
- นัดตรวจซ้ำ
- ส่งต่อสัตวแพทย์
- แสดงประวัติการฟื้นตัว
- วิเคราะห์อัตราการติดตามสำเร็จ

กฎทางธุรกิจ

- การติดตามต้องอ้างอิงการผ่าตัดที่เกิดขึ้นจริง
- ต้องบันทึกวันเวลาที่ติดตาม
- ต้องระบุช่องทางและผู้รับผิดชอบ
- หากพบความผิดปกติต้องสร้างกระบวนการติดตามหรือส่งต่อ
- ต้องแยกการติดตามทางโทรศัพท์ออกจากการตรวจร่างกายจริง

- ต้องกำหนดนิยามของตัวชี้วัดให้ชัดเจน
- ต้องแยกการผ่าตัดที่วางแผนไว้กับการผ่าตัดที่เกิดขึ้นจริง
- ต้องแยกกรณียกเลิก เลื่อน และทำไม่สำเร็จ
- ต้องกำหนดช่วงเวลาที่ใช้วิเคราะห์
- ต้องคำนึงถึงประเภทและระดับความซับซ้อนของการผ่าตัดในการเปรียบเทียบผลการดำเนินงาน

## 4. กระบวนการทำงานหลักของโดเมน (Core Business Processes)

เมื่อพิจารณาความสามารถทั้ง 20 กลุ่ม สามารถนำมาจัดเป็นกระบวนการทำงานหลักของคลินิกได้ 8 กระบวนการ

| ลำดับ | กระบวนการ              | รายละเอียด                            |
| ----- | ---------------------- | ------------------------------------- |
| 1     | การรับคำขอผ่าตัด       | รับคำสั่งจากสัตวแพทย์และตรวจสอบข้อมูล |
| 2     | การประเมินก่อนผ่าตัด   | ประเมินความพร้อมและความเสี่ยง         |
| 3     | การวางแผนผ่าตัด        | กำหนดวิธีการและผู้รับผิดชอบ           |
| 4     | การจัดตารางและทรัพยากร | จัดสรรห้อง บุคลากร และอุปกรณ์         |
| 5     | การเตรียมก่อนผ่าตัด    | ตรวจสอบความพร้อมทั้งหมด               |
| 6     | การดำเนินการผ่าตัด     | ดำเนินการผ่าตัดหรือหัตถการจริง        |
| 7     | การดูแลหลังผ่าตัด      | เฝ้าระวังและติดตามการฟื้นตัว          |
| 8     | การจำหน่ายและติดตามผล  | ส่งมอบสัตว์และติดตามผลการรักษา        |

### 4.1 กระบวนการผ่าตัดแบบครบวงจร

ยกตัวอย่าง ลูกค้านำสุนัขชื่อเจ้าดำเข้ารับการผ่าตัดทำหมัน

1. สัตวแพทย์ตรวจรักษาเจ้าดำใน Clinical & Medical Management
2. สัตวแพทย์ประเมินว่าจำเป็นต้องผ่าตัดทำหมัน
3. สัตวแพทย์สร้างคำขอผ่าตัด
4. ระบบส่งคำขอไปยัง Surgery & Treatment Management
5. เจ้าหน้าที่ตรวจสอบข้อมูลคำขอ
6. สัตวแพทย์ประเมินความพร้อมก่อนผ่าตัด
7. ตรวจสอบประวัติแพ้ยาและโรคประจำตัว
8. ดำเนินการตรวจเพิ่มเติมตามความจำเป็น
9. เจ้าของสัตว์ได้รับข้อมูลเกี่ยวกับการผ่าตัด
10. เจ้าของให้ความยินยอม
11. สัตวแพทย์จัดทำแผนการผ่าตัด
12. ระบบจัดสรรห้องผ่าตัด
13. ระบบจัดสรรสัตวแพทย์และทีมผ่าตัด
14. เจ้าหน้าที่เตรียมเครื่องมือและเวชภัณฑ์
15. ตรวจสอบความพร้อมก่อนผ่าตัด
16. เริ่มกระบวนการระงับความรู้สึก
17. บันทึกข้อมูลการเฝ้าระวังระหว่างระงับความรู้สึก
18. ดำเนินการผ่าตัด
19. บันทึกรายละเอียดการผ่าตัด
20. บันทึกยาและวัสดุที่ใช้จริง
21. ประเมินผลหลังผ่าตัด
22. ส่งเจ้าดำเข้าสู่กระบวนการพักฟื้น
23. ติดตามสัญญาณชีพและอาการ
24. ประเมินความพร้อมก่อนจำหน่าย
25. จัดทำคำแนะนำหลังผ่าตัด
26. ส่งมอบเจ้าดำให้เจ้าของ
27. สร้างนัดหมายติดตามผล
28. ส่งข้อมูลผลการผ่าตัดกลับไปยัง Clinical
29. บันทึกประวัติการรักษาให้สมบูรณ์

สิ่งสำคัญคือ ทุกขั้นตอนต้องมีข้อมูลอ้างอิงร่วมกัน เพื่อให้สามารถตรวจสอบได้ว่าใครเป็นผู้ดำเนินการ ดำเนินการเมื่อใด ใช้ยาอะไร และเกิดผลลัพธ์อย่างไร

### 4.2 กระบวนการทำหัตถการทั่วไป

ตัวอย่าง ลูกค้าพาแมวชื่อมะลิมาทำแผล

1. สัตวแพทย์ตรวจบาดแผล
2. สัตวแพทย์สร้างคำสั่งทำหัตถการ
3. ระบบส่งคำสั่งไปยัง Surgery & Treatment
4. เจ้าหน้าที่ตรวจสอบประเภทหัตถการ
5. จัดสรรบุคลากร
6. เตรียมเครื่องมือและเวชภัณฑ์
7. ตรวจสอบตัวตนสัตว์เลี้ยง
8. ดำเนินการทำแผล
9. บันทึกรายละเอียดการทำแผล
10. บันทึกวัสดุและยาที่ใช้
11. ประเมินผลหลังทำหัตถการ
12. บันทึกคำแนะนำการดูแลแผล
13. ส่งข้อมูลกลับไปยัง Clinical
14. นัดหมายติดตามหรือตัดไหมตามความเหมาะสม

กระบวนการนี้ไม่จำเป็นต้องผ่านขั้นตอนการผ่าตัดและการระงับความรู้สึกทั้งหมด ระบบจึงต้องรองรับกระบวนการที่แตกต่างกันตามประเภทบริการ

### 4.3 กระบวนการผ่าตัดฉุกเฉิน

การผ่าตัดฉุกเฉินอาจมีข้อจำกัดด้านเวลาและต้องให้ความสำคัญกับความเร่งด่วนทางการแพทย์

กระบวนการที่ควรรองรับ ได้แก่

1. รับสัตว์ป่วยฉุกเฉินจาก Appointment & Queue หรือ Clinical
2. สัตวแพทย์ประเมินความเร่งด่วน
3. สร้างคำขอผ่าตัดฉุกเฉิน
4. กำหนดสัตวแพทย์ผู้รับผิดชอบ
5. ตรวจสอบห้องผ่าตัดที่พร้อมใช้งาน
6. จัดสรรทีมผ่าตัด
7. ดำเนินการประเมินความพร้อมตามสถานการณ์
8. ตรวจสอบเอกสารและความยินยอมตามข้อกำหนดที่เกี่ยวข้อง
9. เตรียมเครื่องมือและเวชภัณฑ์
10. ดำเนินการผ่าตัด
11. บันทึกเหตุผลที่ต้องดำเนินการเร่งด่วน
12. บันทึกผลการผ่าตัด
13. ดูแลสัตว์หลังผ่าตัด
14. ส่งต่อไปยัง Inpatient Care หากจำเป็น

ข้อกำหนดสำคัญ: ระบบต้องรองรับการจัดลำดับความสำคัญของงานฉุกเฉินโดยไม่ทำให้ข้อมูลการประเมิน การตัดสินใจ และผู้รับผิดชอบสูญหาย

### 4.4 กระบวนการยกเลิกหรือเลื่อนผ่าตัด

1. เจ้าของแจ้งขอยกเลิกหรือเลื่อนผ่าตัด
2. เจ้าหน้าที่ค้นหารายการผ่าตัด
3. ตรวจสอบสถานะปัจจุบัน
4. ตรวจสอบว่ายังไม่เริ่มดำเนินการจริง
5. บันทึกเหตุผล
6. ตรวจสอบค่าใช้จ่ายหรือเงินมัดจำที่เกี่ยวข้อง
7. เปลี่ยนสถานะรายการ
8. คืนช่วงเวลาห้องผ่าตัด
9. คืนการจัดสรรบุคลากร
10. ตรวจสอบรายการวัสดุที่เบิกเตรียมไว้
11. แจ้งผู้เกี่ยวข้อง
12. หากต้องเลื่อน ให้สร้างกำหนดการใหม่

ต้องแยกการยกเลิกคำขอ การยกเลิกตาราง และการหยุดผ่าตัดที่เริ่มดำเนินการแล้วออกจากกัน เพราะมีผลต่อเวชระเบียนและการตรวจสอบย้อนหลังแตกต่างกัน

## 6. ความสัมพันธ์กับ Domains อื่น (Domain Integration & Data Ownership)

ประเด็นนี้มีความสำคัญมากในการออกแบบ Veterinary Clinic ERP เพราะ Surgery & Treatment Management ต้องทำงานร่วมกับหลายระบบ

หลักการคือ แต่ละ Domain ต้องมีเจ้าของข้อมูลที่ชัดเจน และไม่ควรจัดเก็บข้อมูลชุดเดียวกันซ้ำโดยไม่จำเป็น

### 6.1 ความสัมพันธ์กับ Customer & Pet Management

| Customer & Pet             | Surgery & Treatment               |
| -------------------------- | --------------------------------- |
| จัดเก็บข้อมูลลูกค้า        | ใช้ข้อมูลเจ้าของสัตว์             |
| จัดเก็บข้อมูลสัตว์เลี้ยง   | ใช้ข้อมูลสัตว์ที่เข้ารับการผ่าตัด |
| จัดเก็บความสัมพันธ์เจ้าของ | ตรวจสอบผู้มีสิทธิให้ความยินยอม    |
| จัดเก็บข้อมูลติดต่อ        | ใช้ติดต่อเจ้าของหลังผ่าตัด        |

Customer & Pet เป็นเจ้าของข้อมูลประจำตัวลูกค้าและสัตว์เลี้ยง ส่วน Surgery เป็นผู้ใช้งานข้อมูลเหล่านั้นเพื่อดำเนินการรักษา

### 6.2 ความสัมพันธ์กับ Appointment & Queue Management

| Appointment & Queue | Surgery & Treatment              |
| ------------------- | -------------------------------- |
| รับคำขอนัดผ่าตัด    | รับข้อมูลนัดหมาย                 |
| จัดตารางนัด         | จัดตารางผ่าตัด                   |
| บริหารคิว           | ติดตามสถานะการเข้ารับบริการ      |
| บันทึกเวลามาถึง     | ใช้ประกอบการเริ่มกระบวนการผ่าตัด |
| ส่งต่อเข้ารับบริการ | รับรายการเพื่อดำเนินการรักษา     |

ต้องแยกตารางนัดหมายออกจากตารางผ่าตัดจริง เพราะการจองนัดไม่ได้หมายความว่าการผ่าตัดได้รับการอนุมัติหรือเกิดขึ้นแล้ว

### 6.3 ความสัมพันธ์กับ Clinical & Medical Management

เป็นความสัมพันธ์ที่สำคัญที่สุดของ Domain นี้

| Clinical & Medical     | Surgery & Treatment      |
| ---------------------- | ------------------------ |
| ตรวจรักษาและประเมินโรค | รับข้อมูลข้อบ่งชี้       |
| วินิจฉัยโรค            | ใช้ข้อมูลประกอบการผ่าตัด |
| ตัดสินใจว่าต้องผ่าตัด  | รับคำขอผ่าตัด            |
| กำหนดแผนการรักษา       | ดำเนินการผ่าตัดตามแผน    |
| สร้างคำสั่งทางการแพทย์ | รับคำสั่งที่เกี่ยวข้อง   |
| ติดตามผลทางคลินิก      | ส่งผลการผ่าตัดกลับ       |
| บริหารเวชระเบียน       | ส่งข้อมูลบันทึกการผ่าตัด |

หลักการสำคัญคือ

- Clinical เป็นเจ้าของข้อมูลการวินิจฉัย
- Clinical เป็นผู้กำหนดความจำเป็นและแผนการรักษา
- Surgery เป็นเจ้าของข้อมูลการดำเนินการผ่าตัดจริง
- Surgery เป็นเจ้าของบันทึกการผ่าตัด
- Clinical นำผลการผ่าตัดไปเชื่อมโยงกับเวชระเบียน

ตัวอย่างเช่น สัตวแพทย์กำหนดให้ใช้ยาชนิดหนึ่งในการผ่าตัด แต่เจ้าหน้าที่เภสัชกรรมเป็นผู้จ่ายยา และบุคลากรผู้ปฏิบัติงานเป็นผู้บันทึกปริมาณที่ใช้จริง

## 9. ข้อกำหนดที่สำคัญในการพัฒนาระบบ (Key Business & System Requirements)

ผมขอเสนอข้อกำหนดสำคัญ 20 ประการที่ควรนำไปใช้เป็นแนวทางในการพัฒนาระบบ

1. Surgery Identification: การผ่าตัดแต่ละครั้งต้องมีรหัสเฉพาะ
2. Pet Reference: ต้องเชื่อมโยงกับสัตว์เลี้ยงที่ถูกต้อง
3. Clinical Reference: ต้องเชื่อมโยงกับรายการตรวจรักษา
4. Surgery Request: ต้องมีคำขอผ่าตัดที่ตรวจสอบได้
5. Preoperative Assessment: ต้องรองรับการประเมินก่อนผ่าตัด
6. Consent Management: ต้องเก็บหลักฐานความยินยอม
7. Surgical Planning: ต้องแยกแผนผ่าตัดออกจากการผ่าตัดจริง
8. Resource Scheduling: ต้องรองรับการจัดสรรบุคลากรและห้องผ่าตัด
9. Emergency Surgery: ต้องรองรับการผ่าตัดฉุกเฉิน
10. Anesthesia Management: ต้องบันทึกข้อมูลการระงับความรู้สึก
11. Intraoperative Monitoring: ต้องรองรับการบันทึกสัญญาณชีพ
12. Procedure Execution: ต้องบันทึกการผ่าตัดและหัตถการจริง
13. Instrument Tracking: ต้องตรวจสอบเครื่องมือที่ใช้
14. Batch Traceability: ต้องตรวจสอบล็อตยาและวัสดุที่ใช้ได้
15. Surgical Record: ต้องมีบันทึกการผ่าตัดครบถ้วน
16. Postoperative Care: ต้องรองรับการดูแลหลังผ่าตัด
17. Complication Management: ต้องบันทึกภาวะแทรกซ้อน
18. Discharge Management: ต้องมีการประเมินก่อนจำหน่าย
19. Follow-up Management: ต้องติดตามผลหลังผ่าตัด
20. Audit Trail: ต้องตรวจสอบประวัติการดำเนินงานและการแก้ไขข้อมูลได้

นอกจากนี้ ยังควรมีข้อกำหนดด้านความปลอดภัยของข้อมูล เช่น การควบคุมสิทธิ์ การบันทึกผู้ดำเนินการ การจัดเก็บเอกสาร และการสำรองข้อมูล

ประเด็นที่ต้องให้ความสำคัญเป็นพิเศษคือ

1\. Clinical ≠ Surgery

Clinical เป็นผู้ตัดสินใจและวางแผนการรักษา ส่วน Surgery เป็นผู้ดำเนินการผ่าตัดและบันทึกผลจริง

2\. Surgery Plan ≠ Surgery Execution

แผนการผ่าตัดไม่ใช่หลักฐานว่าการผ่าตัดเกิดขึ้นแล้ว

3\. Anesthesia Plan ≠ Anesthesia Record

แผนการระงับความรู้สึกไม่ใช่ข้อมูลการดำเนินการจริง

4\. Material Reservation ≠ Material Consumption

การจองหรือเบิกวัสดุไม่ใช่หลักฐานว่าวัสดุนั้นถูกใช้จริงทั้งหมด

5\. Surgery Completed ≠ Patient Recovered

การผ่าตัดเสร็จสิ้นไม่ได้หมายความว่าสัตว์ฟื้นตัวสมบูรณ์

6\. Postoperative Discharge ≠ Financial Settlement

การจำหน่ายสัตว์กลับไม่ใช่การชำระเงินเสร็จสิ้น

การแยกความหมายเหล่านี้จะช่วยให้ระบบมีความถูกต้องและสามารถตรวจสอบย้อนหลังได้

### ข้อสรุปของ Domain นี้

Domain Surgery & Treatment Management ควรทำหน้าที่เป็นศูนย์กลางการดำเนินงานด้านการผ่าตัดและหัตถการของคลินิกสัตวแพทย์ ตั้งแต่การรับคำขอ การประเมินความพร้อม การวางแผน การจัดสรรทรัพยากร การดำเนินการจริง ไปจนถึงการดูแลและติดตามผลหลังการรักษา

สิ่งสำคัญที่สุดคือ การแยกข้อมูลและเหตุการณ์แต่ละประเภทออกจากกันอย่างชัดเจน เพื่อให้ระบบสามารถรองรับการดำเนินงานจริงได้ ไม่ใช่เพียงจัดเก็บรายการว่ามีการผ่าตัดเกิดขึ้นเท่านั้น

## 12. ลำดับการออกแบบขั้นต่อไป

หากต้องการนำ Domain นี้ไปพัฒนาเป็นระบบ ERP สำหรับคลินิกสัตวแพทย์ ผมแนะนำให้ลงรายละเอียดต่ออีก 4 ระดับ โดยเรียงตามลำดับดังนี้

ขั้นที่ 1: Business Capability Breakdown

แตกความสามารถทั้ง 20 กลุ่มออกเป็นความสามารถย่อย พร้อมกำหนดขอบเขต หน้าที่ ผู้รับผิดชอบ และความสัมพันธ์ระหว่างความสามารถ

ขั้นที่ 2: Business Process & Business Rules

ออกแบบขั้นตอนปฏิบัติงานจริง เงื่อนไข และกฎทางธุรกิจ เช่น

- กระบวนการรับคำขอผ่าตัด
- กระบวนการประเมินก่อนผ่าตัด
- กระบวนการขอความยินยอม
- กระบวนการวางแผนและอนุมัติผ่าตัด
- กระบวนการจัดตารางผ่าตัด
- กระบวนการระงับความรู้สึก
- กระบวนการผ่าตัดจริง
- กระบวนการดูแลหลังผ่าตัด
- กระบวนการจัดการภาวะแทรกซ้อน
- กระบวนการจำหน่ายและติดตามผล

ขั้นที่ 3: Database Architecture & Complete ERD

ออกแบบตารางทั้งหมด พร้อมรายละเอียด

- Primary Key
- Foreign Key
- Data Types
- Index
- Relationships
- Constraints
- Data Dictionary
- Status Lifecycle
- Audit Trail

ขั้นที่ 4: Application Architecture & API Specification

ออกแบบหน้าจอ โมดูลระบบ และ API เช่น

- หน้าจอทะเบียนผ่าตัดและหัตถการ
- หน้าจอคำขอผ่าตัด
- หน้าจอประเมินก่อนผ่าตัด
- หน้าจอเอกสารความยินยอม
- หน้าจอแผนการผ่าตัด
- หน้าจอตารางผ่าตัด
- หน้าจอจัดทีมผ่าตัด
- หน้าจอบันทึกการระงับความรู้สึก
- หน้าจอบันทึกการผ่าตัด
- หน้าจอเฝ้าระวังระหว่างผ่าตัด
- หน้าจอดูแลหลังผ่าตัด
- หน้าจอจำหน่ายสัตว์
- หน้าจอติดตามผล
- หน้าจอรายงานการผ่าตัด

## ข้อเสนอแนะเพิ่มเติมก่อนออกแบบฐานข้อมูล

สำหรับ Domain นี้ ผมแนะนำให้ให้ความสำคัญกับ 6 เรื่องเป็นพิเศษ

1. Surgery Lifecycle: กำหนดวงจรชีวิตการผ่าตัดตั้งแต่รับคำขอจนถึงเสร็จสิ้น
2. Preoperative Assessment & Consent: กำหนดโครงสร้างการประเมินความพร้อมและเอกสารความยินยอม
3. Surgical Planning & Resource Scheduling: กำหนดโครงสร้างแผนผ่าตัดและการจัดสรรทรัพยากร
4. Anesthesia & Intraoperative Monitoring: กำหนดการบันทึกข้อมูลการระงับความรู้สึกและการเฝ้าระวัง
5. Surgical Execution & Postoperative Care: แยกการผ่าตัดจริงออกจากการดูแลหลังผ่าตัด
6. Cross-Domain Integration & Traceability: กำหนดการเชื่อมต่อกับ Clinical, Pharmacy, Laboratory, Inpatient Care และ Billing

ทั้ง 6 เรื่องนี้มีผลโดยตรงต่อโครงสร้างฐานข้อมูล การออกแบบหน้าจอ การกำหนดสิทธิ์ และความถูกต้องของข้อมูลทางการแพทย์

ข้อเสนอแนะของผม: ควรออกแบบ Surgery Lifecycle และ Surgical Record Structure ให้ชัดเจนก่อนเริ่มสร้างตารางฐานข้อมูล เพราะเป็นแกนหลักที่เชื่อมโยงความสามารถทั้ง 20 กลุ่มเข้าด้วยกัน และจะช่วยให้ระบบรองรับได้ตั้งแต่คลินิกสัตวแพทย์ทั่วไปไปจนถึงโรงพยาบาลสัตว์ที่มีห้องผ่าตัดหลายห้องและทีมแพทย์เฉพาะทางครับ
