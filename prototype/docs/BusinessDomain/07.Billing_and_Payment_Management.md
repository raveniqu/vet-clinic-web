# Domain 07: การบริหารจัดการการเรียกเก็บเงินและการรับชำระเงิน (Billing & Payment Management)

Domain นี้เป็นหนึ่งในโดเมนหลักของระบบบริหารจัดการคลินิกสัตวแพทย์ (Veterinary Clinic ERP) ทำหน้าที่บริหารกระบวนการคิดค่าบริการ การสร้างรายการเรียกเก็บเงิน การจัดทำใบแจ้งหนี้ การรับชำระเงิน การจัดการยอดค้างชำระ การคืนเงิน การออกเอกสารทางการเงินให้ลูกค้า ตลอดจนการตรวจสอบความถูกต้องของธุรกรรมการเงินที่เกิดขึ้นจากการให้บริการของคลินิก

หากมองในมุมของการพัฒนาระบบ ERP โดเมนนี้ถือเป็นศูนย์กลางของกระบวนการทางการเงินระหว่างคลินิกกับลูกค้า โดยรับข้อมูลรายการบริการและสินค้าเรียกเก็บจาก Domain อื่น ๆ แล้วนำมาคำนวณเป็นยอดที่ลูกค้าต้องชำระ

ตัวอย่างเช่น

คุณสมชายพาสุนัขชื่อเจ้าดำเข้ารับการตรวจรักษา เนื่องจากมีอาการอาเจียน

ในระหว่างการให้บริการ เจ้าดำได้รับบริการดังนี้

1. ค่าตรวจร่างกายโดยสัตวแพทย์
2. ค่าตรวจเลือด
3. ค่าตรวจวิเคราะห์ทางห้องปฏิบัติการ
4. ค่ายาที่ได้รับจากห้องจ่ายยา
5. ค่าฉีดยา
6. ค่าบริการอื่น ๆ ที่เกี่ยวข้อง

เมื่อกระบวนการตรวจรักษาเสร็จสิ้น ระบบจะต้องรวบรวมรายการค่าใช้จ่ายทั้งหมดจากหน่วยงานที่เกี่ยวข้อง ตรวจสอบความถูกต้อง คำนวณส่วนลดและภาษี (หากมี) จากนั้นสร้างใบแจ้งหนี้เพื่อเรียกเก็บเงินจากคุณสมชาย

เมื่อลูกค้าชำระเงิน ระบบจะบันทึกรายการรับชำระ ออกใบเสร็จรับเงิน และปรับปรุงสถานะยอดค้างชำระให้ถูกต้อง

หากลูกค้าชำระเงินเพียงบางส่วน ระบบต้องสามารถบันทึกยอดที่ได้รับและยอดคงเหลือได้ หรือหากลูกค้าชำระเงินเกิน ระบบต้องสามารถจัดการยอดเงินส่วนเกินตามนโยบายของคลินิกได้

ดังนั้น Domain นี้ไม่ได้มีหน้าที่เพียงการคำนวณค่ารักษาและรับเงินเท่านั้น แต่ต้องครอบคลุมกระบวนการทางการเงินที่เกิดขึ้นจากการให้บริการ ตั้งแต่การสร้างรายการเรียกเก็บเงินจนถึงการปิดยอดธุรกรรม

## 1. วัตถุประสงค์หลักของโดเมน

การบริหารจัดการการเรียกเก็บเงินและการรับชำระเงินมีวัตถุประสงค์สำคัญ 15 ประการ

1. บริหารรายการค่าใช้จ่ายที่เกิดขึ้นจากการให้บริการของคลินิก
2. รวบรวมรายการบริการและสินค้าที่ต้องเรียกเก็บเงินจากหลาย Domain
3. คำนวณค่าบริการและราคาสินค้าอย่างถูกต้อง
4. จัดทำใบแจ้งหนี้และเอกสารเรียกเก็บเงิน
5. รองรับการคิดค่าบริการตามประเภทบริการและเงื่อนไขที่กำหนด
6. รองรับการให้ส่วนลดและการใช้สิทธิประโยชน์ของลูกค้า
7. รองรับการคำนวณภาษีและการออกเอกสารภาษีตามข้อกำหนดที่เกี่ยวข้อง
8. รองรับการรับชำระเงินหลายช่องทาง
9. รองรับการชำระเงินเต็มจำนวนและการชำระเงินบางส่วน
10. บริหารยอดค้างชำระและลูกหนี้การค้า
11. รองรับการคืนเงินและการยกเลิกรายการเรียกเก็บเงิน
12. จัดทำใบเสร็จรับเงินและเอกสารทางการเงิน
13. ตรวจสอบความถูกต้องของรายการรับชำระเงิน
14. เชื่อมโยงข้อมูลกับระบบบัญชีและการเงิน
15. สนับสนุนการวิเคราะห์รายได้และประสิทธิภาพทางการเงินของคลินิก

เป้าหมายสูงสุด: ทำให้คลินิกสามารถบริหารจัดการรายได้และการเรียกเก็บเงินได้อย่างถูกต้อง โปร่งใส ตรวจสอบย้อนหลังได้ ลดความผิดพลาดในการคิดค่าบริการ และสามารถติดตามสถานะทางการเงินของลูกค้าได้อย่างครบถ้วน

# 3. รายละเอียดกลุ่มความสามารถทางธุรกิจ

## 3.1 การบริหารรายการค่าบริการ (Service Charge Management)

เป็นกระบวนการจัดการรายการค่าบริการที่เกิดขึ้นจากการให้บริการทางการแพทย์และบริการทั่วไปของคลินิก โดยรายการค่าบริการแต่ละรายการจะถูกนำไปใช้ในการคำนวณค่าใช้จ่ายของลูกค้า

ตัวอย่างรายการค่าบริการ

- ค่าตรวจรักษาทั่วไป
- ค่าตรวจสุขภาพ
- ค่าปรึกษาสัตวแพทย์
- ค่าฉีดวัคซีน
- ค่าทำแผล
- ค่าฉีดยา
- ค่าทำหัตถการ
- ค่าผ่าตัด
- ค่าบริการวางยาสลบ
- ค่าบริการพักฟื้น
- ค่าบริการเฝ้าสังเกตอาการ
- ค่าบริการฉุกเฉิน

ข้อมูลที่ควรจัดเก็บ

| รายการข้อมูล        | รายละเอียด                           |
| ------------------- | ------------------------------------ |
| รหัสรายการค่าบริการ | รหัสอ้างอิงรายการ                    |
| รหัสประเภทบริการ    | ประเภทบริการที่เรียกเก็บ             |
| ชื่อบริการ          | ชื่อที่แสดงในเอกสาร                  |
| รายละเอียดบริการ    | คำอธิบายเพิ่มเติม                    |
| จำนวน               | จำนวนหน่วยบริการ                     |
| หน่วยนับ            | ครั้ง ชั่วโมง หรือรายการ             |
| ราคาต่อหน่วย        | ราคาก่อนส่วนลด                       |
| ส่วนลด              | จำนวนเงินหรืออัตราส่วนลด             |
| ยอดรวม              | ยอดหลังคำนวณ                         |
| สาขา                | สาขาที่ให้บริการ                     |
| สถานะ               | รอเรียกเก็บ เรียกเก็บแล้ว หรือยกเลิก |

ความสามารถของระบบ

1. เพิ่มรายการค่าบริการ
2. เลือกบริการจากรายการมาตรฐาน
3. กำหนดจำนวนและราคาต่อหน่วย
4. เพิ่มรายการค่าบริการเฉพาะกรณี
5. เชื่อมโยงรายการกับรายการตรวจรักษา
6. เชื่อมโยงกับสัตว์เลี้ยงที่ได้รับบริการ
7. ตรวจสอบรายการที่ถูกเรียกเก็บแล้ว
8. ป้องกันการเรียกเก็บรายการเดียวกันซ้ำโดยไม่ได้ตั้งใจ

กฎทางธุรกิจ

- รายการค่าบริการต้องมีแหล่งที่มาชัดเจน
- ต้องสามารถตรวจสอบได้ว่าบริการนั้นเกิดขึ้นจริงหรือได้รับอนุมัติให้เรียกเก็บ
- ต้องแยกบริการที่เสนอราคาออกจากบริการที่ดำเนินการจริง
- การแก้ไขรายการที่เรียกเก็บแล้วต้องมีประวัติ
- การยกเลิกรายการต้องมีเหตุผลและผู้อนุมัติตามสิทธิ์

ข้อสำคัญคือ รายการบริการและราคามาตรฐานควรเป็นข้อมูลที่บริหารจากระบบรายการบริการกลาง (Service Catalog) ส่วน Billing รับผิดชอบการนำข้อมูลดังกล่าวมาใช้เรียกเก็บเงินจริง

## 3.2 การบริหารรายการสินค้าเรียกเก็บเงิน (Product Charge Management)

เป็นกระบวนการนำสินค้าหรือเวชภัณฑ์ที่ลูกค้าได้รับไปใช้หรือได้รับกลับบ้าน มาคำนวณเป็นค่าใช้จ่าย

ตัวอย่างเช่น

- ยาที่จ่ายให้สัตว์เลี้ยง
- วัคซีน
- อาหารสัตว์ทางการแพทย์
- อาหารเสริมที่คลินิกจำหน่าย
- เวชภัณฑ์
- อุปกรณ์ทางการแพทย์ที่จำหน่ายให้ลูกค้า

ข้อมูลที่ควรจัดเก็บ

| รายการข้อมูล              | รายละเอียด                           |
| ------------------------- | ------------------------------------ |
| รหัสรายการสินค้าเรียกเก็บ | รหัสรายการ                           |
| รหัสสินค้า                | อ้างอิงทะเบียนสินค้า                 |
| รหัสรายการจ่ายยา          | อ้างอิงรายการจ่ายยาจริง              |
| รหัสล็อตสินค้า            | ระบุล็อตสินค้าที่จ่าย                |
| จำนวน                     | จำนวนสินค้าที่เรียกเก็บ              |
| หน่วยนับ                  | หน่วยของสินค้า                       |
| ราคาต่อหน่วย              | ราคาขายต่อหน่วย                      |
| ส่วนลด                    | ส่วนลดสินค้า                         |
| ยอดรวม                    | ยอดเรียกเก็บ                         |
| สถานะ                     | รอเรียกเก็บ เรียกเก็บแล้ว หรือยกเลิก |

ความสามารถของระบบ

1. รับข้อมูลสินค้าจากระบบเภสัชกรรม
2. รับข้อมูลการจ่ายยาจริง
3. นำรายการสินค้าเข้าสู่รายการเรียกเก็บ
4. คำนวณราคาสินค้าตามจำนวน
5. รองรับการขายสินค้าโดยไม่ต้องมีรายการตรวจรักษา
6. รองรับสินค้าที่จำหน่ายเป็นชุด
7. ตรวจสอบรายการสินค้าที่ถูกเรียกเก็บแล้ว
8. เชื่อมโยงรายการสินค้าเข้ากับใบแจ้งหนี้

กฎทางธุรกิจ

- ต้องเรียกเก็บตามจำนวนที่จ่ายหรือจำหน่ายจริง
- ต้องอ้างอิงทะเบียนสินค้าจาก Pharmacy & Inventory Management
- ต้องไม่สร้างข้อมูลสินค้าซ้ำกับทะเบียนสินค้าหลัก
- การคืนสินค้าอาจต้องเชื่อมโยงกับกระบวนการคืนสินค้าและปรับปรุงคลัง
- ต้องแยกรายการยาที่สัตวแพทย์สั่งออกจากรายการยาที่เภสัชกรจ่ายจริง

ตัวอย่างเช่น สัตวแพทย์สั่งยา 10 เม็ด แต่เภสัชกรจ่ายจริง 8 เม็ด ระบบ Billing ควรรับข้อมูลจากรายการจ่ายยาจริง 8 เม็ด ไม่ใช่นำจำนวนตามใบสั่งยามาเรียกเก็บโดยอัตโนมัติ

## 3.3 การบริหารอัตราค่าบริการ (Pricing Management)

เป็นการกำหนดและบริหารราคาสินค้าและบริการของคลินิก เพื่อให้สามารถคิดค่าบริการได้อย่างถูกต้องตามนโยบายของกิจการ

ตัวอย่างการกำหนดราคา

- ค่าตรวจทั่วไป 300 บาท
- ค่าตรวจสุขภาพ 500 บาท
- ค่าฉีดวัคซีน 450 บาท
- ค่าตรวจเลือด 800 บาท
- ค่าผ่าตัดตามประเภทการผ่าตัด
- ค่ายาตามรายการและหน่วยจำหน่าย

ข้อมูลที่ควรจัดเก็บ

| รายการข้อมูล         | รายละเอียด                |
| -------------------- | ------------------------- |
| รหัสรายการราคา       | รหัสอัตราค่าบริการ        |
| รหัสบริการหรือสินค้า | รายการที่ต้องการกำหนดราคา |
| ราคามาตรฐาน          | ราคาปกติ                  |
| ราคาต่ำสุด           | ราคาต่ำสุดที่อนุญาต       |
| ราคาสูงสุด           | ราคาสูงสุดที่กำหนด        |
| ประเภทลูกค้า         | กลุ่มลูกค้าที่ใช้ราคา     |
| สาขา                 | สาขาที่ใช้ราคา            |
| วันที่เริ่มต้น       | วันเริ่มใช้ราคา           |
| วันที่สิ้นสุด        | วันสิ้นสุดราคา            |
| สถานะ                | ใช้งานหรือไม่ใช้งาน       |

ความสามารถของระบบ

1. กำหนดราคาสินค้าและบริการ
2. กำหนดราคาตามสาขา
3. กำหนดราคาตามประเภทลูกค้า
4. กำหนดราคาตามช่วงเวลา
5. กำหนดราคาโปรโมชั่น
6. กำหนดราคาแพ็กเกจ
7. กำหนดราคาเฉพาะสมาชิก
8. แสดงประวัติการเปลี่ยนแปลงราคา

กฎทางธุรกิจ

- การเปลี่ยนแปลงราคาต้องไม่เปลี่ยนแปลงใบแจ้งหนี้เก่าย้อนหลัง
- ต้องมีวันเริ่มต้นและสิ้นสุดการใช้ราคา
- การกำหนดราคาพิเศษต้องเป็นไปตามสิทธิ์ที่ได้รับ
- ต้องสามารถตรวจสอบราคาที่ใช้ ณ วันที่เกิดรายการได้
- ต้องแยกราคาขายออกจากต้นทุนสินค้า

ข้อสำคัญคือ เมื่อสร้างรายการเรียกเก็บเงิน ระบบควรบันทึกราคาที่ใช้จริงไว้ในรายการนั้น ไม่ควรอ้างอิงราคาปัจจุบันตลอดเวลา เพราะราคามาตรฐานอาจมีการเปลี่ยนแปลงในอนาคต

## 3.4 การรวบรวมรายการเรียกเก็บเงิน (Charge Aggregation)

เป็นกระบวนการรวบรวมค่าใช้จ่ายทั้งหมดที่เกิดขึ้นจากการให้บริการ โดยรับข้อมูลจากหลาย Domain ภายในระบบ ERP

ตัวอย่างแหล่งที่มาของรายการเรียกเก็บเงิน

| แหล่งข้อมูล                       | รายการที่ส่งมาเรียกเก็บ               |
| --------------------------------- | ------------------------------------- |
| Clinical & Medical                | ค่าตรวจรักษาและบริการทางการแพทย์      |
| Pharmacy & Inventory              | ค่ายาและเวชภัณฑ์ที่จ่ายจริง           |
| Laboratory & Diagnostic Imaging   | ค่าตรวจเลือดและค่าตรวจวินิจฉัยด้วยภาพ |
| Surgery & Treatment               | ค่าผ่าตัดและค่าหัตถการ                |
| Inpatient Care (หากมี Domain แยก) | ค่าห้องพักและค่าดูแลสัตว์ป่วย         |
| Service Catalog                   | ข้อมูลบริการและราคามาตรฐาน            |

ความสามารถของระบบ

1. รับรายการเรียกเก็บจาก Domain ต้นทาง
2. ตรวจสอบความถูกต้องของรายการ
3. ตรวจสอบรายการซ้ำ
4. รวมรายการตามลูกค้า
5. รวมรายการตามสัตว์เลี้ยง
6. รวมรายการตามการเข้ารับบริการ
7. แยกรายการตามประเภทค่าใช้จ่าย
8. ตรวจสอบรายการที่ยังไม่ถูกเรียกเก็บ
9. รองรับการรวมค่าใช้จ่ายหลายครั้งเข้าด้วยกันตามนโยบาย
10. รองรับการเรียกเก็บแยกตามสัตว์เลี้ยงหรือแยกตามผู้รับผิดชอบค่าใช้จ่าย

กฎทางธุรกิจ

- ทุกรายการต้องสามารถระบุแหล่งที่มาได้
- ต้องป้องกันการนำรายการต้นทางเดียวกันมาเรียกเก็บซ้ำ
- ต้องรองรับรายการที่เกิดขึ้นภายหลังจากสร้างใบแจ้งหนี้แล้ว
- ต้องสามารถตรวจสอบรายการที่ยังไม่ได้เรียกเก็บ
- ต้องไม่เปลี่ยนแปลงข้อมูลการให้บริการจริงจาก Domain ต้นทาง

ตัวอย่างเช่น ลูกค้านำสัตว์เลี้ยงสองตัวมาตรวจรักษาในวันเดียวกัน คลินิกอาจกำหนดให้แยกใบแจ้งหนี้ตามสัตว์เลี้ยง หรือรวมเป็นใบแจ้งหนี้เดียวกันได้ตามนโยบายการเรียกเก็บ

## 3.5 การคำนวณค่าบริการ (Charge Calculation)

เป็นกระบวนการคำนวณยอดค่าใช้จ่ายทั้งหมดจากรายการสินค้าและบริการที่รวบรวมได้

องค์ประกอบของการคำนวณประกอบด้วย

1. ราคาต่อหน่วย
2. จำนวนหน่วย
3. ยอดรวมก่อนส่วนลด
4. ส่วนลดระดับรายการ
5. ส่วนลดระดับเอกสาร
6. ยอดหลังหักส่วนลด
7. ภาษีที่เกี่ยวข้อง
8. ค่าธรรมเนียมเพิ่มเติม
9. ยอดสุทธิที่ต้องชำระ

ตัวอย่างการคำนวณ

| รายการ                         | จำนวนเงิน |
| ------------------------------ | --------- |
| ค่าตรวจรักษา                   | 300 บาท   |
| ค่าตรวจเลือด                   | 800 บาท   |
| ค่ายา                          | 500 บาท   |
| ค่าบริการฉีดยา                 | 100 บาท   |
| รวมก่อนส่วนลด                  | 1,700 บาท |
| ส่วนลด                         | 100 บาท   |
| ยอดหลังหักส่วนลด               | 1,600 บาท |
| ภาษี (ตัวอย่าง 7% หากเข้าข่าย) | 112 บาท   |
| ยอดสุทธิ                       | 1,712 บาท |

ตัวเลขนี้เป็นเพียงตัวอย่างเพื่ออธิบายการคำนวณ ไม่ใช่การกำหนดอัตราภาษีหรือวิธีคำนวณที่ใช้ได้กับทุกกิจการ

ความสามารถของระบบ

- คำนวณยอดรวมแต่ละรายการ
- คำนวณส่วนลด
- คำนวณภาษี
- คำนวณค่าธรรมเนียม
- คำนวณยอดสุทธิ
- รองรับการปัดเศษทศนิยมตามนโยบาย
- แสดงรายละเอียดวิธีคำนวณ
- ตรวจสอบความถูกต้องของยอดเงิน

กฎทางธุรกิจ

- ต้องกำหนดลำดับการคำนวณให้ชัดเจน
- ต้องป้องกันการคำนวณส่วนลดซ้ำ
- ต้องจัดเก็บยอดก่อนและหลังการคำนวณ
- ต้องกำหนดหลักเกณฑ์การปัดเศษอย่างสม่ำเสมอ
- ต้องรองรับการคำนวณภาษีที่แตกต่างกันตามประเภทสินค้าและบริการ
- ยอดสุทธิในเอกสารต้องสามารถตรวจสอบย้อนกลับได้จากรายการย่อย

## 3.6 การบริหารส่วนลด (Discount Management)

เป็นการจัดการส่วนลดที่คลินิกมอบให้ลูกค้า โดยอาจเป็นส่วนลดทั่วไป ส่วนลดสมาชิก ส่วนลดโปรโมชั่น หรือส่วนลดตามเงื่อนไขทางธุรกิจ

ประเภทส่วนลดที่ควรรองรับ

1. ส่วนลดเป็นจำนวนเงิน
2. ส่วนลดเป็นเปอร์เซ็นต์
3. ส่วนลดเฉพาะสินค้า
4. ส่วนลดเฉพาะบริการ
5. ส่วนลดทั้งใบแจ้งหนี้
6. ส่วนลดสมาชิก
7. ส่วนลดพนักงาน
8. ส่วนลดโปรโมชั่น
9. ส่วนลดจากคูปอง
10. ส่วนลดกรณีพิเศษที่ได้รับอนุมัติ

ข้อมูลที่ควรจัดเก็บ

- รหัสส่วนลด
- ชื่อส่วนลด
- ประเภทส่วนลด
- จำนวนหรืออัตราส่วนลด
- เงื่อนไขการใช้
- ยอดซื้อขั้นต่ำ
- ส่วนลดสูงสุด
- วันที่เริ่มต้นและสิ้นสุด
- กลุ่มลูกค้าที่มีสิทธิ์
- สินค้าหรือบริการที่เข้าร่วม
- ผู้อนุมัติ
- สถานะส่วนลด

ความสามารถของระบบ

- สร้างโปรโมชั่น
- กำหนดเงื่อนไขการใช้ส่วนลด
- ใช้ส่วนลดอัตโนมัติตามเงื่อนไข
- กรอกรหัสคูปอง
- ตรวจสอบสิทธิ์ลูกค้า
- จำกัดจำนวนครั้งในการใช้ส่วนลด
- กำหนดผู้มีสิทธิ์อนุมัติส่วนลดพิเศษ
- วิเคราะห์มูลค่าส่วนลดที่มอบให้ลูกค้า

กฎทางธุรกิจ

- ต้องไม่ใช้ส่วนลดเกินกว่าที่กำหนด
- ต้องตรวจสอบว่าส่วนลดสามารถใช้ร่วมกับโปรโมชั่นอื่นได้หรือไม่
- ต้องจัดเก็บเหตุผลเมื่อให้ส่วนลดพิเศษ
- ต้องบันทึกผู้อนุมัติส่วนลด
- ต้องสามารถตรวจสอบประวัติการใช้ส่วนลดได้

## 3.7 การบริหารภาษี (Tax Management)

เป็นการจัดการภาษีที่เกี่ยวข้องกับการขายสินค้าและการให้บริการของคลินิก โดยระบบต้องสามารถคำนวณภาษีและจัดเก็บรายละเอียดภาษีของแต่ละรายการได้

ข้อมูลที่ควรบริหาร

- ประเภทภาษี
- อัตราภาษี
- ประเภทสินค้าและบริการที่เกี่ยวข้อง
- ราคาที่รวมภาษีแล้ว
- ราคาที่ยังไม่รวมภาษี
- มูลค่าฐานภาษี
- จำนวนภาษี
- วันที่มีผลบังคับใช้
- สถานะการใช้ภาษี

ความสามารถของระบบ

1. กำหนดประเภทภาษี
2. กำหนดอัตราภาษี
3. กำหนดสินค้าและบริการที่ต้องเสียภาษี
4. คำนวณภาษีแยกตามรายการ
5. รองรับราคาที่รวมภาษีและไม่รวมภาษี
6. แสดงรายละเอียดภาษีในเอกสาร
7. จัดทำข้อมูลสำหรับส่งต่อระบบบัญชี
8. จัดเก็บประวัติการเปลี่ยนแปลงอัตราภาษี

กฎทางธุรกิจ

- ต้องใช้หลักเกณฑ์ภาษีที่ถูกต้องตามประเภทกิจการและธุรกรรม
- ต้องไม่ถือว่าสินค้าและบริการทุกประเภทมีภาษีเหมือนกัน
- ต้องจัดเก็บฐานภาษีและยอดภาษีแยกจากกัน
- ต้องรักษาประวัติภาษีที่ใช้ในธุรกรรมแต่ละครั้ง
- การออกเอกสารภาษีต้องเป็นไปตามข้อกำหนดที่เกี่ยวข้อง

สำหรับประเทศไทย ควรออกแบบให้รองรับการตั้งค่าภาษีมูลค่าเพิ่ม การยกเว้นภาษี และรูปแบบเอกสารภาษีตามสถานะและข้อกำหนดของกิจการ โดยไม่ควรฝังอัตราภาษีไว้ในโปรแกรมโดยตรง

## 3.8 การสร้างใบแจ้งหนี้ (Invoice Generation)

เป็นกระบวนการสร้างเอกสารเรียกเก็บเงินจากลูกค้า โดยรวบรวมรายการค่าใช้จ่ายทั้งหมดและแสดงรายละเอียดที่ลูกค้าต้องชำระ

ข้อมูลที่ควรจัดเก็บ

| รายการข้อมูล    | รายละเอียด             |
| --------------- | ---------------------- |
| รหัสใบแจ้งหนี้  | เลขที่เอกสาร           |
| ลูกค้า          | ผู้รับผิดชอบค่าใช้จ่าย |
| สัตว์เลี้ยง     | สัตว์ที่เกี่ยวข้อง     |
| รายการตรวจรักษา | รายการเข้ารับบริการ    |
| วันที่ออกเอกสาร | วันที่สร้างใบแจ้งหนี้  |
| วันครบกำหนด     | วันที่ต้องชำระ         |
| ยอดก่อนส่วนลด   | ยอดรวมรายการ           |
| ส่วนลด          | มูลค่าส่วนลด           |
| ภาษี            | จำนวนภาษี              |
| ยอดสุทธิ        | ยอดที่ต้องชำระ         |
| ยอดชำระแล้ว     | จำนวนเงินที่ได้รับ     |
| ยอดคงเหลือ      | จำนวนเงินที่ยังค้าง    |
| สถานะ           | สถานะใบแจ้งหนี้        |

ความสามารถของระบบ

1. สร้างใบแจ้งหนี้
2. รวมรายการค่าใช้จ่าย
3. แยกรายการตามประเภท
4. ระบุข้อมูลลูกค้าและสัตว์เลี้ยง
5. ระบุวันที่ออกและวันครบกำหนด
6. พิมพ์ใบแจ้งหนี้
7. ส่งใบแจ้งหนี้ผ่านช่องทางออนไลน์
8. ออกใบแจ้งหนี้ฉบับใหม่ตามกระบวนการที่อนุญาต
9. แสดงประวัติการออกเอกสาร

กฎทางธุรกิจ

- ใบแจ้งหนี้ต้องมีเลขที่ไม่ซ้ำกัน
- ต้องระบุผู้รับผิดชอบค่าใช้จ่าย
- ต้องตรวจสอบรายการเรียกเก็บก่อนยืนยัน
- ใบแจ้งหนี้ที่ยืนยันแล้วไม่ควรถูกลบโดยพลการ
- การแก้ไขเอกสารที่ยืนยันแล้วต้องเป็นไปตามกระบวนการปรับปรุงเอกสาร
- ต้องแยกสถานะใบแจ้งหนี้ออกจากสถานะการชำระเงิน

## 3.9 การบริหารรายการเรียกเก็บเงิน (Billing Management)

เป็นการควบคุมสถานะของรายการเรียกเก็บเงินตั้งแต่เริ่มสร้างจนถึงการชำระเงินหรือปิดรายการ

สถานะที่ควรรองรับ เช่น

- ร่างรายการเรียกเก็บเงิน
- รอตรวจสอบ
- รอยืนยัน
- ยืนยันแล้ว
- เรียกเก็บแล้ว
- ชำระบางส่วน
- ชำระครบแล้ว
- เกินกำหนดชำระ
- ยกเลิก
- ปรับปรุงรายการ

ความสามารถของระบบ

- ค้นหารายการเรียกเก็บเงิน
- ตรวจสอบรายการเรียกเก็บที่ยังไม่ออกเอกสาร
- แสดงรายการตามลูกค้า
- แสดงรายการตามสัตว์เลี้ยง
- แสดงรายการตามสาขา
- แสดงรายการตามวันเวลา
- ตรวจสอบสถานะใบแจ้งหนี้
- ติดตามการเปลี่ยนแปลงสถานะ

กฎทางธุรกิจ

- ต้องมีลำดับสถานะที่ชัดเจน
- การเปลี่ยนสถานะต้องเป็นไปตามเงื่อนไข
- ต้องบันทึกผู้ดำเนินการและวันเวลา
- ต้องไม่ถือว่าการออกใบแจ้งหนี้หมายถึงการรับเงินแล้ว
- ต้องสามารถแยกใบแจ้งหนี้ที่ยังไม่ถึงกำหนดกับใบแจ้งหนี้ที่เกินกำหนดได้

## 3.10 การรับชำระเงิน (Payment Collection)

เป็นกระบวนการรับเงินจากลูกค้าเพื่อชำระค่าใช้จ่ายที่เกิดขึ้นจากการใช้บริการของคลินิก

รูปแบบการรับชำระเงิน

2. ชำระเงินบางส่วน
3. ชำระเงินหลายครั้ง
4. ชำระหลายช่องทางในรายการเดียว
5. ชำระแทนโดยบุคคลอื่น
6. ชำระโดยบริษัทหรือองค์กรที่รับผิดชอบค่าใช้จ่าย

ข้อมูลที่ควรจัดเก็บ

| รายการข้อมูล      | รายละเอียด                   |
| ----------------- | ---------------------------- |
| รหัสรายการรับชำระ | รหัสธุรกรรม                  |
| รหัสใบแจ้งหนี้    | เอกสารที่นำมาชำระ            |
| ลูกค้า            | ผู้ชำระหรือผู้รับผิดชอบหนี้  |
| จำนวนเงิน         | ยอดที่ได้รับ                 |
| วันที่รับชำระ     | วันที่ได้รับเงิน             |
| ช่องทางรับชำระ    | เงินสด โอนเงิน บัตร เป็นต้น  |
| เลขอ้างอิงธุรกรรม | หมายเลขอ้างอิงจากช่องทางชำระ |
| ผู้รับชำระ        | พนักงานที่ดำเนินการ          |
| สาขา              | สาขาที่รับชำระ               |
| สถานะ             | สำเร็จ รอตรวจสอบ หรือยกเลิก  |

ความสามารถของระบบ

- รับชำระเงิน
- เลือกใบแจ้งหนี้ที่ต้องการชำระ
- รับชำระหลายใบแจ้งหนี้ในครั้งเดียว
- รองรับการชำระบางส่วน
- บันทึกผู้ชำระเงิน
- บันทึกหมายเลขอ้างอิงธุรกรรม
- ออกใบเสร็จรับเงิน
- ปรับปรุงยอดค้างชำระ
- ตรวจสอบประวัติการรับชำระ

กฎทางธุรกิจ

- การรับชำระแต่ละครั้งต้องมีรหัสธุรกรรมไม่ซ้ำกัน
- ต้องไม่บันทึกการชำระเงินสำเร็จจากหลักฐานที่ยังไม่ได้รับการตรวจสอบ
- ต้องสามารถแยกผู้ชำระเงินออกจากเจ้าของสัตว์เลี้ยงได้
- การยกเลิกรายการรับชำระต้องมีเหตุผลและสิทธิ์อนุมัติ
- ต้องตรวจสอบยอดรับชำระกับยอดใบแจ้งหนี้

## 3.11 การบริหารช่องทางชำระเงิน (Payment Method Management)

เป็นการบริหารรูปแบบและช่องทางที่ลูกค้าสามารถใช้ชำระเงินให้กับคลินิกได้

ช่องทางที่ควรรองรับ

- เงินสด
- โอนเงินผ่านธนาคาร
- พร้อมเพย์
- บัตรเครดิต
- บัตรเดบิต
- คิวอาร์โค้ด
- กระเป๋าเงินอิเล็กทรอนิกส์
- ระบบรับชำระเงินออนไลน์
- การชำระผ่านคู่สัญญาหรือบริษัทประกัน ตามข้อตกลง

ข้อมูลที่ควรจัดเก็บ

- รหัสช่องทางชำระเงิน
- ชื่อช่องทาง
- ประเภทช่องทาง
- ธนาคารหรือผู้ให้บริการ
- หมายเลขบัญชีหรือรหัสร้านค้า
- ค่าธรรมเนียม
- สาขาที่เปิดใช้งาน
- สถานะการใช้งาน

ความสามารถของระบบ

1. เพิ่มช่องทางรับชำระ
2. กำหนดช่องทางตามสาขา
3. กำหนดค่าธรรมเนียม
4. เชื่อมต่อระบบรับชำระออนไลน์
5. ตรวจสอบสถานะธุรกรรม
6. บันทึกเลขอ้างอิงจากผู้ให้บริการ
7. ตรวจสอบค่าธรรมเนียมการรับชำระ

กฎทางธุรกิจ

- ช่องทางชำระเงินแต่ละประเภทต้องมีการกำหนดค่าอย่างชัดเจน
- ต้องไม่บันทึกธุรกรรมเป็นสำเร็จเพียงเพราะลูกค้าแสดงหน้าจอการโอนเงิน
- ต้องมีการตรวจสอบผลจากธนาคารหรือผู้ให้บริการตามความเหมาะสม
- ค่าธรรมเนียมรับชำระต้องแยกจากยอดค่าบริการ
- ต้องจัดเก็บข้อมูลอ้างอิงสำหรับตรวจสอบย้อนหลัง

## 3.12 การชำระเงินบางส่วน (Partial Payment Management)

เป็นการรองรับกรณีที่ลูกค้าไม่สามารถชำระเงินเต็มจำนวนในครั้งเดียว หรือคลินิกอนุญาตให้แบ่งชำระตามเงื่อนไขที่กำหนด

ตัวอย่าง

ลูกค้ามีใบแจ้งหนี้จำนวน 5,000 บาท

- ครั้งที่ 1 ชำระ 2,000 บาท
- ครั้งที่ 2 ชำระ 1,000 บาท
- ครั้งที่ 3 ชำระ 2,000 บาท

ระบบต้องแสดงยอดคงเหลือหลังการชำระแต่ละครั้ง

ข้อมูลที่ควรจัดเก็บ

- รหัสใบแจ้งหนี้
- จำนวนเงินที่ต้องชำระ
- จำนวนเงินที่ชำระแล้ว
- จำนวนเงินคงเหลือ
- วันที่ครบกำหนด
- วันที่ชำระแต่ละครั้ง
- เงื่อนไขการแบ่งชำระ
- ผู้อนุมัติ
- สถานะการชำระ

ความสามารถของระบบ

- กำหนดเงื่อนไขการแบ่งชำระ
- รับชำระหลายครั้ง
- คำนวณยอดคงเหลืออัตโนมัติ
- แสดงประวัติการชำระแต่ละครั้ง
- กำหนดวันครบกำหนดแต่ละงวด
- แจ้งเตือนยอดค้างชำระ
- ปิดใบแจ้งหนี้เมื่อได้รับชำระครบ

กฎทางธุรกิจ

- ยอดชำระสะสมต้องไม่เกินยอดที่เรียกเก็บโดยไม่มีการจัดการยอดเงินส่วนเกิน
- ต้องบันทึกธุรกรรมการชำระแต่ละครั้งแยกกัน
- ต้องไม่เขียนทับประวัติการชำระเดิม
- ต้องรองรับการชำระหลายช่องทางในแต่ละงวด

## 3.13 การบริหารยอดค้างชำระ (Outstanding Balance Management)

เป็นการติดตามยอดเงินที่ลูกค้ายังไม่ได้ชำระให้กับคลินิก โดยอาจเกิดจากการชำระบางส่วน การให้เครดิต หรือการเรียกเก็บเงินตามรอบที่กำหนด

ตัวอย่างสถานการณ์

- ลูกค้าได้รับอนุญาตให้ชำระภายหลัง
- ลูกค้าชำระเงินไม่ครบ
- บริษัทเป็นผู้รับผิดชอบค่าใช้จ่ายแทนลูกค้า
- ลูกค้ามีใบแจ้งหนี้หลายรายการที่ยังไม่ชำระ

ข้อมูลที่ควรจัดเก็บ

- รหัสลูกหนี้
- รหัสลูกค้า
- รหัสใบแจ้งหนี้
- ยอดหนี้เริ่มต้น
- ยอดชำระสะสม
- ยอดคงเหลือ
- วันครบกำหนด
- จำนวนวันที่ค้างชำระ
- สถานะหนี้
- ประวัติการติดตาม

ความสามารถของระบบ

1. แสดงยอดค้างชำระรายลูกค้า
2. แสดงยอดค้างชำระรายใบแจ้งหนี้
3. แสดงรายการหนี้เกินกำหนด
4. จัดกลุ่มอายุหนี้
5. บันทึกการติดตามลูกหนี้
6. แจ้งเตือนก่อนถึงกำหนด
7. แจ้งเตือนเมื่อเกินกำหนด
8. กำหนดวงเงินเครดิตตามนโยบาย
9. แสดงประวัติการชำระหนี้

กฎทางธุรกิจ

- ต้องแยกยอดหนี้ออกจากยอดที่ชำระแล้ว
- ต้องไม่ถือว่าใบแจ้งหนี้ที่ยังไม่ถึงกำหนดเป็นหนี้ผิดนัด
- การอนุมัติเครดิตต้องเป็นไปตามสิทธิ์
- ต้องมีประวัติการติดตามหนี้
- ต้องสามารถตรวจสอบยอดหนี้ย้อนหลังได้

## 3.14 การบริหารเงินมัดจำและเงินล่วงหน้า (Deposit & Advance Payment Management)

เป็นการบริหารเงินที่ลูกค้าชำระให้คลินิกล่วงหน้าก่อนที่จะได้รับบริการ หรือชำระเพื่อยืนยันการจองบริการบางประเภท

ตัวอย่าง

- เงินมัดจำสำหรับการผ่าตัด
- เงินมัดจำสำหรับการจองห้องพักสัตว์ป่วย
- เงินล่วงหน้าสำหรับการรักษาต่อเนื่อง
- เงินสำรองสำหรับกรณีที่ต้องรักษาหลายวัน
- เงินมัดจำสำหรับบริการที่มีค่าใช้จ่ายสูง

ข้อมูลที่ควรจัดเก็บ

| รายการข้อมูล         | รายละเอียด                          |
| -------------------- | ----------------------------------- |
| รหัสเงินมัดจำ        | รหัสธุรกรรม                         |
| ลูกค้า               | ผู้ชำระเงิน                         |
| สัตว์เลี้ยง          | สัตว์ที่เกี่ยวข้อง                  |
| วัตถุประสงค์         | เหตุผลในการรับเงิน                  |
| จำนวนเงิน            | ยอดที่รับไว้                        |
| วันที่รับเงิน        | วันที่ได้รับเงิน                    |
| ใบแจ้งหนี้ที่นำไปหัก | เอกสารที่เกี่ยวข้อง                 |
| ยอดที่นำไปใช้        | จำนวนเงินที่ใช้แล้ว                 |
| ยอดคงเหลือ           | จำนวนเงินที่ยังเหลือ                |
| สถานะ                | คงเหลือ ใช้แล้ว คืนเงิน หรือหมดอายุ |

ความสามารถของระบบ

- รับเงินมัดจำ
- รับเงินล่วงหน้า
- ระบุวัตถุประสงค์
- ผูกเงินมัดจำกับรายการนัดหมายหรือบริการ
- นำเงินมาหักจากใบแจ้งหนี้
- ตรวจสอบยอดคงเหลือ
- คืนเงินมัดจำตามเงื่อนไข
- ตรวจสอบประวัติการใช้เงินมัดจำ

กฎทางธุรกิจ

- เงินมัดจำต้องแยกจากรายได้ที่เกิดขึ้นจริงตามหลักเกณฑ์บัญชี
- ต้องไม่ถือว่าเงินรับล่วงหน้าคือค่าบริการที่ดำเนินการเสร็จแล้ว
- การนำเงินมัดจำไปหักต้องมีรายการอ้างอิง
- ต้องป้องกันการนำเงินมัดจำก้อนเดียวไปหักซ้ำ
- การคืนเงินต้องมีเหตุผลและการอนุมัติ

## 3.15 การออกใบเสร็จรับเงิน (Receipt Management)

เป็นการจัดทำเอกสารเพื่อยืนยันว่าคลินิกได้รับเงินจากลูกค้าแล้ว

ใบเสร็จรับเงินเป็นหลักฐานการรับเงิน ไม่ใช่เพียงเอกสารแสดงยอดค่าใช้จ่าย

ข้อมูลที่ควรจัดเก็บ

- เลขที่ใบเสร็จรับเงิน
- วันที่ออกใบเสร็จ
- ผู้ชำระเงิน
- ผู้รับเงิน
- รายการที่รับชำระ
- จำนวนเงิน
- วิธีการชำระเงิน
- เลขที่ใบแจ้งหนี้ที่เกี่ยวข้อง
- สาขาที่ออกเอกสาร
- สถานะเอกสาร

ความสามารถของระบบ

1. ออกใบเสร็จรับเงิน
2. พิมพ์ใบเสร็จ
3. ส่งใบเสร็จผ่านช่องทางออนไลน์
4. ออกใบเสร็จจากการชำระเต็มจำนวน
5. ออกหลักฐานการรับชำระบางส่วนตามรูปแบบเอกสารที่กำหนด
6. ค้นหาใบเสร็จย้อนหลัง
7. ตรวจสอบรายการรับเงินที่เกี่ยวข้อง
8. จัดการเอกสารที่ยกเลิก

กฎทางธุรกิจ

- ต้องออกเอกสารตามการรับเงินที่เกิดขึ้นจริง
- เลขที่เอกสารต้องไม่ซ้ำกัน
- ต้องแสดงจำนวนเงินที่ได้รับจริง
- ต้องเชื่อมโยงกับรายการรับชำระ
- เอกสารที่ออกแล้วต้องไม่ถูกลบโดยพลการ
- การยกเลิกใบเสร็จต้องมีหลักฐานและประวัติ

## 3.16 การออกเอกสารภาษี (Tax Invoice Management)

เป็นการจัดทำเอกสารภาษีที่เกี่ยวข้องกับการขายสินค้าและการให้บริการตามข้อกำหนดของกฎหมาย

ประเภทเอกสารที่ควรพิจารณารองรับ

- ใบกำกับภาษีอย่างย่อ
- ใบกำกับภาษีเต็มรูป
- ใบเพิ่มหนี้
- ใบลดหนี้
- เอกสารประกอบการยกเลิกเอกสารภาษีตามหลักเกณฑ์ที่เกี่ยวข้อง

ข้อมูลที่ควรจัดเก็บ

- เลขที่เอกสารภาษี
- วันที่ออกเอกสาร
- ชื่อผู้ซื้อ
- ที่อยู่ผู้ซื้อ

- สาขาผู้ออกเอกสาร
- เอกสารอ้างอิง
- สถานะเอกสาร

ความสามารถของระบบ

- ออกเอกสารภาษี
- ตรวจสอบข้อมูลผู้ซื้อ
- คำนวณมูลค่าภาษี
- แสดงรายละเอียดภาษีแยกรายการ
- ออกเอกสารอ้างอิงจากใบแจ้งหนี้
- ค้นหาเอกสารภาษีย้อนหลัง
- รองรับการออกเอกสารอิเล็กทรอนิกส์ตามข้อกำหนด
- จัดการใบเพิ่มหนี้และใบลดหนี้

กฎทางธุรกิจ

- ต้องตรวจสอบคุณสมบัติของผู้ประกอบการและประเภทธุรกรรมก่อนออกเอกสาร
- ต้องไม่ออกเอกสารภาษีโดยไม่มีข้อมูลที่จำเป็น
- ต้องรักษาลำดับและประวัติเลขที่เอกสาร
- ต้องแยกใบเสร็จรับเงินออกจากใบกำกับภาษี แม้เอกสารบางประเภทจะสามารถรวมอยู่ในเอกสารเดียวกันได้ตามกฎหมาย
- การแก้ไขเอกสารภาษีต้องเป็นไปตามข้อกำหนดที่เกี่ยวข้อง

## 3.17 การคืนเงิน (Refund Management)

เป็นกระบวนการคืนเงินให้ลูกค้าเมื่อเกิดกรณีที่คลินิกต้องคืนเงินทั้งหมดหรือบางส่วนจากยอดที่เคยรับชำระ

ตัวอย่างสถานการณ์

- ลูกค้าชำระเงินเกิน
- มีการยกเลิกบริการหลังจากชำระเงินแล้ว
- มีการเรียกเก็บเงินผิดพลาด
- มีการคืนสินค้าตามเงื่อนไข
- มีการเรียกเก็บค่าบริการซ้ำ
- คลินิกไม่สามารถให้บริการตามที่ตกลงไว้

ข้อมูลที่ควรจัดเก็บ

| รายการข้อมูล         | รายละเอียด                                 |
| -------------------- | ------------------------------------------ |

| ลูกค้า               | ผู้รับเงินคืน                              |

| เหตุผล               | สาเหตุการคืนเงิน                           |

| ผู้ร้องขอ            | ผู้ขอคืนเงิน                               |
| ผู้อนุมัติ           | ผู้อนุมัติการคืนเงิน                       |
| วันที่คืนเงิน        | วันที่ดำเนินการ                            |
| สถานะ                | รออนุมัติ กำลังดำเนินการ สำเร็จ หรือปฏิเสธ |

ความสามารถของระบบ

1. สร้างคำขอคืนเงิน
2. อ้างอิงใบแจ้งหนี้เดิม
3. อ้างอิงรายการรับชำระเดิม
4. ตรวจสอบยอดเงินที่สามารถคืนได้
5. กำหนดผู้อนุมัติ
6. บันทึกช่องทางการคืนเงิน
7. ติดตามสถานะการคืนเงิน
8. ปรับปรุงยอดรับชำระและยอดคงเหลือ
9. ออกเอกสารที่เกี่ยวข้องกับการคืนเงิน
10. ตรวจสอบประวัติการคืนเงิน

กฎทางธุรกิจ

- ต้องคืนเงินได้ไม่เกินยอดที่สามารถคืนได้จริง
- ต้องไม่คืนเงินรายการเดิมซ้ำ
- ต้องมีเหตุผลและหลักฐานประกอบ
- การคืนเงินต้องผ่านการอนุมัติตามวงเงิน
- ต้องแยกสถานะคำขอคืนเงินออกจากสถานะการคืนเงินจริง
- ต้องเชื่อมโยงกับธุรกรรมรับชำระเดิมเสมอเมื่อเป็นการคืนเงินจากการชำระเดิม

## 3.18 การยกเลิกและปรับปรุงรายการเรียกเก็บ (Billing Adjustment & Cancellation)

เป็นกระบวนการแก้ไขรายการเรียกเก็บเงินที่เกิดข้อผิดพลาด หรือมีความจำเป็นต้องปรับปรุงยอดหลังจากสร้างเอกสารแล้ว

ตัวอย่าง

- เรียกเก็บค่าบริการผิดรายการ
- คำนวณจำนวนสินค้าไม่ถูกต้อง
- บันทึกราคาผิด
- เรียกเก็บค่าบริการซ้ำ
- มีการเพิ่มบริการภายหลัง
- มีการลดค่าบริการตามผลการตรวจสอบ
- ยกเลิกบริการที่ยังไม่ได้ดำเนินการ

ข้อมูลที่ควรจัดเก็บ

- รหัสรายการปรับปรุง
- รหัสใบแจ้งหนี้
- ประเภทรายการปรับปรุง
- รายละเอียดเดิม
- รายละเอียดใหม่
- จำนวนเงินก่อนปรับปรุง
- จำนวนเงินหลังปรับปรุง
- เหตุผล
- ผู้ร้องขอ
- ผู้ดำเนินการ
- ผู้อนุมัติ
- วันและเวลาที่ดำเนินการ

ความสามารถของระบบ

- เพิ่มรายการเรียกเก็บเพิ่มเติม
- ลดจำนวนเงินที่เรียกเก็บ
- ยกเลิกรายการที่ผิดพลาด
- ออกเอกสารปรับปรุง
- บันทึกประวัติการแก้ไข
- กำหนดสิทธิ์ผู้อนุมัติ
- เชื่อมโยงรายการปรับปรุงกับเอกสารเดิม

กฎทางธุรกิจ

- ต้องไม่แก้ไขเอกสารทางการเงินที่ยืนยันแล้วโดยไม่มีร่องรอย
- ต้องแยกการยกเลิกใบแจ้งหนี้ออกจากการคืนเงิน
- ต้องแยกการปรับปรุงยอดออกจากการรับชำระ
- ต้องมีเอกสารอ้างอิงสำหรับการปรับปรุง
- ต้องสามารถตรวจสอบยอดก่อนและหลังปรับปรุงได้

## 3.19 การบริหารบัญชีลูกหนี้ (Accounts Receivable Management)

เป็นการบริหารข้อมูลลูกหนี้ที่เกิดจากการให้บริการและการขายสินค้าของคลินิก โดยมุ่งเน้นการติดตามยอดเงินที่คลินิกมีสิทธิ์เรียกเก็บจากลูกค้า

ตัวอย่างลูกหนี้

- ลูกค้าทั่วไปที่ได้รับอนุญาตให้ชำระภายหลัง
- บริษัทที่รับผิดชอบค่าใช้จ่ายแทนเจ้าของสัตว์
- องค์กรที่ทำสัญญาให้บริการกับคลินิก
- ลูกค้าที่ใช้วงเงินเครดิต
- ลูกค้าที่มีการแบ่งชำระ

ความสามารถของระบบ

1. สร้างข้อมูลลูกหนี้จากใบแจ้งหนี้
2. แสดงยอดลูกหนี้รายราย
3. แสดงยอดลูกหนี้ตามช่วงเวลา
4. ติดตามวันครบกำหนด
5. บันทึกการติดตามลูกหนี้
6. บันทึกการรับชำระหนี้
7. จัดการยอดหนี้ที่มีข้อโต้แย้ง
8. จัดการหนี้สูญหรือหนี้ที่ต้องปรับปรุงตามนโยบาย
9. จัดทำรายงานอายุลูกหนี้

ตัวอย่างการจัดกลุ่มอายุหนี้

| กลุ่มอายุหนี้  | ความหมาย                     |
| -------------- | ---------------------------- |
| ยังไม่ถึงกำหนด | ลูกหนี้ที่ยังไม่ครบกำหนดชำระ |
| 1–30 วัน       | ค้างชำระไม่เกิน 30 วัน       |
| 31–60 วัน      | ค้างชำระ 31–60 วัน           |
| 61–90 วัน      | ค้างชำระ 61–90 วัน           |
| มากกว่า 90 วัน | ค้างชำระเกิน 90 วัน          |

กฎทางธุรกิจ

- ลูกหนี้ต้องมีเอกสารอ้างอิง
- ต้องแยกยอดลูกหนี้ออกจากยอดเงินรับล่วงหน้า
- ต้องมีหลักเกณฑ์การให้เครดิต
- ต้องจัดเก็บประวัติการรับชำระหนี้
- การตัดหนี้สูญต้องผ่านการอนุมัติ
- ต้องเชื่อมโยงข้อมูลกับระบบบัญชีและการเงิน

ข้อสำคัญคือ Billing รับผิดชอบการติดตามสถานะการเรียกเก็บและการรับชำระ ส่วนการบันทึกบัญชีลูกหนี้ การตั้งสำรอง และการตัดหนี้สูญตามหลักบัญชีเป็นความรับผิดชอบของ Finance & Accounting Management

## 3.20 การกระทบยอดการรับชำระเงิน (Payment Reconciliation)

เป็นกระบวนการตรวจสอบว่ารายการรับชำระเงินที่บันทึกในระบบตรงกับเงินที่ได้รับจริงจากธนาคาร ผู้ให้บริการรับชำระเงิน หรือช่องทางอื่นหรือไม่

ตัวอย่าง

ลูกค้าชำระเงินผ่าน QR Payment จำนวน 1,712 บาท

ระบบ Billing บันทึกธุรกรรมสำเร็จ แต่คลินิกยังต้องตรวจสอบว่าผู้ให้บริการรับชำระเงินส่งยอดดังกล่าวเข้าบัญชีจริงหรือไม่

- รหัสรายการกระทบยอด
- ช่องทางรับชำระ
- วันที่ทำรายการ
- ยอดที่ระบบบันทึก
- ยอดที่ผู้ให้บริการรายงาน
- ค่าธรรมเนียม
- ยอดเงินสุทธิ
- เลขอ้างอิงธุรกรรม
- ผลการตรวจสอบ
- ผู้ตรวจสอบ
- วันเวลาที่ตรวจสอบ

ความสามารถของระบบ

1. นำเข้ารายการจากธนาคาร
2. นำเข้ารายการจากผู้ให้บริการรับชำระเงิน
3. เปรียบเทียบยอดรับชำระ
4. ตรวจสอบรายการที่ตรงกัน
5. ตรวจสอบรายการที่ไม่ตรงกัน
6. ตรวจสอบรายการซ้ำ
7. ตรวจสอบรายการที่ยังไม่พบยอดเงิน
8. บันทึกผลการกระทบยอด
9. ส่งรายการผิดปกติให้ผู้รับผิดชอบตรวจสอบ

กฎทางธุรกิจ

- ต้องแยกสถานะการรับชำระจากสถานะการกระทบยอด
- ต้องไม่ถือว่ารายการที่ลูกค้าแจ้งว่าโอนแล้วเป็นรายการที่กระทบยอดสำเร็จ
- ต้องจัดเก็บข้อมูลจากแหล่งข้อมูลต้นทาง
- ต้องตรวจสอบค่าธรรมเนียมแยกจากยอดเงินที่ลูกค้าชำระ
- ต้องสามารถตรวจสอบรายการที่ไม่ตรงกันย้อนหลังได้

## 5.2 ความสัมพันธ์ระหว่าง Clinical กับ Billing

ควรกำหนดความรับผิดชอบดังนี้

- Clinical เป็นผู้บันทึกการตรวจรักษา
- Clinical เป็นผู้กำหนดแผนการรักษาและคำสั่งทางการแพทย์
- Clinical ส่งข้อมูลบริการที่เกิดขึ้นจริงหรือได้รับอนุมัติให้เรียกเก็บ
- Billing เป็นผู้รวบรวมและคำนวณค่าใช้จ่าย
- Billing เป็นผู้สร้างใบแจ้งหนี้และรับชำระเงิน

ข้อควรระวัง: การสั่งตรวจหรือสั่งยาไม่ได้หมายความว่าจะสามารถเรียกเก็บเงินได้ทันทีเสมอไป ต้องพิจารณาสถานะการดำเนินงานจริงและเงื่อนไขการเรียกเก็บของบริการนั้น

## 5.3 ความสัมพันธ์ระหว่าง Pharmacy กับ Billing

ควรกำหนดความรับผิดชอบดังนี้

- Clinical เป็นผู้สั่งยา
- Pharmacy เป็นผู้ตรวจสอบและจ่ายยาจริง
- Pharmacy บันทึกจำนวนยาที่จ่าย
- Pharmacy ส่งรายการจ่ายจริงไปยัง Billing
- Billing คำนวณราคายาและนำไปเรียกเก็บ
- Inventory ปรับปรุงจำนวนสินค้าคงคลัง

หลักการสำคัญคือ การสั่งยาไม่ใช่การจ่ายยา และการจ่ายยาไม่ใช่การรับชำระเงิน ทั้งสามกระบวนการต้องแยกจากกัน

## 6.1 การควบคุมการเปลี่ยนแปลงข้อมูลทางการเงิน

ผมแนะนำให้ใช้หลักการสำคัญ 4 ประการ

1. ไม่ลบธุรกรรมที่เกิดขึ้นจริงโดยพลการ การแก้ไขต้องผ่านกระบวนการยกเลิกหรือปรับปรุง
2. เก็บประวัติทุกครั้ง ต้องทราบว่าใครดำเนินการ เมื่อใด และเพราะเหตุใด
3. แยกการอนุมัติออกจากการดำเนินการ โดยเฉพาะการคืนเงินและส่วนลดพิเศษ
4. ตรวจสอบย้อนกลับได้ ต้องสามารถเชื่อมโยงตั้งแต่รายการบริการ ใบแจ้งหนี้ การรับชำระ และการคืนเงิน

## 6.2 การควบคุมความถูกต้องของธุรกรรม

ระบบควรรองรับการป้องกันปัญหาที่อาจเกิดขึ้น เช่น

- ลูกค้าชำระเงินแล้ว แต่ระบบไม่ได้รับการตอบกลับ
- ลูกค้ากดชำระเงินซ้ำ
- ระบบได้รับข้อความยืนยันการชำระเงินซ้ำ
- ใบแจ้งหนี้ถูกเปิดพร้อมกันจากพนักงานหลายคน
- มีการยกเลิกรายการหลังจากรับชำระเงินแล้ว
- มีการคืนเงินมากกว่ายอดที่รับเงินจริง
- มีการเปลี่ยนแปลงราคาหลังจากออกใบแจ้งหนี้

ควรใช้การควบคุมธุรกรรมในฐานข้อมูล การตรวจสอบรหัสอ้างอิงที่ไม่ซ้ำ และการจัดการสถานะธุรกรรมอย่างเป็นระบบ

# 11. ประเด็นสำคัญที่ต้องคำนึงถึงในการออกแบบระบบจริง

ผมขอเน้นประเด็นที่มีผลต่อสถาปัตยกรรมซอฟต์แวร์และฐานข้อมูลเป็นพิเศษ

11.1 ต้องแยกใบเสนอราคา ใบแจ้งหนี้ และใบเสร็จรับเงินออกจากกัน

เอกสารทั้งสามมีวัตถุประสงค์แตกต่างกัน

- ใบเสนอราคา: แสดงราคาที่คาดว่าจะเรียกเก็บ
- ใบแจ้งหนี้: แสดงยอดเงินที่เรียกเก็บจากลูกค้า
- ใบเสร็จรับเงิน: แสดงเงินที่คลินิกได้รับจริง

ไม่ควรใช้เอกสารชนิดเดียวแทนกันทั้งหมด

11.2 ต้องรองรับการเรียกเก็บเงินหลายครั้งในหนึ่งการเข้ารับบริการ

ตัวอย่างเช่น สัตว์เลี้ยงเข้ารับการรักษาหลายวัน อาจมีค่าใช้จ่ายเกิดขึ้นทุกวัน ระบบจึงต้องรองรับการเรียกเก็บเป็นงวด หรือรวมยอดทั้งหมดเมื่อสิ้นสุดการรักษา

11.3 ต้องรองรับลูกค้าหนึ่งรายกับสัตว์เลี้ยงหลายตัว

การเรียกเก็บเงินอาจเกิดขึ้นกับสัตว์หลายตัวในเวลาเดียวกัน แต่ต้องสามารถแยกค่าใช้จ่ายตามสัตว์แต่ละตัวได้

11.4 ต้องรองรับการชำระเงินหลายช่องทางในใบแจ้งหนี้เดียวกัน

ตัวอย่างเช่น ใบแจ้งหนี้ 5,000 บาท ลูกค้าชำระเงินสด 2,000 บาท และโอนเงิน 3,000 บาท ระบบต้องสามารถเชื่อมโยงธุรกรรมทั้งสองรายการเข้ากับใบแจ้งหนี้เดียวกันได้

11.5 ต้องรองรับการเรียกเก็บเงินภายหลังการให้บริการ

ค่าใช้จ่ายบางรายการอาจเกิดขึ้นหลังจากสร้างใบแจ้งหนี้เบื้องต้นแล้ว เช่น ค่ายาที่จ่ายเพิ่มเติม หรือค่าบริการที่เกิดขึ้นระหว่างการรักษา

ระบบต้องสามารถจัดการรายการเพิ่มเติมโดยไม่ทำให้เอกสารและประวัติเดิมเสียหาย

11.6 ต้องรองรับหลายสาขา

หากคลินิกมีหลายสาขา ต้องสามารถแยกข้อมูลตามสาขา ได้แก่

- รายการเรียกเก็บ
- ใบแจ้งหนี้
- รายการรับชำระ
- ใบเสร็จรับเงิน
- การคืนเงิน
- การปิดยอดประจำวัน
- รายงานรายได้

  11.7 ต้องรองรับการทำงานแบบตรวจสอบย้อนหลังได้

ทุกธุรกรรมสำคัญควรมีข้อมูลผู้สร้าง ผู้แก้ไข ผู้อนุมัติ วันเวลา และเหตุผลในการดำเนินการ

## 12.1 ข้อสรุปด้านสถาปัตยกรรมธุรกิจ

สำหรับการออกแบบ Veterinary Clinic ERP ผมแนะนำให้ยึดหลักการสำคัญ 5 ประการ

1. แยกการให้บริการออกจากการเรียกเก็บเงิน เพราะการดำเนินการทางการแพทย์และการคิดค่าบริการเป็นคนละกระบวนการ
2. แยกการเรียกเก็บเงินออกจากการรับชำระเงิน เพราะลูกค้าอาจชำระเต็มจำนวน ชำระบางส่วน หรือชำระภายหลัง
3. แยกการรับเงินออกจากการบันทึกบัญชี เพราะเป็นคนละความรับผิดชอบทางธุรกิจ
4. กำหนดเจ้าของข้อมูลให้ชัดเจน เพื่อป้องกันข้อมูลซ้ำซ้อนระหว่าง Domain
5. ออกแบบให้ตรวจสอบย้อนหลังได้ โดยเฉพาะรายการเรียกเก็บ การรับชำระ การคืนเงิน และเอกสารภาษี

## 12.2 ลำดับการออกแบบขั้นต่อไป

หากจะนำ Domain นี้ไปพัฒนาระบบ ERP จริง ผมแนะนำให้ลงรายละเอียดต่ออีก 4 ระดับ โดยเรียงตามลำดับดังนี้

| ขั้นตอน   | สิ่งที่จะออกแบบ                              | ผลลัพธ์                                           |
| --------- | -------------------------------------------- | ------------------------------------------------- |
| ขั้นที่ 1 | Business Capability Breakdown                | แตก 22 กลุ่มเป็นความสามารถย่อย                    |
| ขั้นที่ 2 | Business Process & Business Rules            | ออกแบบกระบวนการทำงานและกฎทางธุรกิจ                |
| ขั้นที่ 3 | Database Architecture & Complete ERD         | ออกแบบตาราง คีย์ ความสัมพันธ์ และ Data Dictionary |
| ขั้นที่ 4 | Application Architecture & API Specification | ออกแบบหน้าจอ โมดูล และ API                        |

ข้อเสนอแนะของผม: ควรเริ่มจากขั้นที่ 1 แล้วดำเนินการต่อเนื่องไปจนถึงขั้นที่ 4 เพื่อให้ได้ระบบ Billing ที่สอดคล้องกับกระบวนการทำงานจริง และสามารถเชื่อมต่อกับ Domain ทั้ง 6 ที่ออกแบบไว้ก่อนหน้าได้อย่างถูกต้อง

เป้าหมายไม่ใช่เพียงการสร้างระบบออกใบแจ้งหนี้และใบเสร็จรับเงิน แต่คือการสร้างระบบบริหารธุรกรรมทางการเงินของคลินิกสัตวแพทย์ที่ครบวงจร ตั้งแต่การเกิดค่าใช้จ่าย การเรียกเก็บ การรับเงิน การคืนเงิน ไปจนถึงการส่งข้อมูลเข้าสู่ระบบบัญชีครับ
