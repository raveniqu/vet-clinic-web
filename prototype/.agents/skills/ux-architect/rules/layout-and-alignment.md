# กฎ UX ด้านการจัดวางเลย์เอาต์และการจัดแนว

> **ขอบเขต:** ใช้กฎเหล่านี้เมื่อออกแบบ พัฒนา ทบทวน หรือปรับปรุงโครงสร้างการจัดวางหน้าจอ การจัดแนว ระยะห่าง การจัดกลุ่มข้อมูล กล่องข้อความ ตาราง ฟอร์ม และการจัดองค์ประกอบเนื้อหา
>
> **ข้อกำหนดส่วนกลาง:** ปฏิบัติตามเกณฑ์ระดับคำสั่ง ลำดับความสำคัญ และขั้นตอนการทำงานใน global.md

---

## LAY-01 — การจัดแนวข้อความใน Accordion

**หลักการ:** ทำให้หัวข้อ Accordion และเนื้อหาที่ขยายออกมามีแนวเริ่มต้นการอ่านตรงกัน เพื่อให้กวาดสายตาได้ต่อเนื่องเป็นเส้นตรง

### ข้อกำหนด

- **SHOULD** จัดตัวอักษรแรกของหัวข้อ Accordion ให้ตรงกับตัวอักษรแรกของเนื้อหาด้านล่าง ไม่ใช่จัดตรงเฉพาะขอบกล่องด้านนอก
- **SHOULD** ใช้ระยะขอบด้านในแนวนอนเท่ากันสำหรับหัวข้อและเนื้อหา หรือจัดให้อยู่ในคอลัมน์ข้อความเดียวกันหากมีไอคอนนำหน้า
- **SHOULD** วางไอคอนเปิดปิดไว้ที่ขอบฝั่งตรงข้าม เพื่อไม่ให้ดันหัวข้อเยื้องออกจากแนวข้อความ
- **AVOID** หัวข้อที่เยื้องเข้ามาหรือเนื้อหาที่เยื้องห่างจากหัวข้อโดยไม่มีเหตุผลด้านลำดับขั้นที่ชัดเจน

### แนวทางการนำไปใช้งาน

| สแต็ก หรือ บริบท  | รูปแบบที่แนะนำ                     | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง                                                                       |
| :---------------- | :--------------------------------- | :----------------------------------------------------------------------------------------------------- |
| **Tailwind CSS**  | `text-start`, ระยะขอบแนวนอนเท่ากัน | `px-4 text-start`, หัวข้อใช้ `flex items-center justify-between gap-3`                                 |
| **Raw CSS**       | จัดแนวจุดเริ่มต้นตัวอักษรตรงกัน    | `text-align: start; padding-inline: 1rem; display: flex; justify-content: space-between; gap: .75rem;` |
| **HTML และ A11y** | ใช้ Semantic Element               | แนะนำ `<details>` และ `<summary>` สำหรับกรณีทั่วไป หรือใช้ Accessible Accordion Component              |

**การตรวจสอบความถูกต้อง:** ทดลองเปิดปิด Accordion แล้วตรวจดูว่าแนวเริ่มต้นของตัวอักษรหัวข้อและเนื้อหาตรงกันจริง ทั้งบนหน้าจอมือถือและเดสก์ท็อป

## LAY-02 — ความกว้างของแถบด้านข้างบนเดสก์ท็อป

**หลักการ:** ป้องกันไม่ให้แถบนำทางด้านข้างกินพื้นที่แนวนอนมากเกินไป จนแย่งพื้นที่ของเนื้อหาหลัก

### ข้อกำหนด

- **SHOULD** กำหนดความกว้างของแถบด้านข้างบนเดสก์ท็อปเป็นขนาดคงที่ที่เหมาะสม เช่น 240px ถึง 280px แทนการใช้ความกว้างเป็นเปอร์เซ็นต์ของหน้าจอ
- **SHOULD** ให้เนื้อหาหลักยืดขยายรับพื้นที่ที่เหลือทั้งหมด และอนุญาตให้ย่อขนาดได้ด้วย `min-w-0` เพื่อป้องกันปัญหาการล้นแนวนอน
- **SHOULD** ปรับแถบนำทางเป็นแบบพับเก็บได้ เมนู Overlay หรือรูปแบบอื่นบนหน้าจอขนาดเล็ก แทนการตรึงขนาดเดสก์ท็อปไว้
- **AVOID** การใช้ `width: 30%` หรือ `w-1/3` กับแถบด้านข้างทั่วไป เมื่อความยาวของข้อความเมนูสามารถแสดงได้ในขนาดที่กะทัดรัดกว่า

### แนวทางการนำไปใช้งาน

| สแต็ก หรือ บริบท  | รูปแบบที่แนะนำ                 | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง                                                                         |
| :---------------- | :----------------------------- | :------------------------------------------------------------------------------------------------------- |
| **Tailwind CSS**  | กำหนดความกว้างคงที่และใช้ Flex | โครงสร้างหลัก: `flex`; แถบด้านข้าง: `hidden md:block md:w-60 md:shrink-0`; เนื้อหาหลัก: `min-w-0 flex-1` |
| **Raw CSS**       | กำหนด flex-basis ชัดเจน        | `.sidebar { flex: 0 0 15rem; } .main { flex: 1; min-width: 0; }`                                         |
| **HTML และ A11y** | โครงสร้าง Semantic Navigation  | ใช้ `<aside>` หรือ `<nav aria-label="...">` เคียงข้างกับ `<main>`                                        |

**การตรวจสอบความถูกต้อง:** ข้อความในแถบด้านข้างแสดงได้ครบถ้วนโดยไม่ล้น และพื้นที่เนื้อหาหลักคงความกว้างที่ใช้งานสะดวกในทุกขนาดหน้าจอ

## LAY-03 — การจัดกลุ่มข้อมูลที่เกี่ยวข้องกัน

**หลักการ:** ลดภาระการกวาดสายตาในรายการข้อมูลขนาดยาว โดยจัดคุณสมบัติที่เกี่ยวข้องกันเป็นกลุ่มที่สังเกตได้ชัดเจน

### ข้อกำหนด

- **SHOULD** จัดกลุ่มข้อมูลตามความหมาย เช่น หน่วยประมวลผล หน่วยความจำ หน้าจอ แทนการจัดกลุ่มตามจำนวนแถวแบบสุ่ม
- **SHOULD** ตั้งหัวข้อย่อยสั้นๆ ให้กับแต่ละกลุ่ม และเว้นระยะห่างระหว่างกลุ่มให้มากกว่าระยะห่างภายในกลุ่ม
- **MUST** เชื่อมโยงป้ายกำกับและค่าของข้อมูลเข้าด้วยกันทั้งทางสายตาและเชิงความหมาย
- **AVOID** รายการคุณสมบัติหลายสิบรายการเรียงต่อกันเป็นแถวยาวเดี่ยวโดยไม่มีการแบ่งกลุ่ม

### แนวทางการนำไปใช้งาน

| สแต็ก หรือ บริบท  | รูปแบบที่แนะนำ                      | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง                                                                                   |
| :---------------- | :---------------------------------- | :----------------------------------------------------------------------------------------------------------------- |
| **Tailwind CSS**  | ระยะห่างต่างระดับตามกลุ่ม           | แต่ละกลุ่ม: `flex flex-col gap-6` หรือ `grid gap-6`; แถวในกลุ่ม: `grid grid-cols-2 gap-x-4 gap-y-2`; หัวข้อกลุ่ม: `font-semibold text-foreground` |
| **Raw CSS**       | Grid หรือ Flex ที่มีระยะห่างต่างกัน | `.groups { display: grid; gap: 1.5rem; } .attribute-rows { display: grid; gap: .5rem 1rem; }`                      |
| **HTML และ A11y** | รายการคำอธิบายเชิงความหมาย          | ใช้ `<section>` พร้อมหัวข้อ หรือใช้ `<dl>` ร่วมกับคู่ `<dt>` และ `<dd>` สำหรับข้อมูลประเภทคุณสมบัติและค่า          |

**การตรวจสอบความถูกต้อง:** ผู้ใช้สามารถกวาดสายตาค้นหาคุณสมบัติที่ต้องการได้ทันทีโดยไม่ต้องอ่านทุกแถวตั้งแต่ต้นจนจบ

## LAY-04 — ลำดับปุ่มในกล่องข้อความยืนยัน

**หลักการ:** จัดตำแหน่งปุ่มและการเคลื่อนที่ของโฟกัสคีย์บอร์ดให้สอดคล้องกับความคาดหวังของผู้ใช้และความต่อเนื่องของงาน

### ข้อกำหนด

- **SHOULD** ยึดตามแบบแผนมาตรฐานของแพลตฟอร์มหรือระบบเดิมเป็นหลัก สำหรับกล่องข้อความยืนยันทั่วไปที่ไม่มีช่องกรอกข้อมูล ปุ่มยกเลิกมักอยู่ซ้าย และปุ่มยืนยันอยู่ขวา
- **SHOULD** หากกล่องข้อความกำหนดให้พิมพ์ข้อความเพื่อยืนยันการกระทำที่สำคัญหรือย้อนกลับไม่ได้ ให้พิจารณาวางปุ่มยืนยันถัดจากช่องกรอกข้อมูลทันที ทั้งในลำดับสายตาและลำดับโฟกัสของคีย์บอร์ด
- **MUST** อธิบายผลลัพธ์ที่จะย้อนกลับไม่ได้ให้ชัดเจน และแยกปุ่มลบหรือการกระทำอันตรายให้แตกต่างจากปุ่มทั่วไปอย่างชัดเจน
- **MUST NOT** ใช้ CSS `order` เพื่อสลับตำแหน่งการแสดงผลจนขัดแย้งกับลำดับ Tab ของคีย์บอร์ด
- **MUST** จัดการขอบเขตโฟกัส การปิดด้วยปุ่ม Escape และการคืนโฟกัสกลับสู่จุดเริ่มต้นเมื่อปิดกล่องข้อความ

### แนวทางการนำไปใช้งาน

| สแต็ก หรือ บริบท  | รูปแบบที่แนะนำ             | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง                                                          |
| :---------------- | :------------------------- | :---------------------------------------------------------------------------------------- |
| **Tailwind CSS**  | แถบปุ่มชิดขอบตามลำดับงาน   | แบบมาตรฐาน: `flex justify-end gap-3`; แบบต่อเนื่องจากช่องกรอก: `flex justify-start gap-3` |
| **Raw CSS**       | จัดตำแหน่งปุ่มด้วย Flexbox | `display: flex; gap: .75rem; justify-content: flex-end;`                                  |
| **HTML และ A11y** | กล่องข้อความพร้อมฟอร์ม     | ใช้ `<dialog>` หรือ Accessible Dialog Component พร้อมป้ายกำกับปุ่มที่ระบุหน้าที่ชัดเจน    |

**การตรวจสอบความถูกต้อง:** ผู้ใช้คีย์บอร์ดเลื่อนโฟกัสผ่านช่องกรอกและปุ่มในลำดับที่สมเหตุสมผล และปุ่มยกเลิกกับปุ่มยืนยันมีความแตกต่างกันชัดเจน

## LAY-05 — การจัดทิศทางการอ่านและปุ่มในกล่องข้อความ

**หลักการ:** รักษาความลื่นไหลของการอ่านตามธรรมชาติ และสร้างลำดับความสำคัญของปุ่มสั่งการให้ชัดเจน

### ข้อกำหนด

- **SHOULD** จัดข้อความอธิบายหลายบรรทัดในกล่องข้อความให้ชิดซ้ายหรือชิดขอบเริ่มต้นเสมอ เพื่อให้อ่านง่าย
- **SHOULD** กำหนดให้มีปุ่มหลักที่เด่นชัดเพียงปุ่มเดียว ส่วนปุ่มรองให้ใช้สไตล์ที่กลมกลืน
- **SHOULD** จัดแถวปุ่มกดด้านล่างให้อยู่มุมขวาสำหรับกล่องข้อความเว็บทั่วไป
- **AVOID** จัดข้อความยาวให้อยู่กึ่งกลางทุกบรรทัด
- **AVOID** วางปุ่มสองปุ่มที่มีสีสันและความเด่นเท่ากันจนแย่งความสนใจ
- **AVOID** จัดปุ่มไว้กึ่งกลางในกล่องข้อความเว็บมาตรฐานโดยไม่มีเหตุผลจำเป็น

### แนวทางการนำไปใช้งาน

| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ                | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง                                                                                                                        |
| :--------------- | :---------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Tailwind CSS** | ข้อความชิดซ้าย ปุ่มเด่นชัดเจน | ข้อความ: `text-start`; แถบปุ่มด้านล่าง: `flex justify-end gap-3`; ปุ่มหลัก: `bg-primary text-primary-foreground hover:bg-primary/90`; ปุ่มรอง: `border border-border text-foreground hover:bg-muted` |
| **Raw CSS**      | จัดแนวและความเด่นต่างระดับ    | `text-align: start; display: flex; justify-content: flex-end; gap: .75rem;` พร้อมสไตล์ปุ่มหลักและปุ่มรอง                                                |

**การตรวจสอบความถูกต้อง:** มองแวบเดียวระบุได้ทันทีว่าการกระทำหลักคืออะไร และสามารถกวาดสายตาอ่านเนื้อหาได้โดยไม่ต้องปรับจุดเริ่มสายตาไปมา

## LAY-06 — การจัดวางป้ายกำกับและค่าของข้อมูล

**หลักการ:** เน้นค่าของข้อมูลซึ่งเป็นสิ่งที่ผู้ใช้ต้องการค้นหาเป็นหลัก โดยไม่สูญเสียบริบทของป้ายกำกับ

### ข้อกำหนด

- **SHOULD** จัดแนวป้ายกำกับและค่าข้อมูลให้เป็นคอลัมน์ที่มั่นคง สม่ำเสมอ หรือซ้อนกันเป็นคู่บนหน้าจอมือถือ
- **SHOULD** ให้น้ำหนักทางสายตาแก่ค่าข้อมูลมากกว่าป้ายกำกับ เช่น ใช้ตัวหนากว่าหรือสีเข้มกว่า
- **MUST** รองรับข้อความขนาดยาวให้ขึ้นบรรทัดใหม่ได้โดยไม่ซ้อนทับหรือหลุดขอบกล่อง
- **AVOID** กำหนดให้น้ำหนักและสีของป้ายกำกับกับค่าข้อมูลเด่นเท่ากันจนแยกไม่ออก

### แนวทางการนำไปใช้งาน

| สแต็ก หรือ บริบท  | รูปแบบที่แนะนำ                 | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง                                                                                                                                |
| :---------------- | :----------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Tailwind CSS**  | Grid สองคอลัมน์พร้อมความต่างสี | แต่ละแถว: `grid grid-cols-1 gap-1 sm:grid-cols-[minmax(8rem,1fr)_minmax(0,2fr)] sm:gap-4`; ป้ายกำกับ: `text-muted-foreground`; ค่าข้อมูล: `font-medium text-foreground` |
| **Raw CSS**       | Grid คอลัมน์ที่ยืดหยุ่น        | `display: grid; grid-template-columns: minmax(8rem, 1fr) minmax(0, 2fr); gap: 1rem;` และปรับเป็นหนึ่งคอลัมน์ในมือถือ                                            |
| **HTML และ A11y** | แท็กคำอธิบายเชิงความหมาย       | ใช้ `<dl>` ครอบคู่ `<dt>` สำหรับป้ายกำกับ และ `<dd>` สำหรับค่าข้อมูล                                                                                            |

**การตรวจสอบความถูกต้อง:** ผู้ใช้สามารถกวาดสายตาไล่ดูคอลัมน์ของค่าข้อมูลได้อย่างรวดเร็ว และระบุได้ชัดเจนว่าค่านั้นสัมพันธ์กับป้ายกำกับใด

## LAY-07 — ระยะห่างระหว่างเซกชัน

**หลักการ:** เว้นระยะห่างพื้นที่ว่างระหว่างเซกชันอิสระให้มากพอที่จะรับรู้ได้ว่าเป็นกลุ่มเนื้อหาคนละหัวข้อ

### ข้อกำหนด

- **SHOULD** กำหนดจังหวะระยะห่างแนวตั้งที่เป็นระบบและสม่ำเสมอสำหรับเซกชันระดับเดียวกัน
- **SHOULD** เว้นระยะห่างระหว่างเซกชันให้ใหญ่กว่าระยะห่างภายในเซกชันอย่างชัดเจน
- **SHOULD** ใช้พื้นที่ว่างสีขาวเป็นตัวแบ่งหลัก เส้นแบ่งหรือการเปลี่ยนสีพื้นหลังเป็นเพียงส่วนเสริม
- **AVOID** บีบระยะห่างระหว่างเซกชันให้แคบพอๆ กับระยะห่างระหว่างย่อหน้า

### แนวทางการนำไปใช้งาน

| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ                    | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง                                                                              |
| :--------------- | :-------------------------------- | :------------------------------------------------------------------------------------------------------------ |
| **Tailwind CSS** | ระยะขอบในแนวตั้งขนาดใหญ่ตามหน้าจอ | `py-16 md:py-24` ประจำแต่ละเซกชัน หรือ `flex flex-col gap-20`                                                 |
| **Raw CSS**      | ระยะขอบในแนวตั้งที่ปรับตามหน้าจอ  | `.page-section { padding-block: 4rem; } @media (min-width: 768px) { .page-section { padding-block: 6rem; } }` |

**การตรวจสอบความถูกต้อง:** ผู้ที่เลื่อนหน้าจอเร็วๆ สามารถรับรู้จุดเริ่มต้นและสิ้นสุดของแต่ละหัวข้อใหญ่ได้ทันที โดยไม่ต้องพึ่งพาเส้นคั่น

## LAY-08 — พื้นหลังที่ครอบคลุมกลุ่มเนื้อหา

**หลักการ:** ทำให้หัวข้อที่เน้นและเนื้อหาที่เกี่ยวข้องเชื่อมโยงเป็นกลุ่มเดียวกัน ไม่แยกหัวข้อให้ลอยเด่นอยู่อย่างโดดเดี่ยว

### ข้อกำหนด

- **SHOULD** เมื่อใช้สีพื้นหลังเพื่อจัดกลุ่มเนื้อหา ให้แผ่สีพื้นหลังครอบคลุมทั้งหัวข้อและเนื้อหาบริวารทั้งหมด ไม่ใช่ตัดพื้นหลังเป็นแถบแคบเฉพาะตัวหนังสือหัวข้อ
- **SHOULD** กำหนดสีพื้นหลังที่คอนเทนเนอร์ชั้นนอกอย่าง `<section>` แล้วจำกัดความกว้างของเนื้อหาภายในแยกต่างหาก
- **AVOID** การใส่แถบสีพื้นหลังคาดเฉพาะข้อความหัวข้อ ซึ่งทำให้หัวข้อดูหลุดออกจากย่อหน้าหรือการ์ดที่อยู่ด้านล่าง

### แนวทางการนำไปใช้งาน

| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ               | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง                                                                                                                                  |
| :--------------- | :--------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Tailwind CSS** | พื้นหลังที่โครงสร้างชั้นนอก  | เซกชันนอก: `bg-muted py-16`; กล่องเนื้อหาด้านใน: `mx-auto max-w-6xl px-4` ครอบทั้งหัวข้อและเนื้อหา                                                          |
| **Raw CSS**      | กำหนดพื้นหลังที่กล่องชั้นนอก | `.highlighted-section { background: #f1f5f9; padding-block: 4rem; } .highlighted-section__inner { max-width: 72rem; margin-inline: auto; padding-inline: 1rem; }` |

**การตรวจสอบความถูกต้อง:** สายตารับรู้ว่าหัวข้อ การ์ด หรือภาพประกอบทั้งหมดนั้นเป็นเนื้อหาในชุดเดียวกันผ่านกรอบพื้นหลังร่วม

## LAY-09 — การเพิ่มระยะห่างระหว่างบล็อกเนื้อหา

**หลักการ:** ป้องกันความอึดอัดของเลย์เอาต์ด้วยการเพิ่มพื้นที่ว่างระหว่างบล็อกที่ไม่เกี่ยวข้องกัน แทนการพึ่งพาเส้นตีกรอบหรือสีสันเพิ่มเติม

### ข้อกำหนด

- **SHOULD** ตรวจสอบการเพิ่มระยะห่างพื้นที่ว่างก่อนตัดสินใจใส่เส้นขอบ กล่องข้อความ เส้นแบ่ง หรือสีสันเพิ่ม
- **SHOULD** เว้นระยะห่างระหว่างบล็อกใหญ่ให้กว้างกว่าระยะห่างระหว่างตัวอักษรและปุ่มควบคุมภายในบล็อก
- **SHOULD** ปรับขนาดระยะห่างตามขนาดหน้าจอ
- **AVOID** กำหนดระยะขอบขนาดเล็กเท่ากันทุกจุดเพียงเพราะต้องการประหยัดความสูงของหน้าจอ

### แนวทางการนำไปใช้งาน

| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ                    | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง                                                                           |
| :--------------- | :-------------------------------- | :--------------------------------------------------------------------------------------------------------- |
| **Tailwind CSS** | ระยะห่างต่างระดับตามบล็อก         | ระหว่างบล็อกใหญ่: `flex flex-col gap-12 md:gap-16`; ภายในบล็อก: `flex flex-col gap-3 md:gap-4`                               |
| **Raw CSS**      | Gap ที่มีขนาดใหญ่และปรับตามหน้าจอ | `.feature-stack { display: grid; gap: 3rem; } @media (min-width: 768px) { .feature-stack { gap: 4rem; } }` |

**การตรวจสอบความถูกต้อง:** แต่ละบล็อกมีความเป็นอิสระต่อกัน ชัดเจน ไม่อึดอัด และเนื้อหาภายในแต่ละบล็อกยังคงเกาะกลุ่มกันดี

## LAY-10 — การจัดการพื้นที่ว่างในตารางที่มีการจัดกลุ่ม

**หลักการ:** หลีกเลี่ยงพื้นที่ว่างขนาดใหญ่ที่เปล่าประโยชน์ เมื่อป้ายกำกับกลุ่มกินพื้นที่ทั้งคอลัมน์ข้างแถวย่อยหลายแถว

### ข้อกำหนด

- **SHOULD** ระวังการใช้เซลล์ที่ผสานแถวยาวมากๆ ซึ่งทำให้ชื่อกลุ่มหลุดหายไปจากสายตาเมื่อผู้ใช้เลื่อนหน้าจอ
- **SHOULD** พิจารณาแยกตารางออกเป็นตารางย่อยที่มีหัวข้อกลุ่มชัดเจน หรือใช้ Sticky group label แทนการกินคอลัมน์ยาว
- **MUST** รักษาความสัมพันธ์ระหว่างป้ายกำกับคอลัมน์และแถวข้อมูลไว้ให้ถูกต้องในเชิงการเข้าถึงได้
- **AVOID** การใช้ผสานแถวขนาดยักษ์เพียงเพื่อแสดงชื่อสั้นๆ ครั้งเดียวจนเกิดพื้นที่ว่างโล่งขนาดใหญ่ทางซ้าย
- **ข้อยกเว้น:** หากงานหลักของผู้ใช้คือการเรียงลำดับข้อมูลข้ามกลุ่มทั้งหมดพร้อมกัน ไม่ควรแยกตาราง

### แนวทางการนำไปใช้งาน

| สแต็ก หรือ บริบท  | รูปแบบที่แนะนำ                | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง                                                      |
| :---------------- | :---------------------------- | :------------------------------------------------------------------------------------ |
| **Tailwind CSS**  | แยกตารางหรือใช้ Sticky header | แต่ละกลุ่มตาราง: `flex flex-col gap-8`; ตาราง: `w-full overflow-x-auto`; หัวข้อ: `sticky top-0 bg-background` |
| **Raw CSS**       | แยกโครงสร้างตารางตามกลุ่ม     | `.table-groups { display: grid; gap: 2rem; } .table-scroll { overflow-x: auto; }`     |
| **HTML และ A11y** | โครงสร้างตารางเชิงความหมาย    | ใช้ `<caption>` หรือ Heading ประจำแต่ละตาราง พร้อมกำหนด `<th scope="col">` ให้ครบถ้วน |

**การตรวจสอบความถูกต้อง:** เมื่อเลื่อนดูแถวล่างๆ ผู้ใช้ยังทราบได้ทันทีว่าแถวนั้นสัมพันธ์กับกลุ่มหรือหัวข้อใด

## LAY-11 — การจัดวางฟอร์มเพื่อลดการกวาดสายตาสลับฟันปลา

**หลักการ:** ลดการเคลื่อนที่ของสายตาระหว่างป้ายกำกับและช่องกรอกข้อมูลให้สั้นที่สุด

### ข้อกำหนด

- **SHOULD** วางป้ายกำกับไว้เหนือช่องกรอกข้อมูลทันทีสำหรับฟอร์มทั่วไป โดยเฉพาะบนหน้าจอมือถือ
- **SHOULD** หากจำเป็นต้องใช้ป้ายกำกับด้านข้าง ให้จัดข้อความป้ายกำกับให้ชิดขวาติดกับช่องกรอกข้อมูล พร้อมเว้นช่องไฟคอลัมน์ขนาดเล็กที่สม่ำเสมอ
- **MUST** รักษาลำดับการอ่านและการกด Tab คีย์บอร์ดจากบนลงล่างอย่างเป็นธรรมชาติ
- **AVOID** ป้ายกำกับชิดซ้ายสุดของหน้าจอในขณะที่ช่องกรอกข้อมูลอยู่อีกฝั่งหนึ่งไกลออกไป

### แนวทางการนำไปใช้งาน

| สแต็ก หรือ บริบท  | รูปแบบที่แนะนำ                       | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง                                                                  |
| :---------------- | :----------------------------------- | :------------------------------------------------------------------------------------------------ |
| **Tailwind CSS**  | แบบซ้อนกันหรือ Grid สองคอลัมน์กระชับ | แนวตั้ง: `grid gap-2`; แนวนอน: `grid grid-cols-[8rem_minmax(0,1fr)] items-center gap-x-3 gap-y-4` |
| **Raw CSS**       | Grid ที่มีช่องไฟคอลัมน์แคบ           | `display: grid; grid-template-columns: 8rem minmax(0, 1fr); column-gap: .75rem; row-gap: 1rem;`   |
| **HTML และ A11y** | เชื่อมโยงป้ายกำกับและช่องกรอก        | ใช้ `<label for="field-id">` คู่กับ `<input id="field-id">` เสมอ                                  |

**การตรวจสอบความถูกต้อง:** สายตาของผู้ใช้สามารถเลื่อนลงมาตรงๆ ได้โดยไม่ต้องกวาดสายตาสลับซ้ายขวาข้ามพื้นที่ว่างกว้าง

## LAY-12 — การจัดวางภาพและข้อความให้เรียบง่าย

**หลักการ:** เมื่อภาพประกอบทรงสูงวางซ้อนกับข้อความยาวแล้วทำให้หน้าจอยืดสูงเกินไป ให้เปลี่ยนองค์ประกอบเป็นแบบวางเคียงข้างกันอย่างเรียบง่าย

### ข้อกำหนด

- **SHOULD** เมื่อภาพประกอบขนาดใหญ่ซ้อนใต้คำอธิบายแล้วทำให้กินความสูงหน้าจอมากเกินไป ให้จัดเป็นเลย์เอาต์สองคอลัมน์โดยวางภาพและข้อความเคียงข้างกันบนหน้าจอกว้าง
- **SHOULD** ปรับเปลี่ยนโครงสร้างองค์ประกอบหลักตามเนื้อหาจริง แทนการแก้ปัญหาด้วยการตัดครอปภาพจนเสียความหมาย
- **SHOULD** ปรับกลับเป็นหนึ่งคอลัมน์บนหน้าจอมือถือโดยรักษาลำดับการอ่านให้เข้าใจง่าย
- **AVOID** การตัดความสูงภาพแบบสุ่ม หรือการใช้ Absolute positioning เพื่อแปะข้อความทับภาพจนอ่านยาก

### แนวทางการนำไปใช้งาน

| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ            | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง                                                                              |
| :--------------- | :------------------------ | :------------------------------------------------------------------------------------------------------------ |
| **Tailwind CSS** | Responsive 2-column grid  | `grid grid-cols-1 items-start gap-8 lg:grid-cols-2`; ภาพ: `w-full h-auto object-contain`                      |
| **Raw CSS**      | Responsive Grid ตามหน้าจอ | `display: grid; grid-template-columns: 1fr; gap: 2rem;` และขยายเป็น `repeat(2, minmax(0, 1fr))` ในหน้าจอกว้าง |

**การตรวจสอบความถูกต้อง:** ภาพประกอบและข้อความอธิบายสามารถมองเห็นร่วมกันได้ครบถ้วนโดยไม่ต้องเลื่อนหน้าจอไกล และอ่านง่ายทั้งบนเดสก์ท็อปและมือถือ
