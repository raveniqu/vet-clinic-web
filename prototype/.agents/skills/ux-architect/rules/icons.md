# กฎ UX ด้านการใช้งานไอคอนและการจัดวาง

> **ขอบเขต:** ใช้กฎเหล่านี้กับไอคอนในระบบนำทาง แถบเครื่องมือ ปุ่ม เมนู การจัดรายการ การแจ้งสถานะ และข้อความเตือน
> **ข้อกำหนดส่วนกลาง:** ปฏิบัติตามเกณฑ์ระดับคำสั่ง ลำดับความสำคัญ และขั้นตอนการทำงานใน global.md

---

## ICON-01 — ความสมดุลทางสายตาของไอคอน

**หลักการ:** การจัดให้อยู่กึ่งกลางตามกรอบสี่เหลี่ยมเรขาคณิต อาจทำให้ไอคอนที่มีรูปทรงไม่สมมาตรดูเอียง จำเป็นต้องปรับตำแหน่งตามจุดศูนย์ถ่วงทางสายตา

### ข้อกำหนด
- **MUST** จัดวางตำแหน่งปุ่มหรือกล่องไอคอนด้วยระบบเลย์เอาต์ปกติก่อน เช่น การจัดกึ่งกลางด้วย Grid หรือ Flexbox
- **SHOULD** ตรวจสอบด้วยสายตาว่าไอคอนดูกึ่งกลางกับกรอบจริงหรือไม่ โดยเฉพาะรูปทรงสามเหลี่ยมหรือรูปทรงอสมมาตร
- **MAY** ขยับชดเชยเฉพาะตัวรูปทรงไอคอนเล็กน้อยหนึ่งถึงสองพิกเซล เพื่อให้ดูสมดุลโดยไม่กระทบพื้นที่สัมผัสของปุ่ม
- **MUST NOT** ใส่ค่าขยับตำแหน่งชดเชยให้กับไอคอนทุกตัวในระบบโดยไม่มีเหตุผลเฉพาะตัวรูปทรง

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | จัดกึ่งกลางพร้อมชดเชยเฉพาะจุด | กล่องปุ่ม: `grid size-12 place-items-center rounded-full bg-primary text-primary-foreground`; ไอคอน: `translate-x-0.5` |
| **Raw CSS** | Grid center พร้อม transform | `display: grid; place-items: center;` และไอคอนใช้ `transform: translateX(1px);` |

**การตรวจสอบความถูกต้อง:** ไอคอนรูปทรงไม่สมมาตร เช่น ปุ่มเล่นวิดีโอ ดูอยู่ตรงกลางวงกลมอย่างเป็นธรรมชาติ

## ICON-02 — น้ำหนักทางสายตาของไอคอน

**หลักการ:** ไอคอนแบบทึบอาจดูเด่นและหนักสายตาเกินข้อความข้างเคียง ควรปรับน้ำหนักของไอคอนให้กลมกลืนกับข้อความ

### ข้อกำหนด
- **SHOULD** ควบคุมให้น้ำหนักทางสายตาของไอคอนประกอบข้อความไม่เด่นแย่งความสนใจจากข้อความหลัก โดยเฉพาะในรายการเมนู
- **SHOULD** เริ่มต้นปรับจากสีของไอคอนก่อนปรับเปลี่ยนขนาด
- **MUST** คงความชัดเจนในการมองเห็นของไอคอนที่สื่อสถานะสำคัญ เช่น ข้อผิดพลาด การเตือน หรือสถานะถูกเลือก
- **MUST NOT** ปรับไอคอนให้ซีดจางจนแยกไม่ออกจากพื้นหลัง

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | สีไอคอนรองรับข้อความหลัก | ไอคอน: `size-5 text-muted-foreground`; ข้อความ: `text-sm font-medium text-foreground` |
| **Raw CSS** | สีแยกตามคลาส | ไอคอนใช้สีเทากลาง เช่น `#64748b` ในขณะที่ข้อความใช้สีเข้ม เช่น `#0f172a` |

**การตรวจสอบความถูกต้อง:** เมื่อมองดูแถวเมนู ข้อความยังคงเป็นจุดนำสายตาหลัก โดยมีไอคอนช่วยเสริมความหมาย

---

## ICON-03 — วางไอคอนในกล่องขนาดคงที่เพื่อจัดแนว

**หลักการ:** การวางไอคอนลงในกล่องขนาดคงที่ช่วยแก้ปัญหาไอคอนที่มีความกว้างยาวไม่เท่ากัน ทำให้การจัดแนวของรายการดูเป็นระเบียบ

### ข้อกำหนด
- **SHOULD** ใช้กล่องหรือพื้นที่รองรับขนาดมาตรฐานสำหรับไอคอนในรายการที่ต้องเรียงแถวตรงกัน เช่น รายการเมนูหรือฟีเจอร์การ์ด
- **MUST** จัดตัวไอคอนให้อยู่กึ่งกลางกล่องด้วยเลย์เอาต์ที่คงที่
- **SHOULD** วางแนวข้อความให้อยู่ในแนวเดียวกันในทุกแถว แม้ขนาดจริงของตัวไอคอนจะต่างกันเล็กน้อย

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | กล่องคงที่สำหรับไอคอน | กล่องไอคอน: `grid size-10 place-items-center rounded-lg bg-muted text-foreground` |
| **Raw CSS** | Fixed container dimensions | `width: 2.5rem; height: 2.5rem; display: grid; place-items: center;` |

**การตรวจสอบความถูกต้อง:** ข้อความในทุกแถวเริ่มต้นที่แนวคอลัมน์เดียวกันอย่างสมบูรณ์

---

## ICON-04 — ความสม่ำเสมอของรูปแบบเส้นและขนาดไอคอน

**หลักการ:** ชุดไอคอนควรมีรูปแบบภาพที่สอดคล้องกัน เช่น ความหนาของเส้นหรือรูปแบบทึบ ไม่ผสมผสานรูปแบบที่ขัดแย้งกันในหน้าจอเดียว

### ข้อกำหนด
- **MUST** ใช้ชุดไอคอนที่มีรูปแบบสอดคล้องกันทั่วทั้งระบบ เช่น เส้นโครงสร้างหรือแบบทึบ
- **SHOULD** รักษาความหนาของเส้นไอคอนให้กลมกลืนกันเมื่อใช้ไอคอนแบบเส้น
- **MUST NOT** ผสมไอคอนหลายสไตล์ปะปนกันในหน้าจอเดียวกันโดยไม่มีเหตุผลด้านการใช้งานที่ชัดเจน

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | ควบคุมขนาดและความหนาเส้น | `size-5 stroke-[1.75]` สม่ำเสมอในทุกจุด |
| **SVG Properties** | กำหนดคุณสมบัติร่วม | `viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.75"` |

**การตรวจสอบความถูกต้อง:** ไอคอนทั้งหมดในหน้าจอดูเป็นชุดภาษาภาพเดียวกัน

---

## ICON-05 — เลือกสัญลักษณ์ไอคอนที่ตรงกับความหมาย

**หลักการ:** ไอคอนควรสื่อถึงความหมายที่ตรงกับสิ่งที่เกิดขึ้นจริงตามความคุ้นเคยของผู้ใช้ เพื่อป้องกันความเข้าใจผิด

### ข้อกำหนด
- **MUST** เลือกใช้สัญลักษณ์ที่เป็นมาตรฐานและผู้ใช้คุ้นเคยกับความหมายนั้นอยู่แล้ว
- **MUST NOT** ประดิษฐ์สัญลักษณ์ใหม่สำหรับฟังก์ชันพื้นฐานที่อาจทำให้ผู้ใช้เดาหน้าที่ผิด
- **SHOULD** ละเว้นการใส่ไอคอนในเมนูที่มีขนาดยาว หากไม่สามารถหาสัญลักษณ์ที่สื่อความหมายได้ชัดเจนในทุกรายการ

### แนวทางการนำไปใช้งาน
| ฟังก์ชัน | สัญลักษณ์มาตรฐาน |
| :--- | :--- |
| **ค้นหา** | แว่นขยาย |
| **การตั้งค่า** | ฟันเฟือง |
| **ลบข้อมูล** | ถังขยะ |
| **แก้ไขข้อมูล** | ดินสอ |

**การตรวจสอบความถูกต้อง:** ผู้ใช้ทั่วไปสามารถคาดเดาหน้าที่ของไอคอนได้ถูกต้องโดยไม่ต้องมีคำอธิบายขนาดยาว

---

## ICON-06 — ใช้ไอคอนคู่กับข้อความกำกับที่มองเห็นได้

**หลักการ:** ไอคอนอย่างเดียวอาจมีความหมายกำกวม การมีข้อความกำกับที่มองเห็นได้ช่วยขจัดความสับสนและช่วยให้อ่านเข้าใจได้เร็วที่สุด

### ข้อกำหนด
- **SHOULD** แสดงข้อความกำกับที่มองเห็นได้ควบคู่กับไอคอนเสมอ โดยเฉพาะการกระทำที่มีความสำคัญ
- **MUST** หากจำเป็นต้องใช้ปุ่มที่มีเฉพาะไอคอน ต้องกำหนดชื่อกำกับการเข้าถึงผ่าน `aria-label` เสมอ
- **MUST** รองรับการเข้าถึงด้วยคีย์บอร์ดและมีจุดสังเกตโฟกัสที่ชัดเจนสำหรับปุ่มไอคอนเดี่ยว

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | ไอคอนคู่ข้อความ | `<button class="inline-flex items-center gap-2 px-3 py-2"><svg ...><span class="text-sm">ส่งออกไฟล์</span></button>` |
| **ปุ่มเฉพาะไอคอน** | กำหนดชื่อกำกับการเข้าถึง | `<button type="button" aria-label="ค้นหาข้อมูล" class="size-10 grid place-items-center">...</button>` |

**การตรวจสอบความถูกต้อง:** ปุ่มที่มีเฉพาะไอคอนมีคำอธิบายที่โปรแกรมอ่านหน้าจอสามารถอ่านได้ และผู้ใช้เข้าใจหน้าที่ได้ทันที

---

## ICON-07 — ไอคอนแสดงสถานะต้องมาพร้อมข้อความอธิบาย

**หลักการ:** ห้ามสื่อสารสถานะความสำเร็จ การแจ้งเตือน หรือข้อผิดพลาดด้วยไอคอนหรือสีเพียงอย่างเดียว ต้องมีข้อความอธิบายประกอบเสมอ

### ข้อกำหนด
- **MUST** แสดงข้อความอธิบายควบคู่กับไอคอนสถานะเสมอ เพื่อรองรับผู้ใช้ที่มีความบกพร่องในการแยกแยะสี
- **MUST** ซ่อนตัวไอคอนตกแต่งจากโปรแกรมอ่านหน้าจอด้วย `aria-hidden="true"` เมื่อมีข้อความอธิบายอยู่แล้ว เพื่อป้องกันการอ่านซ้ำซ้อน
- **MUST** เชื่อมโยงข้อความสถานะเข้ากับช่องกรอกข้อมูลหรือพื้นที่ที่เกี่ยวข้องเชิงโค้ด

### แนวทางการนำไปใช้งาน

```html
<!-- ข้อความแจ้งเตือนข้อผิดพลาดพร้อมไอคอน -->
<div class="flex items-center gap-2 text-destructive text-sm mt-1" role="alert">
  <svg aria-hidden="true" class="size-4 shrink-0 fill-current">...</svg>
  <span>กรุณากรอกรหัสผ่านอย่างน้อย 8 ตัวอักษร</span>
</div>
```

**การตรวจสอบความถูกต้อง:** แม้จะปิดการแสดงผลสีหรือไอคอน ข้อความเตือนยังคงสื่อความหมายได้อย่างสมบูรณ์

---

## ICON-08 — พื้นที่การกดและสถานะการโต้ตอบของปุ่มไอคอน

**หลักการ:** ปุ่มไอคอนต้องมีพื้นที่การกดที่กว้างพอสำหรับนิ้วมือ และแสดงสถานะเมื่อชี้เมาส์หรือได้รับโฟกัสอย่างชัดเจน

### ข้อกำหนด
- **MUST** กำหนดขนาดพื้นที่สัมผัสของปุ่มไอคอนอย่างน้อย 44 x 44 พิกเซลสำหรับอุปกรณ์หน้าจอสัมผัส แม้ตัวไอคอนจะมีขนาดเพียง 20 พิกเซล
- **MUST** แสดงสถานะเมื่อชี้เมาส์และเมื่อได้รับโฟกัสคลุมทั้งพื้นที่ของปุ่ม
- **MUST** สำหรับปุ่มสลับสถานะ ต้องสะท้อนสถานะจริงผ่านแอตทริบิวต์ `aria-pressed`

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | พื้นที่กดมาตรฐานพร้อมสถานะ | `size-11 grid place-items-center rounded-lg hover:bg-muted focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ring` |
| **Raw CSS** | ขนาดพื้นที่สัมผัส | `min-width: 44px; min-height: 44px; display: grid; place-items: center; border-radius: 0.5rem;` |

**การตรวจสอบความถูกต้อง:** สามารถใช้นิ้วแตะปุ่มไอคอนได้ง่าย และมีกรอบโฟกัสแสดงชัดเจนเมื่อใช้คีย์บอร์ด
