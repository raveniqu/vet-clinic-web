# กฎ UX ด้านการใช้งานและการตอบสนองต่อผู้ใช้

> **ขอบเขต:** ใช้กฎเหล่านี้กับพฤติกรรมการโต้ตอบ การออกแบบเพื่อการสัมผัส การนำทาง การควบคุมการป้อนข้อมูล และการตอบสนองสถานะ
> **ข้อกำหนดส่วนกลาง:** ปฏิบัติตามเกณฑ์ระดับคำสั่ง ลำดับความสำคัญ และขั้นตอนการทำงานใน global.md

---

## USAB-01 — ช่องกรอกข้อมูลต้องมีป้ายกำกับที่มองเห็นได้ชัดเจนเสมอ

**หลักการ:** ผู้ใช้ต้องเข้าใจหน้าที่ของช่องกรอกข้อมูลได้ทันที และยังคงตรวจสอบได้แม้เริ่มพิมพ์ข้อความแล้ว

### ข้อกำหนด
- **MUST** มีป้ายกำกับที่มองเห็นได้ชัดเจนและคงอยู่ตลอดเวลาสำหรับทุกช่องกรอกข้อมูล
- **MUST** เชื่อมโยงป้ายกำกับกับช่องกรอกข้อมูลผ่านแอตทริบิวต์ `for` และ `id`
- **MUST** ทำให้การคลิกที่ป้ายกำกับสามารถย้ายโฟกัสไปยังช่องกรอกข้อมูลนั้นได้
- **MUST NOT** พึ่งพาเพียงตำแหน่งทางสายตาเพื่อบอกว่าป้ายกำกับเป็นของช่องใด

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | บล็อกป้ายกำกับและช่องกรอก | `flex flex-col gap-1.5 min-h-11 focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ring` |
| **Raw CSS** | กำหนดขนาดและระยะขอบ | `display: block; margin-bottom: 0.375rem; min-height: 2.75rem;` |
| **HTML และ A11y** | เชื่อมโยง Label กับ Input | `<label for="full-name">ชื่อจริง</label><input id="full-name">` |

**การตรวจสอบความถูกต้อง:** คลิกที่ป้ายกำกับแล้วเคอร์เซอร์เลื่อนไปอยู่ที่ช่องกรอกข้อมูลทันที

## USAB-02 — แสดงสถานะของระบบให้มองเห็นได้ชัดเจน

**หลักการ:** ผู้ใช้ต้องทราบสถานะปัจจุบันของระบบเสมอ โดยเฉพาะเมื่อมีการกรองข้อมูลหรือเลือกมุมมองที่เปลี่ยนไปจากค่าเริ่มต้น

### ข้อกำหนด
- **MUST** สื่อสารให้ชัดเจนเมื่อหน้าจออยู่ในสถานะที่ผ่านการกรองข้อมูล เช่น แสดงตัวนับตัวกรองที่ใช้งานอยู่
- **MUST** อัปเดตตัวเลขและข้อความสถานะให้ตรงกับข้อมูลจริงในระบบเมื่อมีการเพิ่มหรือล้างตัวกรอง
- **SHOULD** ใช้ข้อความที่ชัดเจน เช่น ตัวกรอง (3 รายการ) แทนการใช้เพียงจุดสี
- **SHOULD** มีปุ่มล้างตัวกรองทั้งหมดที่สังเกตเห็นและกดใช้งานได้ง่าย
- **MUST NOT** ปล่อยให้ผลลัพธ์ที่ผ่านการกรองดูเหมือนกับผลลัพธ์ทั้งหมดโดยไม่มีจุดบ่งชี้

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | แสดง Badge สถานะพร้อมข้อความ | `inline-flex items-center gap-2 rounded-full bg-primary/10 px-3 py-1 text-primary` |
| **Raw CSS** | Indicator badge | `display: inline-flex; align-items: center; gap: 0.5rem; border-radius: 9999px;` |

**การตรวจสอบความถูกต้อง:** เมื่อกดใช้ตัวกรอง หน้าจอจะระบุจำนวนตัวกรองที่ทำงานอยู่ และมีปุ่มล้างตัวกรองแสดงให้เห็น

## USAB-03 — องค์ประกอบที่โต้ตอบได้ต้องมีจุดสังเกตชัดเจน

**หลักการ:** ผู้ใช้ต้องแยกแยะได้ทันทีว่าส่วนใดกดได้หรือกดไม่ได้ตั้งแต่ก่อนที่จะเริ่มมีปฏิสัมพันธ์

### ข้อกำหนด
- **MUST** แสดงจุดสังเกตของปุ่ม ลิงก์ ช่องเลือก และปุ่มอัปโหลดให้มองเห็นได้ชัดเจน
- **SHOULD** ขีดเส้นใต้ลิงก์ที่ฝังอยู่ในเนื้อหาข้อความ ไม่ใช้ความต่างของสีเพียงอย่างเดียว
- **MUST** มีสถานะเมื่อชี้เมาส์และเมื่อได้รับโฟกัสจากคีย์บอร์ดที่มองเห็นได้ชัดเจน
- **MUST NOT** จัดสไตล์ข้อความธรรมดาให้ดูเหมือนปุ่ม หรือใช้เคอร์เซอร์แบบรูปมือกับสิ่งที่ไม่สามารถกดได้

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | จุดสังเกตชัดเจนและสถานะโฟกัส | `underline underline-offset-4 hover:text-primary focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ring` |
| **Raw CSS** | Text decoration และ Hover/Focus | `text-decoration: underline; text-underline-offset: 4px; cursor: pointer;` |

**การตรวจสอบความถูกต้อง:** มองแวบแรกสามารถแยกแยะได้ว่าข้อความใดเป็นลิงก์และส่วนใดเป็นปุ่มกด

## USAB-04 — เมนูต้องสื่อความหมายและมีพื้นที่กดขนาดใหญ่

**หลักการ:** รายการเมนูควรมีคำอธิบายประกอบเมื่อจำเป็น และทั้งแถวต้องสามารถกดได้ ไม่ใช่กดได้เฉพาะตัวหนังสือเล็กๆ

### ข้อกำหนด
- **SHOULD** กำหนดหัวข้อที่ชัดเจนให้แต่ละรายการเมนู และใส่คำอธิบายสั้นๆ เสริมหากมีประโยชน์
- **MUST** ทำให้พื้นที่ทั้งแถวของรายการเมนูสามารถกดได้ รวมถึงไอคอน หัวข้อ และคำอธิบาย
- **MUST** แสดงการตอบสนองเมื่อชี้เมาส์หรือได้รับโฟกัสครอบคลุมทั้งแถว
- **AVOID** การใส่ไอคอนที่ไม่สื่อความหมายลงในทุกรายการเพียงเพื่อการตกแต่ง

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | แถวเมนูกดได้ทั้งแถว | `flex items-start gap-3 rounded-lg p-3 hover:bg-muted focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ring` |
| **Raw CSS** | Full-row clickable area | `display: flex; gap: 0.75rem; padding: 0.75rem; border-radius: 0.5rem;` |

**การตรวจสอบความถูกต้อง:** เลื่อนเมาส์ไปชี้ที่ส่วนใดของแถวเมนูก็จะแสดงสถานะพร้อมกด และคลิกติดได้ทั้งแถว

## USAB-05 — มีปุ่มล้างข้อความในช่องค้นหาที่มีข้อมูล

**หลักการ:** เมื่อพิมพ์คำค้นหาแล้ว ผู้ใช้ควรสามารถล้างคำค้นหาทั้งหมดเพื่อเริ่มค้นหาใหม่ได้ด้วยการคลิกเพียงครั้งเดียว

### ข้อกำหนด
- **MUST** แสดงปุ่มกากบาทสำหรับล้างข้อความเมื่อมีข้อความในช่องค้นหา
- **MUST** ทำให้ปุ่มล้างข้อความล้างค่าในช่องและรีเซ็ตผลการค้นหาจริง
- **MUST** กำหนดชื่อกำกับการเข้าถึง เช่น ล้างคำค้นหา ให้กับปุ่มกากบาท
- **SHOULD** คืนโฟกัสกลับไปที่ช่องค้นหาทันทีหลังกดล้างข้อความ เพื่อให้พิมพ์ต่อได้สะดวก

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | วางปุ่มล้างด้านขวาของช่อง | คอนเทนเนอร์: `relative`; ช่องกรอก: `pr-10`; ปุ่ม: `absolute right-2 top-1/2 -translate-y-1/2 size-8` |
| **JavaScript** | ล้างค่าและคืนโฟกัส | `clearBtn.addEventListener('click', () => { input.value = ''; input.focus(); });` |

**การตรวจสอบความถูกต้อง:** เมื่อมีข้อความในช่องค้นหา ปุ่มล้างจะปรากฏขึ้น และเมื่อกดแล้วช่องจะว่างเปล่าพร้อมรับการพิมพ์ใหม่ทันที

## USAB-06 — ค่าของแถบเลื่อนต้องมองเห็นได้เหนือตำแหน่งนิ้วสัมผัส

**หลักการ:** บนหน้าจอสัมผัส นิ้วมือของผู้ใช้จะบดบังตำแหน่งตัวเลื่อน การแสดงตัวเลขค่าที่เลือกไว้เหนือแถบเลื่อนช่วยให้อ่านค่าได้ชัดเจนขณะลาก

### ข้อกำหนด
- **MUST** แสดงตัวเลขของค่าที่กำลังเลือกในตำแหน่งที่ไม่ถูกนิ้วมือบดบัง โดยตำแหน่งด้านบนของแถบเลื่อนเป็นจุดที่ปลอดภัยที่สุด
- **SHOULD** มีช่องกรอกตัวเลขโดยตรงควบคู่ไปด้วย หากผู้ใช้ต้องการความแม่นยำสูง
- **MUST NOT** วางตัวเลขบอกค่าไว้ใต้แถบเลื่อนหรือจุดที่นิ้วสัมผัสจะบังตัวเลข

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | วางกล่องข้อความค่าด้านบน | `flex flex-col gap-2 relative` พร้อมกล่องบอกค่าอยู่ด้านบนแถบเลื่อน |
| **Raw CSS** | Relative layout | จัดตำแหน่งตัวเลขค่าไว้เหนือ `<input type="range">` |

**การตรวจสอบความถูกต้อง:** เมื่อใช้นิ้วลากแถบเลื่อนบนหน้าจอมือถือ สามารถมองเห็นตัวเลขที่เปลี่ยนไปได้ตลอดเวลา

## USAB-07 — แสดงตัวเลือกจำนวนไม่มากให้เห็นและกดได้โดยตรง

**หลักการ:** หากมีตัวเลือกเพียงสองถึงห้ารายการ การแสดงเป็นปุ่มหรือการ์ดให้เห็นทั้งหมดช่วยให้ตัดสินใจได้เร็วกว่าการซ่อนไว้ในเมนูดรอปดาวน์

### ข้อกำหนด
- **SHOULD** แสดงตัวเลือกจำนวนไม่มากในรูปแบบ Radio cards, ปุ่มสลับ หรือเช็กบ็อกซ์ที่มองเห็นได้ทันที
- **MUST** ใช้รูปแบบการเลือกที่ถูกต้อง: Radio สำหรับเลือกได้เพียงหนึ่ง และ Checkbox สำหรับเลือกได้หลายรายการ
- **MUST** ทำให้สถานะถูกเลือกและยังไม่ถูกเลือกมีความแตกต่างกันชัดเจน
- **MUST NOT** แตกตัวเลือกที่มีจำนวนมากนับสิบรายการออกมาจนเต็มหน้าจอโดยไม่จำเป็น

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | Grid การ์ดตัวเลือก | `grid grid-cols-2 gap-3 sm:grid-cols-3` พร้อมสถานะ `peer-checked:border-primary peer-checked:bg-primary/5` |
| **Raw CSS** | Choice cards | ใช้โครงสร้าง `<label>` ครอบ `<input type="radio">` และจัดสไตล์การ์ด |

**การตรวจสอบความถูกต้อง:** ตัวเลือกแสดงให้เห็นครบถ้วน สามารถกดเลือกได้ในคลิกเดียวโดยไม่ต้องเปิดดรอปดาวน์

## USAB-08 — ขยายพื้นที่สัมผัสให้กดได้สะดวก

**หลักการ:** องค์ประกอบขนาดเล็ก เช่น เช็กบ็อกซ์ สวิตช์ หรือไอคอน ควรมีพื้นที่กดที่กว้างพอสำหรับนิ้วมือ เพื่อลดความผิดพลาดในการกด

### ข้อกำหนด
- **MUST** ขยายพื้นที่เป้าหมายการกดให้มีขนาดเพียงพอ โดยเฉพาะบนอุปกรณ์หน้าจอสัมผัส
- **MUST** ให้การคลิกที่ป้ายกำกับหรือแถวรอบเช็กบ็อกซ์สามารถสลับค่าได้ด้วย
- **SHOULD** กำหนดขนาดพื้นที่สัมผัสอย่างน้อยประมาณ 44 x 44 พิกเซลสำหรับปุ่มบนมือถือ
- **MUST** เว้นระยะห่างระหว่างปุ่มที่อยู่ใกล้กัน เพื่อไม่ให้กดผิดปุ่ม

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | กำหนดขนาดขั้นต่ำ | `min-h-11 min-w-11 inline-flex items-center justify-center p-2` |
| **Raw CSS** | Min dimensions | `min-height: 44px; min-width: 44px; display: inline-flex; align-items: center;` |

**การตรวจสอบความถูกต้อง:** สามารถใช้นิ้วแตะโดนปุ่มหรือเช็กบ็อกซ์ได้อย่างง่ายดายบนหน้าจอมือถือ

## USAB-09 — มีตัวเลือกสำเร็จรูปสำหรับค่าที่ใช้งานบ่อย

**หลักการ:** การเตรียมปุ่มลัดสำหรับค่าที่ผู้ใช้มักเลือกบ่อย เช่น ช่วงเวลา ยอดเงิน หรือวันที่ ช่วยประหยัดเวลาและลดภาระในการพิมพ์

### ข้อกำหนด
- **SHOULD** มีปุ่มตัวเลือกสำเร็จรูปสำหรับค่าที่ใช้บ่อย เช่น เช้า บ่าย เย็น หรือยอดเงิน 100, 500, 1000 บาท
- **MUST** แสดงค่าที่เลือกลงในช่องกรอกข้อมูล และเปิดโอกาสให้ผู้ใช้แก้ไขเพิ่มเติมได้เองเสมอ
- **MUST NOT** ส่งข้อมูลหรือทำรายการทันทีเพียงเพราะผู้ใช้กดเลือกค่าสำเร็จรูป

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | แถวปุ่มลัดสำเร็จรูป | `flex flex-wrap gap-2` พร้อมปุ่มแบบ `rounded-full border border-border px-3 py-1 text-sm hover:bg-muted` |
| **Raw CSS** | Quick choice chips | `display: flex; flex-wrap: wrap; gap: 0.5rem;` |

**การตรวจสอบความถูกต้อง:** กดปุ่มสำเร็จรูปแล้วค่านั้นจะถูกกรอกลงในช่อง และผู้ใช้สามารถแก้ไขตัวเลขเองได้

## USAB-10 — เลือกชนิดของ Input ให้ตรงกับข้อมูล

**หลักการ:** การเลือกชนิดของ Input ที่ถูกต้องทำให้เบราว์เซอร์และคีย์บอร์ดบนมือถือแสดงแป้นพิมพ์ที่เหมาะสมต่อการป้อนข้อมูล

### ข้อกำหนด
- **MUST** เลือกชนิดของ Input ให้ตรงกับประเภทข้อมูล เช่น email, tel, password, search, date
- **SHOULD** ใช้แอตทริบิวต์ `inputmode="numeric"` สำหรับรหัสตัวเลขที่ไม่ใช่จำนวนทางคณิตศาสตร์ เช่น เลขบัตรประชาชน หรือรหัสยืนยัน
- **MUST NOT** ใช้ `type="number"` กับตัวเลขที่มีเลขศูนย์นำหน้า เช่น รหัสไปรษณีย์ หรือเบอร์โทรศัพท์

### ชนิดของข้อมูลและแอตทริบิวต์
| ข้อมูล | แอตทริบิวต์ที่ถูกต้อง |
| :--- | :--- |
| **อีเมล** | `type="email"` |
| **เบอร์โทรศัพท์** | `type="tel"` |
| **รหัสผ่าน** | `type="password"` |
| **รหัสยืนยันตัวเลข** | `type="text" inputmode="numeric"` |
| **วันที่และเวลา** | `type="datetime-local"` |

**การตรวจสอบความถูกต้อง:** เมื่อแตะช่องกรอกข้อมูลบนมือถือ คีย์บอร์ดที่เปิดขึ้นมาตรงกับชนิดข้อมูล เช่น แสดงแป้นตัวเลขสำหรับเบอร์โทร

## USAB-11 — วางปุ่มสลับการมองเห็นรหัสผ่านแยกจากช่องกรอก

**หลักการ:** การวางปุ่มรูปลูกตาซ้อนทับอยู่ภายในช่องกรอกรหัสผ่านอาจขัดแย้งกับไอคอนของตัวจัดการรหัสผ่านของระบบ

### ข้อกำหนด
- **MUST NOT** วางปุ่มเปิดปิดรหัสผ่านซ้อนทับลงบนช่องกรอกด้วยการจัดตำแหน่งแบบ Absolute
- **MUST** วางปุ่มเปิดปิดรหัสผ่านเป็นกล่องที่อยู่ข้างเคียงกัน แต่อยู่ภายในกรอบเดียวกันทางสายตา
- **MUST** ใช้ปุ่ม `<button type="button">` พร้อมชื่อกำกับการเข้าถึงที่บอกสถานะชัดเจน เช่น แสดงรหัสผ่าน หรือซ่อนรหัสผ่าน
- **MUST** ซ่อนรหัสผ่านเป็นค่าเริ่มต้น และคงค่าที่พิมพ์ไว้เดิมเมื่อกดสลับการมองเห็น

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | Flexbox กรอบร่วม | กรอบนอก: `flex rounded-lg border border-input focus-within:ring-2 focus-within:ring-ring focus-within:outline-hidden`; ช่องกรอก: `flex-1 border-0 bg-transparent`; ปุ่ม: `px-3 border-l border-input` |
| **Raw CSS** | Password group | `.password-group { display: flex; border: 1px solid #cbd5e1; border-radius: 0.5rem; }` |

**การตรวจสอบความถูกต้อง:** ปุ่มเปิดปิดรหัสผ่านไม่ทับซ้อนกับไอคอนของเบราว์เซอร์ และสามารถกดสลับได้สะดวก

## USAB-12 — ขยายพื้นที่ลากโดยไม่ต้องขยายขนาดไอคอน

**หลักการ:** จุดจับสำหรับลากปรับขนาดหรือสลับตำแหน่งควรลากได้ง่าย แต่ตัวไอคอนไม่ควรใหญ่จนเกะกะสายตา

### ข้อกำหนด
- **MUST** ทำให้จุดจับสำหรับลากปรับขนาดหรือเลื่อนลำดับสามารถแตะและลากได้ง่าย
- **SHOULD** ขยายพื้นที่สัมผัสที่มองไม่เห็นรอบตัวไอคอน แทนการขยายขนาดรูปไอคอนให้ใหญ่เกินไป
- **MUST** เชื่อมโยงเหตุการณ์การลากเข้ากับพื้นที่สัมผัสที่ขยายนั้นอย่างแท้จริง
- **MUST** มีทางเลือกในการใช้งานด้วยคีย์บอร์ดควบคู่ไปด้วยเสมอสำหรับผู้ที่ไม่สะดวกใช้เมาส์ลาก

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | ขยาย Padding รอบไอคอน | `relative p-3 min-h-11 min-w-11 inline-flex items-center justify-center` |
| **Raw CSS** | Hit area wrapper | `display: inline-flex; padding: 0.75rem; min-width: 44px; min-height: 44px;` |

**การตรวจสอบความถูกต้อง:** สามารถใช้นิ้วแตะเพื่อเริ่มลากจุดจับได้ง่ายโดยไม่ต้องเล็งอย่างแม่นยำ

## USAB-13 — แถบนำทางบนเดสก์ท็อปต้องเปิดเผยและเข้าถึงได้ทันที

**หลักการ:** หน้าจอเดสก์ท็อปมีพื้นที่กว้างขวาง การซ่อนเมนูหลักไว้หลังไอคอนแฮมเบอร์เกอร์ทำให้ผู้ใช้มองไม่เห็นตัวเลือกและใช้งานช้าลง

### ข้อกำหนด
- **MUST NOT** ซ่อนเมนูนำทางหลักบนเดสก์ท็อปไว้หลังเมนูแฮมเบอร์เกอร์ หากหน้าจอยังมีพื้นที่เพียงพอ
- **SHOULD** แสดงลิงก์นำทางหลักให้เห็นทันทีบนแถบด้านบนหรือแถบด้านข้างบนหน้าจอเดสก์ท็อป
- **MAY** พับเมนูเป็นแฮมเบอร์เกอร์ได้เฉพาะบนหน้าจอขนาดกะทัดรัด เช่น บนมือถือ

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | สลับตามขนาดหน้าจอ | เมนูเต็ม: `hidden md:flex items-center gap-6`; ปุ่มมือถือ: `md:hidden` |
| **Raw CSS** | Media query | ซ่อนปุ่มเปิดเมนูในหน้าจอกว้าง และแสดงแถบลิงก์นำทางเต็มรูปแบบ |

**การตรวจสอบความถูกต้อง:** บนหน้าจอคอมพิวเตอร์ เมนูหลักจะปรากฏให้เห็นทันทีโดยไม่ต้องคลิกเปิดเมนูใดๆ

## USAB-14 — หลีกเลี่ยงการใส่ฟอร์มที่ซับซ้อนในกล่องข้อความป๊อปอัป

**หลักการ:** แบบฟอร์มขนาดยาวที่มีหลายขั้นตอน ไม่เหมาะที่จะอยู่ในกล่องข้อความป๊อปอัป เพราะเสี่ยงต่อการปิดโดยไม่ตั้งใจจนข้อมูลสูญหาย

### ข้อกำหนด
- **SHOULD** วางแบบฟอร์มที่มีความยาว หลายขั้นตอน หรือมีความสำคัญสูง ไว้ในหน้าเฉพาะ แทนการใช้กล่องข้อความป๊อปอัป
- **MUST** คำนึงถึงการป้องกันข้อมูลสูญหาย หากผู้ใช้เผลอกดปิดกล่องข้อความที่มีการกรอกข้อมูลค้างไว้
- **MAY** ใช้กล่องข้อความป๊อปอัปได้เฉพาะงานสั้นๆ ที่มีเพียงไม่กี่ช่องกรอก

### แนวทางการนำไปใช้งาน
| ลักษณะงาน | รูปแบบหน้าที่เหมาะสม |
| :--- | :--- |
| **ฟอร์มยาว / หลายขั้นตอน** | หน้าเพจเฉพาะ หรือขั้นตอนแบบเต็มหน้าจอ |
| **การยืนยันสั้นๆ / กรอก 1-2 ช่อง** | กล่องข้อความป๊อปอัป |

**การตรวจสอบความถูกต้อง:** ฟอร์มที่มีความสำคัญไม่มีปัญหาการเลื่อนหน้าจอซ้อนกัน และไม่สูญเสียข้อมูลจากการกดปิดพลาด

## USAB-15 — ห้ามเปิดกล่องข้อความป๊อปอัปซ้อนกันหลายชั้น

**หลักการ:** การเปิดป๊อปอัปขึ้นมาทับบนป๊อปอัปอีกชั้นหนึ่ง สร้างความสับสนเรื่องลำดับชั้น และทำให้การจัดการโฟกัสคีย์บอร์ดผิดพลาดได้ง่าย

### ข้อกำหนด
- **MUST NOT** เปิดกล่องข้อความป๊อปอัปใหม่ขึ้นมาซ้อนทับบนกล่องข้อความเดิมในขั้นตอนการทำงานปกติ
- **SHOULD** เปลี่ยนเนื้อหาภายในกล่องข้อความเดิมตามขั้นตอน หรือปิดกล่องข้อความแรกก่อนเปิดกล่องข้อความถัดไป
- **MUST** จัดการการย้อนกลับและการคืนโฟกัสของคีย์บอร์ดให้ถูกต้องเมื่อจบขั้นตอน

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ |
| :--- | :--- |
| **การจัดการสถานะ** | ควบคุมผ่านตัวแปรสถานะขั้นตอนเดียว แทนการซ้อนคอมโพเนนต์ Dialog หลายตัว |
| **A11y** | รักษา Focus trap ให้อยู่ในหน้าต่างเดียวที่กำลังทำงานอยู่ |

**การตรวจสอบความถูกต้อง:** ในทุกช่วงเวลา หน้าจอจะมีกล่องข้อความที่เปิดใช้งานอยู่เพียงชั้นเดียวเสมอ

## USAB-16 — วางตัวเลือกที่ใช้บ่อยไว้ในลำดับแรกๆ

**หลักการ:** การจัดลำดับตัวเลือกที่ผู้ใช้มักเลือกบ่อยที่สุดไว้ด้านบน ช่วยประหยัดเวลาในการค้นหา

### ข้อกำหนด
- **SHOULD** วางตัวเลือกยอดนิยม ตัวเลือกที่เพิ่งใช้ หรือตัวเลือกที่เกี่ยวข้องกับบริบท ไว้ที่ส่วนต้นของรายการ
- **SHOULD** ยังคงมีตัวเลือกอื่นๆ ให้เข้าถึงได้ตามปกติ ไม่ตัดตัวเลือกอื่นทิ้ง
- **MUST** จัดลำดับข้อมูลในโครงสร้าง DOM จริงให้ตรงกับลำดับที่มองเห็น เพื่อให้โปรแกรมอ่านหน้าจออ่านได้ถูกต้อง
- **MUST NOT** สลับเฉพาะการแสดงผลด้วย CSS `order` จนขัดแย้งกับลำดับการกด Tab

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **การจัดการข้อมูล** | เรียงลำดับ Array ข้อมูลก่อนเรนเดอร์ | นำรายการยอดนิยมขึ้นต้นข้อมูล แล้วตามด้วยรายการที่เรียงตามตัวอักษร |
| **Tailwind CSS** | แสดงรายการตามลำดับ | `flex flex-col gap-2` เรนเดอร์ตามลำดับ DOM จริง |

**การตรวจสอบความถูกต้อง:** ลำดับการกด Tab ผ่านคีย์บอร์ดตรงกับลำดับตัวเลือกที่มองเห็นบนหน้าจอ

## USAB-17 — แจ้งเตือนเมื่อมีการเปิดใช้งาน Caps Lock ในช่องรหัสผ่าน

**หลักการ:** การเปิดปุ่ม Caps Lock ค้างไว้อาจทำให้พิมพ์รหัสผ่านผิดซ้ำๆ โดยไม่รู้ตัว การแจ้งเตือนทันทีช่วยลดความหงุดหงิดของผู้ใช้

### ข้อกำหนด
- **SHOULD** แสดงข้อความแจ้งเตือนที่มองเห็นได้ชัดเจนติดกับช่องรหัสผ่าน เมื่อตรวจพบว่า Caps Lock กำลังเปิดอยู่
- **MUST** ใช้ข้อความอธิบายคู่กับไอคอน ไม่ใช้เพียงสีส้มหรือสีเตือนอย่างเดียว
- **MUST** ซ่อนข้อความแจ้งเตือนทันทีเมื่อปิด Caps Lock หรือออกจากช่องรหัสผ่าน
- **MUST NOT** คาดเดาจากตัวพิมพ์ใหญ่ ให้ตรวจจับจากสถานะคีย์บอร์ดจริงของเบราว์เซอร์

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | กล่องข้อความแจ้งเตือน | `<p id="caps-warning" role="status" class="text-sm text-amber-600 dark:text-amber-400 mt-1">...</p>` |
| **JavaScript** | ตรวจสอบ Modifier state | `input.addEventListener('keyup', (e) => { warning.textContent = e.getModifierState('CapsLock') ? 'ปุ่ม Caps Lock กำลังเปิดอยู่' : ''; });` |

**การตรวจสอบความถูกต้อง:** เมื่อเปิด Caps Lock แล้วพิมพ์ในช่องรหัสผ่าน ข้อความแจ้งเตือนจะปรากฏขึ้นทันที

## รายการตรวจสอบก่อนส่งมอบงาน

- [ ] **USAB-01:** ทุกช่องกรอกข้อมูลมีป้ายกำกับที่คลิกเพื่อโฟกัสได้
- [ ] **USAB-02:** มีการแสดงสถานะตัวกรองที่ชัดเจนและมีปุ่มล้างตัวกรอง
- [ ] **USAB-03:** องค์ประกอบที่กดได้มีจุดสังเกตและสถานะโฟกัสชัดเจน
- [ ] **USAB-04:** เมนูมีพื้นที่กดครอบคลุมทั้งแถวและข้อความสื่อความหมาย
- [ ] **USAB-05:** ช่องค้นหาที่มีข้อความมีปุ่มล้างที่ทำงานได้จริง
- [ ] **USAB-06:** ตัวเลขค่าของแถบเลื่อนมองเห็นได้เหนือตำแหน่งนิ้วสัมผัส
- [ ] **USAB-07:** ตัวเลือกจำนวนไม่มากแสดงเป็นปุ่มหรือการ์ดให้เห็นโดยตรง
- [ ] **USAB-08:** พื้นที่สัมผัสของปุ่มมีขนาดอย่างน้อย 44 x 44 พิกเซลบนมือถือ
- [ ] **USAB-09:** มีตัวเลือกสำเร็จรูปสำหรับค่าที่ใช้งานบ่อยและแก้ไขได้
- [ ] **USAB-10:** กำหนดชนิดของ Input ตรงกับชนิดข้อมูลเพื่อเรียกคีย์บอร์ดที่ถูกต้อง
- [ ] **USAB-11:** ปุ่มเปิดปิดรหัสผ่านวางแยกจากช่องกรอกและไม่ทับซ้อนไอคอนระบบ
- [ ] **USAB-12:** จุดจับสำหรับลากมีพื้นที่สัมผัสกว้างและมีทางเลือกคีย์บอร์ด
- [ ] **USAB-13:** เมนูหลักบนเดสก์ท็อปเปิดเผยให้เห็นโดยไม่ซ่อนหลังแฮมเบอร์เกอร์
- [ ] **USAB-14:** ฟอร์มขนาดยาวหรือซับซ้อนไม่อยู่ในกล่องข้อความป๊อปอัป
- [ ] **USAB-15:** ไม่มีการเปิดกล่องข้อความป๊อปอัปซ้อนกันหลายชั้น
- [ ] **USAB-16:** ตัวเลือกที่ใช้บ่อยวางไว้ลำดับแรกๆ โดยเรียงลำดับ DOM ถูกต้อง
- [ ] **USAB-17:** มีการแจ้งเตือนเมื่อเปิดปุ่ม Caps Lock ขณะกรอกรหัสผ่าน
