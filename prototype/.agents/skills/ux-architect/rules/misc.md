# กฎ UX ด้านปฏิสัมพันธ์เบ็ดเตล็ดและการออกแบบเชิงลึก

> **ขอบเขต:** ใช้กฎเหล่านี้กับระบบคะแนนรีวิว รหัสยืนยัน การเคลื่อนไหว ไฟล์ภาพ แผนที่ การยินยอมเงื่อนไข การกู้คืนข้อมูล หน้าจอว่างเปล่า และหน้าแจ้งข้อผิดพลาด
> **ข้อกำหนดส่วนกลาง:** ปฏิบัติตามเกณฑ์ระดับคำสั่ง ลำดับความสำคัญ และขั้นตอนการทำงานใน global.md

## MISC-01 — แสดงวันที่เผยแพร่หรือวันที่อัปเดตบทความ

**หลักการ:** วันที่ช่วยให้ผู้ใช้ประเมินความสดใหม่และความน่าเชื่อถือของเนื้อหา โดยเฉพาะเนื้อหาด้านเทคนิคหรือข่าวสารที่เปลี่ยนแปลงเร็ว

### ข้อกำหนด
- **MUST** แสดงวันที่ที่ช่วยประเมินความทันสมัยของบทความในตำแหน่งที่สังเกตเห็นได้ง่าย
- **SHOULD** แสดงทั้งวันที่เผยแพร่และวันที่แก้ไขล่าสุด หากข้อมูลทั้งสองมีความแตกต่างที่มีนัยสำคัญ
- **MUST NOT** ปลอมแปลงวันที่หรือแสดงว่าอัปเดตแล้วโดยไม่มีการแก้ไขเนื้อหาจริง
- **MUST** ใช้แท็กเชิงความหมาย `<time>` พร้อมแอตทริบิวต์ `datetime` ที่ระบุรูปแบบวันที่มาตรฐาน

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **HTML และ A11y** | แท็ก Time เชิงความหมาย | `<time datetime="2026-10-09">9 ตุลาคม 2026</time>` |
| **Tailwind CSS** | จัดแถวข้อมูลเสริม | `flex items-center gap-2 text-sm text-muted-foreground` |
| **Raw CSS** | Metadata styling | `display: flex; gap: 0.5rem; font-size: 0.875rem; color: #64748b;` |

**การตรวจสอบความถูกต้อง:** ผู้อ่านสามารถแยกแยะวันที่เผยแพร่และวันที่อัปเดตได้อย่างชัดเจน

## MISC-02 — ยกระดับระบบแสดงคะแนนรีวิว

**หลักการ:** ค่าเฉลี่ยและรูปดาวเพียงอย่างเดียวไม่เพียงพอต่อการตัดสินใจ การแสดงจำนวนผู้รีวิวทั้งหมดและสัดส่วนคะแนนช่วยสร้างความน่าเชื่อถือ

### ข้อกำหนด
- **MUST** แสดงจำนวนผู้รีวิวทั้งหมดควบคู่กับคะแนนเฉลี่ยเสมอ
- **SHOULD** แสดงแถบการกระจายตัวของคะแนนตั้งแต่ 5 ดาวถึง 1 ดาว พร้อมจำนวนหรือสัดส่วนของแต่ละระดับ
- **SHOULD** อนุญาตให้คลิกที่แต่ละระดับดาวเพื่อกรองดูเฉพาะรีวิวในกลุ่มนั้นได้
- **MUST** นำข้อมูลคะแนนและสัดส่วนมาจากฐานข้อมูลจริง ห้ามสร้างภาพกราฟิกที่ไม่ตรงกับความจริง

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | แถบแสดงสัดส่วนคะแนน | แถบพื้น: `h-2 rounded-full bg-muted overflow-hidden`; แถบค่า: `h-full bg-amber-500` |
| **Raw CSS** | Progress bar styling | `height: 0.5rem; border-radius: 9999px; background-color: #e2e8f0;` |

**การตรวจสอบความถูกต้อง:** เมื่อคลิกที่ระดับคะแนน ระบบสามารถกรองรายการรีวิวได้ และโปรแกรมอ่านหน้าจออ่านตัวเลขได้ถูกต้อง

## MISC-03 — วางรหัสยืนยันตัวเลขให้อ่านได้ทันทีในการแจ้งเตือน

**หลักการ:** ผู้ใช้ควรมองเห็นรหัสยืนยันได้ทันทีจากข้อความแจ้งเตือนย่อบนหน้าจอมือถือ โดยไม่ต้องกดเปิดอ่านข้อความเต็ม

### ข้อกำหนด
- **MUST** วางรหัสยืนยันไว้ที่ช่วงต้นของข้อความแจ้งเตือนหรือข้อความสั้น
- **SHOULD** ใช้ข้อความสั้นกระชับ ระบุหน้าที่ของรหัส และไม่ซ่อนรหัสไว้หลังข้อความเกริ่นนำขนาดยาว
- **SHOULD** รองรับการกรอกอัตโนมัติบนหน้าเว็บด้วย `autocomplete="one-time-code"`

### แนวทางการนำไปใช้งาน
| รูปแบบ | ตัวอย่างข้อความ |
| :--- | :--- |
| **ข้อความสั้นที่ถูกต้อง** | `รหัสยืนยันของคุณคือ 123456 สำหรับเข้าสู่ระบบ` |
| **ข้อความที่ควรหลีกเลี่ยง** | `ยินดีต้อนรับสู่บริการ... ข้อความยาวมาก... รหัสของคุณคือ 123456` |

**การตรวจสอบความถูกต้อง:** สามารถอ่านรหัสยืนยันได้จากแถบแจ้งเตือนด้านบนของมือถือโดยไม่ต้องสลับแอป

## MISC-04 — เลือกระยะเวลาแอนิเมชันให้เหมาะสม

**หลักการ:** แอนิเมชันที่เร็วเกินไปทำให้มองไม่ทัน ส่วนที่ช้าเกินไปทำให้ผู้ใช้รู้สึกว่าระบบทำงานอืดอาด

### ข้อกำหนด
- **SHOULD** ใช้ระยะเวลา 100 ถึง 200 มิลลิวินาทีสำหรับแอนิเมชันขนาดเล็ก เช่น การชี้เมาส์ การกดปุ่ม หรือการเปิดเมนูสั้นๆ
- **SHOULD** ใช้ระยะเวลา 200 ถึง 300 มิลลิวินาทีสำหรับการเปลี่ยนผ่านขนาดใหญ่ เช่น การเปิดกล่องข้อความหรือแถบด้านข้าง
- **MUST** ปิดหรือลดทอนแอนิเมชันลงเมื่อตรวจพบว่าผู้ใช้เปิดโหมดลดการเคลื่อนไหว
- **SHOULD** เคลื่อนไหวเฉพาะคุณสมบัติ `transform` หรือ `opacity` เพื่อประสิทธิภาพในการเรนเดอร์

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | การเปลี่ยนผ่านที่นุ่มนวลและรองรับโหมดลดการเคลื่อนไหว | `transition duration-150 ease-out motion-reduce:transition-none` |
| **Raw CSS** | Transition พร้อม media query | `transition: transform 150ms ease-out;` พร้อม `@media (prefers-reduced-motion: reduce)` |

**การตรวจสอบความถูกต้อง:** แอนิเมชันตอบสนองฉับไว ไม่หน่วงการทำงาน และปิดได้อย่างสมบูรณ์ในโหมดลดการเคลื่อนไหว

## MISC-05 — เลือกใช้รูปแบบไฟล์ภาพที่ทันสมัย

**หลักการ:** ไฟล์ภาพยุคใหม่ช่วยลดขนาดข้อมูลลงอย่างมากโดยยังคงคุณภาพที่ดี ช่วยให้หน้าเว็บโหลดได้รวดเร็วขึ้น

### ข้อกำหนด
- **SHOULD** ส่งไฟล์ภาพในรูปแบบ WebP หรือ AVIF เมื่อเบราว์เซอร์รองรับ ควบคู่กับมีไฟล์สำรอง
- **MUST** กำหนดขนาดความกว้างและความสูงของภาพในโค้ด เพื่อป้องกันปัญหาเลย์เอาต์กระตุกขณะโหลด
- **MUST NOT** เลือกไฟล์ภาพโดยดูแต่ขนาดไฟล์ ต้องตรวจสอบความคมชัดของรายละเอียดและภาพที่มีพื้นหลังโปร่งใสด้วย

### แนวทางการนำไปใช้งาน

```html
<picture>
  <source srcset="/images/hero.avif" type="image/avif">
  <source srcset="/images/hero.webp" type="image/webp">
  <img src="/images/hero.jpg" alt="คำอธิบายภาพ" width="1200" height="675" loading="lazy" class="w-full h-auto">
</picture>
```

**การตรวจสอบความถูกต้อง:** ภาพโหลดได้รวดเร็ว คมชัด และไม่ทำให้เนื้อหาด้านล่างกระโดดเมื่อภาพโหลดเสร็จ

## MISC-06 — ใช้แผนที่ที่มีรายละเอียดเหมาะกับงาน

**หลักการ:** หากเป้าหมายคือการบอกตำแหน่งคร่าวๆ แผนที่แบบเรียบง่ายหรือภาพนิ่งโหลดได้เร็วกว่าแผนที่แบบโต้ตอบเต็มรูปแบบ

### ข้อกำหนด
- **SHOULD** ใช้ภาพแผนที่แบบคงที่หรือแผนที่อย่างง่าย เมื่อผู้ใช้ต้องการทราบเพียงตำแหน่งที่ตั้งโดยรวม
- **MUST NOT** ตัดทอนรายละเอียดจนทำให้อ่านชื่อถนนหรือจุดสังเกตสำคัญไม่ออก ในกรณีที่ผู้ใช้จำเป็นต้องนำทาง
- **SHOULD** หลีกเลี่ยงการโหลดแผนที่แบบโต้ตอบขนาดใหญ่ที่กินทรัพยากรสูง หากไม่จำเป็นต่อหน้าที่หลักของหน้านั้น

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **ภาพแผนที่คงที่** | ปรับขนาดและมุมมอง | `<img src="/map-preview.webp" alt="แผนที่ตั้งสาขา" class="w-full aspect-video rounded-lg object-cover">` |
| **ลิงก์เปิดแผนที่จริง** | ลิงก์ไปยังแอปแผนที่ | `<a href="https://maps.google.com/..." class="...">เปิดดูในแอปแผนที่</a>` |

**การตรวจสอบความถูกต้อง:** หน้าจอโหลดได้รวดเร็ว และผู้ใช้ยังคงเข้าถึงเส้นทางหรือแผนที่ละเอียดได้เมื่อต้องการ

## MISC-07 — ใส่ค่า Alt ว่างสำหรับภาพตกแต่ง

**หลักการ:** การใส่ `alt=""` เป็นการแจ้งให้โปรแกรมอ่านหน้าจอข้ามภาพตกแต่งไป ซึ่งแตกต่างจากการไม่ใส่แอตทริบิวต์ `alt` ที่จะทำให้โปรแกรมอ่านชื่อไฟล์ภาพออกมา

### ข้อกำหนด
- **MUST** ใส่ `alt=""` ให้กับภาพที่ใช้เพื่อการตกแต่งล้วนๆ และไม่ได้สื่อความหมายเพิ่มเติม
- **MUST** เขียนคำบรรยายใน `alt` สำหรับภาพที่เป็นเนื้อหา หรือภาพที่ทำหน้าที่เป็นปุ่มกด
- **MUST NOT** ละเว้นการใส่แอตทริบิวต์ `alt` เพราะจะทำให้โปรแกรมอ่านหน้าจออ่านชื่อไฟล์ที่ฟังไม่รู้เรื่อง

### แนวทางการนำไปใช้งาน
| บทบาทของภาพ | โค้ด HTML ที่ถูกต้อง |
| :--- | :--- |
| **ภาพตกแต่งลวดลาย** | `<img src="/pattern.svg" alt="" aria-hidden="true">` |
| **ภาพเนื้อหาสำคัญ** | `<img src="/chart.webp" alt="กราฟแสดงสถิติรายรับประจำปี">` |

**การตรวจสอบความถูกต้อง:** โปรแกรมอ่านหน้าจอไม่อ่านชื่อไฟล์ภาพตกแต่ง และอ่านคำบรรยายของภาพเนื้อหาได้ถูกต้อง

## MISC-08 — ปรับขั้นตอนยอมรับเงื่อนไขให้กระชับเมื่อกฎหมายอนุญาต

**หลักการ:** ในกรณีที่กฎหมายและนโยบายความเป็นส่วนตัวอนุญาต การระบุว่าการกดปุ่มดำเนินการถือเป็นการยอมรับเงื่อนไข ช่วยลดการคลิกเช็กบ็อกซ์ที่ไม่จำเป็น

### ข้อกำหนด
- **MAY** ลดการใช้เช็กบ็อกซ์ยอมรับข้อตกลงได้ เฉพาะเมื่อได้รับการยืนยันว่าสอดคล้องกับข้อกำหนดทางกฎหมาย
- **MUST** แสดงข้อความระบุเงื่อนไขอย่างชัดเจนติดกับปุ่มยืนยัน พร้อมลิงก์ที่เปิดอ่านข้อกำหนดได้จริง
- **MUST NOT** นำเช็กบ็อกซ์ที่กฎหมายบังคับให้ออกความยินยอมโดยชัดแจ้งออกไปเป็นอันขาด
- **MUST NOT** มัดรวมความยินยอมรับข่าวสารทางการตลาดเข้ากับข้อกำหนดการใช้งานโดยไม่แยกให้ชัดเจน

### แนวทางการนำไปใช้งาน

```html
<div class="mt-4 text-sm text-muted-foreground">
  การกดสร้างบัญชี ถือว่าคุณยอมรับ
  <a href="/terms" class="underline underline-offset-2 text-primary hover:underline focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ring rounded-xs">ข้อกำหนดการใช้งาน</a>
  และ
  <a href="/privacy" class="underline underline-offset-2 text-primary hover:underline focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ring rounded-xs">นโยบายความเป็นส่วนตัว</a>
</div>
```

**การตรวจสอบความถูกต้อง:** ผู้ใช้เข้าใจว่าการคลิกปุ่มมีความหมายถึงการยอมรับ และสามารถคลิกลิงก์เพื่ออ่านเงื่อนไขได้

## MISC-09 — กำหนดชุดตัวเลือกสำเร็จรูปให้เลือกได้ทันที

**หลักการ:** การเตรียมชุดตัวเลือกที่พบบ่อย เช่น ชุดสี หรือจำนวนที่ใช้บ่อย ช่วยลดความซับซ้อนเมื่อเทียบกับการเปิดเครื่องมือเลือกแบบเต็ม

### ข้อกำหนด
- **SHOULD** เตรียมชุดตัวเลือกสำเร็จรูปที่ใช้บ่อยเป็นปุ่มกดให้เลือกได้ทันที
- **MUST** ทำให้สถานะการเลือกสามารถเข้าถึงและใช้งานได้ด้วยคีย์บอร์ด
- **MUST** แสดงสถานะตัวเลือกที่กำลังทำงานอยู่ให้ชัดเจน โดยไม่อาศัยสีเพียงอย่างเดียว

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | แถวปุ่มตัวเลือกสี | `flex items-center gap-2` พร้อมปุ่มที่มีจุดสังเกตสถานะถูกเลือก |
| **A11y** | ระบุชื่อสีเป็นข้อความ | กำหนด `aria-label="สีน้ำเงิน"` บนแต่ละปุ่มสี |

**การตรวจสอบความถูกต้อง:** ผู้ใช้สามารถกดเลือกค่าสำเร็จรูปได้ทันที และทราบว่าค่าใดกำลังถูกเลือกอยู่

## MISC-10 — จัดการเนื้อหาขนาดยาวให้อ่านและขยายดูได้สะดวก

**หลักการ:** เนื้อหาที่มีขนาดยาวในตารางหรือการ์ดควรแสดงตัวอย่างสั้นๆ ก่อน พร้อมเปิดให้อ่านฉบับเต็มได้อย่างสะดวกโดยไม่ตัดทอนข้อมูลทิ้ง

### ข้อกำหนด
- **SHOULD** ตัดทอนข้อความให้แสดงตัวอย่างสั้นๆ ในหน้ารายการ และมีปุ่มอ่านเพิ่มเติมเพื่อเปิดดูฉบับเต็ม
- **MUST** มีช่องทางให้ผู้ใช้อุปกรณ์มือถืออ่านข้อความฉบับเต็มได้ ไม่พึ่งพาการชี้เมาส์เพื่อดูข้อความลอย
- **MUST NOT** ตัดทอนข้อมูลสำคัญจนส่งผลต่อความเข้าใจ เช่น ยอดเงิน หรือเงื่อนไขสำคัญ

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | ตัดข้อความสองบรรทัด | `line-clamp-2` พร้อมปุ่มเปิดอ่านเพิ่มเติม |
| **JavaScript** | ขยายข้อความ | สลับคลาสเพื่อแสดงข้อความเต็มเมื่อคลิกปุ่ม |

**การตรวจสอบความถูกต้อง:** ผู้ใช้บนหน้าจอมือถือสามารถแตะเพื่ออ่านเนื้อหาที่ถูกตัดทอนได้อย่างครบถ้วน

## MISC-11 — เลือกระหว่างการให้กู้คืนกับการถามยืนยัน

**หลักการ:** การกระทำที่ความเสี่ยงต่ำและทำย้อนกลับได้ ควรให้ทำได้ทันทีพร้อมปุ่มกู้คืน ส่วนการกระทำที่อันตรายและย้อนกลับไม่ได้จำเป็นต้องมีกล่องข้อความยืนยัน

### ข้อกำหนด
- **SHOULD** ใช้การลบทันทีพร้อมแสดงแถบแจ้งเตือนและปุ่มกู้คืน สำหรับการกระทำความเสี่ยงต่ำ เช่น การลบข้อความร่าง
- **MUST** ใช้กล่องข้อความยืนยันที่มีความรอบคอบ สำหรับการกระทำอันตรายร้ายแรง เช่น การลบบัญชีผู้ใช้ถาวร
- **MUST** ตรวจสอบให้แน่ใจว่าปุ่มกู้คืนสามารถนำข้อมูลกลับคืนมาได้จริง ไม่ใช่เพียงข้อความจำลอง

### แนวทางการนำไปใช้งาน
| ระดับความเสี่ยง | รูปแบบการตอบสนองที่ถูกต้อง |
| :--- | :--- |
| **ความเสี่ยงต่ำ (กู้คืนได้)** | ดำเนินการทันที พร้อมแถบแจ้งเตือนด้านล่างและปุ่มกู้คืนข้อมูล |
| **ความเสี่ยงสูง (กู้คืนไม่ได้)** | เปิดกล่องข้อความยืนยัน อธิบายผลลัพธ์ และอาจให้พิมพ์ข้อความยืนยัน |

**การตรวจสอบความถูกต้อง:** เมื่อกดปุ่มกู้คืน ข้อมูลจะกลับคืนสู่สถานะเดิมอย่างถูกต้องสมบูรณ์

---

## MISC-12 — การเลื่อนหน้าจอไม่สิ้นสุดเทียบกับการแบ่งหน้า

**หลักการ:** การเลื่อนหน้าจอแบบไม่สิ้นสุดเหมาะกับการค้นหาสำรวจเนื้อหาทั่วไป ส่วนการแบ่งหน้าเหมาะกับงานที่ผู้ใช้ต้องการค้นหาข้อมูลเฉพาะเจาะจงหรือต้องการเข้าถึงส่วนท้ายของหน้า

### ข้อกำหนด
- **SHOULD** ใช้การแบ่งหน้าสำหรับผลการค้นหา ตารางข้อมูล หรือหน้าจอที่ผู้ใช้ต้องการกลับมายังตำแหน่งเดิมได้
- **SHOULD** ใช้การเลื่อนหน้าจอแบบโหลดต่อเนื่องสำหรับฟีดข่าวสารหรือเนื้อหาเพื่อความบันเทิง
- **MUST NOT** ใช้การเลื่อนแบบไม่สิ้นสุดในหน้าที่ผู้ใช้จำเป็นต้องเข้าถึงลิงก์ในส่วนท้ายของหน้า

### แนวทางการนำไปใช้งาน
| บริบทการใช้งาน | รูปแบบที่เหมาะสม |
| :--- | :--- |
| **ตารางข้อมูล / ร้านค้า / รายการค้นหา** | การแบ่งหน้าพร้อมตัวเลขหน้าชัดเจน |
| **ฟีดเนื้อหาสำรวจทั่วไป** | การเลื่อนหน้าจอแบบโหลดอัตโนมัติ |

**การตรวจสอบความถูกต้อง:** สามารถแชร์ลิงก์หรือคั่นหน้าของหน้าผลลัพธ์ที่ต้องการได้เมื่อใช้การแบ่งหน้า

---

## MISC-13 — บริหารความคาดหวังขณะรอโหลดข้อมูล

**หลักการ:** ผู้ใช้รู้สึกว่าเวลารอนานขึ้นเมื่อไม่มีสิ่งใดเคลื่อนไหว การแสดงสถานะการโหลดที่โปร่งใสช่วยลดความหงุดหงิด

### ข้อกำหนด
- **MUST** แสดงตัวบ่งชี้สถานะการโหลดทันทีเมื่อการทำงานใช้เวลามากกว่าสี่ร้อยมิลลิวินาที
- **SHOULD** เปลี่ยนข้อความแจ้งเตือนเมื่อการโหลดใช้เวลานานผิดปกติ เช่น กำลังประมวลผลขั้นตอนสุดท้าย
- **MUST NOT** แสดงเปอร์เซ็นต์ความคืบหน้าที่สร้างขึ้นมาหลอกๆ โดยไม่ตรงกับงานจริง

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | โครงร่างจำลองการโหลด | `animate-pulse bg-muted rounded-md` |
| **A11y** | แจ้งสถานะการโหลด | กำหนด `role="status"` หรือ `aria-busy="true"` |

**การตรวจสอบความถูกต้อง:** มีการแจ้งเตือนความคืบหน้า และหากเกิดข้อผิดพลาดจะแสดงทางเลือกให้ลองใหม่

---

## MISC-14 — รัศมีความโค้งมนขององค์ประกอบที่ซ้อนกัน

**หลักการ:** เมื่อวางกล่องมุมโค้งซ้อนไว้ในอีกกล่องหนึ่ง รัศมีความโค้งมนของกล่องด้านในต้องน้อยกว่ากล่องด้านนอก เพื่อให้ช่องไฟรอบมุมดูสม่ำเสมอ

### ข้อกำหนด
- **SHOULD** กำหนดรัศมีความโค้งมนของกล่องด้านในให้เท่ากับรัศมีความโค้งมนของกล่องด้านนอกลบด้วยความหนาของช่องไฟ
- **AVOID** การใช้มุมโค้งมนขนาดใหญ่เท่ากันทั้งกล่องนอกและกล่องใน จนทำให้มุมด้านในดูบวมและช่องไฟไม่เท่ากัน

### สูตรการคำนวณทางสายตา
```text
รัศมีกล่องด้านใน = รัศมีกล่องด้านนอก - ระยะห่างขอบด้านใน
```

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | โค้งมนต่างระดับ | กล่องนอก: `rounded-2xl p-4`; กล่องใน: `rounded-lg` |
| **Raw CSS** | Radius calculation | กล่องนอกใช้ `border-radius: 16px; padding: 8px;` กล่องในใช้ `border-radius: 8px;` |

**การตรวจสอบความถูกต้อง:** ช่องไฟบริเวณมุมระหว่างกล่องนอกและกล่องในมีความหนาสม่ำเสมอตลอดแนวโค้ง

---

## MISC-15 — ออกแบบหน้าจอว่างเปล่าให้มีประโยชน์

**หลักการ:** หน้าจอว่างเปล่าไม่ควรเป็นเพียงพื้นที่โล่ง แต่ควรบอกสาเหตุและแนะนำสิ่งที่ผู้ใช้สามารถทำต่อไปได้

### ข้อกำหนด
- **MUST** แยกแยะหน้าจอว่างเปล่าตามสาเหตุ: ยังไม่มีข้อมูล กรอกตัวกรองแล้วไม่พบ หรือเกิดข้อผิดพลาดในการโหลด
- **MUST** มีปุ่มสั่งการหรือคำแนะนำขั้นตอนถัดไปเสมอ เช่น ปุ่มสร้างรายการใหม่ หรือปุ่มล้างตัวกรอง
- **MUST NOT** ใช้ภาพหรือข้อความเดียวกันกับทุกกรณีของหน้าจอว่างเปล่า

### แนวทางการนำไปใช้งาน

```html
<div class="flex flex-col items-center justify-center p-8 text-center">
  <div class="rounded-full bg-muted p-4 text-muted-foreground">
    <svg aria-hidden="true" class="size-8">...</svg>
  </div>
  <h3 class="mt-4 text-lg font-semibold text-foreground">ยังไม่มีเอกสารในหมวดหมู่นี้</h3>
  <p class="mt-2 text-sm text-muted-foreground max-w-sm">
    เริ่มต้นสร้างเอกสารฉบับแรกของคุณเพื่อจัดการงานได้อย่างเป็นระบบ
  </p>
  <button type="button" class="mt-6 rounded-lg bg-primary px-4 py-2 text-primary-foreground font-medium hover:bg-primary/90 focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ring">
    สร้างเอกสารใหม่
  </button>
</div>
```

**การตรวจสอบความถูกต้อง:** ผู้ใช้เข้าใจว่าทำไมหน้าจอจึงว่าง และมีปุ่มนำทางไปสู่ขั้นตอนถัดไปทันที

## MISC-16 — หน้าแจ้งข้อผิดพลาดต้องมีทางไปต่อ

**หลักการ:** เมื่อผู้ใช้พบหน้าข้อผิดพลาด เช่น ลิงก์เสียหรือระบบขัดข้อง ต้องมีทางออกที่ชัดเจนเพื่อไม่ให้ผู้ใช้ติดค้าง

### ข้อกำหนด
- **MUST** อธิบายสาเหตุของข้อผิดพลาดด้วยภาษาที่เข้าใจง่าย ไม่ใช้เพียงรหัสตัวเลขทางเทคนิค
- **MUST** มีปุ่มนำทางกลับสู่หน้าหลัก หรือปุ่มลองใหม่อีกครั้งอย่างชัดเจน
- **SHOULD** มีช่องค้นหาหรือรายการหน้าที่แนะนำเพื่อช่วยให้ผู้ใช้ไปต่อได้

### แนวทางการนำไปใช้งาน
| สิ่งที่ควรมี | ตัวอย่างองค์ประกอบ |
| :--- | :--- |
| **คำอธิบายชัดเจน** | `ไม่พบหน้าที่คุณกำลังค้นหา หน้าดังกล่าวอาจถูกย้ายหรือลบไปแล้ว` |
| **ปุ่มสั่งการหลัก** | ปุ่มกลับสู่หน้าหลัก หรือปุ่มติดต่อฝ่ายสนับสนุน |

**การตรวจสอบความถูกต้อง:** หน้าข้อผิดพลาดมีปุ่มที่พากลับสู่ส่วนที่ใช้งานได้ของเว็บไซต์อย่างชัดเจน

---

## MISC-17 — เสริมรายละเอียดเล็กๆ ที่สร้างความประทับใจ

**หลักการ:** การใส่ลูกเล่นปฏิสัมพันธ์เล็กๆ ช่วยสร้างเอกลักษณ์และความน่าใช้งาน แต่ต้องไม่รบกวนหน้าที่หลักและการเข้าถึง

### ข้อกำหนด
- **MAY** เพิ่มการตอบสนองที่ประณีตหลังฟังก์ชันหลัก ความปลอดภัย และประสิทธิภาพทำงานได้อย่างสมบูรณ์แล้ว
- **MUST** ระวังไม่ให้ลูกเล่นบดบังป้ายกำกับ ข้อความเตือน หรือข้อมูลสำคัญ
- **MUST NOT** ซ่อนข้อมูลที่จำเป็นไว้หลังการชี้เมาส์ที่อุปกรณ์สัมผัสเปิดดูไม่ได้
- **MUST** รองรับการปิดการเคลื่อนไหวเมื่อผู้ใช้เปิดโหมดลดการเคลื่อนไหว

### แนวทางการนำไปใช้งาน
| สแต็ก หรือ บริบท | รูปแบบที่แนะนำ | ตัวอย่างคลาส โค้ด หรือ โครงสร้าง |
| :--- | :--- | :--- |
| **Tailwind CSS** | การขยับเล็กน้อยเมื่อชี้เมาส์ | `transition-transform duration-150 hover:-translate-y-0.5 motion-reduce:transform-none` |
| **Raw CSS** | Hover micro-interaction | `transition: transform 150ms;` พร้อม `:hover { transform: translateY(-2px); }` |

**การตรวจสอบความถูกต้อง:** ปิดแอนิเมชันแล้วงานหลักยังคงทำงานได้สมบูรณ์ และลูกเล่นไม่หน่วงการใช้งาน
