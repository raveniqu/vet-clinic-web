# กฎ UX ด้านภาษาและการรับรู้ของผู้ใช้

> **ขอบเขต:** ใช้กฎเหล่านี้กับข้อความแจ้งสถานะ ข้อความเตือนข้อผิดพลาด ปุ่มสั่งการ ลิงก์นำทาง เช็กบ็อกซ์ การแสดงผลตัวเลข และตัวเลือกการเรียงลำดับ
> **ข้อกำหนดส่วนกลาง:** ปฏิบัติตามเกณฑ์ระดับคำสั่ง ลำดับความสำคัญ และขั้นตอนการทำงานใน global.md

---

## LANG-01 — ข้อความแจ้งเตือนและปุ่มสั่งการต้องสื่อความหมายชัดเจน

**หลักการ:** สื่อสารด้วยภาษาธรรมชาติที่ผู้ใช้เข้าใจง่าย บอกขั้นตอนถัดไปที่ทำได้จริง และระบุหน้าที่ของปุ่มอย่างเจาะจง

### ข้อกำหนด
- **MUST** เขียนข้อความแจ้งเตือน สถานะความคืบหน้า และข้อผิดพลาดเป็นภาษาธรรมชาติที่ผู้ใช้ทั่วไปเข้าใจได้
- **MUST NOT** แสดงเฉพาะรหัสเทคนิค เช่น รหัส 500 หรือ System Error โดยไม่มีคำอธิบายความหมายสำหรับผู้ใช้
- **MUST** ระบุขั้นตอนถัดไปที่ทำได้จริงเมื่อเกิดปัญหา เช่น ตรวจสอบข้อมูล ลองใหม่อีกครั้ง หรือกลับสู่หน้าหลัก
- **MUST** ตั้งชื่อปุ่มจากกริยาและผลลัพธ์ที่ชัดเจน เช่น เพิ่มงาน ส่งคำสั่งซื้อ หรือดูรายละเอียด แทนคำกว้างๆ
- **SHOULD** ชี้แจงสถานะอย่างตรงไปตรงมาโดยไม่กล่าวโทษผู้ใช้

### ตารางเปรียบเทียบการใช้คำ
| รูปแบบที่ควรหลีกเลี่ยง | รูปแบบที่แนะนำ |
| :--- | :--- |
| `500 Internal Server Error` | `ขณะนี้ระบบไม่สามารถบันทึกข้อมูลได้ โปรดลองอีกครั้งในภายหลัง` |
| `404 Not Found` | `ไม่พบหน้าที่ต้องการ โปรดตรวจสอบที่อยู่ลิงก์หรือกลับไปหน้าหลัก` |
| `ช่องนี้เว้นว่างไม่ได้` | `กรุณากรอกที่อยู่อีเมลของคุณ` |
| ปุ่ม `ตกลง` | ปุ่ม `บันทึกข้อมูลส่วนตัว` |
| `โปรดรอสักครู่...` | `กำลังแปลงไฟล์วิดีโอ...` |

**การตรวจสอบความถูกต้อง:** อ่านข้อความแล้วตอบได้ทันทีว่าเกิดอะไรขึ้น ต้องทำอะไรต่อ และคาดเดาผลลัพธ์ของการกดปุ่มได้

## LANG-02 — ข้อความของลิงก์ต้องระบุปลายทางชัดเจน

**หลักการ:** ข้อความของลิงก์ควรบอกปลายทางหรือเนื้อหาที่จะได้รับ แม้จะอ่านข้อความนั้นเดี่ยวๆ โดยไม่อ่านประโยครอบข้าง

### ข้อกำหนด
- **MUST** ใช้ข้อความลิงก์ที่มีความหมายสมบูรณ์ในตัวเอง โดยระบุหัวข้อ เนื้อหา หรือจุดหมายปลายทาง
- **MUST NOT** ใช้คำว่า คลิกที่นี่ ที่นี่ อ่านต่อ หรือ ดูเพิ่มเติม โดดเดี่ยว โดยไม่ระบุว่านำพาไปที่ใด
- **SHOULD** วางคำสำคัญไว้ช่วงต้นของข้อความลิงก์เพื่อช่วยให้กวาดสายตาได้รวดเร็ว
- **SHOULD** ให้ข้อความที่มองเห็นตรงกับข้อความที่โปรแกรมอ่านหน้าจอออกเสียง

### ตารางเปรียบเทียบการใช้คำ
| รูปแบบที่ควรหลีกเลี่ยง | รูปแบบที่แนะนำ |
| :--- | :--- |
| `คลิกที่นี่ เพื่อดูยอดเงินคงเหลือ` | `ดูยอดเงินคงเหลือในบัญชี` |
| `อ่านต่อ` | `อ่านขั้นตอนการสมัครสมาชิกฉบับเต็ม` |
| `คลิกที่นี่เพื่อจัดการข้อมูล` | `จัดการการตั้งค่าบัญชีของคุณ` |
| `เรียนรู้เพิ่มเติม` | `อ่านรายละเอียดบริการด้านความปลอดภัย` |

**การตรวจสอบความถูกต้อง:** หากดึงรายการลิงก์ทั้งหมดออกมาแสดงแยกจากหน้าเว็บ ผู้อ่านยังคงเข้าใจว่าแต่ละลิงก์พาไปที่ใด

## LANG-03 — ระบุสัญลักษณ์บนลิงก์ที่เปิดในแท็บใหม่

**หลักการ:** แจ้งเตือนผู้ใช้ล่วงหน้าเมื่อการกดลิงก์จะเปิดหน้าต่างหรือแท็บใหม่ เพื่อไม่ให้ตกใจเมื่อบริบทการใช้งานเปลี่ยนไป

### ข้อกำหนด
- **MUST** เพิ่มสัญลักษณ์หรือข้อความกำกับ เช่น ไอคอนลูกศรเฉียง เมื่อลิงก์ถูกกำหนดให้เปิดในแท็บใหม่
- **MUST** ใช้หลักเกณฑ์นี้กับทั้งลิงก์ภายในระบบและลิงก์ไปยังเว็บไซต์ภายนอก หากพฤติกรรมคือการเปิดแท็บใหม่
- **MUST NOT** แสดงสัญลักษณ์เปิดแท็บใหม่บนลิงก์ที่เปิดในหน้าต่างเดิม
- **SHOULD** ทำให้โปรแกรมอ่านหน้าจอรับรู้พฤติกรรมการเปิดแท็บใหม่นี้ด้วยข้อความกำกับสำหรับเทคโนโลยีช่วยเหลือ

### แนวทางการนำไปใช้งาน

```html
<!-- Tailwind CSS: แสดงไอคอนต่อสายตา พร้อมข้อความกำกับสำหรับโปรแกรมอ่านหน้าจอ -->
<a
  href="https://example.com/guide"
  target="_blank"
  rel="noopener noreferrer"
  class="inline-flex items-center gap-1 text-primary underline underline-offset-4 hover:text-primary/80 focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ring rounded-xs"
>
  อ่านคู่มือการใช้งานระบบ
  <span aria-hidden="true">↗</span>
  <span class="sr-only">(เปิดในแท็บใหม่)</span>
</a>
```

**การตรวจสอบความถูกต้อง:** สังเกตเห็นได้ชัดเจนว่าลิงก์ใดเปิดแท็บใหม่ และพฤติกรรมจริงตรงกับสัญลักษณ์ที่แสดง

## LANG-04 — ป้ายกำกับของเช็กบ็อกซ์ต้องใช้ประโยคเชิงบอกเล่า

**หลักการ:** เมื่อทำเครื่องหมายถูก ข้อความควรบอกสิ่งที่ผู้ใช้ต้องการให้เกิดขึ้นอย่างชัดเจน ไม่ใช้ประโยคปฏิเสธซ้อนที่ทำให้สับสน

### ข้อกำหนด
- **MUST** เขียนป้ายกำกับของเช็กบ็อกซ์ในรูปประโยคเชิงบวกหรือบอกเล่า ที่สะท้อนผลเมื่อถูกเลือก
- **MUST NOT** ใช้ประโยคปฏิเสธ เช่น ไม่ต้องการ... หรือ อย่าส่ง... จนทำให้สับสนระหว่างการเลือกและไม่เลือก
- **MUST** ทำให้ความหมายของการเลือกสอดคล้องกับค่าจริงที่บันทึกในระบบ
- **SHOULD** ระบุความยินยอมให้เฉพาะเจาะจง เช่น รับข่าวสารทางอีเมล หรือ รับข้อเสนอโปรโมชัน

### ตารางเปรียบเทียบการใช้คำ
| รูปแบบที่ควรหลีกเลี่ยง | รูปแบบที่แนะนำ |
| :--- | :--- |
| `ไม่ต้องการรับจดหมายข่าว` | `รับจดหมายข่าวสารทางอีเมล` |
| `ไม่ต้องการให้ส่งข้อเสนอพิเศษ` | `รับข้อเสนอพิเศษและสิทธิประโยชน์` |
| `ยกเลิกการแจ้งเตือนทางระบบ` | `เปิดรับการแจ้งเตือนทางระบบ` |

**การตรวจสอบความถูกต้อง:** เมื่อทำเครื่องหมายถูกในช่อง สามารถอธิบายได้ทันทีว่าระบบจะทำอะไร โดยไม่ต้องตีความคำปฏิเสธซ้ำซ้อน

## LANG-05 — จัดกลุ่มตัวเลขขนาดยาวให้อ่านและตรวจทานง่าย

**หลักการ:** ตัวเลขที่มีหลายหลักควรแบ่งเป็นกลุ่มตามประเภทข้อมูล เพื่อให้อ่านง่ายและลดความผิดพลาดในการกรอกหรือตรวจทาน

### ข้อกำหนด
- **MUST** แบ่งตัวเลขหลายหลักออกเป็นกลุ่มเมื่อการแสดงผลติดกันทำให้อ่านหรือตรวจทานยาก
- **MUST** เลือกรูปแบบการแบ่งกลุ่มตามประเภทข้อมูลจริง เช่น หมายเลขบัตร หมายเลขโทรศัพท์ รหัสอ้างอิง หรือจำนวนเงิน
- **SHOULD** แสดงตัวเลขสถิติขนาดใหญ่ในรูปแบบย่อได้ในบริบทที่ไม่ต้องการความละเอียดทุกหลัก เช่น จำนวนผู้ติดตาม
- **MUST** มีช่องทางให้ดูตัวเลขเต็มได้เสมอเมื่อความแม่นยำเป็นสิ่งจำเป็น
- **MUST NOT** ย่อหรือปัดเศษตัวเลขที่ต้องมีความแม่นยำสูง เช่น ยอดเงินชำระ หรือรหัสพัสดุ

### ตารางตัวอย่างการจัดกลุ่ม
| ค่าตั้งต้น | การแสดงผลที่อ่านง่าย | ประเภทข้อมูล |
| :--- | :--- | :--- |
| `123456789123` | `1234 5678 9123` | รหัสอ้างอิงทั่วไป |
| `4012888888881881` | `4012 8888 8888 1881` | หมายเลขบัตร |
| `0812345678` | `081 234 5678` | หมายเลขโทรศัพท์ |
| `74853` | `74.8K` (แสดงค่าเต็มเมื่อคลิกหรือตรวจ) | จำนวนผู้ติดตาม |

**การตรวจสอบความถูกต้อง:** ตัวเลขอ่านและตรวจทานได้ง่ายขึ้น และค่าจริงในระบบไม่สูญหายหรือเพี้ยนไป

## LANG-06 — ป้ายตัวเลือกการเรียงลำดับต้องใช้ภาษาที่เป็นมิตรต่อผู้ใช้

**หลักการ:** ใช้ภาษาที่อธิบายผลลัพธ์ของการจัดเรียงโดยตรง แทนคำศัพท์เชิงเทคนิคของฐานข้อมูลที่ต้องแปลความหมายในใจ

### ข้อกำหนด
- **MUST** ใช้ชื่อตัวเลือกที่สื่อถึงผลลัพธ์ที่ผู้ใช้จะได้รับ เช่น ยอดนิยม ราคาต่ำสุดก่อน ราคาสูงสุดก่อน หรือรีวิวดีที่สุด
- **SHOULD NOT** แสดงคำว่า เรียงจากน้อยไปมาก เรียงจากมากไปน้อย หรือคำย่อฐานข้อมูลโดยไม่มีบริบทอธิบาย
- **SHOULD** แสดงตัวเลือกที่มีจำนวนไม่มากเป็นปุ่มหรือแท็บให้เห็นโดยตรง แทนการซ่อนไว้ในดรอปดาวน์
- **MUST** ทำให้การจัดเรียงจริงตรงกับชื่อป้ายที่แสดงเสมอ

### ตารางเปรียบเทียบการใช้คำ
| รูปแบบที่ควรหลีกเลี่ยง | รูปแบบที่แนะนำ |
| :--- | :--- |
| `ราคา (น้อยไปมาก)` | `ราคาต่ำสุดก่อน` |
| `ราคา (มากไปน้อย)` | `ราคาสูงสุดก่อน` |
| `คะแนนรีวิว จากมากไปน้อย` | `คะแนนรีวิวสูงสุดก่อน` |
| `ตัวเลือกเรียงลำดับในเมนูดรอปดาวน์` | แสดงปุ่มตัวเลือก: `ยอดนิยม · ราคาต่ำสุด · ราคาสูงสุด · ล่าสุด` |

**การตรวจสอบความถูกต้อง:** ผู้ใช้คาดเดาได้ทันทีว่าเมื่อกดเลือกแล้ว รายการบนหน้าจอจะเรียงลำดับอย่างไร

## รายการตรวจสอบก่อนส่งมอบงาน

- [ ] **LANG-01:** ข้อความผิดพลาดอธิบายเป็นภาษาธรรมชาติ มีขั้นตอนถัดไป และปุ่มระบุการกระทำชัดเจน
- [ ] **LANG-02:** ข้อความของลิงก์ระบุจุดหมายปลายทางชัดเจน ไม่มีคำคลุมเครือโดดเดี่ยว
- [ ] **LANG-03:** ลิงก์ที่เปิดแท็บใหม่มีสัญลักษณ์กำกับและสื่อสารกับโปรแกรมอ่านหน้าจอ
- [ ] **LANG-04:** เช็กบ็อกซ์ใช้ประโยคบอกเล่าเชิงบวก ไม่ใช้ข้อความปฏิเสธซ้อน
- [ ] **LANG-05:** ตัวเลขยาวแบ่งเป็นกลุ่มตามประเภทข้อมูล และยังเข้าถึงค่าเต็มได้
- [ ] **LANG-06:** ตัวเลือกการเรียงลำดับใช้ภาษาที่เข้าใจผลลัพธ์ได้ทันทีและตรงกับการทำงานจริง
